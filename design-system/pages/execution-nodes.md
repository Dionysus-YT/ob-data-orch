# 执行节点 · P1

## 页面与列模型

单张工作面：标题与自动刷新/刷新/注册 → 原有搜索与资格筛选 → 表格 → 已加载统计与右下角最新刷新时间。六列按真实内容分配宽度，表头相对内容居中，单元格垂直居中，不分割为独立卡片，不增加常驻 Inspector。节点名称列此次按用户明确要求居中，属于本页对齐调整。

| 列 | 展示与交互 |
| --- | --- |
| 节点 | 名称链接详情，平台次行；节点 ID 在名称 Tooltip 中完整展示，搜索仍支持 ID。 |
| 节点状态 | 管理、Agent、运行环境、任务槽位四类独立排列，用 Ant Badge + Space 展示实际类别状态。不能将通用接收资格映射成导出、普通导入、旁路导入模块可用。阻断首因可见，其余原因 Tooltip。 |
| 资源使用率 | CPU、内存、磁盘均用 Ant Progress 条及百分比，按低于 50%、50% 至不足 80%、80% 及以上分为浅蓝、黄色、红色三档；浅蓝、红色复用 primary-hover / danger，黄色由现有 warning-border 与 warning 按 70% / 30% 混合，不新增全局 token。分档只表达占用大小，不判断健康或任务资格。列表不常驻逐行采样时间、使用/总容量或目录路径；内存与磁盘悬停、键盘聚焦时用 Ant Tooltip 只显示容量数值与单位，例如“12.0 GiB / 16.0 GiB”，斜杠前后依次为已用量与总量；不显示“已用”“总量”文字或“内存：”“磁盘：”标题，也不重复使用率或磁盘聚合口径文案。离线快照降低强调并在提示中标记；缺失容量提示“容量尚未采集”，缺失使用率显示破折号，不能呈现为 0%。 |
| 执行额度 | 紧凑圆环，蓝色已用、橙色预留、灰色可用；中心只显示 `(已用 + 预留) / 总量` 百分比，不显示“总体占用”。下方按总量、预留、已用排列，GiB 紧随各数值右侧，不独立换行。各分段悬停可见值、占比和含义，下方按钮支持键盘聚焦及零值提示；未知仍显示待核对。 |
| 我的任务 / 全部任务 | 服务端完整聚合运行/等待/核对中数量，采用 Badge 与链接；可信全局管理员显示全部任务，其他账号显示本人任务。缺失投影显示破折号，有效空集合才显示零。链接任务中心并携带节点与账号范围，分页不从当前单页猜测。 |
| 操作 | 行内使用 Ant Dropdown + Menu，触发器为带 EllipsisOutlined 的三点 Button，菜单提供编辑、删除；启用、环境检查继续在详情页。删除明确为永久删除配置，保留历史任务和执行证据、撤销机器身份及未使用注册码；运行或待核对执行时拒绝。确认框先说明对象、不可恢复和历史保留，不自动归档。 |

右上角自动刷新使用 Ant Select，提供关闭、15/30/60/120/300 秒，默认 60 秒，仅本页面会话持有间隔。右下角最新刷新时间是最后一次成功读取列表的时间，失败时保留旧值，不冒充 Agent 资源采样时间。慢请求不重叠，写事务期间跳过，授权失效不继续周期请求；切换间隔或卸载取消旧定时回调，迟到响应沿用读取代与会话隔离。

刷新期间按钮显示 Ant loading 与“刷新中”，列表保留可信旧数据并显示 Ant Spin；按钮和读取入口共同防重。成功后按钮显示勾选图标与“已刷新”，右下角状态及时间同步更新；提示保留至下次读取或会话失效，快速响应也可感知。失败清除成功提示、保留上次成功时间并展示错误；授权失效仍清空事实，卸载或失效响应不得发布完成反馈。

资源图表只是采样事实，不能反向决定任务资格。内存已用量由同一采样的物理总量减可用量得到，不从百分比或 JVM 预算反推。磁盘取已配置目录所在磁盘的最高使用率，其已用与总量必须来自同一份磁盘事实；多个目录可能落在同一磁盘，禁止把重复容量累加为整机容量；任一目录事实无效时保持未知。已用/总量以总量选择共用的 B/KiB/MiB/GiB/TiB/PiB 单位，真实零可用量或零已用量不丢弃。

### 已确认的类别映射

2026-10-09 用户纠正通用资格不能代表模块可用，并确认以下映射；本节取代此前按导入/导出类型展示任务可用性的方案。

| 类别 | 后端事实 | 文案 |
| --- | --- | --- |
| 管理 | `ENABLED` / `DISABLED` / `MAINTENANCE` | 已启用 / 已禁用 / 维护中 |
| Agent | `PENDING` | 待关联 |
| Agent | 已关联 + `NEVER_CONNECTED` / `ONLINE` / `OFFLINE` | 从未连接 / 在线 / 离线 |
| 运行环境 | `NOT_CHECKED` | 未检查 |
| 运行环境 | 原因包含 `ENVIRONMENT_CHECK_AUTHORIZATION_REQUIRED` | 待授权，优先于未授权自动采集的检查中 |
| 运行环境 | `UNCONFIRMED`，且无需补授权 | 待核验，使用 warning，不显示检查异常 |
| 运行环境 | 阻断原因包含 `ENVIRONMENT_CHECK_IN_PROGRESS` | 检查中 |
| 运行环境 | `NORMAL` / `ABNORMAL` / `EXPIRED` | 检查通过 / 检查异常 / 检查已失效 |
| 任务槽位 | `AVAILABLE` / `BUSY` / `UNKNOWN` | 有空位 / 已满 / 未知 |

待关联时不展示未经关联成立的在线结论；环境检查中的明确原因优先于旧环境状态。其余类别互不覆盖。`acceptsNewTasks` 仅用于现有可接收/不可接收筛选与阻断展示；运行环境检查通过不承诺任一种具体任务已经可执行。任务槽位使用 Agent 技术 Worker 上界与占用，与 JVM 执行预算分开。

## 当前接入与后续预算边界

CPU/内存来自授权列表；磁盘通过既有详情 GET 补读，三个并发、采样缓存、修订/启动身份/采样时间匹配，列表更新取消旧代等待，权限失效或卸载清理缓存。页面不触发 Agent 检查、工具执行或真实连接探测。

2026-10-10 已接入服务端 `executionQuota`：物理内存扣除系统预留为总量，执行分配分别投影为预留与已用。未知或无法核对时显示“待核对”，不显示伪造零值。`capacityTotal/capacityUsed` 为 Agent 技术 Worker 上界与占用，仍不是 JVM 预算；预算阻断不能覆盖槽位类别。禁止用主机内存百分比、单页任务数量、示例预算或槽位计数补造额度。

节点登记/编辑增加系统预留和每任务堆外预算的 Ant InputNumber，单位 GiB，空值/零值自动策略；当前默认堆 4G 只读，已有任务参数允许覆盖。比例为可调整工程默认，不能描述为实测承载保证。权限、Agent、启动与原子分配的实际边界见[节点业务设计](../../docs/02-design/execution-node-module.md#2026-10-10-资源预算与任务范围接入)；页面接入与合成测试不声明真实工具或服务已升级。

维护入口见[节点索引](../../web/src/workbench/nodes/README.md)。浏览器覆盖真实页面、离线与未知状态、320/640/1280/1440/1920 布局、200% 缩放及圆环悬停/聚焦；所有数据均为合成夹具。

## 注册与编辑抽屉

2026-10-10 将注册/编辑的独立大表单收敛为 Management / Table 下的右侧 Ant Drawer，按数据源定版规则复用 520px 宽度并限制为视口宽度。保持列表、筛选和刷新间隔的原会话；原有 `/nodes/new`、`/nodes/:id/edit` 路由直接访问同一抽屉。标题固定，正文独立滚动，底栏右对齐取消与保存；不新增 Shell、Token、字段或注册协议。

- 基本信息以浅灰分组呈现：节点名称独占一行，下一行分别选择“操作系统”和“CPU 架构”，窄屏依次排列。按用户确认，操作系统按 Windows、Linux 分类，不在选项中使用具体发行版；CPU 架构采用 lscpu 的 x86_64、aarch64 命名。Windows 下 aarch64 禁用，从 Linux aarch64 切换为 Windows 时归为 x86_64。两个控件由唯一平台值派生，不持有第二份配置；保存期、读取期、授权失效及会话结束后不能更改组合。列表次行显示“操作系统 · CPU 架构”，详情分别展示两项。内部平台枚举、安装包目标及三个指定麒麟环境的支持边界保持原契约，分类命名不扩大实际支持范围。工具运行时以一个浅灰分组呈现工具目录与 Java 8 路径。导出目录保持逐行输入，提示随目标平台变化，不转换已填路径。
- 两种平台的字段帮助均由唯一平台值派生，说明架构选择、工具安装根目录、Java 8 完整路径、导出目录格式及 Agent 运行账号权限。提示与占位示例随选择切换，已填路径保持原值；不在帮助中列发行版名称或系统版本。首次关联区域与注册码弹层按节点平台说明管理员或 root/sudo 启动方式，沿用包内固定入口，不改注册码生命周期或支持范围。
- 执行内存预算是唯一可选折叠区，默认收起；已有显式预算或预算校验失败时展开。保留 GiB 输入、自动策略、4 GiB 默认堆及任务覆盖边界，不将工程默认比例描述为承载保证。
- 客户端与服务端字段错误均进入可聚焦汇总，链接实际输入；预算链接先展开折叠区。输入、错误与帮助建立程序关联，首次打开不报错。
- 未保存关闭、离开或切换节点须确认，默认聚焦“继续编辑”；取消保留当前输入。保存期间禁止关闭和路由离开，业务入口防重；列表旧读取失效，周期读取暂停，编辑保存成功后重新读取列表。
- 创建成功仍跳转节点详情继续 Agent 关联，保存只创建已禁用、待关联的节点；不会自动签发注册码、启动 Agent 或启用节点。编辑成功保留抽屉，以短时 Ant Message 确认保存，无需重新注册。启用与请求环境检查同样只确认动作，任务级预检查边界继续放在详情说明；复制成功短时确认，复制失败在注册材料操作区保留 Ant Alert。
- 401/403/404 使表单旧配置和提交资格失效；列表授权失效同步清空打开的表单。重新读取授权成功前保持阻断，撤销前的迟到写响应不能恢复字段或反馈。

表单、修订、dirty 指纹、校验与 DTO 转换由 `useNodeForm.ts` 唯一持有；页面只协调 Drawer、导航、焦点与列表事务。一次性关联材料继续由详情页的 `useNodeEnrollment.ts` 管理，不进入表单或列表。验证结果及限制见[注册重构记录](../../docs/03-technical/evidence/execution-node-registration-2026-10-10.md)。

### 工具安装根目录与平台布局

登记的工具目录仍为包含 `bin`、`lib`、`conf` 的 4.3.5 安装根目录。Windows 启动文件位于 `<安装根>\bin\windows\obdumper.bat` 和 `obloader.bat`，Linux 位于 `<安装根>/bin/obdumper` 和 `obloader`；不将 `bin/windows` 当成安装根目录，也不自动改写路径。固定环境检查与已有任务预检查共用平台布局规则，错误层级不得判为通过。
