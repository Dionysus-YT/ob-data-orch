# Login · Page Spec

> 状态：P1 · 2026-11-02 · 依据 [DEC-067](../../docs/01-product/decisions.md#dec-067-登录页采用客户品牌标识)及用户选定的第二版页面、第一款 LD 图标
>
> 实现入口：[登录页维护索引](../../internal/deployment/loginpage/README.md)；由 `internal/deployment/login_page.go` 嵌入模板、Token 与本地素材。

登录页位于 Product Shell 之外，不属于任何 Archetype；只收窄 P0，不重定义 Shell、Token 或组件语义。

## 结构

| 区域 | 内容 | 规则 |
| --- | --- | --- |
| 场景区（左，宽视口约 60%） | 选定第二版的原始浅蓝立体场景；宽视口右侧柔和斜边 | 原 JPEG 及配色保持不变，仅在 CSS 使用透明渐变蒙版柔化边缘，不重新提取前景、调色或添加覆盖色层。列最小 384px；较高桌面视口减缓斜边，小窗口取消蒙版，保留左右分栏 |
| 客户标识（左上） | “青海农信 QHRC”透明标识 | 独立于装饰裁切容器，保持原图比例，最大 275×57px；窄屏保留；移除矩形白底，原始 PNG 留作来源比对 |
| 登录区（右，宽视口约 40%） | 第一款 LD 图标 + `LDP / 导数平台` → 失败提示 → 账户、密码、登录 | 列最小 576px；白底留白、400px 唯一表单，无卡片边框或阴影；身份组合位于表单上方 |

## 规则

- 颜色、字体、间距、圆角只消费 `tokens.ts` 生成的 Token；`tokens.css` 由 `npm run tokens:generate` 同时写入前端与登录页，`tokens:check` 校验两处一致。
- 产品展示名称按 2026-11-02 用户决定统一为 `LDP`（Loader & Dumper Platform），中文“导数平台”；采用用户选定的第一款 LD 字形图标，不扩大轻量可视化编排定位。Product Header 按 P0 使用单行 `LD 图标 + LDP 导数平台`；登录文档标题使用 `登录 · LDP`，登录后的文档标题与帮助弹窗也统一为 LDP。代码、资源文件名、API 和运行标识保留现役约定。
- 标识与插画材质色是静态品牌素材，不映射为全局 Token 或业务状态色；客户标识与场景仅用于本页，LD 图标另复用于 Product Header。交互、焦点使用 Primary，失败使用 Danger。不保留旧眉标、轨道纹样、能力行或工具名称；用户后续明确要求删除三类能力和工具名称，以此为准。
- 基础字号沿用 Token：`LDP` 使用分区字号，“导数平台”使用标题字号。图标以 72px 图片盒承接透明安全距，实际着色约 56px；横向组合与下方表单各自居中，间隔 40px。
- 图片与 favicon 必须随二进制嵌入为 `data:` URL；公司标识、LD 图标和装饰场景不引用受保护前端资源或外部地址。场景使用优化 JPEG，图标保留透明 PNG，禁止用整个设计稿截图替代表单。
- 认证前没有 Ant Design：输入框、主按钮与失败提示按 Ant 现役视觉（40px large 控件、2px 焦点光晕、Alert error）手写，仅限本页。
- 账户和密码采用现有 Ant Outlined 图标与占位文字，保留关联的原生 `label` 作为辅助技术名称；控件间距与按钮前间距为 24px。删除重复的传输与会话说明，不改变 HTTPS、会话期限或认证行为。
- 初始账户和密码均为空，不预置 `admin`、不回填失败输入；表单使用 `autocomplete="off"` 提示浏览器不要自动恢复，不能据此声称清除了用户密码管理器中已保存的凭据。
- 浏览器原生登录失败使用 POST→303→GET，GET 落地页保留对应失败状态及 `role="alert"`，密码框标记 `aria-invalid`；通过独立的短时固定反馈枚举 Cookie 传递，读取后清除，刷新只发干净 GET，不重提口令、不重复报错或增加认证尝试。API/非导航调用方保留直接失败状态及原成功协议，详见[安全契约](../../docs/03-technical/credential-access-security-contract.md#登录失败导航与一次性反馈)。
- 渐进增强脚本负责显示/隐藏密码、大写锁定提示、防重复提交及清理浏览器恢复的表单值；脚本不可用时原生提交和刷新仍正确。提交前及后退恢复时，遮罩、显隐名称、按下状态及图标同步；SVG 显隐直接切换 `hidden` 属性。`pageshow` 清空表单并解除 busy；缓存恢复时另移除旧错误及字段错误状态。
- 视口：按用户最终 OMS 小窗口参考，始终保留左右布局。列使用 `minmax(384px, 3fr) minmax(576px, 2fr)`，画布最小 960×560；宽窗口近似 60/40，缩小时自然接近 40/60，表单始终 400px。空间不足时允许浏览器横向或纵向滚动，不改为上下布局、不隐藏插画、不缩小字体或控件。1280 及以上无需整页横向滚动；极窄窗口需横向查看登录区。
- 初次打开在视口至少 900px、表单可完整显示时聚焦账户，且不引起滚动；更窄窗口不因初始聚焦而跳到右侧表单。调整窗口不重建页面或表单，不丢正在输入的内容，不锁定页面滚动位置；页面刷新或后退则清空登录表单。
- 不增加记住密码、找回密码、注册、SSO、验证码、版权或营销文案。
