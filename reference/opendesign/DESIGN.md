# OB Data Orch 前端设计规范

状态：Codex 开发交付基线  
更新日期：2026-08-26  
视觉方向：Operator Signal / Tech Utility

## 1. 使用方式

本文件规定视觉 Token、组件表现和响应式规则。发生冲突时按以下顺序处理：

1. 真实项目的 API、类型、权限和安全契约；
2. `ob-data-orch-workbench-prototype.html` 中已经确认的交互行为；
3. 本文件中的视觉和组件规则；
4. `frontend-style-plan.md` 中的背景、理由和开放问题。

`frontend-style-plan.md` 不是像素级实现规范。原型和本文件更新后，旧规划中的字体、页面数量或“下一阶段”措辞不得反向覆盖当前实现。

## 2. 产品姿态

OB Data Orch 是 OceanBase Loader/Dumper 的受控编排工作台，不是通用数据库客户端或监控大屏。

- 高信息密度，但不以小字号和浅灰文字制造密度。
- 优先表达控制面事实、节点事实、门禁和恢复路径。
- 深墨导航负责定位，浅雾工作区负责操作。
- 主交互色只标识当前动作；状态使用独立语义色并始终配套文字。
- 不添加无来源 KPI、ETA、性能数字或“智能”能力。

## 3. 核心 Token

生产实现应集中绑定在 `web/src/operator-signal.css`，页面和组件不得重复声明另一套根 Token。

```css
:root {
  --bg: oklch(98% 0.005 250);
  --surface: oklch(100% 0 0);
  --fg: oklch(22% 0.02 240);
  --muted: oklch(50% 0.018 240);
  --border: oklch(90% 0.008 240);
  --accent: oklch(58% 0.16 145);

  --info: oklch(50% 0.12 250);
  --success: oklch(45% 0.10 155);
  --warning: oklch(48% 0.10 75);
  --danger: oklch(48% 0.16 28);

  --font-display: 'Segoe UI Variable Display', 'Microsoft YaHei UI',
    'PingFang SC', 'Noto Sans CJK SC', sans-serif;
  --font-ui: 'Segoe UI Variable Text', 'Microsoft YaHei UI',
    'PingFang SC', 'Noto Sans CJK SC', sans-serif;
  --font-mono: 'Cascadia Mono', 'SFMono-Regular', Consolas,
    ui-monospace, monospace;
}
```

派生颜色使用 `color-mix(in oklch, ...)`。禁止在业务组件中新增原始 Hex、按色相命名的 Token 或第二主色。

### 语义色

| 语义 | Token | 用途 |
|---|---|---|
| 信息 / 运行中 | `--info` | 进行中的任务、运行任务占用 |
| 成功 / 可调度 | `--success` | 已成功、已连接、可调度 |
| 警告 / 等待 | `--warning` | 等待节点、需复核、门禁未满足 |
| 错误 / 失败 | `--danger` | 已确认失败、危险操作 |
| 中性 | `--muted` | 已登记、未开始、禁用属性 |

颜色不能成为唯一状态载体。每个状态必须包含可读标签；圆点、进度条和浅底只作为辅助编码。

## 4. 排版

| 角色 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 26 / 34px | 650 |
| 抽屉标题 | 20 / 28px | 600 |
| 分区标题 | 16 / 24px | 600 |
| 正文与表格 | 14 / 22px | 400–550 |
| 辅助信息 | 12 / 18px | 400–550 |
| 状态摘要数字 | 23–24 / 30px | 500，等宽 |

- 中文标题不使用负字距，行高不得低于 `1.35`。
- UI 标签和按钮使用约 `0.02em` 正字距。
- ID、命令、时间、端口、版本、容量和百分比使用等宽字体及 `tabular-nums`。
- 不加载外部 Web Font，避免离线或内网部署发生闪烁和布局漂移。

## 5. 产品壳与布局

- 侧栏：224px，深墨背景；导航行 44px。
- 顶栏：52px，仅承载全局帮助、身份和全局动作。
- 常规页面内容最大宽度：1600px；1920px 下不得退回窄居中栏。
- 内容边距：桌面 28–32px，手机 14px。
- 控件最小高度：44px；导出向导根据权威参照可局部使用 34px 紧凑控件，但可点击热区仍需满足 44px 或有等效间距。
- 表格行：56px 起；列宽优先保障名称、状态和主要事实，低优先级列在窄屏隐藏或重排。

列表页和详情页使用独立路由。长详情不得常驻窄侧栏挤压主表格。抽屉只承载新增、编辑和短流程确认。

## 6. 公共组件契约

### PageHeader

- 左侧：唯一 `h1` 和一句任务导向说明。
- 右侧：最多一个实心主操作，其余为次要按钮。
- 小屏改为上下排列，不压缩标题。

### StatusSummary / StatusProgress

- 所有任务中心、数据源、执行节点和日志中心调用同一组件，不逐页复制方法。
- 每项包含状态圆点、标签、数值、解释和 4px 实心进度条。
- 进度条必须提供 `role="progressbar"`、范围、当前值和业务化无障碍名称。
- 分母为零时显示 0%，不得制造“100% 正常”。

### RefreshButton / DataTableState

- 刷新按钮和结果区域同步设置 `aria-busy`。
- 加载时保留上下文标题，禁止整页空白。
- 空状态说明为什么为空和下一步；筛选空状态与首次空状态文案不同。
- 请求错误使用 `role="alert"`，并在原位置提供重试。

### WorkbenchButton

- 同一操作组只能有一个实心主按钮。
- 主按钮使用深化后的绿色背景和浅色文字，默认与悬停均满足 4.5:1。
- `:focus-visible` 使用 2px 清晰焦点环；禁用是唯一允许降低对比的状态。

### WorkbenchStatus

- 状态圆点尺寸 8px；状态文字不可省略。
- 环境、配置、连接结果和任务终态是不同事实，不合并为同一个“正常/异常”。

### 表格

- 桌面以扫描效率为先，不嵌套卡片。
- 任务、数据源、节点和日志在 640px 以下重排为带字段标签的信息卡，不依赖横向滚动。
- 行操作使用明确动词；图标按钮必须有可访问名称。

### 抽屉与对话框

- 抽屉打开后锁定背景滚动，建立焦点约束，关闭后返回触发控件。
- 有未保存修改时必须确认。
- 危险操作说明影响范围；不得承诺由服务端决定的删除或归档结果。

## 7. 页面规则

### 运行概览

状态摘要、任务活动、待处理事项和最近任务构成首屏。所有演示数据必须明确标注，不暗示真实生产指标。

### 数据源管理

连接状态、启用状态和环境属性独立展示。连接字段变化后已有测试立即失效。测试、保存和危险操作必须有互斥 Busy 状态。

### 导出向导

以 `docs/02-design/assets/high-fidelity/export-v1-wizard.html` 为信息结构参照：六步索引、主表单、272px 摘要和容器内操作栏。该页面允许使用已经确认的蓝色交互体系作为局部例外，不扩散到其他页面。

参数适用性按内容、格式、租户兼容模式和后端契约动态门控。切换模式时必须清理或过滤隐藏残留值。

### 任务中心与任务详情

任务中心是一级入口，详情是独立二级页面。失败详情优先呈现原因、影响、建议动作和检查点资格；恢复操作生成新任务，不覆盖原任务。

### 执行节点

列表只负责筛选和状态扫描，详情独立呈现管理状态、Agent 关联、心跳、环境、容量、目录空间、任务、事件和审计。只有全部调度门禁通过才显示“可调度”。

### 日志中心

日志支持节点、级别、时间范围和内容筛选。页面只展示系统已有事件或日志 API，不模拟远程终端、任意文件读取或实时 Shell。

## 8. 响应式与可访问性

验收宽度：360、390、430、600、768、820、1024、1366、1440、1920px。

- 页面和内部工作区均不得产生非必要横向滚动。
- 920px 以下产品壳改为移动导航结构；不能仅把桌面侧栏堆在页面顶部。
- 所有交互可由键盘完成；焦点顺序跟随 DOM 阅读顺序。
- 每页一个 `h1`，标题不跳级；使用原生按钮、链接、输入和表格语义。
- 正文对比至少 4.5:1，图标和控件边界至少 3:1。
- 动态刷新使用 `aria-live` / `aria-busy`；错误使用 `role="alert"`。
- 位移、缩放和旋转动画遵守 `prefers-reduced-motion`。

## 9. 禁止事项

- 不在生产 Vue 中使用 `v-html` 注入整份原型或动态插入脚本。
- 不复制页面专用的状态摘要、刷新和表格空态实现。
- 不修改 API 含义来迎合原型。
- 不把禁用或证据不足的能力实现成可提交入口。
- 不引入渐变光晕、彩色 KPI 卡片、Emoji 功能图标或装饰性动画。
