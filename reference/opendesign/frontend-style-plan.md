# OB Data Orch 前端视觉重设计与原型规划 v2

## 意图摘要

基于 `ob-data-orch` 现有 Vue 3 代码与产品契约，重新定义一套面向产品评估者的高保真桌面 Web 视觉基线。v2 不沿用旧版“冷灰底 + OceanBase 蓝 + 均质企业后台”的外观，但保留已确认的信息架构、安全语义和能力边界；目标是让产品更像一套成熟的数据库操作控制台，而不是套用通用管理模板。

本规划是意图与验收标准的来源，`ob-data-orch-workbench-prototype.html` 是当前实现。两者已在本轮完成融合；只读代码仓库保持不变。

## 1. 已确认的项目事实

### 产品定位

- OB Data Orch 是 OB Loader/Dumper 4.3.5 的轻量可视化编排平台，不是通用数据库客户端、SQL 编辑器或 ETL 平台。
- 核心价值是把复杂命令参数转为安全的向导配置，并统一承载预检查、命令核对、执行、任务状态与日志。
- 首要用户是开发人员、运维人员、DBA、数据源管理员、节点管理员和系统管理员。
- 产品需要严格区分“代码存在”“合成验证通过”“真实功能可用”和“发布证据齐备”。界面不可把门控能力写成已支持。

### 当前前端实现

- 技术栈：Vue 3.5、TypeScript、Vite、Vue Router、Lucide Vue。
- 全局结构：`ProductShell.vue` 提供 216px 左侧导航、48px 顶栏与内容区。
- 主要路由：首页、数据源、导出/普通导入/旁路导入向导、任务、模板、执行节点、日志、系统设置与权限/凭据。
- 可直接复用的基础组件：`WorkbenchButton`、`WorkbenchIconButton`、`WorkbenchStatus`、`WorkbenchFormField`。
- 当前页面存在两套视觉事实：Design System v0.1 与 `style.css` 中仍服务旧页面的 Card、Wizard、Tree 等历史样式。v2 仅继承两者中已验证的业务密度、状态语义和组件契约，不继承旧配色、圆角、阴影或层级表达。

### 当前设计债务

- 首页仍是空态，尚未体现“系统是否正常、是否繁忙、个人任务是否异常”的扫描价值。
- Export 向导已有真实 API 链路，但步骤顺序、信息分层和旧 Tree/Card 样式尚未对齐 2026-08-22 的产品定版。
- 任务详情信息完整，但运行、成功、失败三类事实的视觉优先级仍需收敛。
- Wizard、Stepper、Log Viewer、Command Preview、Object Selector 尚未进入公共设计系统；原型中应作为 Export 业务模式验证，不提前包装成通用框架。

### 旧视觉基线的问题诊断

- 冷灰背景、白卡片和标准蓝按钮缺少领域辨识度，第一眼更像通用 SaaS 管理台，而不是数据库编排工具。
- 侧栏、顶栏、页面标题和卡片都处在相近的浅色层级，产品壳与任务工作区没有形成清晰的空间关系。
- 过多信息依赖“小字号 + 灰色 + 细边框”降权，复杂页面扫描时缺少一个稳定的视觉锚点。
- 状态色与主交互蓝竞争注意力；运行事实、可点击动作和环境属性容易在视觉上混为一类。
- 34px 控件和 48px 顶栏虽然紧凑，但连续操作时显得局促，图标按钮的视觉尺寸与 44px 可点击热区也未形成一致节奏。
- `OB` 品牌标记、默认蓝色和标准卡片组合过于保守，无法支撑产品评估场景中的“已完成、可信、可交付”印象。

## 2. 设计目标

1. 让产品评估者在 30 秒内理解这是“安全、专注、可追溯的数据库操作控制台”，并能记住其视觉特征。
2. 让普通开发/运维人员在一个稳定流程中完成数据源选择、导出配置、预检查、命令核对与提交。
3. 让状态、门控、失败原因和恢复资格可被快速扫描，且不依赖颜色单独表达。
4. 证明同一视觉系统能够覆盖概览、数据管理、复杂向导和任务详情四种信息密度。
5. 保留与现有 Vue 代码的映射关系，使后续实现可以复用现有组件和 API 语义。
6. 用更清晰的产品壳、操作焦点和证据层级解决旧版均质、泛化和显得陈旧的问题。

## 3. 非目标

- 不改写后端、路由、API、状态机、参数映射或安全契约。
- 不展示 SQL 编辑器、任意命令、任意文件浏览或平台范围外能力。
- 不虚构任务数量、成功率、吞吐量、ETA、节点资源或客户数据。
- 不把 CUT、SQL、对象存储、检查点继续等证据未齐能力表现为稳定可用。
- 不设计移动端完整产品壳；正式验收仍以 1280、1440、1920px 桌面宽度为主。

## 4. 原型交付范围

### 交付格式

- 当前交付为一个自包含 HTML：`ob-data-orch-workbench-prototype.html`。
- 单文件内提供四个可切换的产品视图，保持统一 Product Shell，避免产出互不一致的孤立页面。
- 所有用户可见文案使用简体中文；品牌名、技术名、命令与代码标识保持原文。
- 所有关键区域、标题、导航项、控件和重复项目添加 `data-od-id`。

### 视图 A：运行概览

**用户目标**：快速判断平台当前是否有可见异常、任务是否需要关注、执行节点是否可用。

**结构**：

- 页面标题、权限范围与快照时间。
- 一条轻量状态摘要带，区分“需关注”“运行中”“节点可用”等事实类型。
- 一张主要任务趋势图；仅使用明确标注的“演示数据”或仓库现有合成夹具，不能暗示真实生产指标。
- “待处理事项”紧凑列表：失败任务、预检查阻断、节点失联等不同事实。
- “最近任务”高密度表格，提供状态、任务类型、数据源、节点、更新时间与单一高频操作。
- 无授权数据或无快照时保留真实空态，不以虚假成功数字填充。

**关键交互**：刷新快照、按状态筛选、进入任务详情、键盘 Focus。

### 视图 B：新建导出任务

**用户目标**：在最少认知负担下完成安全的导出配置，并在提交前核对脱敏命令。

**已确认视觉参照**：`docs/02-design/assets/high-fidelity/export-v1-wizard.html` 是导出任务视图的权威高保真来源。该视图采用单一白色向导容器、六步顶部索引、主表单与 272px 摘要栏、容器内固定操作 Footer，以及蓝色主交互状态；其他视图继续沿用 v2 工作台视觉基线。参照稿中的业务结构优先，当前代码中更新后的参数契约、校验与证据门控优先。

**固定六步**：

1. 数据源
2. 导出内容
3. 导出对象
4. 数据格式
5. 执行与输出
6. 预检查与命令

**结构**：

- 六步水平步骤条，当前步骤使用细 2px 主色指示；已完成可回退，未来步骤不可点击。
- 主列承载当前步骤唯一决策；右侧 272px 摘要列只回显关键选择，不形成第二套编辑器。
- 每步最多一个“高级设置”折叠区；第 1 步不显示空高级区，第 6 步只读确认。
- 固定 Footer 保持“上一步 / 状态提示 / 唯一主操作”位置稳定。
- 第 6 步展示摘要、六项预检查、脱敏命令和复制操作；任何字段修改都使预检查失效。

**关键交互**：

- 步骤切换与已完成步骤回退。
- 数据源搜索和选择。
- 导出内容单选、对象范围切换、CSV/CUT/SQL 格式选择。
- 高级设置展开/折叠；不适用项保留可见并说明禁用原因。
- 表单即时校验、预检查失败态、重试预检查、复制脱敏命令。
- 最终提交按钮在预检查通过前禁用；原型只模拟界面状态，不触发真实执行。

### 视图 C：任务详情

**用户目标**：理解任务当前事实、找到失败原因，并选择安全且有资格的下一步。

**结构**：

- 任务标题、不可变任务 ID、任务类型、运行模式与状态。
- 首屏事实摘要：数据源、节点、开始/更新时间、预检查与结果证据等级。
- 冻结配置与脱敏命令作为可展开区域。
- 日志使用时间、级别、来源、消息四列，保持等宽信息和连续性提示。
- 失败状态优先显示原因、影响、建议动作与检查点资格；恢复动作不能覆盖原任务。

**关键交互**：状态视图切换（运行中/成功/失败）、日志级别筛选、复制命令、展开失败详情、打开取消确认对话框。

### 视图 D：数据源管理

**用户目标**：快速确认可用于任务的数据源，理解连接与启用状态，并安全完成新增、编辑、测试、启停和删除/归档操作。

**列表结构**：

- 页面标题与唯一主操作“新增数据源”位于同一基线；页面不增加无来源的 KPI 卡片。
- 筛选带包含关键词、环境、兼容模式、连接状态和启用状态；有活动筛选时提供明确的“重置筛选”。
- 高密度表格显示名称、环境、兼容模式、连接地址、系统租户凭据、连接状态、启用状态、最近测试时间和操作。
- 数据源名称、主机、集群与租户等长字段在单元格内安全截断，并提供可访问的完整值查看方式。
- 列表默认按名称升序；可排序列显示 `aria-sort` 和清晰的升降序状态。
- 连接状态严格区分“可连接、连接失败、测试已失效、测试已过期、测试已请求、测试不可用、未测试”，不得压缩成简单成功/失败两类。
- 环境是属性标签，启用状态是配置状态，连接结果是运行事实；三者在颜色、形状和文案上保持独立。

**新增/编辑抽屉**：

- 使用右侧抽屉承载新增与编辑，不离开列表上下文；抽屉打开时锁定背景滚动并建立 Focus Trap。
- 表单按“基本信息 / 连接信息 / 系统租户凭据 / 连接测试”分区，避免一张超长无层级表单。
- 真实字段覆盖数据源名称、环境、连接类型、兼容模式、主机、端口、集群、租户、用户名、默认数据库、密码、系统租户用户和系统租户密码。
- 连接测试需要选择可用执行节点；测试结果显示状态、完成时间与失败原因，不伪造延迟或吞吐指标。
- 修改任何影响连接的字段后，已有测试结果立即标记为“测试已失效”。
- 保存与测试连接不能同时执行；Busy、错误与成功反馈必须与触发控件保持上下文关联。
- 有未保存修改时关闭抽屉，显示“放弃修改”确认；关闭后焦点返回原触发控件。

**危险操作与安全边界**：

- 启用可直接执行；禁用必须确认，并说明不会取消已运行任务、等待任务仍会重新检查状态。
- 删除/归档使用同一确认入口，由服务端根据引用关系决定物理删除或归档；界面不能预先承诺删除结果。
- 密码、令牌和完整可连接凭据不出现在列表、通知、日志或演示数据中。
- 原型复用 `dataSourceUiFixture.ts` 的安全摘要字段；Fixture 模式下新增、编辑、测试、启停和删除均只演示界面反馈，不执行真实业务操作。

**关键交互**：搜索、组合筛选、排序、刷新、打开行操作菜单、新增/编辑抽屉、连接测试、启用、禁用确认、删除/归档确认、ESC 关闭、Focus Return 与未保存修改确认。

## 5. 关键流程

```text
运行概览
  ├─ 选择“新建导出任务” → 导出向导第 1 步
  ├─ 选择“数据源管理” → 数据源列表
  └─ 选择最近任务 → 任务详情

数据源管理
  ├─ 搜索 / 筛选 / 排序 → 定位目标数据源
  ├─ 新增 / 编辑 → 抽屉表单 → 连接测试 → 保存
  └─ 行操作 → 启用 / 禁用确认 / 删除或归档确认

导出向导
  数据源 → 内容 → 对象 → 格式 → 执行与输出 → 预检查与命令
                                              ├─ 失败 → 返回对应步骤修改
                                              └─ 通过 → 模拟提交 → 任务详情/运行中

任务详情
  ├─ 运行中 → 查看日志 / 取消确认
  ├─ 成功 → 查看结果事实 / 保存为模板入口
  └─ 失败 → 查看原因 / 基于原配置新建 / 资格允许时检查点继续
```

## 6. 视觉系统

### 方向名称：Operator Signal

从 OpenDesign 方向库选择 `tech-utility` 作为正式基线：高信息密度、等宽友好、细分隔线与克制状态底色。v2 的辨识点不是装饰，而是“深墨控制壳 + 浅雾工作区 + 信号绿动作 + 证据化数据排版”。

### 六个根色彩 Token

以下值绑定到 Web Prototype 种子的六个根变量，生成时原样使用：

- `--bg: oklch(98% 0.005 250)`：浅雾页面背景。
- `--surface: oklch(100% 0 0)`：表单、表格与浮层工作面。
- `--fg: oklch(22% 0.02 240)`：主文字，同时派生深墨侧栏背景。
- `--muted: oklch(50% 0.018 240)`：说明、时间与次级元数据。
- `--border: oklch(90% 0.008 240)`：细分隔线、表格行和输入框边界。
- `--accent: oklch(58% 0.16 145)`：唯一主交互信号绿。

使用规则：

- 侧栏使用 `--fg`，文字使用 `--surface` 及其混合色；主内容区不得大面积深色化。
- 信号绿只用于当前导航/步骤的短标记与当前视图唯一主操作；不用于大面积卡片底色。
- Success、Warning、Danger 仍作为语义状态色，但只能出现在状态点、细边框和浅底标签中，并且必须配套文字或图形。
- 普通选中态优先使用前景色、边框粗细或浅混合底色，不把所有选中元素都染成绿色。
- 禁止蓝紫渐变、霓虹光晕、全黑控制台、彩色 KPI 卡片和大面积品牌色背景。

### 字体

- Display：`-apple-system, BlinkMacSystemFont, 'Inter', 'Segoe UI', system-ui, sans-serif`。
- Body：`-apple-system, BlinkMacSystemFont, 'Inter', 'Segoe UI', system-ui, sans-serif`。
- Mono：`'JetBrains Mono', 'IBM Plex Mono', ui-monospace, Menlo, monospace`。
- 中文环境由系统中文字体回退承接；不加载外部 Web Font，不因字体未安装造成闪烁或布局漂移。
- 页面标题 26/34、分区标题 16/24、正文与表格 14/22、元数据 12/18；关键运行数字使用 24/30 等宽数字，不做营销式超大数字。
- 任务 ID、哈希、命令、时间、端口、线程数和表格数值统一启用等宽字体与 `tabular-nums`。

### 布局与密度

- 1440px 为主画板，1280px 保持必要业务列，1920px 只扩展内容呼吸区，不拉宽短字段和表单。
- Product Shell 从现有 `ProductShell.vue` 演进：224px 深墨侧栏、52px 浅色顶栏、28px 页面横向内边距、24px 页面顶部节奏。
- 侧栏按现有四个 `navGroups` 分区；组标题用 11px 等宽大写/字距标签，导航项采用 40px 行高与 3px 当前项短标记。
- 顶栏不再承担大面积品牌表达，只保留全局状态、帮助和账户；页面标题区直接与工作面相连。
- 主体层级依靠 1px 细分隔线、字体权重、留白与局部背景差建立；只允许 Dialog、Popover 和悬浮操作使用阴影。
- 表单、按钮与图标按钮的实际交互高度至少 44px；导航行 44px、表头 40px、常规表格行 48px、日志行 44px。
- 圆角采用 4/6/10px 三档：输入与按钮 6px，浮层 10px，表格与主要工作面不做“大圆角卡片”。
- 页面内容最大宽度按路由区分：概览 1360px、数据源 1360px、向导 1180px、任务详情 1360px；沿用 `route.meta.contentWidth` 的现有实现机制。
- 每个视图只保留一个 Primary Action；其他操作使用 Secondary、Text 或 Icon Button。

### 决定性视觉表达

唯一视觉加强点是“证据轨道”：一条贯穿关键视图的细线式状态结构，将配置、预检查、命令确认、执行与结果事实串联。活动节点使用一次信号绿，历史节点使用深墨，未知/门控节点使用空心标记；轨道旁只展示时间、证据等级和失败原因，不做彩色时间线或流程插画。

### 产品壳与工作面关系

- 深墨侧栏代表“平台范围”，浅色工作区代表“当前任务”；两者在 52px 顶栏处形成干净的直角切分。
- 品牌标记改为紧凑的 `OB / ORCH` 双行字标，不再使用彩色圆角方块；品牌区只出现一次。
- 页面标题、简短说明和主操作位于同一水平基线，标题下不再额外套卡片。
- 概览使用“单一运行摘要 + 一张证据趋势/空态 + 两个表格区”，避免四到六张同构 KPI 卡片。
- 数据源管理使用“筛选带 + 单一高密度表格 + 右侧编辑抽屉”，不把每个数据源拆成卡片。
- 向导使用“步骤索引 / 主决策区 / 证据摘要”三层，而不是 Card 套 Card；任务详情使用“事实摘要 / 证据轨道 / 日志”纵向递进。

## 7. 组件与状态要求

### 直接复用

- Button：Primary、Secondary、Text、Danger。
- Icon Button：30px 紧凑视觉，交互热区在原型中提升到至少 44px。
- Status：运行事实用图形 + 文字；配置状态用 Tag；环境是属性，不伪装成异常。
- Form Field：Label、Required、Helper、Error。

## 8. 内容与数据规则

- 优先复用仓库已有的合成夹具与字段名称，如数据源、节点、任务类型和错误分类。
- 所有示例运行指标必须标记“演示数据”，不得使用“真实”“生产”或“已验证”等误导性文案。
- 不展示密码、真实连接串、完整敏感命令或真实客户数据。
- 命令预览只能显示脱敏形态；密码位置使用固定占位。
- 不显示工具未可靠提供的百分比、ETA、文件数量或字节数。
- 证据未齐能力使用“门控 / 待受控验证 / 历史只读”等准确标签。

## 9. 响应式与可访问性

- 正式桌面检查：1280、1440、1920px；不依赖页面级横向滚动完成主流程。
- 920px 以下可将主体双列重排为单列，但不承诺完整移动端 Product Shell。
- 每个可聚焦元素有清晰 `:focus-visible`；普通文字对比度至少 4.5:1，图标与大字至少 3:1。
- 状态不只依赖颜色；图标按钮有 `aria-label`；表格排序使用 `aria-sort`。
- 长字段省略时提供完整值；日志和命令允许安全换行或受控横向滚动，不能覆盖相邻区域。
- 主要触控/点击目标至少 44px；原型不通过不可见伪元素扩大热区。

## 10. 实现约束

- 使用 Web Prototype 种子和已有布局原语组合，不从零重写全套 CSS；产品壳、向导和日志所需的新类必须集中定义。
- 六个主题色只在根变量定义；侧栏、交互态和层级色使用 `color-mix(in oklch, ...)` 派生，不在组件中散落新色值。
- 方向库的 `tech-utility` 字体栈与六个根色值必须原样绑定；状态色作为语义扩展，不得取代主色。
- 不调用 `scrollIntoView()`；视图和步骤切换通过状态控制。
- 页面保持自包含，不热链外部图片；本产品不需要装饰性人物或场景图。
- 交互仅操作原型内的合成状态，不调用真实 API、不连接数据库、不启动工具。
- 原型逻辑应覆盖导航、数据源组合筛选与排序、抽屉、连接测试反馈、启停/归档确认、步骤切换、折叠、校验、对话框和复制反馈。

## 12. 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 现有全局样式包含旧视觉规则 | 原型可能混入旧蓝色、5px 圆角、650 字重和 Card 阴影等迁移债务 | 旧样式只作为业务结构参考；v2 统一绑定 `tech-utility` Token 与新密度规则 |
| 深墨侧栏被误做成全黑开发者主题 | 工作区可读性下降，状态色过亮 | 深色仅限平台壳；主任务区保持浅色，禁止霓虹、光晕和纯黑背景 |
| 信号绿同时承担交互与成功语义 | 用户难以区分“可点击”和“已成功” | Primary 用实心绿；Success 用小状态点/浅底标签，并始终配文字 |
| Web Prototype 种子偏营销页面 | 可能弱化工作台信息密度 | 保留种子的 Token/Focus/响应式基础，使用其 Grid、Table、Form 原语适配产品壳，不采用营销 Hero/CTA 节奏 |
| 业务能力证据等级复杂 | 文案可能把可见能力误写成可发布能力 | 每个门控项显示证据标签；优先引用产品契约，不根据代码存在推断支持 |
| 单文件承载四个视图 | 状态逻辑可能膨胀 | 数据源页只模拟一组安全 Fixture 与关键操作状态；任务相关视图仍只覆盖一条主流程 |
| 数据源状态维度较多 | 环境、启用与连接结果可能被错误合并 | 三类事实使用不同标签形态与文案；筛选条件也分别保留 |
| 数据源抽屉字段较多 | 1280px 下表单拥挤或滚动失控 | 分区展示、固定抽屉标题/操作区、内容区独立滚动，单列回退时保持字段顺序 |
| 首页缺少真实运行快照 | 无法展示生产数据 | 使用明确标注的合成演示状态；默认入口仍保留“尚无快照”模式 |
