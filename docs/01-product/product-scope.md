# OB Data Orch 产品范围

> 文档状态：V1.0 产品范围基线已收口，官方能力待受控验证  
> 提炼来源：[总体 PRD V0.1](PRD.md)  
> 目标工具版本：OceanBase Loader/Dumper V4.3.5  
> 更新日期：2026-07-20

本文档用于快速对齐 V1.0 的产品边界，不替代总体 PRD。未在 PRD 中确认或尚未完成官方参数核验的内容，不构成产品承诺。

## 当前连接范围

当前工程切片只接受私有 ODP 连接，导出范围限定为单表 CSV。数据源在创建、编辑和命令生成边界均拒绝非 ODP 类型；云 ODP、ODP Sharding 与直连 OBServer 不属于当前切片。本次连接范围决策不改变既有兼容模式产品基线；首条 CSV 导出对 Oracle 模式的限制仍以切片与官方参数映射为准。租户/集群的具体连接表达可以作为已登记数据源的用户名事实保留，但 `--cluster` 等官方参数映射尚未确认时必须标记为“待官方参数映射确认”，不能自行生成命令参数。

## 产品背景

OB Loader/Dumper 提供 OceanBase 数据导入、导出能力，但命令行参数多，存在必填、依赖、互斥、条件显示和版本适用关系。手工配置容易产生遗漏或非法组合，多用户、多执行机器场景下也缺少统一的数据源、执行节点、任务状态、历史命令和日志管理。

OB Data Orch 以轻量 Web 调度平台降低官方命令行工具的使用门槛，将已核验的官方能力转化为向导式配置，并集中完成任务调度、命令确认、状态追踪和日志查看。

## 产品目标

- 降低 OB Loader/Dumper 的学习和使用成本。
- 通过参数联动和提交前检查阻止非法组合。
- 在执行前展示可核对、可复制的完整命令。
- 集中管理数据源和实际运行工具的执行节点。
- 统一展示任务状态、阶段、可靠进度、日志和失败信息。
- 支持历史任务和模板复用，减少重复配置。
- 保持轻量、清晰、可落地，不建设大而全的数据库客户端。

## 主要用户

| 用户 | 核心诉求 |
|---|---|
| 开发人员 / 普通用户 | 创建导入/导出任务，核对命令，查看自己的任务和失败原因，复用历史配置 |
| 运维人员 / DBA | 管理授权范围内任务与模板，排查失败，关注执行节点状态和高风险操作 |
| 数据源管理员 | 管理数据源连接信息和基础连接测试，不承担具体任务权限诊断 |
| 节点管理员 | 管理执行节点、Agent 关联和工具环境，不天然查看业务任务内容 |
| 系统管理员 | 管理平台设置、固定角色、对象范围和审计，不天然拥有全部业务对象权限 |

上述表同时保留用户画像和五类固定权限角色的对应关系；最终职责与组合规则见[权限与安全基线](../02-design/access-control-security-module.md)。

## V1.0 范围

### 核心任务流程

- OBDUMPER 导出向导。
- OBLOADER 普通导入向导。
- OBLOADER 旁路导入独立向导。
- 三类流程的参数校验、完整命令预览、提交执行和任务追踪。

### 公共支撑模块

- 首页运行概览。
- 数据源管理与基础连接测试。
- 执行节点注册、心跳、工具版本和基础资源状态。
- 任务中心、任务详情和实时增量日志。
- 敏感信息脱敏和关键操作审计。
- 模板中心、独立日志中心、节点详情和完整系统设置为 P1 建议范围。

### 首页边界

- 用于快速了解系统是否正常、是否繁忙、个人任务是否异常。
- 只保留一张主要任务趋势图，不堆砌复杂图表。
- 关注实际运行 Loader/Dumper 的执行节点，不监控调度平台所在服务器的资源状态。

## V1.0 明确不做

- 通用数据库客户端、SQL 编辑器或日常数据库对象管理。
- 自研导入、导出协议或迁移执行内核。
- 官方工具未支持的格式、对象、参数或执行能力。
- 自动创建或修改目标表结构。
- 复杂数据清洗、字段转换或 ETL 编排。
- 数据源模块中的复杂权限诊断、对象扫描、容量或性能分析、任务可行性判断。
- 浏览器大文件上传、定时任务、审批流、智能参数推荐或耗时预测。
- 复杂基础设施监控、资源拓扑、日志分析平台或 AI 根因诊断。
- 旁路导入断点续传或从失败点继续。
- 无密码数据源账户；V1.0 数据源密码保持必填。
- 接入其他数据迁移引擎，或将产品定位扩大为通用数据迁移平台。

## 产品设计原则

1. **以任务为中心**：围绕创建、确认、执行、追踪和复盘组织页面。
2. **向导式操作**：按用户决策顺序拆分参数，前置选择控制后续内容。
3. **官方能力一一映射**：执行选项必须映射到官方命令行、官方配置文件或平台调度字段。
4. **官方默认优先**：平台默认不改变官方行为，高级参数由用户主动展开。
5. **主动约束参数**：互斥、依赖和条件显示在界面与提交校验中共同落实。
6. **完整命令可见**：导出、普通导入和旁路导入在提交前均展示完整命令。
7. **数据源独立管理**：向导选择已有且可用的数据源，不重复填写或在向导内修改连接信息。
8. **两类导入分离**：普通导入与旁路导入是两条独立流程，旁路导入不是高级开关。
9. **状态、管理、分析分层**：首页看状态，列表做管理，详情看参数、命令、进度、日志和错误。
10. **不伪造运行信息**：只有工具输出可可靠解析时才显示百分比，不生成虚假 ETA。

## 与官方能力的边界

| 层次 | 职责 |
|---|---|
| OB Loader/Dumper | 实际执行导入、导出及旁路导入能力 |
| 执行节点 | 运行官方工具命令并上报进程、日志与基础资源状态 |
| 平台 | 管理任务配置，校验参数，生成命令，调度执行，采集日志和展示状态 |

V1.0 只对官方能力做可视化封装，不重新实现数据处理能力。参数名、默认值、合法范围、格式适用性、互斥、依赖和版本限制必须以 V4.3.5 官方命令行文档及实际 `--help` 为准。平台调度字段必须与官方执行参数明确区分。

## 待确认事项

### 产品与管理规则

- 数据源名称已确认平台内全局唯一。
- 数据源无引用时可删除，存在任务或模板引用时只能归档。
- 数据源兼容模式连接成功后自动识别；无法可靠识别时人工选择并标记待校验。
- 模板默认在使用时重新选择数据源；固定引用只作为有权预选且可更换。
- 生产任务使用独立能力、预检查和二次确认，不引入审批流。
- 登录页是否由统一认证替代。
- 五类角色、对象范围、生产环境和权限配置字段规则已经确认；认证接入与权限实现仍待技术设计。
- 任务取消对各类工具进程、数据库端任务的准确语义。

### 官方能力核验

- 三类任务全部参数、默认值、合法范围、互斥、依赖、条件显示和版本限制。
- 导出对象类型、单库/多库表达式及兼容模式差异的完整映射。
- 各导入/导出格式的专属参数、数据类型限制和组合规则。
- 普通导入文件匹配、控制文件、字段映射和检查点继续能力的准确边界。
- 旁路导入支持的数据格式、版本组合、RPC 端口获取方式和元数据预检边界。
- `session.config.json` 中任务级、节点级与工具全局配置的边界。
- 数据源的租户兼容模式与官方 `--compat-mode`（MySQL DDL 兼容转换）必须采用不同字段语义和映射规则。

PRD 第 11.3 节提出普通导入和导出可在特定条件下从检查点继续。OBDUMPER 与 OBLOADER V4.3.5 的 `--retry` 已进入参数映射基线；`dump.ckpt` / `load.ckpt` 的生成、发现、不可变快照、路径和兼容语义仍须通过对应 P0 用例，验证前不得把恢复行为作为已通过能力进入验收。

仍缺少官方语义的项目标记为**待官方参数映射确认**；参数语义已知但运行行为缺少证据的项目标记为**待受控验证**。两者在证据完成前均不得写成已支持能力。
