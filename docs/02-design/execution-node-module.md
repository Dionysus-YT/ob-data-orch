## 1. 评审目标

建立轻量的执行节点管理入口，使管理员能够回答：哪些机器已纳管、Agent 是否在线、OBLOADER/OBDUMPER 环境是否可用、当前还能否接收新任务、节点正在执行什么任务，以及任务为什么不能选择某个节点。

本模块向首页、三类任务向导和任务中心提供节点事实，不建设服务器运维平台，也不替代具体任务的路径、数据库、权限或参数预检查。

## 2. 模块边界

### 2.1 包含

- 节点列表、节点注册、查看与编辑管理信息。
- Agent 首次关联、心跳和最近上报时间。
- OBLOADER、OBDUMPER 启动文件、工具版本与基础可执行性检查。
- Java、操作系统、工作目录、日志目录等基础环境事实。
- CPU、内存、相关目录磁盘可用空间和运行任务数的当前快照。
- 最大并发任务数、管理状态、维护状态与接收新任务结论。
- 当前任务、最近任务、最近节点事件和跳转入口。
- 启用、禁用、进入/退出维护、重新检查环境、删除或归档。

### 2.2 不包含

- CPU、内存、磁盘历史曲线、容量预测或基础设施拓扑。
- 告警规则、通知策略、自动扩缩容或跨集群资源编排。
- 远程 SSH、终端、文件管理器、进程管理器或任意命令执行。
- 在线安装、升级、卸载 OB Loader/Dumper、Java 或 Agent。
- 在平台内编辑 `session.config.json`、`session.properties` 等工具配置文件。
- 自动调整 JVM 内存、工具并发、节点并发或数据库资源。
- 在节点检查中验证数据源连接、数据库权限、对象或任务级文件路径。
- 从节点页面直接取消、重试或迁移任务；任务操作仍归属任务详情。

## 3. 设计原则

1. **事实分层**：心跳、环境、管理状态和容量分别记录，不用一个“节点状态”混合表达。
2. **结论可解释**：是否可接收新任务必须列出不满足原因，不能只显示红色“异常”。
3. **任务最终判定**：节点页提供通用事实，具体任务仍在预检查和启动前复验路径、版本和任务条件。
4. **不静默改派**：已提交任务绑定的执行节点不可原地变更，节点异常不触发无提示迁移。
5. **只读环境核对**：环境检查只读取和验证，不安装软件、不修改配置、不创建业务文件。
6. **当前快照而非监控平台**：基础资源只服务节点选择和排障，不提供复杂趋势或伪精确容量建议。

## 4. 角色与权限

| 角色 | 可见范围 | 允许操作 |
|---|---|---|
| 普通任务用户 | 有权使用节点的名称、可用性、版本和容量摘要 | 在任务向导选择节点、查看不可用原因 |
| 运维人员 | 授权范围内节点详情、当前/最近任务和基础事件 | 重新检查环境、进入/退出维护、查看日志入口 |
| 节点管理员 | 授权范围内节点及完整基础环境信息 | 注册、编辑、启停、维护、删除/归档、工具环境和并发配置 |
| 系统管理员 | 默认不因系统管理角色获得节点业务权限 | 需要兼任节点管理员或另有节点能力后按授权范围操作 |

工具路径、主机地址、Agent 日志和注册信息可按权限脱敏；具体角色、对象范围与职责分离遵循[权限与安全基线](access-control-security-module.md)，本稿不定义权限数据库模型。

## 5. 页面结构

| 页面 | 主要职责 | 优先级 |
|---|---|---|
| 节点列表 | 定位节点、理解可用性、查看基础负载并执行状态化操作 | P0 |
| 注册 / 编辑节点 | 维护平台管理字段、关联 Agent、配置工具与目录入口 | P0 |
| 节点详情 | 查看环境事实、资源快照、任务、事件和操作记录 | P1 |

V1.0 不新增节点监控、节点组拓扑、工具安装中心或远程运维等二级页面。

## 6. 节点对象与状态模型

### 6.1 节点对象

一个执行节点代表一台由 Agent 关联、能够运行官方 OBLOADER 或 OBDUMPER 命令的机器。节点名称是平台识别名；主机名、IP、操作系统和资源信息以 Agent 最近可信上报为事实。

项目发布包同时包含 POSIX 启动文件、Windows 批处理入口、OBLOADER、OBDUMPER 和 `conf/session.config.json`。平台仍分别核对两个工具的实际启动文件和版本，不因它们位于同一发布包就合并为一个模糊“工具正常”结论。

### 6.2 四个状态维度

| 维度 | 状态 | 含义 |
|---|---|---|
| 管理状态 | 已启用 / 维护中 / 已禁用 | 管理员是否允许节点接收新任务 |
| 心跳状态 | 在线 / 离线 / 从未连接 | 最近心跳是否处于系统设置的有效窗口 |
| 环境状态 | 未检查 / 正常 / 异常 / 已过期 | 最近一次通用环境检查是否可作为当前依据 |
| 容量状态 | 可用 / 繁忙 | 当前运行任务数是否低于最大并发任务数 |

“异常”和“繁忙”不再与“禁用、维护”混成单一枚举。列表默认呈现一个聚合的“接收新任务”结论，详情可展开四个维度和原因。

### 6.3 接收新任务结论

节点通用层面的“可接收新任务”至少要求：

- 管理状态为已启用；
- 心跳在线；
- 环境检查正常且未失效；
- 当前运行任务数低于最大并发任务数；
- 任务所需的 OBLOADER 或 OBDUMPER 启动文件存在、可执行且版本满足要求。

任务选择时还需叠加任务专属条件，例如本地路径可读/可写、临时目录空间、Direct Load 配置可读取和当前用户权限。节点列表中的通用结论不能替代任务预检查。

### 6.4 状态新鲜度

- 心跳超时阈值来自系统设置，本稿不写死秒数。
- 资源快照和环境检查均展示采样/检查时间。
- 离线后保留最后可信值并标注时间，不把旧值显示为实时值。
- 工具路径、工具文件、Java 或关键目录发生变化时，环境检查结果应失效；可靠的变化识别机制待技术设计。

## 7. 节点列表

### 7.1 页面目标

让管理员和运维人员快速识别不能接收新任务的节点，并进入对应详情或任务，不把列表做成服务器监控大屏。

### 7.2 筛选

- 关键字：节点名称、最近上报主机名或地址。
- 管理状态。
- 心跳状态。
- 环境状态。
- 工具版本或工具可用性。
- 节点组：仅当项目配置节点组时显示，V1.0 不新增独立节点组管理页面。
- 接收新任务：可接收 / 不可接收。

### 7.3 默认列表字段

| 字段 | 展示规则 |
|---|---|
| 节点名称 | 主标识；进入节点详情 |
| 主机摘要 | 最近可信主机名和地址；按权限脱敏 |
| 管理状态 | 已启用、维护中或已禁用 |
| 在线状态 | 在线、离线或从未连接，并显示最后心跳 |
| 工具摘要 | 分别显示 OBLOADER / OBDUMPER 版本或不可用原因 |
| 接收新任务 | 可接收或不可接收；不可接收时展示首要原因和完整原因入口 |
| 任务容量 | 当前运行数 / 最大并发数；达到上限显示繁忙 |
| 资源摘要 | 当前 CPU、内存和相关目录磁盘可用空间，带采样时间 |
| 操作 | 查看、重新检查、维护/启用/禁用和更多 |

Agent 版本、操作系统、Java、完整路径和最近任务不占用默认列表列，进入详情查看。

### 7.4 默认排序与空状态

- 默认把不可接收新任务且最近仍在线的节点放在前面，其次按运行任务数降序；精确排序可在评审后锁定。
- 无节点：说明需要先在机器上部署 Agent 并完成关联；只向有权限用户展示“注册节点”。
- 筛选无结果：保留筛选条件并提供清除筛选。
- 所有节点离线：使用页面级提示说明新任务可能无法启动，不生成基础设施故障结论。

## 8. 注册与编辑节点

### 8.1 注册流程

```text
创建节点记录
→ 填写管理信息和最大并发
→ 获取 Agent 关联指引
→ 在目标机器完成 Agent 部署与关联
→ 收到首次心跳和环境事实
→ 执行环境检查
→ 检查通过后启用
```

- 平台不通过 SSH 远程安装 Agent 或工具。
- Agent 的认证载体、有效期和轮换方式属于安全技术设计；产品只要求注册指引可追踪且敏感信息不重复明文展示。
- 创建节点记录后、首次心跳前显示“从未连接”，不能启用为可接收任务节点。

### 8.2 管理字段

| 字段 | 必填 | 规则 |
|---|---:|---|
| 节点名称 | 是 | 建议平台内全局唯一，避免任务与日志引用歧义 |
| 描述 | 否 | 说明机器用途，不承载连接凭据 |
| 节点组 | 否 | 仅用于权限或生产节点限制；无配置时不显示 |
| 最大并发任务数 | 是 | 大于 0；不根据 CPU 自动替用户设置 |
| OBDUMPER 启动文件 | 条件必填 | 承载导出任务时必须配置并检查 |
| OBLOADER 启动文件 | 条件必填 | 承载普通/旁路导入时必须配置并检查 |
| 默认工作目录 | 是 | Agent 所在机器的绝对路径；不提供浏览器文件管理器 |
| 日志目录 | 是 | 工具与 Agent 日志归集位置；路径合法性由环境检查验证 |

### 8.3 Agent 上报只读字段

- 主机名和地址。
- 操作系统及架构。
- Agent 版本。
- Java 版本。
- CPU、内存和相关目录磁盘信息。
- 实际工具版本。
- 最近心跳和采样时间。

这些字段不能通过表单伪造或覆盖；管理员可以修改平台显示名称和路径配置，但机器事实以 Agent 检查结果为准。

### 8.4 工具版本模型

- OBLOADER 与 OBDUMPER 分别配置一个当前活动启动文件并分别核对版本。
- V1.0 不建设同一节点多版本工具库存、自动切换或在线升级。
- 某一工具不可用不必导致另一工具不可用；节点可只承载导出或只承载导入。
- 版本与平台目标版本不一致时显示明确差异；是否允许某个兼容范围由系统工具设置和任务参数元数据决定，不在节点页推断。

## 9. 环境检查

### 9.1 检查范围

通用环境检查只验证：

1. Agent 当前可通信；
2. 配置的 OBLOADER / OBDUMPER 启动文件存在并可执行；
3. 能够取得各工具实际版本；
4. Java 存在且能够取得版本；
5. 默认工作目录、日志目录存在且具备基础访问能力；
6. 能够读取 CPU、内存、相关目录磁盘和运行任务数；
7. 旁路导入所需 `session.config.json` 可读取时，取得路径、相关配置值与指纹。

### 9.2 明确不检查

- 数据源连通性和数据库账号权限。
- 具体任务的输入/输出路径、对象存储凭据或目标表。
- 某个任务是否有足够磁盘、CPU 或内存完成。
- OBLOADER/OBDUMPER 实际数据执行可行性。
- 业务对象、格式、参数组合或 Direct Load 数据库端版本矩阵。

上述事项在任务预检查中针对选定节点和实际配置验证。

### 9.3 检查结果

| 结果 | 处理 |
|---|---|
| 正常 | 所有适用必需项通过，记录时间和检查证据摘要 |
| 异常 | 至少一个适用必需项失败，列出失败项和脱敏原始错误 |
| 未检查 | 从未完成环境检查 |
| 已过期 | 关键配置变化或检查证据不再代表当前环境 |

环境检查不展示无法证明的百分比；重新检查期间保留上一结果并显示“检查中”，完成后原子更新结果。

## 10. 节点详情

节点详情采用五个紧凑内容区：

1. **运行概览**：四维状态、接收新任务结论、任务容量和资源快照。
2. **工具与目录**：Agent、OS、Java、OBLOADER、OBDUMPER、工作目录、日志目录和 Direct Load 配置摘要。
3. **当前与最近任务**：展示有限数量任务并跳转任务详情/任务中心。
4. **最近节点事件**：首次关联、上下线、检查失败、状态变更等有限事件；完整查询进入日志中心。
5. **操作记录**：注册、编辑、检查、启停、维护、删除/归档等审计摘要。

节点详情不内嵌历史资源图、完整 Agent 日志检索、文件浏览器或远程终端。

## 11. 节点操作

### 11.1 启用

- 首次心跳已收到且最近环境检查正常后才允许启用。
- 启用只恢复候选资格；仍需满足在线、容量、工具和任务条件。

### 11.2 进入维护

- 停止接收新任务，不自动取消正在运行的任务。
- 操作前展示当前运行任务数；如有运行任务，明确说明其继续运行。
- 退出维护后重新依据心跳、环境和容量计算可用性。

### 11.3 禁用

- 用于较长期停用或退役准备，需二次确认。
- 不自动取消运行任务；等待调度任务在启动前复验时被阻断。
- 历史任务中的节点快照不受影响。

### 11.4 删除或归档

- 从未被任务、日志或审计引用的节点可物理删除。
- 存在引用时只能归档，且历史名称、版本和路径摘要继续可追溯。
- 在线、存在运行任务或等待任务时不得物理删除。

### 11.5 重新检查环境

- 只读检查，不修改工具、目录或配置。
- 离线时不可发起，并说明最后心跳时间。
- 检查结果变化不改写历史任务快照。

## 12. 与任务向导及任务中心的关系

### 12.1 任务选择

- 三类向导都显式选择执行节点，不静默自动选中或自动替换。
- 默认节点策略如保留，仅用于候选排序或推荐说明，不绕过用户选择；与系统设置的最终边界待后续评审。
- 候选项展示节点名称、工具版本、接收新任务结论、任务容量和相关路径检查入口。
- 不可选择项保留必要可见性并解释原因；与当前任务完全无关或无权限的节点不显示。

### 12.2 提交与启动复验

- 提交前复验节点在线、已启用、非维护、环境正常、未达并发上限、工具版本适用，并完成任务级路径检查。
- 提交后保存节点名称、节点 ID、工具启动文件、版本、工作目录、配置指纹和检查证据快照。
- 启动前再次复验关键事实；失败时任务保持等待调度并展示具体阻断原因，达到任务启动超时后的终态规则待系统设置与任务状态实现评审。
- 不因节点不可用而静默改派；需要换节点时，先按任务详情规则处理原任务，再基于原配置新建草稿并重新预检查，节点页不代办任务取消。

### 12.3 运行中节点失联

- 节点离线不等于工具进程已失败或已停止。
- 任务保留最后可信状态并显示“状态核对中”，沿用 TC-R07 / TC-FR03。
- Agent 恢复后核对进程、退出码、日志和数据库端事实，再更新任务状态。

### 12.4 本地路径与配置边界

- 节点页验证默认工作/日志目录，不验证每个任务实际输入或输出路径。
- 普通导入和旁路导入的本地文件可读性、导出的输出目录可写性及 `--tmp-path` 空间都在任务预检查中验证。
- `session.config.json` 的 Direct Load 配置只读展示实际值、路径、读取时间和指纹，不在任务或节点页面编辑。

## 13. 首页与日志中心关系

- 首页节点健康区只展示节点名称、接收新任务结论、运行任务数、CPU、内存和最后心跳等摘要。
- 首页默认优先异常、离线、维护、禁用或繁忙节点，点击进入节点列表/详情。
- 节点详情仅展示最近有限事件；跨节点、长时间范围和 Agent 原始日志查询进入日志中心。
- V1.0 不因首页展示 CPU/内存而扩展历史曲线、阈值告警或自动诊断。

## 14. 条件与异常矩阵

| 编号 | 条件 | 页面处理 | 依据 |
|---|---|---|---|
| EN-C01 | 节点从未收到心跳 | 显示从未连接，不允许启用或选择 | 注册边界 |

## 15. 安全与审计

- 注册、编辑、环境检查、启用、禁用、维护、删除和归档均记录操作人、时间、结果与必要摘要。
- Agent 关联认证、平台到 Agent 通信和密钥轮换留待安全技术设计，但不得使用可长期重复展示的明文共享凭据。
- 工具路径、工作目录、主机地址、原始错误和 Agent 日志按角色脱敏。
- 节点页面不提供任意命令输入，环境检查项目必须来自平台固定检查清单。
- 任务用户只能看到选择节点所需信息，不能借节点详情获取无权限主机信息或其他用户日志。

## 16. 验收基线

1. 管理员可创建节点记录，看到 Agent 首次关联、心跳和环境检查结果。
2. 列表能用简洁字段说明节点是否可接收新任务以及原因。
3. OBLOADER 与 OBDUMPER 分别检查，单个工具异常不会误伤另一类任务。
4. 节点管理、心跳、环境和容量不会被混成互斥不清的单一状态。
5. CPU、内存和磁盘只展示当前快照和采样时间，不生成历史监控或性能结论。
6. 维护或禁用不自动取消运行任务，已提交任务不静默改派。
7. 节点离线时运行任务不被立即判失败，恢复后按真实进程证据核对。
8. 节点页不承担任务级路径、数据库、对象、格式和参数检查。
9. Direct Load 节点配置只读进入任务快照，不在平台中编辑。
10. 有历史引用的节点归档后仍能从任务详情追溯原节点事实。

## 17. 已确认产品决策

EN-R01～EN-R19 已于 2026-07-17 全部确认。确认的是执行节点模块边界、状态、环境、资源、任务关系和管理操作的产品语义；Agent 协议、安全认证、阈值与调度实现仍保持待技术设计或后续专项评审。

| 编号 | 议题 | 已确认方案 |
|---|---|---|
| EN-R01 | 模块边界 | 只管理节点注册、在线、环境、容量和任务支撑事实，不建设服务器运维/监控平台 |
| EN-R02 | 状态模型 | 管理、心跳、环境、容量四维分离，页面派生“接收新任务”结论 |
| EN-R03 | 可用性解释 | 不可接收新任务必须展示具体原因，通用结论不替代任务预检查 |
| EN-R04 | 注册方式 | 平台提供 Agent 关联指引，不通过 SSH 远程安装 Agent 或工具 |
| EN-R05 | 工具模型 | OBLOADER、OBDUMPER 分别配置一个活动启动文件并独立检查；V1.0 不做多版本库存和自动切换 |
| EN-R06 | 环境检查 | 只读检查 Agent、工具、Java、基础目录和资源事实，不运行数据任务或修改环境 |

| EN-R09 | 繁忙语义 | 仅当前运行任务数达到最大并发时派生繁忙；资源采样不在无明确阈值时自动阻断 |
| EN-R10 | 任务选择 | 三类向导显式选择节点；默认策略最多用于排序/推荐，不静默自动选中 |
| EN-R11 | 节点快照 | 提交保存节点、工具版本/路径、工作目录、配置指纹和检查证据，不被后续编辑覆盖 |
| EN-R12 | 启动复验 | 提交前和启动前都复验节点关键事实；失败时展示等待阻断原因 |

## 18. 待确认与后续验证项

- 节点名称是否全局唯一。
- Agent 注册认证形式、关联信息有效期和轮换规则：待安全技术设计。
- 心跳超时和任务启动超时已在[系统设置模块专项评审稿](system-settings-module.md)中形成产品语义建议；具体数值、环境检查过期阈值和实现仍待确认。
- 默认节点排序/推荐的入口和不静默选择边界已进入系统设置评审；精确策略枚举和优先级仍待调度设计。
- 节点组与生产任务能力已纳入权限配置基线；精确授权绑定、持久化和服务端校验仍待技术设计。
- 多操作系统下工具启动文件、Java 和目录权限检查的受控验证口径。
