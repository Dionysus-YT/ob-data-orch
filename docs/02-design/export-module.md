## 1. 评审目标

把 PRD 中的六步导出向导推进为可逐项评审的产品方案，明确页面职责、官方参数分组、已核验约束、风险交互和待确认决策。本稿不定义 API、数据库表、命令生成实现或高保真 UI。

## 2. 模块边界

### 包含

- 选择已启用、当前配置已成功测试的数据源。
- 配置导出范围和官方支持的对象类型。
- 配置仅 DDL、仅数据或 DDL + 数据。
- 在官方支持的格式中选择一种数据格式。
- 配置官方支持的输出位置、基础执行参数和高级参数。
- 执行参数预检查、完整命令预览、复制和提交。
- 提交后进入统一任务详情、日志和失败处理。

### 不包含

- 数据库对象浏览器或默认全库对象树扫描。
- 平台自定义导出格式或数据处理引擎。
- 自动修改数据库参数、自动推荐“极速模式”或自动估算耗时。
- 在命令预览区直接编辑命令绕过规则。
- 超出 OBDUMPER V4.3.5 官方能力的存储、对象或参数。

## 4. 六步向导总览

```text
1. 选择数据源
→ 2. 选择导出对象
→ 3. 选择导出内容
→ 4. 选择数据格式（仅包含数据时）
→ 5. 执行与输出配置
→ 6. 参数预检查、完整命令与执行确认
→ 任务详情和日志
```

| 步骤 | 必须回答的问题 | 主要输出 |
|---|---|---|
| 1. 数据源 | 从哪个 OceanBase 数据源导出 | 连接与兼容模式摘要 |
| 2. 对象 | 导出全部对象还是指定对象 | 官方对象参数组合 |
| 3. 内容 | 导出定义、数据还是两者 | `--ddl` 与数据格式的显示条件 |
| 4. 格式 | 数据以哪一种官方格式输出 | 唯一数据格式及专属参数 |
| 5. 执行与输出 | 输出到哪里、在哪个节点、如何运行 | 路径、节点、性能和高级配置 |
| 6. 确认 | 参数是否合法，最终执行什么 | 检查结果、只读完整命令和任务快照 |

## 5. 步骤 1：选择数据源

### 页面内容

- 按名称和环境筛选数据源。
- 单选数据源并展示名称、环境、连接方式、地址/SQL 端口、租户、集群、兼容模式、最近测试状态和时间。
- 提供“重新测试连接”，测试语义与数据源模块一致。

### 规则

- 仅展示用户有权限、已启用且当前连接配置至少成功测试过一次的数据源。
- 不在向导中编辑地址、端口、租户、集群、用户名或密码。
- 进入下一步前连接测试必须成功。
- 任务提交前仍重新检查连接；数据源模块不设硬过期时间。
- 生产数据源展示明确环境标识，但导出权限和生产操作风险在任务预检查与提交确认中处理。

## 6. 步骤 2：选择导出对象

### 导出范围

- **全部导出**：生成 `--all`，隐藏指定对象区域。
- **指定对象导出**：至少添加一个合法对象类型和对象表达式。
- 两种范围在产品界面中严格互斥。虽然官方工具同时收到 `--all` 和具体对象时会优先执行 `--all`，平台仍必须阻止这种会掩盖用户配置的组合。

### 官方对象类型基线

| 页面对象类型 | 官方参数 | 数据能力 | 主要适用条件 |
|---|---|---|---|
| 全部对象 | `--all` | DDL；搭配数据格式时包含全部表数据 | 与任意具体对象参数互斥 |
| 表 | `--table` | DDL 或数据 | 支持多个名称、`*` 和官方表达式 |
| 表组 | `--table-group` | 仅 DDL | 不导出数据 |
| 视图 | `--view` | 仅 DDL | 不导出数据 |
| 触发器 | `--trigger` | 仅 DDL | 仅 Oracle 兼容模式 |
| 用户 | `--obj-user` | 仅 DDL | 公有云模式不支持；存在权限要求 |
| 角色 | `--role` | 仅 DDL | 仅 Oracle 兼容模式；公有云模式不支持 |
| 序列 | `--sequence` | 仅 DDL | 受 OceanBase 数据库版本限制 |
| 同义词 | `--synonym` | 仅 DDL | 仅 Oracle 兼容模式 |
| 类型 | `--type` | 仅 DDL | 仅 Oracle 兼容模式及适用数据库版本 |
| 类型体 | `--type-body` | 仅 DDL | 依赖 `--type` |
| 包 | `--package` | 仅 DDL | 仅 Oracle 兼容模式 |
| 包体 | `--package-body` | 仅 DDL | 仅 Oracle 兼容模式 |
| 函数 | `--function` | 仅 DDL | 兼容模式和数据库版本条件需校验 |
| 存储过程 | `--procedure` | 仅 DDL | 兼容模式和数据库版本条件需校验 |

对象完整列表、数据库版本门槛、权限要求和大小写规则进入完整参数映射表；未逐项锁定的部分统一标记为“待官方参数映射确认”。

### 单库与多库

- 对象表达式不带数据库/Schema 前缀时，使用任务中的默认数据库 `-D`。
- 任一对象表达式包含 `schema.object` 时进入官方多库模式。
- 多库模式由 OBDUMPER 内部拆分为多个单库子任务，平台只展示统一任务和按 Schema 汇总的对象摘要，不暴露内部拆分配置。
- 混合使用带前缀和不带前缀对象时，不带前缀对象仍使用默认数据库。

### 校验

- `--all` 与具体对象配置不可同时存在。
- 仅 DDL 对象不能进入“仅数据”任务。
- `--type-body` 未选择对应 `--type` 时阻断。
- 兼容模式或数据库版本不支持的对象类型不显示或禁用，并说明原因。
- 不合法表达式、空对象清单和无法确定默认数据库时阻断。

## 7. 步骤 3：选择导出内容

| 页面选项 | 命令结构 | 后续流程 |
|---|---|---|
| 仅对象定义 | `--ddl` + 对象参数 | 跳过数据格式步骤 |
| 仅数据 | 一种数据格式 + 可导出数据的对象参数 | 必须进入格式步骤 |
| 对象定义和数据 | `--ddl` + 一种数据格式 + 对象参数 | 必须进入格式步骤 |

规则：

- 只有表和 `--all` 能与数据格式形成数据导出；视图、角色等对象只产生 DDL。
- 同一任务可以同时包含表 DDL、表数据和其他对象 DDL，但摘要必须分别展示。
- “DDL + 数据”增加文件数量和执行时间的风险提示，不承诺耗时估算。
- 仅 DDL 时清除已选数据格式的实际生效状态，最终命令不得包含数据格式参数。

## 8. 步骤 4：选择数据格式

### 格式卡片

| 页面格式 | 官方命令 | 已核验说明 |
|---|---|---|
| CSV | `--csv` | 推荐格式；支持 CSV 专属分隔、包围、转义等参数 |
| CUT | `--cut` | 使用字符串分隔字段 |
| POS（定长） | `--pos`，或在线资料所述 CUT + 空 `--column-splitter` + 控制文件 | 实际 `--help` 已列出独立 `--pos`，与现有在线资料口径不同；在受控实测前不锁定最终命令映射 |
| Insert SQL | `--sql` | 输出 INSERT SQL 数据文件 |
| Parquet | `--par` | 列式格式；`--block-size` 不生效 |
| ORC | `--orc` | 列式格式；内存风险较高；`--block-size` 不生效 |
| Avro | `--avro` | V4.3.5 官方支持 |

### 通用规则

- 同一导出任务只选择一种数据格式。
- 切换格式后保留通用参数；前一格式专属值是否在当前草稿内临时保留由 EX-R05 决定。
- 最终配置和命令只包含当前格式适用参数。
- DDL 是导出内容，不作为数据格式卡片。
- 任何未经官方映射的格式字段标记为“待官方参数映射确认”。

### 已核验的格式约束

- `--column-delimiter` 与 `--column-quote` 同义且不能同时指定；前者已过时，官方推荐 `--column-quote`。
- `--column-quote-mode` 仅适用于 CSV，支持 all、all_not_null、minimal、non_numeric、none，默认 non_numeric。
- `--column-separator` 仅适用于 CSV；V4.3.5 起支持多字符。
- `--column-splitter` 仅适用于 CUT/POS。
- `--escape-character` 仅适用于 CSV 或 CUT。
- `--remove-newline` 仅适用于 CUT，并可能改变导出数据，属于高风险参数。
- `--line-separator` 适用于 CSV、CUT、POS、SQL；`--file-encoding` 默认 UTF-8。
- `--null-string` 仅适用于 CSV/CUT，默认 `\N`；`--skip-header` 仅适用于 CSV。
- 日期时间值格式参数主要适用于 CSV/CUT，并受数据类型与兼容模式限制。
- 压缩导出适用于 CSV、CUT、POS、SQL；算法为 zstd、zlib、gzip、snappy，压缩等级适用范围随算法变化。

## 9. 步骤 5：执行与输出配置

### 输出位置

官方 V4.3.5 已核验支持：

- 执行节点本地绝对路径；
- Aliyun OSS；
- Amazon S3；
- Tencent COS；
- Huawei OBS。

对象存储 URI 由 scheme、bucket、path 和官方参数组成，不提供“任意 URI”输入。访问密钥和 secret-key 按敏感信息处理，默认脱敏，不写入普通日志。

### 输出相关参数基线

| 页面能力 | 官方参数 | 规则 |
|---|---|---|
| 输出位置 | `-f / --file-path` | 必填；本地绝对路径或官方存储 URI |
| 日志目录 | `--log-path` | 可选；不指定时使用官方默认行为 |
| 扁平目录 | `--no-nested-dir` | 可选；改变默认目录层级 |
| 控制文件 | `--ctl-path` | 仅在适用格式或预处理场景显示 |
| 文件拆分 | `--block-size` | 对 ORC、Parquet 不生效；单位和合法格式必须校验 |
| 对象存储临时目录 | `--tmp-path` | Multipart Upload 本地分块目录；校验执行节点空间和写权限 |
| 导出总量上限 | `--max-file-size` | 单进程达到上限后停止导出，单位 Byte |
| 空结果文件 | `--retain-empty-files` | 仅 where/partition 结果为空等适用场景显示 |
| 目录非空处理 | `--skip-check-dir` | 可能覆盖同名文件，专家配置并二次确认 |

### 执行参数分层

| 页面层级 | 参数分类 | 代表参数 |
|---|---|---|
| 普通模式 | 数据源快照、内容/格式、对象范围、主输出、执行节点 | `--database`、格式参数、对象参数、`--file-path` |
| 高级配置 | 文本序列化、压缩、文件布局、导出性能和节点资源 | `--column-quote-mode`、`--compress`、`--thread`、`--mem`、`--tmp-path` |
| 专家配置 | DDL 行为、查询筛选、一致性、日期时间格式、逻辑库和高风险选项 | `--drop-object`、`--sequence-policy`、`--query-sql`、`--snapshot`、`--logical-database` |
| 不展示 | CLI 元参数、导入侧参数、废弃参数和官网未公开参数 | `--mix`、`--parallel`、`--storage-uri`、`--server` |

参数层级不改变官方语义，也不能绕过互斥和版本校验。

### 补充后的参数分类

- **连接与会话**：区分数据源快照、sys 安全配置、字符集、会话配置和逻辑库；向导不重复填写地址和认证信息。
- **格式序列化**：CSV、CUT/POS、通用文本和日期时间参数按格式、兼容模式与数据类型条件显示。
- **DDL 与对象处理**：`--drop-object`、`--add-extra-message`、`--retain-schema`、`--compact-schema`、`--sequence-policy` 进入专家配置。
- **筛选与一致性**：where、partition、query、flashback、snapshot、weak-read、列筛选和隐藏主键统一在任务级预检查。
- **性能与资源**：区分 `--thread` 导出线程、`--parallel-macro` 宏块处理、`--fetch-size` 游标抓取、`--mem` JVM 内存和检查点恢复。
- **兼容治理**：导入侧、已废弃及 help-only 参数保留解析元数据，但不出现在新建任务表单。

## 11. 步骤 6：预检查与完整命令

### 预检查

至少检查：

- 数据源当前是否可连接；
- 当前账号是否满足本次实际对象和操作要求；
- 执行节点在线、工具版本正确且能够访问输出位置；
- 本地目录存在性、可写性、可用空间和非空目录规则；
- 对象存储 scheme、bucket、path、endpoint/region 及凭据完整性；
- 对象表达式、兼容模式、数据库版本和对象类型是否合法；
- 内容、格式和专属参数组合是否合法；
- 参数互斥、依赖、范围和风险确认是否完成。

数据源连接测试不承担这些任务级判断。

### 命令确认

- 展示实际可执行的完整 OBDUMPER 命令。
- 按连接、对象、内容/格式、输出和性能参数分组高亮。
- 数据源密码、sys 凭据、对象存储密钥默认脱敏。
- 命令只读；复制默认复制脱敏版本。
- 任一参数或输出配置变化后，原预检查失效并重新生成命令。

## 12. 失败与检查点继续

- OBDUMPER V4.3.5 官方 `--retry` 支持从最近保存点继续导出。
- 保存点文件为输出目录中的 `dump.ckpt`；不存在时不能继续。
- “从检查点继续”只在失败导出任务满足检查点、输出位置、工具版本和原参数条件时显示。
- 继续执行使用原任务不可变参数快照，不允许先修改参数再继续。
- 不满足条件时提供“基于原配置新建”和“从头重新执行”。
- 检查点兼容性和允许变化的环境字段仍需在完整参数映射与实际工具验证中补齐。

## 13. 验收基线

1. 用户无需手写命令即可完成基础导出配置。
2. 仅 DDL 时不出现数据格式步骤。
3. 全部对象与指定对象不能形成歧义组合。
4. 数据格式单选，专属参数不会跨格式进入最终命令。
5. POS 页面语义明确，且最终命令映射已通过实际程序验证。
6. 输出位置仅限 V4.3.5 官方支持范围。
7. 提交前完成任务级预检查并展示完整只读命令。
8. 敏感连接和存储信息默认脱敏。
9. 失败任务只有存在有效 `dump.ckpt` 时才显示检查点继续。
10. 任务提交后可在任务详情查看参数快照、命令、阶段和日志。

## 14. 已确认产品决策

EX-R01～EX-R17 已于 2026-07-17 全部确认。确认的是产品展示、分层和风险处理方案；其中明确标注“待实测”的命令映射与工具行为仍不得视为官方能力已经定版。

| 编号 | 议题 | 已确认方案 |
|---|---|---|
| EX-R01 | 导出范围 | “全部对象 / 指定对象”严格单选，平台不接受官方会优先 `--all` 的歧义组合 |
| EX-R02 | 内容模型 | 固定为仅 DDL、仅数据、DDL + 数据三选一 |

## 15. 官方资料待实测点

已对官网资料和发布包中的 `obdumper 4.3.5-RELEASE --help` 完成交叉核对。109 个参数的含义、分类、产品处置和来源见[导出参数映射基线](export-parameter-mapping.md)。核查结果如下：

上述冲突项的验证环境、安全边界、用例和证据标准已整理至[最小受控验证计划](export-controlled-validation.md)，当前尚未执行。

- `--block-size` 的正文说明写明默认值为 `0`，同页选项列表写明默认值为 `1024MB`；本稿不预设默认值。
- `--all` 的组合说明明确列举 CSV、SQL、CUT，但同页也提供 ORC、Parquet、Avro 格式；`--all` 与后三类格式的完整组合需实际核验。
- 实际帮助确认空文件参数为 `--retain-empty-files`；不再采用 `--retain-empty-file` 拼写。
- POS 在 V4.3.5 当前页被描述为 CUT + 空 splitter + 控制文件，但旧版官方导出示例和实际 help 使用独立 `--pos`；最终生成方式待受控验证。
- `--mix`、`--file-suffix`、`--ignore-escape`、`--parallel` 已由官网资料确认属于导入侧，不进入导出配置。
- `--storage-uri`、`--file-name`、`--upload-behavior` 已由官方发布说明标记废弃，不提供新建入口。
- `--compact-schema` 和 `--sequence-policy` 有历史官网或发布说明依据，但 V4.3.5 当前选项页约束不完整，进入专家配置候选并待实测。
- `--server`、`--public-synonym`、`--commit-size` 仅本地 help 可见，官网缺少足够语义，不进入配置。
- `--tenant` 独立长参数与官网推荐的 `user@tenant#cluster` 组合形式需验证优先级。

这些差异不影响向导结构，但会阻断参数元数据定版和最终命令生成验收。
