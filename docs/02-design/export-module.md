## 1. 评审目标

把导出向导推进为可逐项评审的产品方案，明确页面职责、官方参数分组、已核验约束、风险交互和待确认决策。本稿不定义 API、数据库表、命令生成实现或高保真 UI。

### 1.1 当前 V1 发布口径（2026-08-22）

产品决策描述目标范围，发布声明还必须满足实现、验证和安全门禁。当前采用以下收敛口径：

- 普通 V1 新建入口只展示 CSV、CUT、SQL；CSV 是已有真实 Windows 链路基线，CUT、SQL 已实现但仍需逐格式真实结果证据。
- POS、Parquet、ORC、Avro 保留旧任务解析和后续门控能力，不在普通 V1 新建入口展示；对象存储在真实凭据认证与远端结果证据完成前保持高级门控。
- 步骤顺序按 2026-09-30 DEC-049 更新为五步；参数能力、常用/高级归属和兼容模式门禁沿用 2026-08-22 定版。运行时与真实数据库验证状态以任务地图为准。
- `--query-sql` 是普通高级筛选参数，不属于敏感参数，不要求 `CAP_SENSITIVE_COMMAND` 或提交级二次确认；仍必须使用普通任务授权、服务端校验、确定性命令生成、预检查和审计。
- 从成功任务保存模板与模板创建草稿保留；未实现的手工新建模板入口不作为 V1 可用能力声明。

## 2. 模块边界

### 包含

- 选择已启用、当前配置已成功测试的数据源。
- 配置导出范围和官方支持的对象类型。
- 配置仅 DDL、仅数据或 DDL + 数据。
- 在官方支持的格式中选择一种数据格式。
- 配置官方支持的输出位置、基础执行参数和高级参数。
- 执行参数预检查、完整命令预览、复制和提交。
- 提交后进入统一任务详情、日志和失败处理。

### 不包含

- 通用数据库对象浏览器或默认全库对象树扫描；导出向导中的有界元数据查询见步骤 2。
- 平台自定义导出格式或数据处理引擎。
- 自动修改数据库参数、自动推荐“极速模式”或自动估算耗时。
- 在命令预览区直接编辑命令绕过规则。
- 超出 OBDUMPER V4.3.5 官方能力的存储、对象或参数。

## 4. 五步向导总览

```text
1. 选择数据源
→ 2. 导出内容与对象（同页）
→ 3. 选择数据格式（仅包含数据时）
→ 4. 执行与输出配置
→ 5. 参数预检查、完整命令与执行确认
→ 任务详情和日志
```

| 步骤 | 常用区 | 唯一高级设置内的分类 | 主要输出 |
|---|---|---|---|
| 1. 数据源 | 已管理数据源、只读连接串、兼容模式 | 无任务级高级设置；连接/会话值只读派生 | 数据源与连接事实快照 |
| 2. 内容与对象 | 结构和数据、仅数据、仅结构；数据库下拉；全部/指定及对象双栏 | 同一高级区内的 DDL、对象排除、数据筛选、列筛选、一致性 | 内容、对象及筛选参数 |
| 3. 格式 | CSV/CUT/SQL、编码、主要分隔符 | 格式序列化、日期时间、压缩 | 唯一数据格式及专属参数 |
| 4. 执行与输出 | 第二步已选节点的只读摘要、数据目录、日志目录、跳过非空目录检查；改节点返回第二步 | 文件布局与生成、性能与资源、门控存储 | 路径、节点和执行参数 |
| 5. 确认 | 检查结果、配置摘要、完整命令 | 无编辑器 | 可提交的不可变预检查与命令快照 |

高级参数采用当前步骤内联折叠区，而不是抽屉。用户偶尔修改少量参数时，折叠区能保留步骤上下文和前后字段关系；展开后用分组标题、锚点或页签导航分类，但不得为每个分类再创建独立折叠框。没有任务级高级项的步骤 1 不显示空折叠区。

### 4.1 参数归属原则

1. 决定“导出什么”的参数放在步骤 2，不放入输出或确认页。
2. 决定“数据如何序列化”的参数放在步骤 3，不因其风险级别移动到其他步骤。
3. 决定“文件写到哪里、如何切分和使用多少资源”的参数放在步骤 4。
4. 数据源、节点或安全策略派生的连接/会话值只读展示，不伪装成任务可编辑参数。
5. 步骤 5 只解释错误并提供返回对应步骤的入口，不复制第二套表单。

## 5. 步骤 1：选择数据源

### 页面内容

- 按名称和环境筛选数据源。
- 单选数据源并展示名称、环境、普通连接串、连接方式、地址/SQL 端口、租户、集群、兼容模式、最近测试状态和时间。连接串只读且不包含密码。
- 提供“重新测试连接”，测试语义与数据源模块一致。

### 规则

- 仅展示用户有权限、已启用且当前连接配置至少成功测试过一次的数据源。
- 不在向导中编辑地址、端口、租户、集群、用户名或密码。
- `--character-set`、`--logical-database`、`--session-config` 及 sys 连接事实由数据源、节点或安全策略派生；本步骤不提供连接/会话高级设置。
- 进入下一步前连接测试必须成功。
- 任务提交前仍重新检查连接；数据源模块不设硬过期时间。
- 生产数据源展示明确环境标识，但导出权限和生产操作风险在任务预检查与提交确认中处理。

## 6. 步骤 2：导出内容与对象（内容区）

| 页面选项 | 命令结构 | 后续流程 |
|---|---|---|
| 导出结构和数据 | `--ddl` + 一种数据格式 + 对象参数 | 进入对象和格式步骤；对象摘要区分 DDL 与表数据 |
| 仅导出数据 | 一种数据格式 + 可导出数据的对象参数 | 进入对象和格式步骤 |
| 仅导出结构 | `--ddl` + 对象参数 | 数据格式步骤显示为不适用且不生成格式参数 |

规则：

- 内容选择属于主流程常用项，不放入高级设置。
- OBDUMPER 4.3.5 只有表和 `--all` 能形成数据输出；`--view` 只能导出定义，不能导出视图数据。仅数据时，所有仅 DDL 对象在同页分类区保留显示但禁用并说明原因。
- “结构和数据”允许同一任务包含表 DDL、表数据和其他对象 DDL，摘要必须分别展示，不能把只导出定义的对象标记为已导出数据。
- 仅结构时，格式值转为 `INACTIVE`，最终命令不得包含数据格式、数据筛选、空文件或数据序列化参数。
- 本步骤只有一个高级设置折叠区；“DDL 与对象处理”分类只在包含结构时活动，承载 `--drop-object`、`--add-extra-message`、`--retain-schema`、`--compact-schema`、`--sequence-policy` 等已映射参数；不适用或证据不足的项可见但禁用。

## 7. 步骤 2：导出内容与对象（数据库、范围和对象区）

### 导出范围

- 数据库/Schema 以可搜索下拉呈现：选择已授权执行节点后，通过同一短租约固定 JDBC 探针按 MySQL `getCatalogs` / Oracle `getSchemas` 读取当前连接账号可见名称，单次最多 100 项。输入关键字继续筛选；目录失败时可选已登记默认值或手动输入明确名称，预检查仍复核访问权限。数据库目录请求的 `objectType=DATABASE` 只允许空 `database`，不得接收 SQL 或任意连接参数。

- **全部导出**：生成 `--all`，隐藏指定对象区域。
- **指定对象导出**：至少选中一个合法对象类型和对象表达式。对象选择区采用左右双栏：左侧按类型显示候选、支持搜索和勾选，右侧展示已选计数、搜索、逐项移除与清空。筛选只影响可见项，不改变已选配置；从整库切回指定范围时保留有效选择。
- 指定对象区选择已授权执行节点后，页面通过该节点的 Agent 固定 JDBC 探针直接读取当前数据库或 Schema 的 `TABLE` 或 `VIEW` 名称。单次最多返回 100 项；截断时提示输入名称关键字继续筛选。名称筛选由固定元数据 API 转义 JDBC 模式通配符，不接受 SQL、驱动、连接串或任意命令。用户也可在折叠区手工添加明确名称；最终对象存在性与访问权限仍由后续固定预检查确认。
- 查询复用短租约和数据库秘密槽位，但独立于基础连接测试结果：要求数据源已启用、最近连接测试为真实 `AGENT_JDBC` 成功、节点已启用且在线、主体同时具备数据源读取和节点使用权限。对象查询若 30 秒内未被 Agent 领取即过期，迟到的 Agent 不得再执行；已领取的查询仍按原短租约完成。页面说明节点未及时处理并允许手动添加，不自动重发真实数据库查询。数据源、凭据或节点事实变化会使未完成查询失效；查询结果仅原发起者在短时有效期内可读取，不写回数据源连接测试状态。
- **排除表**：映射 `--exclude-table`，在全部导出或包含表的范围下按官方规则活动，收进同页唯一高级设置。
- 两种范围在产品界面中严格互斥。虽然官方工具同时收到 `--all` 和具体对象时会优先执行 `--all`，平台仍必须阻止这种会掩盖用户配置的组合。

### 官方对象类型基线

| 页面对象类型 | 官方参数 | 数据能力 | 主要适用条件 |
|---|---|---|---|
| 全部对象 | `--all` | DDL；搭配数据格式时包含全部表数据 | 与任意具体对象参数互斥 |
| 表 | `--table` | DDL 或数据 | 支持多个名称、`*` 和官方表达式 |
| 表组 | `--table-group` | 仅 DDL | 不导出数据 |
| 视图 | `--view` | 仅 DDL | OBDUMPER 4.3.5 明确不支持导出视图数据 |
| 触发器 | `--trigger` | 仅 DDL | 仅 Oracle 兼容模式 |
| 用户 | `--obj-user` | 仅 DDL | 公有云模式不支持；存在权限要求 |
| 角色 | `--role` | 仅 DDL | 仅 Oracle 兼容模式；公有云模式不支持 |
| 序列 | `--sequence` | 仅 DDL | 受 OceanBase 数据库版本限制 |
| 同义词 | `--synonym` | 仅 DDL | 仅 Oracle 兼容模式 |
| 类型 | `--type` | 仅 DDL | 仅 Oracle 兼容模式及适用数据库版本 |
| 类型体 | `--type-body` | 仅 DDL | 依赖 `--type` |
| 包 | `--package` | 仅 DDL | 仅 Oracle 兼容模式 |
| 包体 | `--package-body` | 仅 DDL | 仅 Oracle 兼容模式 |
| 函数 | `--function` | 仅 DDL | 兼容模式和数据库版本条件需校验 |
| 存储过程 | `--procedure` | 仅 DDL | 兼容模式和数据库版本条件需校验 |

对象完整列表、数据库版本门槛、权限要求和大小写规则进入完整参数映射表。下拉中保留全部官方对象类型；不适用当前内容、兼容模式、数据库版本或权限证据的选项显示禁用原因，未逐项锁定的部分标记为“待官方参数映射确认”。

### 单库与多库

- 对象表达式不带数据库/Schema 前缀时，使用任务中的默认数据库 `-D`。
- 任一对象表达式包含 `schema.object` 时进入官方多库模式。
- 多库模式由 OBDUMPER 内部拆分为多个单库子任务，平台只展示统一任务和按 Schema 汇总的对象摘要，不暴露内部拆分配置。
- 混合使用带前缀和不带前缀对象时，不带前缀对象仍使用默认数据库。

### 校验

- `--all` 与具体对象配置不可同时存在。
- 仅 DDL 对象不能进入“仅数据”任务。
- `--type-body` 未选择对应 `--type` 时阻断。
- 兼容模式或数据库版本不支持的对象类型保留显示但禁用，并说明“Oracle 模式兼容”“MySQL 模式兼容”或具体证据门槛。
- 不合法表达式、空对象清单和无法确定默认数据库时阻断。

### 唯一高级设置

高级设置内部按以下分类呈现，分类本身不是独立折叠框：

- **数据筛选**：`--where`、`--partition`、`--query-sql`。
- **列与类型筛选**：`--include-column-names`、`--exclude-column-names`、`--exclude-data-types`、`--exclude-virtual-columns`、`--enable-hidden-pk`。
- **一致性**：`--flashback-scn`、`--flashback-timestamp`、`--snapshot`、`--weak-read`。

`--query-sql` 使用普通多行文本输入，不标记为敏感，不要求额外 capability 或二次确认；页面不提供 SQL 编辑器、文件浏览或 `file://`。它与 `--where`、`--partition`、`--flashback-scn`、`--flashback-timestamp` 互斥：选择前即禁用冲突项；恢复到冲突草稿时阻断并指向冲突字段，不静默删除用户值。

## 8. 步骤 3：选择数据格式

### 格式卡片

| 页面格式 | 官方命令 | 常用区字段 | V1 新建状态 |
|---|---|---|---|
| CSV | `--csv` | 文件编码、列分隔符、行分隔符 | 展示；推荐默认格式 |
| CUT | `--cut` | 文件编码、列切分符、行分隔符 | 展示 |
| Insert SQL | `--sql` | 文件编码、行分隔符 | 展示 |

POS、Parquet、ORC、Avro 不出现在普通 V1 新建卡片中。它们的历史能力版本、任务快照和结果必须继续可读；后续若重新进入新建入口，必须发布新元数据版本并通过对应证据门禁。

### 通用规则

- 同一导出任务只选择一种数据格式。
- 仅结构时本步骤保持步骤位置和摘要，但表单显示“不适用”，不要求选择格式。
- 切换格式后保留通用参数；前一格式专属值是否在当前草稿内临时保留由 EX-R05 决定。
- 最终配置和命令只包含当前格式适用参数。
- DDL 是导出内容，不作为数据格式卡片。
- 任何未经官方映射的格式字段标记为“待官方参数映射确认”。

### 已核验的格式约束

- `--column-delimiter` 与 `--column-quote` 同义且不能同时指定；前者已过时，官方推荐 `--column-quote`。
- `--column-quote-mode` 仅适用于 CSV，支持 all、all_not_null、minimal、non_numeric、none，默认 non_numeric。
- `--column-separator` 仅适用于 CSV；V4.3.5 起支持多字符。
- `--column-splitter` 在当前普通入口仅适用于 CUT。
- `--escape-character` 仅适用于 CSV 或 CUT。
- `--remove-newline` 仅适用于 CUT，并可能改变导出数据，属于高风险参数。
- `--line-separator` 适用于 CSV、CUT、SQL；`--file-encoding` 默认 UTF-8。
- `--null-string` 仅适用于 CSV/CUT，默认 `\N`；`--skip-header` 仅适用于 CSV。
- 日期时间值格式参数主要适用于 CSV/CUT，并受数据类型与兼容模式限制。
- 压缩导出适用于 CSV、CUT、SQL；算法为 zstd、zlib、gzip、snappy，压缩等级适用范围随算法变化。

### 唯一高级设置

- **格式序列化**：CSV 的表头、包围、转义、空值和修剪；CUT 的尾分隔符、换行处理、转义、空值和修剪；SQL 只展示官方适用项。
- **日期时间**：按格式、兼容模式和已验证数据类型展示。MySQL 已验证的 DATE/DATETIME 参数可配置；Oracle NLS/TZ/LTZ 等未完成证据的参数保留显示并禁用。
- **压缩**：开关、算法、等级。gzip/snappy 不支持压缩等级时立即禁用并清除活动状态，但草稿命名空间可保留旧值用于恢复提示。

## 9. 步骤 4：执行与输出配置

### 输出位置

普通 V1 以执行节点本地路径作为主流程。OBDUMPER 4.3.5 官方支持的 OSS、S3、COS、OBS 保留在同页高级门控分类中；真实凭据认证与远端结果证据完成前不可提交，不提供任意 URI 输入。访问密钥和 secret-key 按秘密处理，不写入命令行或普通日志。

### 输出相关参数基线

| 页面能力 | 官方参数 | 规则 |
|---|---|---|
| 输出位置 | `-f / --file-path` | 必填；本地值是用户填写的本次任务完整绝对路径，平台不追加子目录；对象存储使用官方 URI |
| 日志目录 | `--log-path` | 可选；不指定时使用官方默认行为 |
| 目录非空处理 | `--skip-check-dir` | 常用区显式复选项；仅勾选时生成，并提示可能覆盖同名文件 |
| 扁平目录 | `--no-nested-dir` | 可选；改变默认目录层级 |
| 文件拆分 | `--block-size` | CSV/CUT/SQL 按官方合法单位校验 |
| 对象存储临时目录 | `--tmp-path` | Multipart Upload 本地分块目录；校验执行节点空间和写权限 |
| 导出总量上限 | `--max-file-size` | 单进程达到上限后停止导出，单位 Byte |
| 空结果文件 | `--retain-empty-files` | CSV/CUT/SQL 的数据导出均可配置；仅结构禁用，不要求先选择 where/partition |

### 执行参数分层

| 页面层级 | 参数分类 | 代表参数 |
|---|---|---|
| 普通模式 | 内容、对象范围、格式主选项、主输出、执行节点 | `--ddl`、对象参数、`--csv/--cut/--sql`、`--file-path` |
| 高级设置 | 当前步骤相关的完整专业参数，按分类组织 | DDL 行为、筛选、一致性、序列化、压缩、文件布局、性能和资源 |
| 派生只读 | 数据源、节点或安全策略提供，不在任务中编辑 | host、port、user、password 引用、`--character-set`、`--logical-database`、`--session-config` |
| 不展示 | CLI 元参数、导入侧参数、废弃参数和官网未公开参数 | `--mix`、`--parallel`、`--storage-uri`、`--server` |

参数层级不改变官方语义，也不能绕过互斥和版本校验。

### 唯一高级设置

- **文件布局与生成**：`--no-nested-dir`、`--block-size`、`--max-file-size`、`--retain-empty-files`。
- **性能与资源**：`--thread`、`--parallel-macro`、`--fetch-size`、`--mem`、检查点相关只读资格。
- **对象存储**：OSS/S3/COS/OBS、受控 URI、凭据引用和 `--tmp-path`，证据不足时显示门控状态而不是伪装可用。
- **兼容治理**：导入侧、已废弃及 help-only 参数保留解析元数据，但不出现在新建任务表单。

`--retain-empty-files` 的界面说明必须覆盖两类语义：指定 `--partition` 或 `--where` 时，空分区/空结果仍生成文件；未使用筛选时，空表也生成空文件。CSV 默认包含表头，同时启用 `--skip-header` 时生成完全空文件。官方说明中的单数拼写 `--retain-empty-file` 视为文案笔误，命令生成统一使用选项列表中的复数 `--retain-empty-files`。

## 11. 步骤 5：预检查与完整命令

### 预检查

至少检查：

- 数据源当前是否可连接；
- 当前账号是否满足本次实际对象和操作要求；
- 执行节点在线、工具版本正确且能够访问输出位置；
- 本地目录可写性、可创建性、可用空间和非空目录规则；已存在目录直接核验，OBDUMPER 将创建的目标目录则核验其最近既有父目录，预检查不提前创建用户目录；
- 对象存储 scheme、bucket、path、endpoint/region 及凭据完整性；
- 对象表达式、兼容模式、数据库版本和对象类型是否合法；
- 内容、格式和专属参数组合是否合法；
- 参数互斥、依赖、范围和风险确认是否完成。

数据源连接测试不承担这些任务级判断。

### 命令确认

- 展示实际可执行的完整 OBDUMPER 命令。
- 按连接、对象、内容/格式、输出和性能参数分组高亮。
- 数据源密码、sys 凭据、对象存储密钥默认脱敏。
- 命令只读；复制默认复制脱敏版本。
- 任一参数或输出配置变化后，原预检查失效并重新生成命令。

## 12. 失败与检查点继续

- OBDUMPER V4.3.5 官方 `--retry` 支持从最近保存点继续导出。
- 保存点文件为输出目录中的 `dump.ckpt`；不存在时不能继续。
- “从检查点继续”只在失败导出任务满足检查点、输出位置、工具版本和原参数条件时显示。
- 继续执行使用原任务不可变参数快照，不允许先修改参数再继续。
- 不满足条件时提供“基于原配置新建”和“从头重新执行”。
- 检查点兼容性和允许变化的环境字段仍需在完整参数映射与实际工具验证中补齐。

## 13. 验收基线

1. 用户无需手写命令即可完成基础导出配置。
2. 仅结构时数据格式步骤明确显示“不适用”，且不生成任何数据格式参数。
3. 全部对象与指定对象不能形成歧义组合。
4. 数据格式单选，专属参数不会跨格式进入最终命令。
5. 普通新建只展示 CSV、CUT、SQL；POS 与结构化格式的历史任务仍可正确读取。
6. 输出位置仅限 V4.3.5 官方支持范围。
7. 提交前完成任务级预检查并展示完整只读命令。
8. 敏感连接和存储信息默认脱敏。
9. 失败任务只有存在有效 `dump.ckpt` 时才显示检查点继续。
10. 任务提交后可在任务详情查看参数快照、命令、阶段和日志。

### 14.1 风险相称与开发效率

安全控制按实际副作用分级，不把生产级授权流程无差别施加到合成、离线和无秘密验证；但低风险分级也不能绕过执行层硬边界。

| 等级 | 场景 | 默认要求 | 开发约束 |
|---|---|---|---|
| S0 | 版本化 fixture、假 Agent、假工具、临时目录，无网络、秘密或用户数据 | 自动化测试与静态检查 | 无需人工确认或外部依赖 |
| S1 | 结构化校验、脱敏命令预览、历史 fixture 重放，不连接真实环境或启动工具 | 本地身份/功能开关和边界负例 | 同一操作不重复确认，错误提供稳定修复动作 |
| S2 | 已登记节点、真实工具或非生产数据源 | 明确对象、节点、动作和期限的授权，执行前预检查并保留证据 | 授权范围内不重复索要内部步骤确认，范围变化或过期须重新授权 |
| S3 | 明确列入敏感命令或高影响能力清单的操作 | 独立 capability、提交级二次确认、审计和不可变风险指纹 | 只适用于契约明确标记的能力；`--query-sql` 不属于本级 |
| S4 | 生产、破坏性、覆盖或不可逆操作 | 独立明确授权、最小权限、二次确认、恢复方案和完整证据 | 不以开发进度为由简化或旁路 |

S0/S1 的可重复入口是 `scripts/verify-export-synthetic.ps1` 或 `scripts/verify-export-synthetic.sh`。任何真实凭据、真实网络、真实工具、用户数据库和生产操作仍按 S2～S4 门禁执行；浏览器开关不能替代服务端授权、命令生成器复验、Agent 固定信封、租约/幂等、日志脱敏或结果证据。

## 16. Export v1 执行与取消闭环

任务状态 `WAITING_SCHEDULE`、`STARTING`、`RUNNING`、`CANCELLING`、`SUCCEEDED`、`FAILED`、`CANCELLED` 的含义由控制面投影；页面不依据 Agent 自报状态直接改写任务。

- 浏览器通过 `POST /api/v1/tasks/{taskId}:cancel` 提交取消意图，必须带 CSRF 和 `Idempotency-Key`；同一幂等键异摘要冲突，重复请求返回同一取消结果。
- `WAITING_SCHEDULE` 任务在短事务内直接写入 `CANCELLED` 和固定 `CANCELLED_BY_REQUEST` 证据；`STARTING/RUNNING` 任务只进入 `CANCELLING`，不由浏览器直接碰触节点进程。
- Agent 在有效租约内调用固定 `OBDUMPER_EXPORT_POLL_CONTROL` 信封轮询；控制面比较 Agent、execution、租约 epoch、冻结任务信封摘要和租约有效期。收到取消后，Agent 使用平台适配的进程树控制终止受控 Java 进程，并按事件序列上报 `PROCESS_CANCELLED`、`PROCESS_EXITED` 与结果事实。
- 进程树已观察到并完成终态事实时投影 `CANCELLED`；未能证明树终止、轮询超时或事件缺口时失败关闭为 `FAILED`，写入固定 `CANCEL_FAILED`/`CANCEL_TIMEOUT`/`EXECUTION_EVIDENCE_UNAVAILABLE` 并保留 `reconciliation_required`，不得把父进程退出当作取消成功。
- 合成模式和未配置真实执行根均失败关闭；取消不接收命令、路径、SQL、秘密或自由原因文本。

结果证据同时保存受控进程退出码、planned/actual argv 摘要比较、固定错误码、可靠耗时和按权限裁剪的输出位置。任务详情只展示授权范围内的结果位置类型或完整值；对象存储在远端 MANIFEST 取证接入前仍不得声称逐对象验证通过。
