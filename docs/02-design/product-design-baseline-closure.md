# 产品设计基线收口评审

> 文档状态：收口结论已确认  
> 评审范围：V1.0 产品范围、模块规则、字段规则、官方能力证据、低保真与技术设计准入  
> 依据：[总体 PRD](../01-product/PRD.md)、[产品范围](../01-product/product-scope.md)、[关键决策](../01-product/decisions.md)

## 1. 收口结论

当前项目的**模块级产品语义基线已经完整形成**：首页、数据源、导出、普通导入、旁路导入、任务中心与详情、执行节点、日志、模板、系统设置、权限与安全均已完成产品规则确认；除数据源外的十个专项模块已经形成字段与条件矩阵并确认。

当前项目**已经完成已规划静态低保真，但尚不满足业务代码开发准入条件**。未完成项主要属于三类：

1. OB Loader/Dumper 4.3.5 官方冲突项和运行行为尚未完成受控验证；
2. 首条纵向切片仍缺少基于真实工具、节点和日志证据的跨流程验证；
3. 认证、权限、Agent、调度、日志、凭据等技术设计只有首版候选，尚未评审定版。

因此，本轮建议结论为：

- 产品范围与模块语义：**可收口**；
- 参数名称覆盖与处置基线：**已建立**；
- 参数实际行为证据：**部分完成，P0 尚未执行**；
- 页面结构和字段条件：**产品与静态低保真基线已形成**；
- 技术设计：**可以进入架构与首条纵向切片设计；接口、数据库和实现级细节需在相关 P0 通过或能力收缩后定版**；
- 业务代码开发：**暂不准入**。

## 3. 跨模块一致性核查

### 3.1 已对齐项

| 主题 | 收口结论 |
|---|---|
| 产品定位 | 所有模块均以 OB Loader/Dumper 官方能力的轻量可视化封装为边界，不扩展为通用迁移平台 |
| 数据源 | 独立管理，三类任务向导只选择已有数据源，不重复填写连接信息 |
| 三类任务 | 导出、普通导入、旁路导入保持同构的配置、预检查、命令确认、提交和追踪骨架 |
| 模式边界 | 普通导入和旁路导入是独立流程；旁路不复用普通导入检查点或断点继续 |
| 参数承载 | 参数基线覆盖实际 `--help` 名称；展示、派生、隐藏、过滤和阻断按任务类型分别判断 |
| 命令透明 | 三类任务均展示完整只读命令，默认脱敏并复制脱敏版本 |
| 任务事实 | 计划命令、实际命令、配置快照、状态、阶段、进度、日志和操作记录统一进入任务详情 |
| 模板 | 只复用活动、显式、非敏感配置；不复用节点、凭据、检查结果、风险确认或运行事实 |
| 首页 | 只聚合授权范围内任务和执行节点事实，不监控调度平台服务器，不建立第二套状态口径 |
| 权限 | 五类固定角色与对象范围共同授权；系统管理员不是业务超级用户，节点管理员负责节点管理 |
| 敏感信息 | 页面、复制、错误、日志、下载和审计使用同一不可关闭脱敏基线 |
| 历史事实 | 数据源、节点、设置、模板或权限变化不改写已提交任务和历史快照 |

### 3.2 本轮修正的陈旧口径

- PRD 中“生产任务二次确认或审批待定”已由 DEC-028、DEC-032 收口为：V1.0 只做独立生产能力、预检查和二次确认，不建设审批流。
- 产品范围中数据源名称、兼容模式、删除/归档和模板数据源策略已经有专项决策，不再作为待确认产品规则。
- 全局交互中的专家配置已经进入 V1.0 权限和字段基线；仍待确认的是具体参数适用性，而不是专家层级是否存在。
- 节点、日志、系统设置和首页中的系统管理员口径已统一为实际对象授权，不再默认全平台业务可见。

### 4.1 验证规模

| 模块 | P0 | P1 | P2 | 当前状态 |
|---|---:|---:|---:|---|
| 导出 | 20 | 10 | 5 | 计划已形成，尚未执行 |
| 普通导入 | 29 | 12 | 8 | 计划已形成，尚未执行 |
| 旁路导入 | 34 | 12 | 10 | 计划已形成，尚未执行 |
| 合计 | 83 | 34 | 23 | 需要隔离非生产环境和授权 |

### 4.2 P0 开发阻断项

以下事项未完成前，不能把对应能力写成已支持，也不能完成命令生成和验收定版：

1. **数据源连接表达**：OBServer、私有 ODP、云 ODP 的用户、租户、集群、SQL/RPC 地址与端口组合。
2. **导出格式与冲突参数**：POS 的独立参数与 CUT 组合口径、`--block-size` 默认值/单位、空文件参数拼写、连接参数优先级。
3. **普通导入核心行为**：内容组合、七类格式、文件匹配、列映射、危险清理、错误阈值和 `load.ckpt` 恢复语义。
4. **旁路核心路径**：连接场景、版本矩阵、RPC 获取、单表边界、格式门禁、全量/增量模式、结构限制和失败/取消语义。
5. **任务中心执行事实**：三类任务可安全取消的阶段、进度日志映射、检查点兼容条件和结果统计口径。

### 4.3 可以延后而不阻断基础流程的项目

- P1 高级/专家能力未验证时保持隐藏、只读或继承官方默认。
- P2 help-only、废弃和兼容参数不进入新任务配置，只保留历史识别和元数据记录。
- 缺少 Oracle、ODP Sharding、对象存储或指定版本环境的用例标记环境阻断，相应字段保持受限，不用推测结论补齐。

### 4.4 最大风险判断

旁路导入参数映射中，103 个长参数已全部建档，但只有 24 项已确认旁路适用、31 项明确不适用、44 项仍待官方参数映射确认，另有 2 项废弃/兼容和 2 项 CLI 元参数。

这不表示平台漏掉 44 个参数，而表示平台已经承载其元数据，但在没有证据前不能让用户自由生成旁路命令。若产品要求“三个模块所有参数均可自由配置”，将与“参数适用性必须与官方能力一致”的已确认原则冲突；当前正确基线是**完整收录、按模式开放、无证据不生成**。

## 5. 低保真设计门禁

PRD 第 26 章明确要求分模块低保真原型和评审。当前字段和交互语义足以进入低保真阶段，但尚未验证页面信息密度、操作发现性和跨页返回体验。

### 5.1 第一批核心流程

1. 数据源列表 → 新增/编辑 → 测试连接 → 保存 → 返回原任务草稿；
2. 导出六步向导 → 预检查 → 完整命令 → 提交 → 任务详情；
3. 普通导入六步向导 → 文件/格式/映射 → 预检查 → 命令 → 任务详情；
4. 旁路导入六步向导 → 适用条件/连接/RPC/单表 → 预检查 → 命令 → 任务详情；
5. 任务中心 → 任务详情 → 当前任务日志 → 日志中心；
6. 模板使用/从成功任务保存 → 新草稿 → 重新检查；
7. 生产任务、专家配置和敏感命令的权限不足、授权、二次确认和审计状态。

截至 2026-07-20，上述七条第一批核心流程的静态低保真均已确认，分别见[核心流程低保真基线](core-flow-low-fidelity.md)、[普通导入低保真基线](normal-import-low-fidelity.md)、[旁路导入低保真基线](direct-load-low-fidelity.md)、[任务中心与任务详情全状态低保真基线](task-center-low-fidelity.md)、[模板中心复用链路低保真基线](template-center-low-fidelity.md)和[权限与安全高风险操作低保真基线](access-control-security-low-fidelity.md)。这些结论确认了共同视觉方向和各模块关键差异，但不替代 P0 受控验证、可交互原型或技术设计。

### 5.2 第二批公共模块

- 首页状态摘要与下钻（已确认，见[首页低保真基线](home-low-fidelity.md)）；
- 执行节点列表、详情、环境重检和维护（已确认，见[执行节点管理低保真基线](execution-node-low-fidelity.md)）；
- 日志中心四类预设与同来源上下文（已确认，见[日志中心低保真基线](log-center-low-fidelity.md)）；
- 模板列表、编辑和兼容差异（已确认）；
- 系统设置分区保存与高影响确认（已确认，见[系统设置低保真基线](system-settings-low-fidelity.md)）；
- 权限配置中的角色、对象范围、依赖清理和并发冲突（已确认）。

### 5.3 低保真验收重点

- 三类向导在结构和术语上保持一致，但旁路专属限制足够醒目；
- 所有参数都能找到归属层级，但默认页面不会被 100 余个参数淹没；
- 条件隐藏、清值、互斥、阻断和预检查失效在交互上可理解；
- 用户能区分官方默认、平台默认、继承值、显式值、派生值和待确认值；
- 生产、敏感命令和危险数据操作的确认不会被普通保存操作稀释；
- 无权限、无数据、未采集、加载失败、过期和未知不会使用同一空状态；
- 键盘操作、焦点顺序、错误关联、颜色对比和日志可读性在可交互原型中单独核查。

已规划静态低保真已经确认，但仍没有可运行页面原型，因此不能进行基于真实交互的响应式、键盘操作或无障碍审计，也不能据此声称 P0 验证、技术设计或开发准入已经完成。

## 6. 技术设计输入

以下内容已经具备产品输入，可用于准备技术专题、识别依赖和评估验证环境；这不代表已经准入接口、数据库或实现级详细设计：

| 技术专题 | 必须承接的产品基线 |
|---|---|
| 认证与权限 | 五类固定角色、对象范围、生产/专家/敏感/审计能力、禁止自助提权、服务端强制过滤 |
| 数据源安全 | 覆盖式凭据更新、不可回显、基础连接测试边界、任务前重新检查 |
| 参数元数据 | 工具版本、参数状态、默认来源、适用模式、条件、互斥、风险和验证证据 |
| 命令生成 | 只生成活动且适用字段，区分计划/实际命令，默认脱敏并保存不可变快照 |
| Agent 与节点 | 注册认证、心跳、环境检查、工具路径、目录、并发、临时凭据和进程证据 |
| 调度与任务状态 | 状态机、启动核对、取消核对、不静默改派、运行事实和幂等操作 |
| 日志 | stdout/stderr/工具/Agent/调度/审计来源、游标、缺口、脱敏、保留和下载限制 |
| 模板兼容 | 显式活动字段提取、参数元数据版本、兼容四态、不可自动迁移 |
| 系统设置 | 分区原子保存、生效值来源、并发控制、高影响确认和历史对象不回写 |
| 安全与审计 | 密钥状态、凭据生命周期、审计原子性、脱敏基线和敏感临时文件清理 |

## 7. 仍需收口的非阻断细节

以下事项不改变 V1.0 模块范围，但应在低保真或技术设计中定版并回写：

| 事项 | 建议归属 | 是否阻断当前低保真 |
|---|---|---|
| 执行节点名称唯一性 | 技术设计前字段规则补充，建议平台全局唯一 | 否 |
| 模板名称唯一性与标签数量/长度 | 低保真字段评审 | 否 |
| 模板兼容服务不可用时的精确返回路径 | 低保真交互评审 | 否 |
| 首页刷新间隔、数据过期阈值和有限列表条数 | 低保真 + 性能设计 | 否 |
| 日志快捷时间范围、查询/上下文/下载上限 | 低保真 + 日志技术设计 | 否 |
| 系统设置数值范围、初始值和清理语义 | 技术设计 | 否 |
| 初始管理员、恢复流程和身份目录同步 | 安全技术设计 | 否 |
| 名称、描述、标签、原因字段的最终长度 | 数据与接口设计前统一字段规范 | 否 |

这些项目不得通过创建新的大型配置模块解决，应在现有页面或技术规范中收口。

### 8.2 低保真评审准入

当前已满足，可以立即进入。低保真阶段不得借视觉简化删除参数承载、条件状态或三类任务差异。

### 8.3 技术设计准入

当前静态低保真门禁已满足，可以进入架构和首条纵向切片技术设计。接口、数据库和实现级详细设计仍应先为切片范围取得相关 P0 证据或明确收缩能力；依赖工具行为的命令生成、状态解析、取消和检查点语义尤其不能提前定版。技术入口见[技术设计入口](../03-technical/README.md)。

### 8.4 业务代码开发准入

当前不满足。至少需要：

1. 与首批开发范围相关的 P0 受控验证通过，或明确从 V1.0 隐藏/阻断失败项；
2. 第一批核心流程低保真评审通过并回写交互问题；
3. 参数元数据、命令生成、任务状态、权限、Agent、日志和凭据安全技术设计评审通过；
4. 建立可追踪的需求—字段—参数—验证—实现关联；
5. 项目纳入可用的版本控制工作区，能够审查和回退变更。

## 9. 建议推进顺序

1. 确认本收口评审结论；
2. 执行数据源连接组合和三类任务 P0 受控验证，优先保证基础 CSV 主路径；
3. 同步制作第一批核心流程低保真原型并进行交互核对；
4. 回写验证与低保真发现，冻结 V1.0 参数元数据和交互基线；
5. 进入认证权限、参数元数据、Agent、调度、日志与安全技术设计；
6. 技术设计与开发准入评审通过后，再进入业务代码开发。
