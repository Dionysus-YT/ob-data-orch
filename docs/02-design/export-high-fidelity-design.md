## 1. 本轮结论与事实源

本设计以 `docs/01-product/product-scope.md` 的 2026-08-22 V1 交互定版和 `docs/02-design/export-module.md` 的 Canonical 为产品事实；视觉语言以冻结的 `docs/02-design/design-system-v0.1.md` 为唯一基线。旧 PRD 第 7 章、历史低保真入口、旧的参数映射入口以及早期 `ExportWizardView.vue` 的步骤顺序仅保留追溯价值，不能覆盖本稿。

高保真交互稿：`assets/high-fidelity/export-v1-wizard.html`。它是独立设计工件，不接入 Vue、路由、API 或真实执行；所有数据均为合成样例，不触发预检查或 OBDUMPER。

## 2. 当前导出模块现状

### 2.1 当前页面、路由与状态

| 用户表面 | 当前入口 | 已有状态 | 结论 |
|---|---|---|---|
| 新建导出向导 | `/exports/new` → `ExportWizardView.vue` | 6 步、草稿创建/更新、命令预览、预检查轮询、提交失败 | 已有主链路，但信息架构与视觉均未对齐新定版 |
| 任务中心 | `/tasks` → `TaskCenterView.vue` | 列表、空态、读取失败、分页 | 已实现，是导出提交后的统一任务入口 |
| 任务详情 | `/tasks/:id` → `TaskDetailView.vue` | 队列/运行、取消、日志、成功结果、失败派生、检查点继续资格 | 已实现安全投影；运行状态和结果事实必须以服务端返回为准 |
| 模板中心 | `/templates` → `TemplateCenterView.vue` | 从成功任务保存、改名、删除、由模板新建草稿 | 部分实现；手工新建模板仍未实现 |

浏览器状态在单个 `ExportWizardView.vue` 内用 `ref`/`computed` 管理，路由 query 的 `step` 只保存当前步骤。草稿、命令和预检查都由 `browserApi()` 调用控制面；没有独立全局 Store。控制面以草稿 revision、预检查标识和不可变任务快照维持一致性。

### 2.2 真实链路与证据分级

已实现的浏览器/API 链路是：选择已授权数据源和节点 → 创建/更新 v6 草稿 → 由控制面生成脱敏命令 → Agent 固定预检查 → 显式提交 → 统一任务详情与脱敏日志。OpenAPI 还声明了取消、成功任务保存模板、失败任务从原配置重建/从头重跑/检查点继续等端点。

已获得真实 Windows 证据的核心链路仍是单表 CSV 导出。CUT、SQL、多对象/DDL、对象存储、结果逐项取证与检查点继续不能因当前代码、契约或原型存在而写成已发布能力。设计中这些能力只按当前 Canonical 的可见性和门控状态呈现。

### 2.3 已废止或不可继续沿用的口径

| 历史项 | 为什么不再是目标 | 本设计处理 |
|---|---|---|
| PRD 的“数据源 → 对象 → 内容”顺序 | 2026-08-22 Canonical 已定为“数据源 → 内容 → 对象” | 统一采用新顺序 |
| 旧 WizardFrame 的树形表单和多层 details | 不属于 Design System v0.1，步骤间密度与层级不稳定 | 改为稳定主表单、单一高级区和右侧摘要 |
| 普通新建展示 POS/Parquet/ORC/Avro | 当前产品口径仅开放 CSV/CUT/SQL | 不在格式主卡片展示；历史任务继续可读 |
| `query-sql` 的敏感能力与提交级确认 | EX-R07 已定为普通高级筛选参数 | 放入步骤 3 高级区，保留服务端校验和普通预检查 |
| 步骤 1 的高级设置 | Canonical 明确无任务级高级项 | 不出现空折叠区 |

## 3. 最终流程与页面矩阵

流程：创建任务 → 选择数据源 → 选择导出内容 → 选择导出对象与筛选 → 选择数据格式 → 配置执行与输出 → 预检查/命令/确认 → 任务详情（运行、成功或失败）。模板新建和失败派生复用同一向导，但以只读来源提示和受限字段替代另起页面。

| 设计页面/状态 | 用户目标 | 核心内容 | 关键操作 | 必要状态 | 当前是否已有实现 |
|---|---|---|---|---|---|
| E01 数据源 | 选一条可用、可追溯的连接事实 | 可选数据源表、环境/测试状态、只读连接快照 | 搜索、选择、重新测试、下一步 | 默认、加载、无可用数据源、读取失败 | 有，需重构 |
| E02 导出内容 | 明确导出 DDL 和/或表数据 | 三个内容选项、后续影响、DDL 高级项 | 单选、展开高级、下一步 | 默认、仅结构 | 有，需拆分并重排 |
| E03 导出对象 | 明确范围、对象表达式和筛选 | 全部/指定、可搜索对象多选、表达式、数据筛选/一致性 | 切换范围、添加对象、录入条件、冲突即时阻断 | 默认、对象菜单、冲突/禁用 | 有，能力和结构均需重构 |
| E04 数据格式 | 选择唯一格式和常用序列化参数 | CSV/CUT/SQL 卡片、编码、分隔符、格式高级项 | 选格式、配置常用/高级项 | 默认、仅结构不适用、格式校验失败 | 有，需按 V1 收缩 |
| E05 执行与输出 | 选节点和本地落盘位置 | 节点、数据/日志目录、非空检查、文件布局和性能 | 选择节点、填路径、风险确认、展开高级 | 默认、节点不可用、路径校验失败、对象存储门控 | 有，需重构 |
| E06 确认与提交 | 核对冻结配置并安全开始 | 摘要、预检查、分组命令、确认语句、提交 | 发起/重试预检查、复制脱敏命令、返回修改、提交 | 检查中、失败、通过、提交中 | 有，需重构 |
| E07 运行详情 | 知道任务是否被领取、可否取消、日志是否连续 | 运行事实、取消、冻结配置、命令证据、日志 | 刷新、取消、进入日志 | 排队、运行、取消中、状态待核对 | 有，需视觉收敛 |
| E08 成功详情 | 核对结果事实并复用非敏感配置 | 结果摘要、文件清单、命令证据、保存模板 | 保存模板、返回任务中心 | 已核验、结果尚不可用 | 有，需视觉收敛 |
| E09 失败详情 | 定位失败并选择安全恢复方式 | 失败原因、日志、检查点资格、派生操作 | 基于原配置新建、从头重跑、检查点继续 | 失败、无检查点、继续任务创建中 | 有，需视觉收敛 |

E01–E06 是同一一等向导页面的状态变化，必须共用 Shell、页头、步骤条、双列主体与固定 Footer。E07–E09 是同一任务详情页的状态变化，必须共用任务头、事实摘要、二级区域和日志边界。

## 4. 高保真设计说明

### 4.1 共用框架

- 使用 216px Sidebar、48px Header、32px 页面横向 Padding；1440px 为主画板，1280px 回退为单主列，1920px 增加留白而不拉宽控件。
- 页头始终是 22px 标题、13px 说明和右侧低优先草稿状态。没有无业务价值的面包屑、搜索或通知。
- 向导步骤条为六个稳定等宽项。当前步骤使用 2px 蓝色顶部/左侧指示和文本，不使用大面积蓝色卡片；已完成步骤用 Success 图标和可回退点击区，未来步骤不可点击。
- 主体为 1fr + 272px 摘要列。摘要列不产生第二套编辑器，只回显决定性选择和预检查失效提示。
- 向导 Footer 固定在内容框底部：左侧上一步，中部“修改将使预检查失效”说明，右侧唯一 Primary。第六步以“运行预检查/提交并启动导出”替换下一步，但位置不变。

### 4.2 字段分层

| 层级 | 呈现 | 例子 |
|---|---|---|
| 常用 | 直接放在当前步骤，不超过一次关键决定 | 内容、范围、格式、节点、路径 |
| 高级 | 每步骤最多一个内联折叠区，展开后使用分组标题和分隔线 | DDL 行为、筛选、一致性、序列化、压缩、性能 |
| 派生只读 | 灰底事实条或只读字段，明确来源 | 连接、密码处理、节点平台、工具版本 |
| 门控 | 可见、禁用且说明原因；无可提交控件 | Oracle 未验证项、对象存储、历史格式 |

### 4.3 确认页的命令预览

命令必须由控制面返回，页面不能拼接。设计按“连接、对象、内容与格式、输出、性能”分行展示 token；复制仅复制脱敏命令；密码显示为固定占位，不出现原值。任何字段修改都回到“预检查已失效”，禁用最终提交。

## 5. 全局一致性 Review

### Visual

通过：页面使用 Design System 的颜色、34px 控件、4px 控件圆角、6px 必要 Surface、22/15/13/12px 排版与 4/8/12/16/24/32px 间距；Lucide 是唯一普通 UI 图标；信息层级由分隔线和排版建立，不使用卡片堆叠或阴影。

待实施约束：Wizard/Stepper/Command Preview/Object Picker 属于 v0.1 尚未冻结的 Extension Candidate。本稿将它们收敛为 Export 业务组件，首轮实现不得假装为通用 Design System；通过第二个真实消费者验证前，不抽象成全局组件。

### UX

通过：每一步只做一个决定；禁用与错误在产生处解释；上一步、下一步、保存/提交的位置稳定；预检查失败直接给“返回步骤 5 修改”入口；任务详情不伪造百分比或 ETA；失败恢复不会修改冻结任务。

### Flow

通过：只有步骤 5 保存草稿，步骤 6 才预检查和提交；提交后不另造“成功页面”，而进入已有任务详情的运行状态。成功/失败是同一详情页的事实投影，模板和派生操作从这里发起，保持审计链和来源关系。

## 6. DESIGN GAP

| 缺口 | 为什么需要 | 前端现状 | 后端/契约现状 | 是否阻塞本轮设计 |
|---|---|---|---|---|
| 完整对象类型选择器 | Canonical 要求展示全部官方对象类型及兼容/证据原因 | 当前仅 `TABLE`/`VIEW` 类型和单一对象输入 | v6 规范化当前也只接受受控子集 | 不阻塞：高保真图以禁用门控呈现；实施前阻塞 |
| Step 3 普通 `query-sql` | Canonical 已取消敏感门控 | 步骤 3 直接输入，冲突项即时禁用 | 控制面以普通任务授权、互斥校验和统一命令生成处理；旧确认字段仅兼容解码 | 不阻塞：已对齐；真实工具行为仍需 EX-V1 证据 |
| 对象存储正式提交 | V1 目标范围的一部分 | 当前有字段与凭据选择 | 真实凭据认证、远端 MANIFEST 取证未完成 | 不阻塞：仅门控，不在可提交主流程 |
| CUT/SQL 真实结果证据 | 决定发布声明 | 可创建草稿/命令 | 结果证据未齐 | 不阻塞设计，阻塞“稳定可用”声明 |
| 结果逐项文件清单 | 成功页需要可核验结果 | 详情页已能展示受控摘要 | 远端 MANIFEST 与部分真实取证待补 | 不阻塞：无事实时显示“不推测” |
| Wizard 设计模式 | 六步连续性需要稳定容器 | `WizardFrame` 是旧基线 | 无服务端影响 | 不阻塞；作为 Export 专属组件重构 |

## 8. 后续前端改造顺序

1. 先为 Export 建立只读页面状态模型和能力展示模型，明确“可用/门控/历史只读”，不接触命令拼装。
2. 以本稿重建 Export 专属 Wizard Frame、Summary Rail、单一 Advanced Section、对象选择器和命令展示组件；只复用 v0.1 token、按钮、状态与表单字段。
3. 一次性迁移 E01–E06 模板与路由步骤顺序，保留草稿 revision、预检查失效和提交 API 语义。
4. 对齐 `query-sql` 普通高级筛选与 CSV/CUT/SQL V1 格式矩阵；历史格式和对象存储仅做安全门控呈现。
5. 收敛 `TaskDetailView` 的运行/成功/失败状态；不改任务状态机、不伪造进度和结果。
6. 为每个 Canonical 约束补 Vue 单测、API 契约负例和 1280/1440/1920 视觉回归；CUT/SQL/对象存储/结果证据仍按任务地图单独验收。
