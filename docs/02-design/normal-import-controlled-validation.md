# 普通导入参数最小受控验证计划

> 文档状态：计划已形成，尚未执行\
> 目标程序：OBLOADER 4.3.5-RELEASE\
> 更新日期：2026-07-17\
> 参数事实依据：[普通导入参数映射基线](normal-import-parameter-mapping.md)\
> 字段规则依据：[普通导入字段与条件矩阵](normal-import-module.md#field-rules)

## 1. 目的

本计划验证官网资料、本地 `--help` 和产品映射之间仍需运行证据的普通导入行为。它不是生产导入方案，也不授权连接现有业务库。未取得隔离环境、最小权限和执行授权前，只完成静态核对，不运行真实导入。

## 2. 安全边界

- 仅使用专用非生产租户、专用数据库和人工构造的小数据集。
- 测试账号只能访问测试数据库，不复用生产凭据。
- 所有目标表统一使用 `nivt_` 前缀，文件放在单独验证目录。
- truncate、delete、replace 等用例每次执行前记录目标库、表名、行数和命令；表必须在白名单中。
- 对象存储只使用专用临时 bucket/前缀和最小权限临时凭据。
- 不测试大规模性能，不制造真实内存水位或服务端合并压力；阈值类参数只验证解析、日志和最小可观察行为。
- 日志、命令和证据中的密码、secret、token、SAS 必须脱敏。
- 每个用例使用独立输入目录或先恢复已知初始状态，结果不得相互污染。

## 3. 最小测试资产

| 资产 | 用途 |
|---|---|
| `nivt_csv` | CSV 分隔、包围、空值、首行、列映射 |
| `nivt_cut` | CUT splitter、escape、trail、header/footer |
| `nivt_pos` | POS + 控制文件定长解析 |
| `nivt_binary` | MySQL 二进制列与 ignore-unhex |
| `nivt_date` | MySQL DATE/DATETIME 默认日期 |
| `nivt_unique` | 主键/唯一键重复数据与 replace/max-discards |
| `nivt_plain` | 无主键表，验证 replace-data 边界 |
| `nivt_ddl` | DDL、replace-object、对象依赖 |
| 小型 ORC/Parquet/Avro 文件 | 列式格式、自动映射、Hive 路径、Avro 类型 |
| 受控压缩文件 | zstd/zlib/gzip/snappy 输入 |
| `load.ckpt` 失败样本 | 普通导入检查点继续 |

每个数据文件控制在可以人工核对的规模。验证结果至少包括：命令、脱敏日志、退出码、导入前后行数、关键查询结果和文件清单。

## 4. 优先级定义

| 优先级 | 范围 | 产品影响 |
|---|---|---|
| P0 | 主流程、格式、文件匹配、互斥、高风险行为、检查点 | 未验证或失败会阻断相关能力定版 |
| P1 | 高级解析、性能、会话和远程存储 | 未验证时字段保持受限或继承官方默认 |
| P2 | help-only、废弃兼容、导出侧与旁路过滤 | 不影响基础普通导入，新建任务默认不展示 |

## 5. P0：主流程和关键边界

### 5.1 参数覆盖与模式过滤

| ID | 验证问题 | 方法 | 通过标准 | 回写位置 |

| NIV-P0-01 | help 参数是否完整 | 从实际 `obloader --help` 提取唯一长参数，与映射表集合比较 | 两边均为 103，集合差异为空 | 参数映射基线 |

P2 参数只有在当前版本官方语义、适用条件和行为证据均齐全后，才能重新进入产品评审。“二进制接受”或“退出码为 0”均不足以开放能力。

## 8. 结果判定

| 状态 | 判定条件 | 产品动作 |
|---|---|---|
| 通过 | 至少两次独立执行一致，目标数据、日志和退出码都满足预期 | 更新参数事实、字段规则和约束状态 |
| 失败 | 工具明确拒绝或结果与官方语义冲突且可重复 | 隐藏、禁用或修正对应能力 |
| 不确定 | 权限、环境或输入不足以区分参数行为 | 保持待实测，不开放 |
| 环境阻断 | 缺少 Oracle、ODP、对象存储等必要环境 | 保持受限并记录所需环境 |
| 需官方确认 | help-only 或多种行为均可解释 | 不先做真实数据验证，取得官方语义后再测 |

## 9. 回写规则

1. [参数映射基线](normal-import-parameter-mapping.md)：更新含义、默认值、适用范围、来源和用例 ID。
2. [字段与条件矩阵](normal-import-module.md#field-rules)：更新显示、默认、清值、派生和阻断规则。
3. [普通导入模块](normal-import-module.md)：更新内容、格式、约束、风险和待确认项。
4. [用户流程](user-flow.md)：只在核心步骤或失败路径变化时更新。
5. [关键决策](../01-product/decisions.md)：只有用户确认产品建议后记录，验证事实不自动升级为产品决策。

每项回写必须引用 NIV 用例 ID，不能把一次人工尝试写成无来源结论。

## 10. 执行前门槛

当前只完成计划，尚未执行真实导入。开始前还需要：

- 非生产 OceanBase 连接和明确执行授权；
- MySQL 兼容测试租户，Oracle/ODP 专属用例需要相应隔离环境；
- 允许创建和清理 `nivt_` 测试对象的专用账号；
- 固定执行节点、工具版本和隔离文件目录；
- 如验证对象存储，提供专用 bucket/前缀和临时最小权限凭据；
- 明确测试结果、日志、输入文件和临时对象的复核与清理责任人。
