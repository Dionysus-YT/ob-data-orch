## 1. 评审目标

把 PRD 中的六步旁路导入向导推进为可逐项评审的产品方案，并确保它与导出、普通导入采用同一套产品语言：完整参数基线、六步任务向导、普通/高级/专家/不展示四层、统一字段状态、任务级预检查、完整只读命令、不可变快照、风险确认和可追溯验证证据。

旁路导入的不同只来自官方能力：RPC 连接、版本门槛、单表、数据导入、表粒度整体提交、结构限制和不支持断点续传。不得把这些必要差异扩大成另一套页面、状态或任务管理模型。

本稿不定义 API、数据库表、命令生成实现、高保真 UI，也不修改执行节点全局配置文件。

## 2. 模块边界

### 包含

- 在独立入口确认旁路导入适用条件。
- 选择已有数据源、连接场景、SQL 端口和 RPC 端口。
- 检查 OBLOADER、OBServer，以及连接 ODP 时的版本组合。
- 选择执行节点可读取的单表数据文件；允许同一目标表的多个分片文件。
- 配置唯一目标表、经官方确认适用于旁路导入的格式和解析参数。
- 配置 `--direct`、`--rpc-port`、`--parallel`、`--thread` 和经核验的共享参数。
- 检查表状态、索引、LOB、BIT/二进制类型、虚拟生成列和替换条件。
- 展示完整命令、风险确认、任务阶段、日志及从头重新执行。

### 不包含

- 普通导入的 DDL、MIX、全部对象、多表、检查点继续和错误阈值语义。
- 浏览器上传、平台文件编辑、自动建表、自动修改表结构或智能列映射。
- 自动修改租户 CPU、数据库参数或执行节点 `session.config.json`。
- 把“小数据不建议使用”实现成平台虚构的固定文件大小门槛。
- 将共享 `--help` 中出现但没有旁路适用证据的参数写成确定能力。

| 产品能力 | 导出 | 普通导入 | 旁路导入统一要求 |
|---|---|---|---|
| 模块入口 | 独立任务入口 | 独立任务入口 | 独立任务入口，不作为普通导入高级开关 |
| 主流程 | 六步向导 | 六步向导 | 六步向导，第一步增加适用条件门槛 |
| 数据源 | 选择已有数据源 | 选择已有数据源 | 选择已有数据源，增加连接场景和 RPC 摘要 |
| 参数承载 | help 全量建档 | help 全量建档 | 同一份 103 参数全集再次分类，不只列三个专属参数 |
| 展示层级 | 普通/高级/专家/不展示 | 普通/高级/专家/不展示 | 完全沿用，分类名称和状态语义不另造 |
| 默认值 | 未设置沿用官方默认 | 未设置沿用官方默认 | 完全沿用，不为匹配建议值擅自生成参数 |
| 条件显示 | 格式/对象/环境驱动 | 格式/对象/环境驱动 | 格式/连接场景/表结构/版本驱动 |
| 预检查 | 连接、输出、对象、参数 | 连接、文件、对象、参数 | 连接、版本、RPC、文件、单表、结构、参数 |
| 完整命令 | 只读、脱敏、可复制 | 只读、脱敏、可复制 | 完全沿用 |
| 任务快照 | 活动值、派生值、版本、命令 | 活动值、派生值、版本、命令 | 完全沿用，并增加 RPC/版本/结构检查证据 |
| 任务详情 | 可靠百分比或阶段降级 | 可靠百分比或阶段降级 | 完全沿用，阶段名称按 Direct Load 日志适配 |
| 失败操作 | 满足条件可 checkpoint 继续 | 满足条件可 checkpoint 继续 | 官方明确不支持继续，只能从头执行或新建 |

“保持一致”不等于强行复用普通导入能力。相同交互必须同构；官方语义不同的地方必须明确不同，不能为了视觉统一而弱化风险。

## 5. 参数承载原则

1. 实际 `obloader --help` 的 103 个长参数全部进入旁路参数映射，不漏项。
2. 三个 Direct Load 专属命令参数只是旁路能力的核心，不是全部配置面。
3. 经官方资料确认适用于旁路导入的连接、文件、格式、解析和风险参数均提供配置或派生入口。
4. 普通导入参数如果被官方明确标记“不适用于旁路导入”，必须过滤。
5. 只有普通导入含义、没有旁路适用证据的共享参数统一标记“待官方参数映射确认”，不直接开放。
6. `session.config.json` 的 Direct Load 配置单独建档，归属执行节点工具配置，不混入单任务命令参数。
7. 普通、高级、专家只是展示层级，不改变官方含义或风险等级。

## 6. 六步向导总览

```text
1. 确认旁路导入适用条件
→ 2. 选择数据源和连接目标
→ 3. 选择单表数据文件
→ 4. 配置目标表与格式
→ 5. 配置执行与旁路参数
→ 6. 参数/版本/结构预检查、完整命令与风险确认
→ 任务详情和日志
```

| 步骤 | 必须回答的问题 | 主要输出 |
|---|---|---|
| 1. 适用条件 | 是否确为大批量、单表并接受整体提交和失败从头执行 | 适用条件确认 |
| 2. 数据源 | 连接云 ODP、私有 ODP 还是 OBServer，SQL/RPC 目标是什么 | 连接与版本摘要 |
| 3. 文件 | 在哪个节点读取哪些同表文件 | 文件路径、匹配结果与单表判定 |
| 4. 表与格式 | 写入哪张表，格式和结构是否适用 | 唯一目标表、格式、结构和模式摘要 |
| 5. 执行 | 客户端/服务端并发及风险行为如何配置 | 活动命令参数和节点配置摘要 |
| 6. 确认 | 版本、RPC、文件、结构和参数是否可执行 | 检查结果、完整命令、风险确认与任务快照 |

## 7. 步骤 1：适用条件确认

进入向导先展示：

- 适用于需要在较短时间内装载大量单表数据的场景；小数据量不建议使用，但 V1.0 不虚构固定大小门槛。
- 通过 RPC 端口传输，不能把 SQL 端口复制为 RPC 端口后默认通过。
- 只允许一张目标表，但该表可以对应多个分片文件。
- 按表粒度整体提交，不是普通会话级或事务级提交。
- 暂不支持任务级重试或断点续传；失败操作明确为从头重新执行。
- BIT/二进制类型和虚拟生成列存在官方限制，提交前必须检查或由用户明确承担未检查风险。
- `--replace-data` 不能解决唯一索引冲突。

用户必须确认理解上述边界才能进入下一步。该入口确认只证明用户看过适用条件，不替代最终绑定实际表、参数和风险范围的二次确认。

## 8. 步骤 2：数据源与连接目标

### 连接场景

| 场景 | SQL 连接 | RPC 连接 | 官方主要条件 |
|---|---|---|---|
| 云数据库 OceanBase + ODP | 数据源 ODP 地址/SQL 端口 | 云上旁路端口，官方常见默认 3307 | `--public-cloud` 与租户按官方场景派生 |
| OceanBase 数据库 + ODP | 数据源 ODP 地址/SQL 端口 | ODP RPC 监听端口，官方默认 2885 | 集群、租户按官方场景派生 |
| OceanBase 数据库 + OBServer | 物理节点地址/SQL 端口 | OBServer RPC 端口，官方默认 2882 | 直连可能产生跨机事务，生产场景提示风险 |

RPC 端口可以来自数据源/节点已知配置、安全查询或有权限用户输入，但必须展示来源。无法查询时不得推测；默认端口只能作为提示，不能替代实际连接预检查。

### 版本门槛

- 连接 OBServer：V4.2.1.x 中 V4.2.1.7 及之后、V4.2.4.0 至 V4.3.0 之前、V4.3.x 中 V4.3.0.1 及之后。
- 连接 ODP：ODP V4.3.0 及之后，同时 OBServer V4.2.1 及之后。
- 工具版本固定核验为 OBLOADER 4.3.5-RELEASE。
- 版本无法取得时不能默认为满足；进入阻断或受权限控制的人工确认策略，具体方案列入评审项。

`--no-sys`、`--sys-user`、`--sys-password` 的官网说明只适用于 OceanBase V4.0.0 之前，与上述旁路支持版本范围没有交集，因此 V1.0 旁路新任务不生成。

## 9. 步骤 3：单表数据文件

### 页面内容

- 执行节点。
- 节点本地文件或目录；远程存储是否适用于 Direct Load：待官方参数映射确认。
- `--file-path`、文件后缀、正则、编码和匹配预览。
- 文件数量、总大小、有限样例和目标表判定结果。
- `--external-data` 用于第三方 CSV 的官方示例，但精确 MANIFEST 行为仍需受控验证。

### 单表规则

- 只能配置一个明确目标表，命令必须生成一个 `--table` 值。
- 可以匹配同一目标表的多个分片文件。
- 匹配结果可能对应多张表、无法判断表名或为零时阻断。
- 不提供 `--all`、`--table '*'` 或其他对象类型。
- 文件变化后，格式、目标表、结构和风险检查全部失效。

## 10. 步骤 4：目标表与格式

### 唯一目标表

- 目标数据库/Schema 与目标表必填。
- 查询目标表是否为空，并由工具规则决定全量或增量旁路模式；不提供手工模式开关。
- 查询索引、唯一索引、LOB、BIT/二进制类型和虚拟生成列。
- 无法取得元数据时不显示“检查通过”，而是显示“未完成”并要求按评审后的安全策略处理。

### 格式基线

| 格式 | 旁路证据状态 | 产品处置 |
|---|---|---|
| CSV | V4.3.5 通用旁路示例和 Cloud 示例均明确使用 `--csv` | 三种连接场景均作为 V1.0 已确认格式 |
| SQL、Parquet、ORC | OceanBase Cloud 的 Direct Load 官方页明确列为可按实际文件选择的格式 | 云 ODP 场景已确认；私有 ODP/OBServer 场景显示“待官方参数映射确认”，不无证据扩大适用范围 |
| CUT、POS、Avro | 普通导入语义已确认，未找到可与 `--direct` 组合的官方证据 | 待官方参数映射确认；验证前不开放 |
| DDL、MIX | 旁路目标是写入表数据，且单表整体提交 | 不进入旁路格式选择 |

格式可用性由“格式 + 连接场景”共同决定，不另建一套向导。CSV 的列分隔符在官方旁路示例中已出现；其他解析参数继续沿用参数基线的逐项证据状态，不能因为格式已确认就把其所有普通导入参数自动复制到 Direct Load。

### 全量与增量模式

- 目标表为空时，工具使用全量旁路模式，可搭配 `--replace-data`。
- 目标表非空时，工具使用增量旁路模式。
- 增量模式下，目标表无索引或 LOB 字段时可搭配 `--replace-data`；存在索引或 LOB 字段时不支持。
- 无论模式如何，`--replace-data` 都不能解决唯一索引冲突。

## 11. 步骤 5：执行与旁路参数

### 参数分层

| 展示层级 | 目的 | 代表参数/配置 |
|---|---|---|
| 普通模式 | 完成一次可执行旁路导入 | 数据源、连接场景、RPC、数据库、单表、文件、当前场景已确认格式、执行节点 |
| 高级配置 | 旁路并发和经核验的文件解析参数 | `--thread`、`--parallel`、CSV 分隔、日志路径 |
| 专家配置 | 替换、清空等高风险行为及节点配置摘要 | `--replace-data`、`--truncate-table`、Direct Load 配置只读摘要 |
| 不展示 | 普通导入专属、DDL/对象、废弃、help-only 和旁路适用性未确认 | `--retry`、`--max-errors`、`--ddl`、`--all`、`--storage-uri`、`--server` |

与另两个模块相同，“不展示”仍保留在完整参数基线中，避免将共享 help 名称误认成遗漏。

### thread 与 parallel

- `--thread` 是客户端到服务端的连接池规模。
- `--parallel` 是 OBServer 用于写入数据与排序的工作线程数，官方默认 1，并建议结合租户 CPU 规格指定。
- 官方建议两者保持一致；不一致时警告，但在证据不足时不擅自阻断。
- 未显式设置时继续沿用各自官方默认，不为了“看起来一致”偷偷生成参数。
- 可以提供一次性的“同步为相同值”辅助操作，是否进入 V1.0 作为待确认产品建议。

### session.config.json

当前发布包包含：

| 配置键 | 发布包值 | 产品处置 |
|---|---:|---|
| `direct_path_load.task_timeout_ms` | `2147483647` | 执行节点工具配置只读摘要 |
| `direct_path_load.heartbeat_timeout_ms` | `60000` | 执行节点工具配置只读摘要 |
| `direct_path_load.heartbeat_interval_ms` | `10000` | 执行节点工具配置只读摘要 |

官网专题页的示例值与发布包值明显不同。V1.0 不把官网示例当作默认值，也不在任务中编辑全局文件；页面展示执行节点实际生效值、配置来源和变更责任边界。

## 13. 步骤 6：预检查与完整命令

### 预检查

至少检查：

- 数据源 SQL 连接、RPC 连接和连接场景派生参数；
- OBLOADER、OBServer、ODP 版本组合；
- 执行节点在线、工具版本正确、输入文件可读；
- 文件匹配结果只对应一个目标表；
- 目标数据库、表存在性、空/非空状态；
- BIT/二进制类型、虚拟生成列、索引、LOB 和唯一索引风险；
- 格式及格式专属参数是否具有旁路适用证据；
- direct、rpc-port、thread、parallel、replace-data 和风险行为的依赖关系；
- 执行节点 Direct Load 配置可读取且生效值已进入任务快照。

### 命令确认

- 展示实际可执行的完整 OBLOADER Direct Load 命令。
- 按连接、RPC、文件、目标表、格式、客户端并发、服务端并发和风险行为分组高亮。
- 密码和存储凭据默认脱敏，复制权限与另两个模块一致。
- 命令只读；任何影响命令或结构事实的变化都会使原检查和确认失效。

### 最终风险确认

绑定当前任务快照确认：单表整体提交、不支持断点继续、失败从头执行、唯一索引风险、结构限制、资源影响，以及直连 OBServer 时可能产生的跨机事务风险。

## 14. 运行与失败处理

任务详情沿用统一页面，旁路阶段按可可靠解析的日志展示：参数校验、文件预处理、数据写入、服务端排序/索引构建/提交、完成或失败。

失败后提供：查看错误、查看日志、复制脱敏命令、基于原配置新建、从头重新执行。不得显示 checkpoint、断点续传或“从失败点继续”。取消在服务端提交阶段的安全语义仍需官方/受控验证，未确认前不承诺可安全取消。

## 15. 已确认产品决策

DL-R01～DL-R20 已于 2026-07-17 全部确认。确认的是产品承载、展示、连接场景、风险和失败处理方案；明确标记“待官方参数映射确认”或待受控验证的格式、参数与工具行为仍不得视为已经验证通过。

## 16. 验收基线

1. 三个模块的向导骨架、字段状态、参数分层、命令确认和任务详情语言一致。
2. 旁路的差异均能追溯到官方能力或 PRD，不存在为了“特殊”而新增的产品概念。
3. 103 个 help 参数全部建档，并明确旁路适用、派生、不适用或待确认状态。
4. 只允许唯一目标表和同表分片文件。
5. SQL/RPC 端口分别展示、分别检查，连接场景和版本组合可追溯。
6. 只有已确认旁路格式可以提交，其他格式不会从普通导入无证据复制。
7. 全量/增量模式和 replace-data 条件来自目标表事实。
8. 不支持结构和唯一索引风险不会被替换参数掩盖。
9. 提交前展示完整只读命令并完成绑定当前快照的风险确认。
10. 失败任务不出现断点续传，从头执行有明确文案。

## 17. 待官方/实测项

- 取消在数据写入、排序、索引构建、整体提交各阶段的安全语义。
