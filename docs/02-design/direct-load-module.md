## 1. 评审目标

旁路导入采用可逐项评审的独立五步方案，并与导出、普通导入使用同一套产品语言：完整参数基线、各自独立的任务向导、普通/高级/专家/不展示四层、统一字段状态、任务级预检查、完整只读命令、不可变快照、风险确认和可追溯验证证据。普通导入按 DEC-051 使用五步，旁路按 DEC-056 使用五步，不共享导入业务参数或状态。

旁路导入的不同只来自官方能力：RPC 连接、版本门槛、单表、数据导入、表粒度整体提交、结构限制和不支持断点续传。不得把这些必要差异扩大成另一套页面、状态或任务管理模型。

本稿不定义 API、数据库表、命令生成实现、高保真 UI，也不修改执行节点全局配置文件。

## 2. 模块边界

### 包含

- 在独立入口确认旁路导入适用条件。
- 选择已有数据源、连接场景、SQL 端口和 RPC 端口。
- 检查 OBLOADER、OBServer，以及连接 ODP 时的版本组合。
- 选择执行节点可读取的单表数据文件；允许同一目标表的多个分片文件。
- 配置唯一目标表、经官方确认适用于旁路导入的格式和解析参数。
- 配置 `--direct`、`--rpc-port`、`--parallel`、`--thread` 和经核验的共享参数。
- 检查表状态、索引、LOB、BIT/二进制类型、虚拟生成列和替换条件。
- 展示完整命令、风险确认、任务阶段、日志及从头重新执行。

### 不包含

- 普通导入的 DDL、MIX、全部对象、多表、检查点继续和错误阈值语义。
- 浏览器上传、平台文件编辑、自动建表、自动修改表结构或智能列映射。
- 自动修改租户 CPU、数据库参数或执行节点 `session.config.json`。
- 把“小数据不建议使用”实现成平台虚构的固定文件大小门槛。
- 将共享 `--help` 中出现但没有旁路适用证据的参数写成确定能力。

## 4. 三模块一致性护栏

| 产品能力 | 导出 | 普通导入 | 旁路导入统一要求 |
|---|---|---|---|
| 模块入口 | 独立任务入口 | 独立任务入口 | 独立任务入口，不作为普通导入高级开关 |
| 主流程 | 五步向导 | 五步向导 | 独立五步，首步有效继续时集中确认适用条件 |
| 数据源 | 选择已有数据源 | 选择已有数据源 | 选择已有数据源，增加连接场景和 RPC 摘要 |
| 参数承载 | help 全量建档 | help 全量建档 | 同一份 103 参数全集再次分类，不只列三个专属参数 |
| 展示层级 | 普通/高级/专家/不展示 | 普通/高级/专家/不展示 | 完全沿用，分类名称和状态语义不另造 |
| 默认值 | 未设置沿用官方默认 | 未设置沿用官方默认 | 完全沿用，不为匹配建议值擅自生成参数 |
| 条件显示 | 格式/对象/环境驱动 | 格式/对象/环境驱动 | 格式/连接场景/表结构/版本驱动 |
| 预检查 | 连接、输出、对象、参数 | 连接、文件、对象、参数 | 连接、版本、RPC、文件、单表、结构、参数 |
| 完整命令 | 只读、脱敏、可复制 | 只读、脱敏、可复制 | 完全沿用 |
| 任务快照 | 活动值、派生值、版本、命令 | 活动值、派生值、版本、命令 | 完全沿用，并增加 RPC/版本/结构检查证据 |
| 任务详情 | 可靠百分比或阶段降级 | 可靠百分比或阶段降级 | 完全沿用，阶段名称按 Direct Load 日志适配 |
| 失败操作 | 满足条件可 checkpoint 继续 | 满足条件可 checkpoint 继续 | 官方明确不支持继续，只能从头执行或新建 |

“保持一致”不等于强行复用普通导入能力。相同交互必须同构；官方语义不同的地方必须明确不同，不能为了视觉统一而弱化风险。

## 5. 参数承载原则

1. 实际 `obloader --help` 的 103 个长参数全部进入旁路参数映射，不漏项。
2. 三个 Direct Load 专属命令参数只是旁路能力的核心，不是全部配置面。
3. 经官方资料确认适用于旁路导入的连接、文件、格式、解析和风险参数均提供配置或派生入口。
4. 普通导入参数如果被官方明确标记“不适用于旁路导入”，必须过滤。
5. 只有普通导入含义、没有旁路适用证据的共享参数统一标记“待官方参数映射确认”，不直接开放。
6. `session.config.json` 的 Direct Load 配置单独建档，归属执行节点工具配置，不混入单任务命令参数。
7. 普通、高级、专家只是展示层级，不改变官方含义或风险等级。

## 6. 五步向导总览

```text
1. 数据源与连接（首次有效继续时确认适用条件）
→ 2. 导入目标（数据库 / Schema、唯一目标表）
→ 3. 文件与格式（执行节点、本地路径、格式与解析）
→ 4. 执行参数
→ 5. 预检查与提交（完整命令、最终快照风险确认）
→ 任务详情和日志
```

| 步骤 | 必须回答的问题 | 主要输出 |
|---|---|---|
| 1. 数据源与连接 | 连接哪个授权目标、使用何种场景与 RPC 端口，是否理解适用边界 | 连接输入、入口阅读确认；版本与连通仍待检查 |
| 2. 导入目标 | 写入哪个数据库 / Schema 的唯一目标表 | 唯一目标绑定；结构和空状态仍待检查 |
| 3. 文件与格式 | 在哪个节点读取哪些同表文件，以什么格式解析 | 节点、路径、格式及活动解析参数；文件事实仍待检查 |
| 4. 执行参数 | 客户端/服务端并发及风险行为如何配置 | 活动命令参数和待核对节点配置 |
| 5. 预检查与提交 | 版本、RPC、文件、结构和参数是否可执行 | 九项检查、完整命令、最终风险确认与任务快照 |

## 7. 首步继续时的适用条件确认

进入向导先展示：

- 适用于需要在较短时间内装载大量单表数据的场景；小数据量不建议使用，但 V1.0 不虚构固定大小门槛。
- 通过 RPC 端口传输，不能把 SQL 端口复制为 RPC 端口后默认通过。
- 只允许一张目标表，但该表可以对应多个分片文件。
- 按表粒度整体提交，不是普通会话级或事务级提交。
- 暂不支持任务级重试或断点续传；失败操作明确为从头重新执行。
- 当前平台对 BIT/二进制类型和虚拟生成列保留受控门禁，提交前必须取得可信检查事实；未知或无法检查时阻断，入口风险确认不能替代结构检查。BIT/二进制相关官方资料冲突按本页现役复核说明处理，不宣称工具必然不支持。
- `--replace-data` 不能解决唯一索引冲突。

首步先选择数据源和连接场景，当前输入合法后点击下一步集中展示上述边界；安全动作“返回配置”不记录确认，明确“已了解，继续配置”才同时记录原四项阅读确认并进入导入目标。同一已确认草稿往返不重复弹，旧弹窗不能作用于已切换会话。该入口确认只证明用户看过适用条件，不替代实际事实检查和最终绑定实际表、参数和风险范围的二次确认。

## 8. 步骤 1：数据源与连接

### 连接场景

| 场景 | SQL 连接 | RPC 连接 | 官方主要条件 |
|---|---|---|---|
| OceanBase 数据库 + ODP | 数据源 ODP 地址/SQL 端口 | ODP RPC 监听端口，官方默认 2885 | 集群、租户按官方场景派生 |
| OceanBase 数据库 + OBServer | 物理节点地址/SQL 端口 | OBServer RPC 端口，官方默认 2882 | 直连可能产生跨机事务，生产场景提示风险 |

RPC 端口按当前场景预填可编辑默认值，不从 SQL 端口推测。场景变化只替换空值或原场景默认值，自定义端口保留；恢复草稿保持保存值。当前传输来源 `MANUAL` 表示用户提交并确认的填写值，含默认预填，不宣称来自查询或节点。未知实际监听、映射和连通仍须预检查；不能因默认值合理而通过。

大批量导入建议选择已登记的固定 ODP 数据源。官方允许连接 OBServer，也允许通过负载均衡转发 ODP RPC，因此不以 F5/VIP 名称禁用候选。现有单主机模型下，所选数据源地址须同时提供 SQL 与 RPC 转发；仅 SQL 可达不足以导入，实际映射、后端及带宽条件需环境验证，不新增任务级地址覆盖。

### 版本门槛

- 连接 OBServer：V4.2.1.x 中 V4.2.1.7 及之后、V4.2.4.0 至 V4.3.0 之前、V4.3.x 中 V4.3.0.1 及之后。
- 连接 ODP：ODP V4.3.0 及之后，同时 OBServer V4.2.1 及之后。
- 工具版本固定核验为 OBLOADER 4.3.5-RELEASE。
- 版本无法取得时不能默认为满足；进入阻断或受权限控制的人工确认策略，具体方案列入评审项。

`--no-sys`、`--sys-user`、`--sys-password` 的官网说明只适用于 OceanBase V4.0.0 之前，与上述旁路支持版本范围没有交集，因此 V1.0 旁路新任务不生成。

## 9. 步骤 3：文件与格式

### 页面内容

- 执行节点。
- 节点本地文件或目录；远程存储是否适用于 Direct Load：待官方参数映射确认。
- `--file-path`、文件后缀、正则、编码和匹配预览。
- 文件数量、总大小、有限样例和目标表判定结果。
- `--external-data` 用于第三方 CSV 的官方示例，但精确 MANIFEST 行为仍需受控验证。

### 单表规则

- 只能配置一个明确目标表，命令必须生成一个 `--table` 值。
- 可以匹配同一目标表的多个分片文件。
- 匹配结果可能对应多张表、无法判断表名或为零时阻断。
- 不提供 `--all`、`--table '*'` 或其他对象类型。
- 文件变化后，格式、目标表、结构和风险检查全部失效。

## 10. 步骤 2：导入目标与结构边界

唯一目标数据库 / Schema 与目标表在第二步配置；本节格式规则在第三步文件与格式中编辑。结构、空状态及模式事实统一在第五步取证，不因第二步导航完成而声称可写。

### 唯一目标表

- 目标数据库/Schema 与目标表必填。
- 查询目标表是否为空，并由工具规则决定全量或增量旁路模式；不提供手工模式开关。
- 查询索引、唯一索引、LOB、BIT/二进制类型和虚拟生成列。
- 无法取得元数据时不显示“检查通过”，而是显示“未完成”并要求按评审后的安全策略处理。

### 格式基线

| 格式 | 旁路证据状态 | 产品处置 |
|---|---|---|
| CSV | V4.3.5 通用旁路示例明确使用 `--csv` | 本地两种连接场景均作为已确认格式，真实组合仍待验证 |
| SQL、Parquet、ORC | 尚未确认私有 ODP/OBServer 的旁路适用性 | 标记“待官方参数映射确认”，不开放配置或生成 |
| CUT、POS、Avro | 普通导入语义已确认，未找到可与 `--direct` 组合的官方证据 | 待官方参数映射确认；验证前不开放 |
| DDL、MIX | 旁路目标是写入表数据，且单表整体提交 | 不进入旁路格式选择 |

格式可用性由“格式 + 连接场景”共同决定，不另建一套向导。CSV 的列分隔符在官方旁路示例中已出现；其他解析参数继续沿用参数基线的逐项证据状态，不能因为格式已确认就把其所有普通导入参数自动复制到 Direct Load。

### 全量与增量模式

- 目标表为空时，工具使用全量旁路模式，可搭配 `--replace-data`。
- 目标表非空时，工具使用增量旁路模式。
- 增量模式下，目标表无索引或 LOB 字段时可搭配 `--replace-data`；存在索引或 LOB 字段时不支持。
- 无论模式如何，`--replace-data` 都不能解决唯一索引冲突。

## 11. 步骤 4：执行与旁路参数

### 参数分层

| 展示层级 | 目的 | 代表参数/配置 |
|---|---|---|
| 普通模式 | 完成一次可执行旁路导入 | 数据源、连接场景、RPC、数据库、单表、文件、当前场景已确认格式、执行节点 |
| 高级配置 | 旁路并发和经核验的文件解析参数 | `--thread`、`--parallel`、CSV 分隔、日志路径 |
| 专家配置 | 替换、清空等高风险行为及节点配置摘要 | `--replace-data`、`--truncate-table`、Direct Load 配置只读摘要 |
| 不展示 | 普通导入专属、DDL/对象、废弃、help-only 和旁路适用性未确认 | `--retry`、`--max-errors`、`--ddl`、`--all`、`--storage-uri`、`--server` |

与另两个模块相同，“不展示”仍保留在完整参数基线中，避免将共享 help 名称误认成遗漏。

### thread 与 parallel

- `--thread` 是客户端到服务端的连接池规模。
- `--parallel` 是 OBServer 用于写入数据与排序的工作线程数，官方默认 1，并建议结合租户 CPU 规格指定。
- 官方建议两者保持一致；不一致时警告，但在证据不足时不擅自阻断。
- 未显式设置时继续沿用各自官方默认，不为了“看起来一致”偷偷生成参数。
- 可以提供一次性的“同步为相同值”辅助操作，是否进入 V1.0 作为待确认产品建议。

### session.config.json

当前发布包包含：

| 配置键 | 发布包值 | 产品处置 |
|---|---:|---|
| `direct_path_load.task_timeout_ms` | `2147483647` | 执行节点工具配置只读摘要 |

## 13. 步骤 5：预检查与提交

### 预检查

至少检查：

- 数据源 SQL 连接、RPC 连接和连接场景派生参数；
- OBLOADER、OBServer、ODP 版本组合；
- 执行节点在线、工具版本正确、输入文件可读；
- 文件匹配结果只对应一个目标表；
- 目标数据库、表存在性、空/非空状态；
- BIT/二进制类型、虚拟生成列、索引、LOB 和唯一索引风险；
- 格式及格式专属参数是否具有旁路适用证据；
- direct、rpc-port、thread、parallel、replace-data 和风险行为的依赖关系；
- 执行节点 Direct Load 配置可读取且生效值已进入任务快照。

### 命令确认

- 展示实际可执行的完整 OBLOADER Direct Load 命令。
- 按连接、RPC、文件、目标表、格式、客户端并发、服务端并发和风险行为分组高亮。
- 密码和存储凭据默认脱敏，复制权限与另两个模块一致。
- 命令只读；任何影响命令或结构事实的变化都会使原检查和确认失效。

### 最终风险确认

绑定当前任务快照确认：单表整体提交、不支持断点继续、失败从头执行、唯一索引风险、结构限制、资源影响，以及直连 OBServer 时可能产生的跨机事务风险。

## 14. 运行与失败处理

任务详情沿用统一页面，旁路阶段按可可靠解析的日志展示：参数校验、文件预处理、数据写入、服务端排序/索引构建/提交、完成或失败。

失败后提供：查看错误、查看日志、复制脱敏命令、基于原配置新建、从头重新执行。不得显示 checkpoint、断点续传或“从失败点继续”。取消在服务端提交阶段的安全语义仍需官方/受控验证，未确认前不承诺可安全取消。

## 16. 验收基线

1. 三个模块的向导骨架、字段状态、参数分层、命令确认和任务详情语言一致。
2. 旁路的差异均能追溯到官方能力或 PRD，不存在为了“特殊”而新增的产品概念。

8. 不支持结构和唯一索引风险不会被替换参数掩盖。
9. 提交前展示完整只读命令并完成绑定当前快照的风险确认。
10. 失败任务不出现断点续传，从头执行有明确文案。

## 18. 2026-10-19 G2 实施与安全收缩

现役独立五步按 DEC-056 执行：数据源与连接、导入目标、文件与格式、执行参数、预检查与提交。前四步只验证已填写内容，不把“可进入下一步”显示为检查通过；第五步使用固定完整检查集统一核对。文件发现结果仅证明当前输入集合，不能代替 SQL/RPC、版本、写权限、表结构或节点配置检查。

配置只接收用户可编辑字段，RPC 端口来源在本轮固定为 `MANUAL`，不根据 SQL 端口或常见默认端口推测。版本、目标表空状态、结构、权限和配置摘要均为可信检查事实，不能由客户端提交或恢复草稿补齐。缺少事实时保持未确认并阻断执行，不增加人工勾选绕过。

节点配置契约按现役安全边界收缩：固定来源为 `toolHome/conf/session.config.json`，只允许三个已确认毫秒数值的安全投影、该投影的指纹和读取时间进入任务证据；未知键名、未知值、原文件及整文件哈希均不保存到浏览器响应或任务快照。不在任务向导编辑配置文件，亦不把官网示例或发布包声明当成当前节点实际生效值。

本轮实现独立配置、103 参数处置目录、唯一命令生成器、草稿、受控文件扫描和固定预检查协议，并继续补齐默认关闭的专用只读探针、提交与执行源码及合成闭环；不能把“未取得真实运行授权”解释为不得实现源码，也不能把源码可达解释为已取得真实准入。提交以独立开关、真实执行总开关、权限、当前九项检查、冻结指纹及提交确认共同门控，默认仍阻断，不采用永久无条件拒绝接口代替完整状态流。

专用 `DirectLoadProbe` 使用单次租约绑定的短时业务连接槽位及固定 v11 Java 入口，不借普通导入业务探针。MySQL 以固定只读查询取得目标表、列、索引和空性事实，核对明确写权限及固定系统视图读权限；BIT、二进制、虚拟列、未识别类型、未确认权限与未知元信息均不能放行。`OB_VERSION()` 只接受严格数字版本；ODP 业务槽位的版本读取与 Oracle 旁路权限、结构契约没有充分绑定事实时保持未知。TCP 仅证明已配置 Host 与手工 RPC 端口可建连，不证明 RPC 协议、认证或导入成功。

本机工具版本来自固定包的静态摘要核验，配置来自固定 `session.config` 三数值安全投影及观测时间；均不运行官方工具，也不接受 Java 结果代填。本机配置观测独立于数据库连接成功，取消、租约变化、凭据或输入绑定变化后不复用旧成功。执行成功还需独立旁路提交证据；客户端退出码、普通导入终态或未绑定系统视图不能单独证明服务端完成。专用固定提交日志的源码与合成验证不替代受控验证中的目标表数据及可得服务端状态核对。

配置安全投影使用独立的 `directLoadConfigFingerprint` 串联完整预检查报告、冻结快照和执行输入，并参与执行 envelope 绑定。只有同一租约完成的本机有效三数值投影且 `DIRECT_LOAD_CONFIG=PASSED` 才能提供该指纹；缺失指纹会使该项保持 `UNKNOWN`，文件发现及非通过配置项禁止携带。Worker 启动前重新读取固定来源并比对安全投影，缺失、未知或不一致均在启动官方工具前阻断；不允许用草稿配置指纹或整文件哈希替代该证据。

真实 SQL/RPC、真实凭据解析及真实 OBLOADER Direct Load 运行仍未准入。本地两种场景仅开放 CSV 配置；G2 合成通过不提升为真实功能可用或发布认证。

<a id="field-rules-12-字段覆盖验收"></a>

### 12. 字段覆盖验收

1. 旁路字段使用与导出、普通导入一致的状态、默认、草稿、派生和失效语义。
2. 页面参数搜索覆盖本地 102 项与 3 个 Direct Load 节点配置键；官方 103 项研究集合单独核对。
3. SQL/RPC、连接场景和版本信息在摘要、命令和快照中一致。
4. 文件只能映射到唯一目标表，不能通过高级配置绕过。
5. 未确认格式和共享参数不会无证据进入最终命令。
6. 全量/增量、结构限制和 replace-data 条件来自实际目标表事实。
7. thread/parallel 的语义和默认不被合并成一个模糊“并发数”。
8. 风险确认绑定当前快照，失败任务永不出现断点继续。

### 1. 评审目标

本文保留旁路导入独有的适用门槛、SQL/RPC 双连接、版本矩阵、单表分片、格式证据边界、Direct Load 并发、整体提交和失败处理等 P3 业务语义；不继承任何历史页面骨架。

本稿是静态低保真和产品交互基线，不是高保真 UI、可运行原型或命令实现。图片中的示例文件、地址、版本结果、命令和值只用于表达页面结构；参数适用性和实际行为仍以 OBLOADER 4.3.5 参数映射及受控验证证据为准。

<a id="business-scenarios-2-与普通导入共享的业务交互语言"></a>

### 2. 与普通导入共享的业务交互语言

旁路导入与普通导入共享步骤状态、字段校验、Save Draft、预检查、只读脱敏命令、不可变快照和任务证据链；具体页面 Composition 由 [P0 MASTER](../../design-system/MASTER.md) 和当前步骤决策模型决定。

共享交互不覆盖官方能力差异。RPC、版本、单表、表级整体提交、结构限制和不支持检查点继续必须显式呈现。

<a id="business-scenarios-3-页面基线"></a>

### 3. 业务场景

<a id="business-scenarios-dl-lf-01-适用条件"></a>

#### DL-LF-01 适用条件


- 明确旁路导入是独立流程，不是普通导入的高级开关；
- 用户需确认大批量单目标表、同表多分片、RPC 通道、表级整体提交、失败从头执行和结构限制；
- 不为“大批量”虚构固定数据量阈值；
- 未完成全部确认时禁止进入下一步。

<a id="business-scenarios-dl-lf-02-连接与版本"></a>

#### DL-LF-02 连接与版本


- 私有 ODP、私有 OBServer 两种连接场景显式单选；
- SQL 连接只读复用已有数据源，RPC 作为 Direct Load 数据通道单独展示和校验；
- RPC 地址和端口显示来源，不允许无依据复制 SQL 地址或端口；
- OBLOADER、OBServer 和 ODP 版本结果按 4.3.5 专题版本矩阵展示，无法取得时不得显示通过。

<a id="business-scenarios-dl-lf-03-单表文件"></a>

#### DL-LF-03 单表文件


- 执行节点本地目录作为已确认来源；
- 远程存储在证据完成前禁用并标记“待官方参数映射确认”；
- 展示文件数量、总大小、有限样例和节点可读状态；
- 多文件只表示同一目标表的数据分片，零文件、多表或无法判定时阻断。

<a id="business-scenarios-dl-lf-04-唯一目标表格式与结构"></a>

#### DL-LF-04 唯一目标表、格式与结构


- 只允许一个明确目标表，不提供多选、全部对象、DDL 或 MIX；
- 格式按连接场景和官方证据开放，当前场景未确认的格式禁用；
- 全量或增量模式由目标表是否为空派生，不提供手工切换；
- 表存在性、BIT/二进制类型、虚拟生成列、索引和 LOB 纳入结构预检查；
- `replace-data` 仅按已确认条件显示，且不能被表达为唯一索引冲突解决方案。

<a id="business-scenarios-dl-lf-05-执行参数与节点配置"></a>

#### DL-LF-05 执行参数与节点配置


- 参数层级和分类入口与普通导入一致；
- `--thread` 表示 OBLOADER 客户端连接池，`--parallel` 表示 OBServer 写入与排序工作线程；
- 两者不一致时警告但不自动联动，可提供一次性同步填充；
- `session.config.json` 只读展示执行节点实际路径、指纹、读取时间和实际值；
- 任务向导不上传、编辑或保存节点级配置文件。

<a id="business-scenarios-dl-lf-06-预检查完整命令与风险确认"></a>

#### DL-LF-06 预检查、完整命令与风险确认


- 预检查覆盖适用条件、SQL/RPC、版本、节点工具、文件、唯一目标表、格式结构和 Direct Load 参数约束；
- 命令只读、默认脱敏、支持复制，并只使用当前已确认的 4.3.5 参数基线；
- 最小命令结构包括 `--rpc-port`、唯一 `--table`、已确认格式、`--file-path`、`--direct`，以及用户显式设置的 `--thread`、`--parallel`；
- 表级整体提交、无检查点、失败从头执行、索引结构、资源影响和直连风险绑定当前任务快照确认；
- 未完成最终风险确认时禁止提交。

<a id="business-scenarios-dl-lf-07-失败后从头执行"></a>

#### DL-LF-07 失败后从头执行


- 任务详情骨架、配置快照、完整命令、执行日志和操作记录与普通导入一致；
- 不显示“从检查点继续”或“从失败点继续”；
- 只提供从头重新执行、基于原配置新建、复制脱敏命令和查看完整日志；
- 展示可靠阶段和持续时间，不虚构进度百分比或 ETA；
- 服务端提交阶段的取消语义未确认前，不承诺可安全取消或自动回滚。

<a id="business-scenarios-5-普通导入与旁路导入的差异护栏"></a>

### 5. 普通导入与旁路导入的差异护栏

| 能力 | 普通导入 | 旁路导入 |
|---|---|---|
| 流程入口 | 普通导入独立入口 | 旁路导入独立入口 |
| 对象范围 | 按官方能力支持多对象表达 | 唯一目标表，同表多分片 |
| 连接 | SQL 数据源连接 | SQL 与 RPC 分开，并检查版本组合 |
| 内容与格式 | DDL、数据、DDL+数据、MIX 及已确认格式 | 仅数据；格式按连接场景证据开放 |
| 模式 | 由普通导入参数确定 | 全量/增量由目标表空状态派生 |
| 并发 | 普通导入线程和资源参数 | `thread` 客户端连接池与 `parallel` 服务端线程分工 |
| 提交与失败 | 符合条件时可检查点继续 | 表级整体提交，不支持检查点继续 |

视觉同构不得导致能力负偏离，也不得把普通导入参数无证据复制到旁路导入。

<a id="business-scenarios-6-当前边界"></a>

### 6. 当前边界

本次确认表示旁路导入关键静态低保真已经通过产品评审，但不表示：

- OBLOADER 4.3.5 的 Direct Load P0 受控验证已经执行；
- 私有 ODP/OBServer 下 SQL、Parquet、ORC 或远程存储已经获得旁路适用证据；
- 响应式、键盘操作、无障碍或真实大文件信息密度已经验证；
- 命令生成、版本检查、节点配置读取、状态解析或取消语义技术设计已经完成；
- 业务代码开发已经准入。
