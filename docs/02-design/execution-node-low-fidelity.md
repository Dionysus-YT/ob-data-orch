> 依据：[执行节点管理模块专项评审稿](execution-node-module.md)、[执行节点管理字段与条件矩阵](execution-node-field-rules.md)

## 1. 评审目标

本文将执行节点的注册、四维状态、通用可用性、环境证据、状态化操作和任务关系落实为静态低保真，覆盖管理员从定位不可用节点到查看原因、核对环境、调整管理状态和追踪关联任务的最小闭环。

设计目标是让管理员和运维人员能够判断节点是否可以接收新任务、结论依据是什么、证据是否仍然新鲜，以及节点变化会怎样影响等待或运行中的任务；同时明确节点通用检查不能替代具体任务的路径、数据库、权限、对象和参数预检查。

本稿不是服务器监控、远程运维、Agent 协议或调度技术设计。图片中的节点、路径、资源数值、版本和时间仅用于表达布局；实际事实仍以 Agent 上报、固定环境检查、任务快照和受控验证证据为准。

## 2. 最小页面集

本轮使用六张页面覆盖节点管理主链路和关键异常状态：

| 能力 | 页面 | 说明 |
|---|---|---|
| 节点定位与可用性判断 | EN-LF-01 | 验证列表筛选、四维状态摘要、工具版本、容量、资源采样和不可用原因 |
| 节点注册与 Agent 关联 | EN-LF-02 | 验证管理字段、任务承载类型、工具路径、基础目录和人工关联边界 |
| 节点详情概览 | EN-LF-03 | 验证四维状态、派生结论、工具环境事实、资源快照、有限任务和节点事件 |
| 通用环境检查 | EN-LF-04 | 验证固定只读清单、异步状态、上一可信结果和 Direct Load 配置证据 |
| 进入维护确认 | EN-LF-05 | 验证运行/等待任务影响、确认条件和不自动取消或迁移的边界 |
| 任务失联与日志跳转 | EN-LF-06 | 验证最后可信状态、状态核对中、等待阻断、任务详情和日志中心边界 |

V1.0 继续使用节点列表、注册/编辑和节点详情三个页面层级，不新增节点监控、节点拓扑、工具安装中心或远程运维页面。

## 3. 页面基线

### EN-LF-01 执行节点列表


- 筛选覆盖节点关键字、管理状态、心跳状态、接收新任务，以及展开后的环境和工具条件；
- 默认列同时展示管理状态、在线状态、OBLOADER/OBDUMPER 独立版本、接收新任务、容量和资源摘要；
- “接收新任务”是派生结论，不可接收时展示首要原因和全部原因入口；
- 离线节点保留最后可信资源值和时间，并明确标注为最后可信而非实时；
- 达到最大并发才派生繁忙，CPU、内存和磁盘快照在无明确硬阈值时不自动阻断；
- 列表用于定位和状态化操作，不增加历史曲线、容量预测或自动诊断。

### EN-LF-02 注册执行节点


- 管理信息只包含名称、描述、可选节点组和最大并发任务数；
- 通过承载任务类型控制 OBDUMPER、OBLOADER 启动文件的条件必填；
- 默认工作目录和日志目录使用节点侧绝对路径，不提供文件浏览器；
- 保存只创建节点记录，不代表节点环境正常、工具可用或能够接收任务；
- 平台提供 Agent 部署与关联指引，不通过 SSH 或远程命令安装 Agent；
- 收到首次心跳后，由有权限用户发起只读环境检查；关联敏感信息仅在创建或轮换时受控展示，不长期明文回显。

### EN-LF-03 节点运行概览


- 页面顶部先展示接收新任务结论、首要原因和全部原因入口；
- 管理、心跳、环境和容量使用四张独立状态卡，不以单一健康分掩盖事实；
- Agent、Java、OBLOADER、OBDUMPER、工作目录、日志目录和 Direct Load 配置均显示来源并保持只读；
- CPU、内存和相关目录磁盘只展示当前快照及采样时间；
- 当前/最近任务和节点事件只展示有限条数，并分别跳转任务中心、任务详情或日志中心；
- 通用环境结论不替代任务级路径、版本、数据库、权限和参数检查。

### EN-LF-04 异步只读环境检查


- 环境检查由有权限用户显式发起，离线时不可发起；
- 检查使用平台固定清单，逐项验证 Agent、工具、Java、基础目录和资源事实；
- 检查异步执行且防止重复提交，进行中保留上一可信结果，完成后原子更新；
- 检查结果逐项展示通过、失败、等待或未取得，并记录证据摘要与时间；
- Direct Load 配置只展示路径、读取时间、已确认值摘要和指纹，不能在平台编辑；
- 通用检查不验证数据源连通性、数据库权限、任务输入/输出路径、目标对象、格式、参数组合或实际数据执行可行性。

### EN-LF-05 进入维护确认


- 弹窗展示节点、管理状态、心跳、当前运行任务、等待任务和最大并发；
- 进入维护后停止接收新任务，但当前运行任务继续运行，不自动取消；
- 已绑定该节点的等待任务在启动前复验时被阻断，不静默改派；
- 用户可以查看受影响任务，并填写不含敏感信息的维护原因；
- 确认前必须明确理解现有任务不会被自动取消或迁移；
- 退出维护后重新依据心跳、环境、容量和工具事实派生接收新任务结论。

### EN-LF-06 节点任务与事件


- 节点离线时，管理状态仍独立保留，环境和容量显示过期或最后可信事实；
- 节点离线不等于工具进程失败，运行任务保留最后可信状态并进入“状态核对中”；
- 等待任务继续显示等待调度，并明确展示节点离线等启动阻断原因；
- Agent 恢复后依据进程、退出码、日志和数据库端事实更新任务状态；
- 节点页面只提供查看任务详情和带节点筛选进入任务中心，不直接取消、重试或迁移任务；
- 最近节点事件仅展示有限记录，完整 Agent/节点日志进入日志中心并携带节点 ID 和时间范围。

## 4. 状态与证据表达

| 维度 | 页面表达 | 禁止推断 |
|---|---|---|
| 管理状态 | 已启用、维护中、已禁用 | 已启用等于在线或环境正常 |
| 心跳状态 | 在线、离线、从未连接及最近心跳 | 离线等于运行任务失败 |
| 环境状态 | 未检查、正常、异常、已过期及检查时间 | 旧检查结果仍代表当前环境 |
| 容量状态 | 当前运行数、最大并发和来源 | CPU/内存采样自动决定繁忙 |
| 通用可用性 | 可接收/不可接收及全部原因 | 通用结论等于当前任务可以执行 |
| 任务状态 | 最后可信状态、核对状态和阻断原因 | 节点异常触发静默改派、取消或失败 |

## 6. 当前边界

本次确认表示执行节点管理的静态低保真已经通过产品评审，但不表示：

- Agent 通信协议、注册认证形式、关联信息有效期或轮换机制已经技术定版；
- 心跳超时、环境检查过期、任务启动超时或默认节点排序算法已经确定；
- 多操作系统下工具启动文件、Java、目录权限和 Direct Load 配置读取已经完成受控验证；
- 通用节点可用性可以替代三类任务的节点、路径、版本、配置和权限预检查；
- 可交互原型、高保真 UI、服务器运维能力、技术设计或业务代码开发已经准入。
