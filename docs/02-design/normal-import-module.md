## 1. 评审目标

把普通导入五步向导推进为可逐项评审的产品方案。设计思路与导出模块一致：本轮承载经核对且属于当前范围的普通导入参数，常用字段保持简洁，性能、解析与风险配置进入唯一高级区，适用条件与含义可从参数目录检索。

本稿不定义 API、数据库表、命令生成实现、高保真 UI，也不替旁路导入作产品设计。

## 2. 模块边界

### 包含

- 选择已启用、当前连接配置已成功测试的数据源。
- 本轮选择执行节点上的本地文件/目录；远程存储保留官方研究，不提供新建配置。
- 按官方规则配置文件后缀、正则、控制文件、列映射和目标对象。
- 配置对象定义、数据或对象定义和数据；MIX 不进入本轮表单。
- 本轮数据格式只提供 CSV、CUT、SQL。
- 按内容、格式和兼容模式配置本轮适用的解析、错误、性能、Oracle NLS 与高风险操作。
- 执行文件与参数预检查、完整命令预览、复制和提交。
- 提交后进入统一任务详情、日志和失败处理。

### 不包含

- `--direct`、`--rpc-port`、`--parallel` 所属的旁路导入能力。
- 浏览器上传、平台文件管理或文件内容编辑器。
- 自动建表、自动修改表结构、智能推导业务字段映射。
- 导入/导出权限诊断、对象级权限诊断或性能诊断作为数据源测试能力。
- 平台自定义数据解析、清洗、转换或执行引擎。
- 仅出现在共享 `--help`、但 4.3.5 官方普通导入语义未确认的参数。

## 4. 参数承载原则

“承载所有参数”在产品中的准确含义是：

1. `--help` 的 103 个长参数全部进入参数基线，不能漏项。
2. 经官方资料确认且属于本轮范围的参数有明确页面入口或受管派生说明；未准入能力和失败操作不混入新建配置。
3. 连接参数归受管数据源与安全上下文；后续命令和任务快照按正式契约脱敏展示，不在向导重复输入秘密或任意会话文件。
4. 页面采用常用区与每步唯一高级区，专家业务项在高级区内分组，不再建立额外展示层级。
5. 旁路专属、CLI 元参数、废弃参数、导出侧参数和官网未确认参数不进入新建普通导入任务。
6. 未显式设置的可选参数沿用官方默认，不主动写入命令。

103 项是共享工具帮助的研究基线；DEC-053 将页面目录收敛为 76 项本轮适用的可配置或受管派生参数。旁路专属、CLI 元参数、废弃/未确认、未开放来源/格式、失败任务恢复和当前不支持的连接环境等 27 项不进入新建目录，完整列表见[映射基线 §5](normal-import-parameter-mapping.md#5-本轮普通导入参数边界)。

### 4.1 本轮参数设计

| 步骤 | 常用区 | 同页唯一高级区 / 受管项 |
|---|---|---|
| 数据源 | 已管理数据源、目标数据库/Schema | 连接与安全上下文受管；不提供字符集、会话文件、旧式 tenant/cluster 或云/Sharding 配置 |
| 导入文件与格式 | 节点本地路径、日志目录、内容、三格式下拉、编码/后缀、主要分隔符和适用开关 | 文件正则、文本解析、压缩输入、MySQL 日期纠错 |
| 对象与映射 | 对象范围、适用表达式、排除表、映射方式与所需控制文件/显式名单 | 排除数据类型；本轮仅 CSV 显示自动列映射 |
| 执行参数 | 含数据时的重复量、写入错误数、脏数据退出状态 | 性能与资源、Oracle NLS、兼容和高风险数据行为 |
| 预检查与命令 | 六项检查状态、脱敏命令预览与复制 | 未知事实与独立执行门禁阻断提交；不提供可编辑执行参数或独立 yes 开关 |

实际 CLI 字段使用与导出一致的 Ant Tooltip，参数名与含义分行，支持悬停与键盘焦点；提示按钮与 Checkbox/Radio 并列，不能改变选项。平台选择、本地阅读确认不伪装成 CLI 参数。

数据写入类 `max-discards`、`max-errors`、`strict`、`rw`、`batch`、`block-size`、`max-tps`、`max-wait-timeout` 只在包含数据时参与配置；仅对象定义仍可设置线程、JVM 内存与适用 Oracle NLS。`block-size` 是读取已有文件的逻辑分块，`max-wait-timeout` 是数据库合并等待；压缩算法与等级识别输入文件。它们不等同于导出物理文件拆分、任务总超时或生成压缩输出。

包含列与排除列按本轮平台规则择一；填写一方后禁用空的另一方，清空后可切换。若收到同时非空的冲突输入，保留两边供修正、本地校验阻断，活动名单不选择任意一边。该约束来源于 DEC-053，不宣称官方 CLI 两参数天然互斥。

## 5. 五步向导总览

```text
1. 选择数据源
→ 2. 导入文件与格式
→ 3. 对象与映射
→ 4. 执行参数
→ 5. 预检查与命令
→ 任务详情和日志
```

| 步骤 | 必须回答的问题 | 主要输出 |
|---|---|---|
| 1. 数据源 | 导入到哪个 OceanBase 数据源和数据库 | 连接、兼容模式与环境摘要 |
| 2. 文件与格式 | 从节点哪里读文件；导入对象定义、数据还是两者；数据是什么格式 | 执行节点、路径、后缀、编码、唯一格式、解析与压缩条件及有效文件集 |
| 3. 对象与映射 | 导入全部对象还是指定对象，文件如何对应目标 | 对象参数、排除项、控制文件与列映射 |
| 4. 执行 | 如何处理错误、性能、会话和高风险行为 | 分类参数快照与风险确认 |
| 5. 确认 | 文件和参数是否可执行，最终执行什么 | 检查结果、只读完整命令和任务快照 |

## 6. 步骤 1：选择数据源

- 单选已有数据源，显示名称、环境、连接方式、地址、SQL 端口、租户、集群、兼容模式、最近测试状态和时间。
- `--host`、`--port`、`--user`、`--password`、适用 sys 选项及受管连接配置归数据源与安全上下文；当前页面只读授权列表，不读取秘密或生成参数。
- 新任务不单独提供 `--tenant`、`--cluster`，只保留官方三段式账号的研究与受管连接摘要；云环境与 ODP Sharding 不在本轮配置。
- 目标数据库/Schema `--database` 必填，可由数据源默认值回填后由任务覆盖。
- 数据源连接测试只说明基础连接成功；任务提交前仍检查本次数据库、对象、权限和参数。

## 7. 步骤 2：导入文件与格式——文件来源

### 文件来源

本轮只提供执行节点本地路径。下列远程类型与第三方文件说明保留官方研究，不建立本轮字段、派生值或目录项。

第二步的内容名称与导出对应为“导入结构和数据 / 仅导入数据 / 仅导入结构”，枚举与命令语义不变。执行节点沿用导出与数据源的“登记名称 · 操作系统 · 架构”显示规则，绑定值仍为节点 ID。文件或目录路径直接说明其属于所选执行节点的允许目录；不再另列没有配置作用的“输入位置”静态字段。

- 执行节点本地绝对路径或单个文件。
- 官方 `--file-path` 支持的 OSS、S3、HDFS、COS、OBS、Azure Blob 和 GCS 等 URI。
- 不提供“任意 URI”；按官方 scheme 展示相应 endpoint、region、凭据或 token 字段。
- `--storage-uri` 已被 `--file-path` 统一承载，新任务不再生成。
- 远程存储使用 `--tmp-path` 时，预检查执行节点目录、权限和空间。

### 文件匹配配置与核对

- 文件后缀 `--file-suffix`：默认随格式继承，用户可覆盖。
- 文件正则 `--file-regular-expression`：高级配置；展示匹配数量和少量样例，不读取业务内容作推断。
- 第三方文件 `--external-data`：仅在文件不是 OBDUMPER 标准输出、需要跳过 MANIFEST 检查时启用，并提示兼容风险。
- 文件编码 `--file-encoding` 可在任务内配置；数据库连接字符集 `--character-set` 归受管上下文，不提供任务级覆盖。
- `--log-path` 未设置时沿用官方写入 `--file-path` 对应目录的行为。
- 文件来源与内容、格式在同一页配置。2026-10-17 按用户要求移除第二步“发现输入文件”按钮及提示；离开第二步只校验本页输入，路径可达性与有效文件集统一由第五步完整预检查按当前后缀、正则、压缩和格式规则核对。

## 8. 步骤 2：导入文件与格式——内容与格式

### 内容模型

| 页面选项 | 命令结构 | 说明 |
|---|---|---|
| 仅导入结构 | `--ddl` + 对象范围 | 不导入表数据 |
| 仅导入数据 | 一种数据格式 + 对象范围 | 必须选择数据格式 |
| 导入结构和数据 | `--ddl` + 一种数据格式 + 对象范围 | 分别导入定义文件与数据文件 |
| MIX 混合文件（本轮不开放） | `--mix` + 对象范围 | 保留官方研究；不建立本轮模式或确认 |

MIX 处理复杂、性能低，且会把文本读入内存解析，不适合大文件；使用时显示风险提示。MIX 与 `--ddl`、任一其他数据格式互斥。

### 数据格式（官方研究范围；本轮仅配置 CSV / CUT / SQL）

| 页面格式 | 官方参数 | 关键约束 |
|---|---|---|
| CSV | `--csv` | 官方推荐；支持列分隔符、包围符、转义和首行跳过 |
| Insert SQL | `--sql` | 数据 SQL，不是 DDL；不支持文件内容中任意 SQL 函数/特殊结构 |
| CUT | `--cut` | 字符串分隔；支持尾分隔符和末行跳过 |
| POS | `--pos` | 定长字节；必须提供控制文件 |
| ORC | `--orc` | 列式格式；支持自动列映射和 Hive 路径 |
| Parquet | `--par` | 列式格式；支持自动列映射和 Hive 路径 |
| Avro | `--avro` | 支持 Primary/Logical Types，不支持 Complex Types |

同一数据导入只选择一种格式。切换格式后只生成当前格式适用参数；其他格式草稿值可临时保留但不生效。

内容、格式或文件条件变化后，旧文件证据失效；第五步完整预检查基于第 2 步当前配置重新计算有效 DDL 文件、数据文件和冲突文件，完整预检查通过后才可提交。

### 压缩文件

- `--compress` 表示输入是经 OBDUMPER 压缩导出的文件，不是让导入任务再次压缩。
- 本轮仅对 CSV、CUT、SQL 显示；POS 保留官方研究。
- 算法为 zstd、zlib、gzip、snappy；zstd 和 zlib 支持相应等级，gzip/snappy 不配置等级。

## 9. 步骤 3：对象与映射

### 导入范围

- **全部导入**：生成 `--all`，与任意具体对象参数严格互斥。
- **指定对象**：至少选择一种对象类型并填写合法表达式。
- 虽然工具同时收到 `--all` 和具体对象时会优先 `--all`，平台仍阻断这种会掩盖用户选择的组合。

### 对象类型

| 页面对象类型 | 官方参数 | 可导入数据 | 主要条件 |
|---|---|---:|---|
| 全部对象 | `--all` | 是 | 与具体对象互斥 |
| 表 | `--table` | 是 | DDL 或数据；控制文件场景大小写需精确匹配 |
| 表组 | `--table-group` | 否 | 仅定义 |
| 视图 | `--view` | 否 | 仅定义 |
| 触发器 | `--trigger` | 否 | 仅定义 |
| 用户 | `--obj-user` | 否 | 有权限与默认忽略用户规则 |
| 角色 | `--role` | 否 | Oracle 兼容模式 |
| 序列 | `--sequence` | 否 | Oracle 兼容模式 |
| 同义词 | `--synonym` | 否 | Oracle 兼容模式 |
| 类型 / 类型体 | `--type` / `--type-body` | 否 | Oracle 兼容模式 |
| 包 / 包体 | `--package` / `--package-body` | 否 | Oracle 兼容模式 |
| 函数 / 存储过程 | `--function` / `--procedure` | 否 | 受兼容模式和版本限制 |

### 文件到列的映射

- 默认按源文件列顺序映射目标表列，不做平台推断。
- 显式列名单提供 `--include-column-names` 或 `--exclude-column-names`，本轮按平台规则择一；处理后文件列数和顺序仍须核对。
- `--exclude-data-types` 跳过指定数据类型。
- `--ctl-path` 使用官方控制文件，不在本轮设计控制文件编辑器。
- `--auto-column-mapping` 只对 CSV、ORC、Parquet 显示；根据源文件列名与目标列名映射。
- `--ctl-path` 与 `--auto-column-mapping` 互斥。
- `--source-type hive` 只对 ORC/Parquet 显示，并与自动列映射配合解析 `key=value` 目录列。

## 10. 步骤 4：执行参数

### 参数分层

| 展示层级 | 目的 | 代表参数 |
|---|---|---|
| 普通模式 | 完成一次可执行导入 | 数据源、数据库、文件、对象、内容、格式、执行节点 |
| 常用执行配置 | 含数据时的错误与重复处理 | `--max-discards`、`--max-errors`、`--strict` |
| 同页唯一高级区 | 性能、JVM、Oracle NLS、兼容和数据行为 | `--thread`、`--rw`、`--batch`、`--block-size`、`--mem`、NLS、replace/truncate/delete |
| 不展示 | 非普通导入、废弃、元参数或语义未确认 | `--direct`、`--rpc-port`、`--parallel`、`--storage-uri`、`--server` |

本轮适用参数可在“全部参数”目录中检索含义、条件与所属步骤；未开放能力不作为可配置项占位。字符集和会话配置只说明受管所有权，不表示已读取或可执行。

### 错误与性能

- `--max-discards`：单表允许的重复数据量，默认 -1；不适用于旁路导入。
- `--max-errors`：单表允许的数据库写入错误数，默认 1000；不适用于旁路导入。
- `--strict`：存在坏记录或丢弃记录时，让进程以非零退出码结束；不改变错误本身的解析。
- `--retry`：失败任务从 `--file-path` 下的 `load.ckpt` 最近保存点继续；只在满足条件的失败任务操作中出现。
- `--thread`：写入并发，官方默认 CPU×2 且上限 32。
- `--rw`：文件解析线程比例，解析线程数为 `thread × rw`。
- `--batch`：每批事务记录数；4.2.0 起默认可按 JVM 内存自适应。
- `--slow`、`--pause`：保留官方阈值研究；精确边界未验证，本轮不提供输入和目录项。
- `--max-tps`：导入限速，默认单位为行/秒。
- `--block-size`：大文件逻辑切分大小，官方默认 64MB。
- `--max-wait-timeout`：等待数据库合并最长时间，官方默认 3 小时。
- `--mem`：JVM 内存，官方发布说明默认 4G；结合执行节点资源检查。

### 高风险数据行为

- `--replace-data` 仅适用于有主键或非空唯一键的目标表；开启前检查适用条件并二次确认。
- `--replace-object` 仅与 `--ddl` 或 `--mix` 生效，会替换已有对象定义。
- `--truncate-table` 与 `--delete-from-table` 仅在包含数据时显示，彼此互斥，均为专家配置和强风险操作。
- `--delete-from-table` 搭配 `--all` 或 `--table '*'` 时，即使输入路径没有某张表的数据文件，也可能删除该表数据；摘要必须明确列出影响范围。
- 平台自己完成二次确认后，可在生成给非交互任务的命令中派生 `--yes`；不把“跳过确认”作为独立用户开关。

## 12. 步骤 5：预检查与完整命令

### 预检查

本轮进入第五步、配置与引用就绪后自动保存必要修订并依次生成脱敏命令、发起完整预检查；移除手动生成命令按钮，保留“重新预检查”。同一配置版本只自动尝试一次，失败或过期不循环重试；修改配置后撤销旧证据。结构检查的当前边界见技术契约，不能把通过解释为全部文件数据或 DDL 已验证。

至少检查：

- 数据源当前可连接，目标数据库/Schema 可访问；
- 当前账号满足本次对象定义、数据写入或替换操作所需权限；
- 执行节点在线、OBLOADER 版本为目标版本并可访问输入位置；
- 文件/目录存在、可读、匹配结果非空，远程存储凭据有效；
- 文件格式、后缀、编码、控制文件和列映射条件一致；
- 目标表存在性、列数/列名及破坏性操作适用范围；
- 对象、内容、格式、兼容模式和全部参数的互斥、依赖与范围；
- 高风险操作已完成本次参数快照对应的确认。

### 命令确认

- 展示实际可执行的完整 OBLOADER 命令，按连接、文件、对象、内容/格式、错误、性能和风险参数分组高亮。
- 密码、sys 凭据、对象存储密钥和 token 默认脱敏。
- 命令只读；复制默认复制脱敏版本，具备权限时才允许受控复制可执行版本。
- 任一影响命令、文件集合或目标对象的字段变化后，原预检查和相关风险确认失效。
- 任务名称不在本页强制填写，也不影响自动生成和预检查。提交时弹窗提供可选名称，最多 200 个 Unicode 字符且不能包含控制字符；留空由服务端按目标库、格式、UTC 时间及任务标识生成，独立保存到冻结快照。

## 13. 失败与检查点继续

- 普通导入支持 `--retry`；旁路导入不支持，二者不能复用同一失败操作。
- 保存点文件为 `--file-path` 下的 `load.ckpt`。
- 只有失败任务存在有效检查点、原输入路径仍可访问、工具版本和不可变参数快照一致时，显示“从检查点继续”。
- 继续执行使用原任务快照，不允许先改参数再继续。
- 不满足条件时提供“基于原配置新建”和“从头重新执行”。

## 15. 验收基线

1. 用户无需手写命令即可完成基础普通导入。
2. 所有经核验的普通导入参数均有配置、派生或失败操作入口。
3. 基础用户不需要浏览全部高级参数，专家可按分类找到任一有效参数。
4. 普通导入不会生成旁路专属参数。
5. 文件匹配、对象范围、内容、格式和列映射不存在歧义组合。
6. MIX 与 DDL+数据格式被清楚区分。
7. 高风险数据操作显示准确影响范围并完成二次确认。
8. 提交前完成任务级预检查并展示完整只读命令。
9. 敏感连接和存储信息默认脱敏。
10. 失败任务只有存在有效 `load.ckpt` 且原参数条件满足时才能从检查点继续。

### 1. 目的与边界

本文把普通导入参数落到字段层，明确字段位置、显示条件、必填条件、默认来源、清值方式、命令映射和预检查失效范围。本轮按 DEC-053 提供适用字段，未开放项保留原 ID 并明确不建表单；命令、文件发现和预检查协议已有 G2 隔离实现，真实数据库、写权限、映射与工具执行仍按技术契约保持未接入。

<a id="field-rules-2-字段状态"></a>

### 2. 字段状态

| 状态 | 含义 | 生成命令 | 提交快照 |
|---|---|---:|---:|
| 未设置 | 用户未覆盖，沿用 OBLOADER 4.3.5 官方默认 | 否 | 记录默认来源或“官方默认” |
| 已显式设置 | 用户在当前适用条件下主动配置 | 是 | 是 |
| 非活动 | 因格式、内容、环境或模式不适用 | 否 | 否；草稿期可按命名空间暂存 |
| 派生 | 从数据源、执行节点、安全配置或确认结果计算 | 需要时 | 是，敏感值脱敏 |
| 阻断 | 映射不确定、依赖不满足或预检查失败 | 否 | 不允许提交 |

通用规则：

- 未设置的可选参数显示“沿用官方默认”，不为追求命令长度主动生成。
- 参数搜索必须能定位所有“可编辑”和“派生”字段，并显示为什么当前隐藏或只读。
- 格式切换只让不适用字段停止生效；草稿值按格式暂存，提交只保存活动值。
- 内容、数据源或兼容模式变化导致原值必然非法时，列出影响并在用户确认后清除。
- 任何影响实际文件集合、目标对象、命令或风险范围的变化都会使相应预检查失效。

### 13. 字段覆盖验收

1. 参数搜索能对每个有效普通导入参数返回可编辑字段、派生摘要或失败任务操作。
2. 不适用参数可解释“为什么当前不可用”，而不是无声消失。

5. 所有活动字段都进入参数摘要和不可变任务快照。
6. 所有命令变化都能使对应预检查失效，所有风险范围变化都能使确认失效。

<a id="business-scenarios-2-六步顺序调整"></a>

### 2. 五步顺序与文件格式同页

低保真评审发现，原方案先配置“对象与映射”、后选择“内容与格式”，存在逆向依赖：

- 官方自动列映射只适用于 CSV、ORC、Parquet；
- Hive 来源只适用于 ORC/Parquet，并依赖自动列映射；
- POS 必须先明确格式，才能要求控制文件；
- 文件后缀、压缩和解析字段也依赖具体格式。

2026-07-20 先将内容与格式移到对象与映射之前；2026-10-15 用户进一步确认合并文件来源与内容格式，便于同页核对路径、后缀、编码、压缩和解析条件。现行顺序为：

```text
1. 选择数据源
→ 2. 导入文件与格式
→ 3. 对象与映射
→ 4. 执行参数
→ 5. 预检查与命令
→ 任务详情和日志
```

该调整只改变普通导入的步骤归属，不要求与旁路向导统一步骤数。两个模块独立维护表单、参数、校验和资格规则；仅复用通用外壳和基础交互组件。

#### NI-LF-01 文件来源与初步发现


- 选择执行节点可访问的本地绝对路径或官方支持的远程存储类型；
- 不提供浏览器上传、任意 URI、平台文件管理或文件内容编辑器；
- 第 2 步同页配置文件来源、内容与格式，只校验当前输入；路径与文件集合由第 5 步完整预检查核对；
- 文件正则、编码、第三方文件模式和远程临时目录按条件展示；
- 本页内容、格式或文件条件变化后使旧证据失效，第 5 步按当前配置重新核对有效文件集。

<a id="business-scenarios-ni-lf-02-内容与格式"></a>

#### NI-LF-02 内容与格式


- 仅对象定义、仅数据、对象定义和数据、MIX 混合文件严格单选；
- MIX 是独立解析模式，与 DDL 加数据格式互斥，不把 MIX 表达成普通组合；
- CSV、Insert SQL、CUT、POS、ORC、Parquet、Avro 严格单选；
- 只显示当前格式活动字段，其他格式草稿值可暂存但不生效；
- 依据已选格式、后缀和解析条件重新计算 DDL 文件、数据文件和冲突文件；
- 压缩表达“读取 OBDUMPER 压缩输入”，不是再次压缩导入数据。

<a id="business-scenarios-ni-lf-03-对象与映射"></a>

#### NI-LF-03 对象与映射


- 全部对象和指定对象互斥；指定对象至少包含一种适用对象表达式；
- 映射方式为按文件列顺序、控制文件、官方自动列映射、显式列名单四选一；
- 官方自动列映射明确标记为 OBLOADER 能力，不包装成平台智能映射；
- 映射预览只展示源文件头/元数据和目标元数据形成的只读准备结果，最终在第 5 步验证；
- 平台不创建目标表、不修改表结构、不提供自由映射表达式编辑器。

<a id="business-scenarios-ni-lf-04-执行参数与高风险操作"></a>

#### NI-LF-04 执行参数与高风险操作


- 普通、高级、专家和全部参数使用统一字段状态与分类搜索入口；
- 未设置的可选项显示“沿用官方默认”，不为追求命令长度主动写出；
- 性能字段展示官方默认或参数关系，不生成伪精确推荐值；
- `replace-data`、`replace-object`、`truncate-table`、`delete-from-table` 只按官方条件显示；
- `truncate-table` 与 `delete-from-table` 互斥；影响范围绑定目标数据库、对象、文件集和参数快照；
- `--yes` 不作为用户开关，平台仅在完成等价确认后为非交互任务派生。

<a id="business-scenarios-ni-lf-05-预检查与完整命令"></a>

#### NI-LF-05 预检查与完整命令


- 预检查按数据源与权限、执行节点与工具、文件集合、内容与格式、对象与列映射、参数约束和高风险确认分组；
- 进入本步配置就绪后自动生成命令并检查；检查失败或过期提供显式重试，避免循环请求；
- 任一阻断项存在时禁止提交，并提供返回对应步骤修正的入口；
- 全部通过后才能提交，提交时保存不可变任务、文件、对象、参数和风险确认快照；
- 提交弹窗可输入名称，留空按服务端规则生成，名称不使当前预检查失效；
- 完整命令只读、默认脱敏并支持复制脱敏命令；
- 普通导入不得生成 `--direct`、`--rpc-port` 或 `--parallel`；
- 图片内示例命令不代替参数映射与受控验证。

<a id="business-scenarios-ni-lf-06-失败任务检查点继续"></a>

#### NI-LF-06 失败任务检查点继续


- 仅失败的普通导入任务可能显示“从检查点继续”；
- 必须同时满足原路径下存在有效 `load.ckpt`、输入路径仍可访问、工具版本匹配和不可变参数快照匹配；
- 继续使用原任务快照，不允许修改参数后继续；
- 不满足条件时仅提供从头重新执行或基于原配置新建；
- 已提交批次不会因后续失败自动回滚；
- 旁路导入不复用检查点继续能力。

<a id="business-scenarios-5-与公共基线及旁路导入的关系"></a>

### 5. 与公共基线及旁路导入的关系

- 数据源选择、命令确认、任务详情和日志继续复用公共业务交互语言；页面骨架遵循 P0 MASTER；
- 普通导入独有的是多对象/多文件、七种格式、列映射、错误容忍、高风险数据行为和检查点继续；
- [旁路导入场景矩阵](direct-load-module.md#business-scenarios)保持独立流程；普通导入不展示或接受旁路专属参数，也不因共享 Task Builder 外壳向旁路引入 `--retry`、多对象或普通错误容忍语义。

<a id="business-scenarios-6-当前边界"></a>

### 6. 当前边界

2026-07-20 的确认表示普通导入关键静态低保真通过产品评审；2026-10-15 另按 DEC-051 准入本页前端配置与职责重构，实际验证以维护索引为准。上述确认不表示：

- OBLOADER 4.3.5 的 P0 受控验证已经执行；
- 真实大文件信息密度已经验证；
- 参数元数据、命令生成、检查点或任务状态技术设计已经完成；
- 导入后端与真实执行已经准入。
