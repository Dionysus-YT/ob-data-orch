## 1. 评审目标

把 PRD 中的普通导入六步向导推进为可逐项评审的产品方案。设计思路与导出模块一致：平台完整承载经官方资料确认、适用于普通导入的参数，用户可以按需自由配置；基础流程保持简洁，全部参数通过分类面板和条件显示提供，而不是把命令行参数无差别平铺。

本稿不定义 API、数据库表、命令生成实现、高保真 UI，也不替旁路导入作产品设计。

## 2. 模块边界

### 包含

- 选择已启用、当前连接配置已成功测试的数据源。
- 选择执行节点可读取的本地文件/目录或官方支持的远程存储路径。
- 按官方规则配置文件后缀、正则、控制文件、列映射和目标对象。
- 配置 DDL、数据、DDL + 数据或独立 MIX 导入。
- 从 CSV、SQL、CUT、POS、ORC、Parquet、Avro 中选择适用格式。
- 配置普通导入全部经核验参数，包括序列化、错误处理、性能、会话和高风险操作。
- 执行文件与参数预检查、完整命令预览、复制和提交。
- 提交后进入统一任务详情、日志和失败处理。

### 不包含

- `--direct`、`--rpc-port`、`--parallel` 所属的旁路导入能力。
- 浏览器上传、平台文件管理或文件内容编辑器。
- 自动建表、自动修改表结构、智能推导业务字段映射。
- 导入/导出权限诊断、对象级权限诊断或性能诊断作为数据源测试能力。
- 平台自定义数据解析、清洗、转换或执行引擎。
- 仅出现在共享 `--help`、但 4.3.5 官方普通导入语义未确认的参数。

## 4. 参数承载原则

“承载所有参数”在产品中的准确含义是：

1. `--help` 的 103 个长参数全部进入参数基线，不能漏项。
2. 经官方资料确认属于普通导入的有效参数，都有明确的页面入口、派生规则或失败任务操作。
3. 连接参数可以由数据源快照派生，但必须在完整命令和任务快照中可见。
4. 普通、高级、专家只是展示层级，不删减官方能力。
5. 旁路专属、CLI 元参数、废弃参数、导出侧参数和官网未确认参数不进入新建普通导入任务。
6. 未显式设置的可选参数沿用官方默认，不主动写入命令。

这不是过度设计：复杂度来自 OBLOADER 的真实参数和约束。产品需要控制的是认知负担和错误组合，而不是删掉有效能力。

## 5. 六步向导总览

```text
1. 选择数据源
→ 2. 选择导入文件与路径
→ 3. 选择导入内容与格式
→ 4. 配置目标对象与文件匹配
→ 5. 执行与高级参数
→ 6. 参数/文件预检查、完整命令与执行确认
→ 任务详情和日志
```

| 步骤 | 必须回答的问题 | 主要输出 |
|---|---|---|
| 1. 数据源 | 导入到哪个 OceanBase 数据源和数据库 | 连接、兼容模式与环境摘要 |
| 2. 文件 | 从哪里读取哪些输入文件 | 文件路径、存储类型、执行节点与匹配预览 |
| 3. 内容与格式 | 导入 DDL、数据、两者还是 MIX；数据是什么格式 | 内容组合、唯一数据格式、有效文件集及专属参数 |
| 4. 对象与匹配 | 导入全部对象还是指定对象，文件如何对应目标 | 对象参数、排除项、控制文件与列映射 |
| 5. 执行 | 如何处理错误、性能、会话和高风险行为 | 分类参数快照与风险确认 |
| 6. 确认 | 文件和参数是否可执行，最终执行什么 | 检查结果、只读完整命令和任务快照 |

## 6. 步骤 1：选择数据源

- 单选已有数据源，显示名称、环境、连接方式、地址、SQL 端口、租户、集群、兼容模式、最近测试状态和时间。
- `--host`、`--port`、`--user`、`--password` 及适用的 `--public-cloud`、`--no-sys`、`--logical-database` 从数据源或安全配置派生。
- `--tenant`、`--cluster` 仅作旧命令兼容；新任务优先使用官方三段式 `<user>@<tenant>#<cluster>`。
- 目标数据库/Schema `--database` 必填，可由数据源默认值回填后由任务覆盖。
- 数据源连接测试只说明基础连接成功；任务提交前仍检查本次数据库、对象、权限和参数。

## 7. 步骤 2：选择文件与路径

### 文件来源

- 执行节点本地绝对路径或单个文件。
- 官方 `--file-path` 支持的 OSS、S3、HDFS、COS、OBS、Azure Blob 和 GCS 等 URI。
- 不提供“任意 URI”；按官方 scheme 展示相应 endpoint、region、凭据或 token 字段。
- `--storage-uri` 已被 `--file-path` 统一承载，新任务不再生成。
- 远程存储使用 `--tmp-path` 时，预检查执行节点目录、权限和空间。

### 初步发现与匹配入口

- 文件后缀 `--file-suffix`：默认随格式继承，用户可覆盖。
- 文件正则 `--file-regular-expression`：高级配置；展示匹配数量和少量样例，不读取业务内容作推断。
- 第三方文件 `--external-data`：仅在文件不是 OBDUMPER 标准输出、需要跳过 MANIFEST 检查时启用，并提示兼容风险。
- 文件编码 `--file-encoding` 与数据库连接字符集 `--character-set` 分开配置。
- `--log-path` 未设置时沿用官方写入 `--file-path` 对应目录的行为。
- 本步骤只完成路径可达性和初步文件发现；第 3 步确定内容与格式后，按活动后缀、压缩和格式规则重新计算有效文件集。

## 8. 步骤 3：导入内容与格式

### 内容模型

| 页面选项 | 命令结构 | 说明 |
|---|---|---|
| 仅对象定义 | `--ddl` + 对象范围 | 不导入表数据 |
| 仅数据 | 一种数据格式 + 对象范围 | 必须选择数据格式 |
| 对象定义和数据 | `--ddl` + 一种数据格式 + 对象范围 | 分别导入定义文件与数据文件 |
| MIX 混合文件 | `--mix` + 对象范围 | 独立解析模式，不等同于 DDL + 数据格式 |

MIX 处理复杂、性能低，且会把文本读入内存解析，不适合大文件；使用时显示风险提示。MIX 与 `--ddl`、任一其他数据格式互斥。

### 数据格式

| 页面格式 | 官方参数 | 关键约束 |
|---|---|---|
| CSV | `--csv` | 官方推荐；支持列分隔符、包围符、转义和首行跳过 |
| Insert SQL | `--sql` | 数据 SQL，不是 DDL；不支持文件内容中任意 SQL 函数/特殊结构 |
| CUT | `--cut` | 字符串分隔；支持尾分隔符和末行跳过 |
| POS | `--pos` | 定长字节；必须提供控制文件 |
| ORC | `--orc` | 列式格式；支持自动列映射和 Hive 路径 |
| Parquet | `--par` | 列式格式；支持自动列映射和 Hive 路径 |
| Avro | `--avro` | 支持 Primary/Logical Types，不支持 Complex Types |

同一数据导入只选择一种格式。切换格式后只生成当前格式适用参数；其他格式草稿值可临时保留但不生效。

选择内容与格式后，系统基于第 2 步路径、后缀、正则、压缩和格式条件重新计算有效 DDL 文件、数据文件和冲突文件；初步发现结果不能直接作为提交依据。

### 压缩文件

- `--compress` 表示输入是经 OBDUMPER 压缩导出的文件，不是让导入任务再次压缩。
- 仅对 CSV、CUT、POS、SQL 显示。
- 算法为 zstd、zlib、gzip、snappy；zstd 和 zlib 支持相应等级，gzip/snappy 不配置等级。

## 9. 步骤 4：目标对象与文件匹配

### 导入范围

- **全部导入**：生成 `--all`，与任意具体对象参数严格互斥。
- **指定对象**：至少选择一种对象类型并填写合法表达式。
- 虽然工具同时收到 `--all` 和具体对象时会优先 `--all`，平台仍阻断这种会掩盖用户选择的组合。

### 对象类型

| 页面对象类型 | 官方参数 | 可导入数据 | 主要条件 |
|---|---|---:|---|
| 全部对象 | `--all` | 是 | 与具体对象互斥 |
| 表 | `--table` | 是 | DDL 或数据；控制文件场景大小写需精确匹配 |
| 表组 | `--table-group` | 否 | 仅定义 |
| 视图 | `--view` | 否 | 仅定义 |
| 触发器 | `--trigger` | 否 | 仅定义 |
| 用户 | `--obj-user` | 否 | 有权限与默认忽略用户规则 |
| 角色 | `--role` | 否 | Oracle 兼容模式 |
| 序列 | `--sequence` | 否 | Oracle 兼容模式 |
| 同义词 | `--synonym` | 否 | Oracle 兼容模式 |
| 类型 / 类型体 | `--type` / `--type-body` | 否 | Oracle 兼容模式 |
| 包 / 包体 | `--package` / `--package-body` | 否 | Oracle 兼容模式 |
| 函数 / 存储过程 | `--function` / `--procedure` | 否 | 受兼容模式和版本限制 |

### 文件到列的映射

- 默认按源文件列顺序映射目标表列，不做平台推断。
- `--include-column-names` 与 `--exclude-column-names` 提供显式列名单；处理后文件列数和顺序必须匹配。
- `--exclude-data-types` 跳过指定数据类型。
- `--ctl-path` 使用官方控制文件，不在本轮设计控制文件编辑器。
- `--auto-column-mapping` 只对 CSV、ORC、Parquet 显示；根据源文件列名与目标列名映射。
- `--ctl-path` 与 `--auto-column-mapping` 互斥。
- `--source-type hive` 只对 ORC/Parquet 显示，并与自动列映射配合解析 `key=value` 目录列。

## 10. 步骤 5：执行与高级参数

### 参数分层

| 展示层级 | 目的 | 代表参数 |
|---|---|---|
| 普通模式 | 完成一次可执行导入 | 数据源、数据库、文件、对象、内容、格式、执行节点 |
| 高级配置 | 文件解析、错误策略、性能、日志与资源 | `--thread`、`--batch`、`--block-size`、`--max-errors`、`--strict`、`--mem` |
| 专家配置 | 会话、兼容、列处理、替换及破坏性行为 | `--session-config`、NLS、`--replace-object`、`--truncate-table`、`--delete-from-table` |
| 不展示 | 非普通导入、废弃、元参数或语义未确认 | `--direct`、`--rpc-port`、`--parallel`、`--storage-uri`、`--server` |

所有有效普通导入参数仍可在“全部参数”分类视图中找到；折叠不等于删除。

### 错误与性能

- `--max-discards`：单表允许的重复数据量，默认 -1；不适用于旁路导入。
- `--max-errors`：单表允许的数据库写入错误数，默认 1000；不适用于旁路导入。
- `--strict`：存在坏记录或丢弃记录时，让进程以非零退出码结束；不改变错误本身的解析。
- `--retry`：失败任务从 `--file-path` 下的 `load.ckpt` 最近保存点继续；只在满足条件的失败任务操作中出现。
- `--thread`：写入并发，官方默认 CPU×2 且上限 32。
- `--rw`：文件解析线程比例，解析线程数为 `thread × rw`。
- `--batch`：每批事务记录数；4.2.0 起默认可按 JVM 内存自适应。
- `--slow`、`--pause`：慢速/暂停阈值；必须满足官方范围关系，精确边界进入受控验证。
- `--max-tps`：导入限速，默认单位为行/秒。
- `--block-size`：大文件逻辑切分大小，官方默认 64MB。
- `--max-wait-timeout`：等待数据库合并最长时间，官方默认 3 小时。
- `--mem`：JVM 内存，官方发布说明默认 4G；结合执行节点资源检查。

### 高风险数据行为

- `--replace-data` 仅适用于有主键或非空唯一键的目标表；开启前检查适用条件并二次确认。
- `--replace-object` 仅与 `--ddl` 或 `--mix` 生效，会替换已有对象定义。
- `--truncate-table` 与 `--delete-from-table` 仅在包含数据时显示，彼此互斥，均为专家配置和强风险操作。
- `--delete-from-table` 搭配 `--all` 或 `--table '*'` 时，即使输入路径没有某张表的数据文件，也可能删除该表数据；摘要必须明确列出影响范围。
- 平台自己完成二次确认后，可在生成给非交互任务的命令中派生 `--yes`；不把“跳过确认”作为独立用户开关。

## 12. 步骤 6：预检查与完整命令

### 预检查

至少检查：

- 数据源当前可连接，目标数据库/Schema 可访问；
- 当前账号满足本次对象定义、数据写入或替换操作所需权限；
- 执行节点在线、OBLOADER 版本为目标版本并可访问输入位置；
- 文件/目录存在、可读、匹配结果非空，远程存储凭据有效；
- 文件格式、后缀、编码、控制文件和列映射条件一致；
- 目标表存在性、列数/列名及破坏性操作适用范围；
- 对象、内容、格式、兼容模式和全部参数的互斥、依赖与范围；
- 高风险操作已完成本次参数快照对应的确认。

### 命令确认

- 展示实际可执行的完整 OBLOADER 命令，按连接、文件、对象、内容/格式、错误、性能和风险参数分组高亮。
- 密码、sys 凭据、对象存储密钥和 token 默认脱敏。
- 命令只读；复制默认复制脱敏版本，具备权限时才允许受控复制可执行版本。
- 任一影响命令、文件集合或目标对象的字段变化后，原预检查和相关风险确认失效。

## 13. 失败与检查点继续

- 普通导入支持 `--retry`；旁路导入不支持，二者不能复用同一失败操作。
- 保存点文件为 `--file-path` 下的 `load.ckpt`。
- 只有失败任务存在有效检查点、原输入路径仍可访问、工具版本和不可变参数快照一致时，显示“从检查点继续”。
- 继续执行使用原任务快照，不允许先改参数再继续。
- 不满足条件时提供“基于原配置新建”和“从头重新执行”。

## 14. 已确认产品决策

NI-R01～NI-R18 已于 2026-07-17 全部确认。确认的是产品承载、展示、边界和风险处理方案；明确标注待官方确认或待实测的工具行为仍不得视为已经验证通过。

| 编号 | 议题 | 已确认方案 |
|---|---|---|
| NI-R01 | 参数承载范围 | 103 个 help 参数全部建档；所有有效普通导入参数均可配置、派生或作为失败操作承载 |
| NI-R02 | 参数展示 | 普通/高级/专家/不展示四层；另提供按分类浏览的“全部参数”入口 |

| NI-R05 | 文件来源 | 本地与官方存储类型；不提供浏览器上传和任意 URI |
| NI-R06 | 文件匹配 | 后缀为基础配置，正则与第三方文件标记进入高级配置，并提供匹配预览 |
| NI-R07 | 列映射 | 默认按顺序；显式列名单、控制文件、自动列映射只按官方能力提供，不做智能推断 |

## 15. 验收基线

1. 用户无需手写命令即可完成基础普通导入。
2. 所有经核验的普通导入参数均有配置、派生或失败操作入口。
3. 基础用户不需要浏览全部高级参数，专家可按分类找到任一有效参数。
4. 普通导入不会生成旁路专属参数。
5. 文件匹配、对象范围、内容、格式和列映射不存在歧义组合。
6. MIX 与 DDL+数据格式被清楚区分。
7. 高风险数据操作显示准确影响范围并完成二次确认。
8. 提交前完成任务级预检查并展示完整只读命令。
9. 敏感连接和存储信息默认脱敏。
10. 失败任务只有存在有效 `load.ckpt` 且原参数条件满足时才能从检查点继续。

## 16. 待官方/实测项

- `--buffer-size` 在本地 help 中解释为 ring buffer capacity，但当前 V4.3.5 官网未给出范围、单位和适用条件。
- `--server` 仅在本地 help 中描述为 remote load/dump，官网未给出部署与安全边界。
- `--public-synonym` 仅在 Usage 中出现，当前官网未给出普通导入对象语义。
- `--enable-hidden-pk` 的官方资料确认的是 OBDUMPER 导出用途，不能据共享 help 推断为普通导入能力。
- `--external-data` 的当前 4.3.5 页面未进入选项表，需用受控文件验证其 MANIFEST 跳过行为。
- `--slow`、`--pause` 的精确边界关系、异常提示和动态行为需受控验证。
- `--retry` 对允许变化的环境字段、检查点兼容性和高完成度建议阈值需留存实测证据。
