# 调度策略契约

2026-10-24 用户授权继续下一个模块开发。本批完成全平台执行并发上限的浏览器设置与实际领取闭环，仅本地及合成验证，不安装服务、不触发真实任务。

- 单例 `platform_scheduling_policy` 的初值为空上限、版本 1，明确表示未配置额外平台硬上限，继续既有节点 JVM 预算和 Agent Worker 约束，不冒充未经确认的默认并发数。首次设置后只接收 1–1024 的整数，不提供关闭上限入口；1024 是首版轻量控制面的有界输入上限，不代表容量承诺或按资源自动调参。
- `GET/PATCH /api/v1/settings/scheduling` 仅允许当前 ACTIVE 系统管理员；分别检查 `SCHEDULING_POLICY_READ/WRITE(platform)`。PATCH 只接收 `maxConcurrentExecutions/reason/confirmed`，要求 CSRF、强 If-Match、幂等键及 1–200 字安全原因。首次设置及降低都须确认，提升仍核对差异。同值不改版本。配置、审计和幂等回执在同一短事务提交；失败回滚，重放前复验权限，旧回执不充当当前配置。
- 新领取在同一 SQLite 写事务读取最新上限并计算全部账号、全部节点、三类任务的未释放执行占用，串行保存与领取不超卖。正式领取先重放已有机器回执，已准入执行不因新上限被取消或重新分配；旧合成领取也检查相同硬约束。策略损坏/缺失或读取失败阻断新领取，未配置上限仅为已初始化的明确状态。
- 占用含 STARTING/RUNNING/CANCELLING、待核对及仍有执行预算的分配。释放沿用已接受 PROCESS_EXITED、START_REJECTED 或 PROCESS_CANCELLED(noProcess=true,treeObserved=true)；租约到期、心跳失联或终态缺证不会释放既有持久预算。降低到当前占用以下只停止新增，直到有可靠释放且低于上限。
- 当前全平台运行数与占用数仅供已有全局任务读取权限的管理员查看，带 UTC 采样时间；返回响应前独立复验该权限，读取期间撤权也裁剪计数。普通系统管理员的这些字段为空且标记 RESTRICTED，不能以本人任务数代替全局事实。记录 SS-SCOPE-01：设计 SS-F027 要求显示全平台数量，但权限契约不从系统管理员推导全局任务读取；首版采用上述收缩投影，不授予新能力。
- 已授权任务详情的等待原因只返回平台容量约束或策略不可用的固定码，不暴露其他任务标识、数量、节点或上限。它是当前调度约束观察，不推断节点、凭据、预检查等其他条件已经通过，不承诺立即启动。
- 页面采用既有独立 Settings 工作面；表单、读取、冻结确认、写事务和幂等重试各属于本域唯一会话。取消/切换/卸载使旧响应失效；结果不确定时旧值标记为最近读取值，取消不等于撤回服务端写入，重新读取后才恢复新编辑。未保存输入离开时明确确认放弃；不增加通用配置引擎。
- 并发首批当时仅开放平台上限；当前时间与候选策略实现见下文。SS-NODE-02 已确认取消新节点任务数默认项，沿用节点 JVM 内存预算；不新增推荐算法或自动选择。

验收覆盖原子并发领取、跨任务类型共享、降低不取消、可信释放、失联保留、机器重放、策略不可用、重启、权限收缩、CSRF/版本/幂等/审计回滚，以及页面三档、键盘和原生 200%。

## 2026-10-24 继续开发：时间策略

- 独立时间策略事务使用 `GET/PATCH /api/v1/settings/scheduling/timing`，沿用当前系统管理员与既有调度 READ/WRITE scope、CSRF、版本、原因、幂等和原子审计。与并发上限分开编辑和版本，修改时间策略不要求先配置平台并发。
- 心跳覆盖为 60–3600 秒，空覆盖继承实际控制面启动基线，本机组合根现为 120 秒。Agent 心跳周期仍为本机配置（当前允许 5 秒–5 分钟），页面明确超时应大于各 Agent 的实际心跳间隔，不修改 Agent 网络周期。新心跳阈值用于节点事实、候选资格和新领取；同一领取事务读取最新覆盖，不能使用保存前的旧阈值。
- 启动期限为 15–3600 秒，初始为空，明确未配置额外启动期限，不把 2 分钟租约误称启动超时。仅新领取冻结 UTC `startup_deadline`；历史空值不回填，已有期限不可变，降低配置不缩短旧执行期限。到期尚无启动事实只附加待核对，不改为失败、不释放预算、不取消或重领。原有租约期限与过期状态规则保持独立。
- 检查间隔为 1–60 秒，初始为空，表示不增加平台节流。它限制控制面对同一 Agent、同一任务类型检查等待队列的最小间隔；不下发 Agent 网络周期，不加快低频 Agent，也不影响续租、日志或控制轮询。持久时点与领取同事务，配置改变后按最新间隔重新计算；机器成功回执先于节流重放，三类任务分开计时避免相位饥饿。
- 缩短心跳阈值、首次配置或缩短启动期限，以及改变检查间隔均要求影响确认；提高心跳/启动期限仍核对差异。允许原本未配置的启动/检查字段继续为空，配置后不提供置空重置。同有效值不创建覆盖、不改版本。
- 固定监视器按控制面时钟检查新启动期限及失联执行，每批最多 64 条；只标记仍活动且未核对的执行，审计同事务，重复扫描不重复写。心跳阈值影响当前观察，启动期限只影响后续领取；没有进程退出证据时继续占用并发和内存预算。
- 节点候选保持固定 `EXPLICIT_SELECTION` 语义：用户显式选择，无推荐、自动选中、提交或改派。候选顺序由下文独立策略管理，不创建推荐数据表。
- SS-NODE-02 已确认：用户选择方案 1，取消旧字段 SS-F025 的新节点默认任务数，沿用节点 JVM 内存预算。具体边界见下文及 [DEC-063](../01-product/decisions.md#dec-063-节点并发沿用-jvm-内存预算)。

## 2026-10-24 收口：候选顺序

- 用户要求继续直到调度模块闭环，准入 `/api/v1/settings/scheduling/candidates` GET/PATCH 与独立版本。沿用当前 ACTIVE SystemAdmin、`SCHEDULING_POLICY_READ/WRITE(platform)`、CSRF、强 If-Match、幂等及原子安全审计；三项设置事务互不携带配置。迁移 `0039` 建立单例 STRICT 策略，升级初值 `EXISTING` 保持原顺序。
- 仅两个内置枚举：`EXISTING` 保留当前节点域顺序；`ONLINE_FIRST` 将已启用、具有 ACTIVE Agent、已知事实版本且心跳处于实际阈值内的节点稳定提前，同组仍保留原顺序。停用节点或未来、缺失、过期心跳不作为优先依据；只使用控制面已有事实，不探测网络或运行工具。
- 设置改变需填写安全原因并确认；相同值不增版本，保存与失败有安全审计，审计失败回滚。来源由初始修订/实际修改记录表达；改回 `EXISTING` 仍保留平台修改记录。旧回执后必须复读实际策略，未知保存结果保留原请求标识，版本冲突不覆盖。
- 导出候选和普通/旁路导入的任务节点列表都在下一次读取时应用；后两者通过 `candidateOrder=platform` 明确表达任务选择用途。执行节点管理与数据源连接测试不应用此排序。配置读取失败时任务候选读取失败关闭，不静默退回旧策略。
- 先按对应现有对象权限过滤，再读取最小心跳进行排序，返回前复验；隐藏节点不参与事实查询、排序或错误。排序不公开额外任务、路径、环境或容量事实；普通导入/旁路保留原节点字段及原授权范围，不借排序扩大读取权限。
- 始终为 `EXPLICIT_SELECTION`：排序不自动选中、不改变已有选择、不清空仍有效节点、不提交或改派。在线仅是排序依据，不意味着环境、预算、平台并发、数据库/文件预检查或任务执行资格通过。未新增推荐分数、推荐历史、节点组策略或自动调度引擎。
- SS-NODE-02 已按下文确认收口；实际安装和真实任务验证分别记录，收口结果须区分本地端到端、安装与真实执行。
