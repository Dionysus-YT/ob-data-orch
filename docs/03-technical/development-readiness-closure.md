# 首条纵向切片开发准入收口

> 文档状态：开发准入基线已确认，DR-R01～DR-R18 已确认
> 适用范围：直连 OBServer 单表 CSV 导出首条切片
> 前置基线：TD、TS、PC、AS、CS、TL、LG、AD 全部已确认
> 更新日期：2026-07-21

## 1. 收口目的

本文件回答三个问题：

1. 现有设计是否已经足够，可以停止继续扩写文档；
2. 当前允许开始哪一种工程工作，哪些能力仍不能接入真实环境；
3. 剩余阻断由工程实现、测试环境、平台运维还是联合验证解决。

本轮只形成准入结论和执行顺序，不创建 Go/Vue 工程、不编写业务代码、不建立正式数据库，也不连接真实数据库或运行 OBDUMPER。

## 2. 第一性原理判断

### 2.1 二元门禁为什么不成立

当前清单把多个“需要实现后才能验证”的项目同时标记为“实现前阻断”：

- VS-P0-08 需要正式参数元数据和确定性命令生成器；
- VS-P0-09 需要正式 Agent、凭据注入、双层脱敏和清理流程；
- VS-P0-11 需要真实 Agent 持久状态、断联和恢复逻辑；
- 正式 OpenAPI、20 表迁移、日志段和 SQLite 索引也必须先有工程实现才能验证。

若坚持“这些 P0 全部通过后才允许写任何代码”，验证对象永远不会存在。反过来，若因为设计完成就直接开放真实数据源、任务提交和发布，又会绕过安全与环境证据。

因此准入必须按风险逐层开放：

```text
已确认设计
→ 工程骨架
→ 合成数据上的隔离组件实现
→ 获授权 Windows 测试环境集成
→ 三个麒麟目标认证
→ 生产发布
```

### 2.2 当前总体结论

- **停止继续扩写首条切片设计**：当前最小契约已经足够；新增实现细节优先进入 OpenAPI、SQL 迁移、测试和代码评审，不再建立新的平行设计体系。
- **工程骨架可准入**：技术选型、目录职责、接口边界、数据模型和测试目标已经确认，不需要等待外部数据库或麒麟机器。
- **隔离组件实现可增量准入**：只使用合成数据、假 Agent、临时 SQLite 和固定测试夹具；能力默认不可供真实用户调用。
- **Windows 真实端到端暂不准入**：直连 OBServer 身份、低权限账号、特殊 CSV 数据、正式 Agent 安全链路和工具包可信来源未全部满足。
- **三个麒麟目标和生产发布不准入**：目标机运行、认证接入、首次管理员、TLS/CA、根密钥恢复、升级备份恢复仍未完成。

DR-R01～DR-R18 已确认：G1 工程骨架正式准入，G2 按组件门禁增量准入；G3/G4 继续阻断。

## 3. 五级准入模型

| 级别 | 名称 | 允许做什么 | 明确禁止 | 当前建议 |
|---|---|---|---|---|
| G0 | 文档与证据基线 | 产品、契约、验证记录、Git 基线 | 把待验证写成通过 | 已完成 |
| G1 | 工程骨架 | Go/Vue 基础工程、配置、日志框架、OpenAPI、迁移器、CI、合成夹具 | 真实凭据、真实任务提交、工具执行 | 可准入 |
| G2 | 隔离组件实现 | 参数生成、状态机、SQLite 仓储、加密、脱敏、Agent 协议的单元/契约测试 | 对真实用户开放、连接真实数据源、把模拟结果标成 P0 | 可按组件门禁增量准入 |
| G3 | Windows 授权集成 | 本机控制面+Agent+4.3.5+获授权非生产 OBServer 的完整切片 | 生产数据、范围不明的 ODP、未脱敏链路 | 阻断 |
| G4 | 正式平台认证与发布 | 三个麒麟目标运行、安装升级、备份恢复、安全运维、发布 | 用交叉编译或 Windows 结果替代目标机证据 | 阻断 |

G1/G2 准入不等于功能完成，也不改变页面或任务能力状态。未达到 G3 的真实执行能力必须通过构建标签、运行配置、功能门禁或测试专用入口保持不可用，不能只靠口头约定。

## 4. G1 工程骨架准入

### 4.1 已满足前提

- 产品范围、专项规则和静态低保真已确认；
- TD、TS、PC、AS、CS、TL、LG、AD 首条切片契约已确认；
- Git 工作区和可回退文档提交已建立；
- Go、Vue/TypeScript、SQLite、REST/SSE、Agent 和跨平台目标已选定；
- Windows 上已有工具、SQLite、安全材料、启动和日志的候选证据；
- `tmp/`、工具压缩包和运行产物已有 Git 排除边界。

### 4.2 G1 允许产物

1. Go workspace/module 和控制面/Agent 空启动入口；
2. Vue 3 + TypeScript + Vite 基础工程和空路由壳；
3. 不含业务表的迁移执行器测试骨架，以及经评审的正式 `0001` 迁移草案；
4. `/api/v1`、`/agent/v1` OpenAPI 契约文件和类型校验；
5. 配置加载、版本信息、健康检查、统一错误和 requestId 中间件；
6. lint、单元测试、契约测试、三目标交叉构建和敏感信息扫描 CI；
7. 合成测试数据、假时钟、假 Agent、临时目录和临时 SQLite 夹具；
8. 不执行真实任务的功能门禁框架。

### 4.3 G1 禁止产物

- 真实数据库连接配置或用户提供的密码；
- 可从页面提交并启动 OBDUMPER 的通路；
- 生产身份、临时“万能管理员”或信任任意请求头的认证绕过；
- 为全部 V1.0 模块生成空 API、空表或前端菜单；
- 把验证用 `tmp/` 程序复制成正式实现而不重新评审和测试；
- 以工程骨架提交替代 P0 证据。

## 5. G2 隔离组件增量门禁

G2 不是一次性开放全部后端。每个组件只在自身门禁满足后进入实现：

| 顺序 | 组件 | 可使用输入 | 实现前门禁 | 实现完成门禁 |
|---:|---|---|---|---|
| 1 | 参数元数据与命令生成 | 固定合成数据源/节点/草稿 | PC-R01～PC-R15 | VS-P0-08 契约测试；未知/非活动/重复参数失败关闭；输出无秘密 |
| 2 | SQLite 迁移与核心仓储 | 临时数据库、合成 ID/密文 | AD-R13～AD-R18 | 20 表迁移、外键/严格表、事务/回滚、并发领取、备份恢复测试 |
| 3 | 凭据加密与安全目录 | 随机合成秘密 | CS-R01～CS-R18、TL-R01～TL-R18 | AES-GCM/AAD、Windows ACL/Linux 权限适配、错误密钥、清理和无原值扫描 |
| 4 | Agent 协议与状态机 | 假控制面、假时钟、假进程 | AS-R01～AS-R16、AD-R09/12 | 租约、幂等、事件序号、失联、核对、preflight 与旧 epoch 负例 |
| 5 | 日志重组与分段 | 合成 stdout/stderr/文件流 | LG-R01～LG-R20 | 跨块秘密、UTF-8、多行、背压、Gap、双层脱敏、崩溃恢复测试 |
| 6 | 控制面最小 API | 合成身份、假 Agent、临时 SQLite | AD-R01～AD-R20 | OpenAPI 契约、404 防枚举、If-Match、幂等、审计原子性和 no-store 测试 |
| 7 | 最小前端链路 | 假 API 或合成后端 | 已确认低保真和 OpenAPI | 数据源→草稿→预检查→命令→任务详情；无真实执行入口 |

组件 4 的纯核心已在 `internal/agentstate` 完成合成验证：指定节点领取、同请求幂等、事件连续序号/缺口、旧租约拒绝、完整终态证据、失联与租约过期核对标识，以及与 execution 隔离的预检查短租约均已覆盖。它是内存控制面模型，不替代后续 SQLite 事务投影、HTTP/机器认证、Agent 本地持久队列、日志补传或真实进程恢复。

组件 5 的纯核心已在 `internal/logstream` 完成合成验证：来源独立跨块重组、超长失败关闭、双层幂等脱敏、来源序号/摘要/Gap 账本，以及 JSONL 段 fsync、封段摘要和未登记尾部恢复均已覆盖。它不替代 Agent 本地可靠队列、SQLite 段/批次索引、HTTP 上传、页面查询、真实工具日志或四个目标环境实测。

组件完成门禁失败时只阻断该组件及其下游，不要求回退已经通过的独立组件，也不能通过禁用测试来继续。

## 7. G4 三目标与生产门禁

### 7.1 三个正式目标

每个环境分别运行同一套发布候选和证据脚本，不允许互相替代：

1. 麒麟 V10 SP3 2403 + Hygon C86（Linux AMD64）；
2. 麒麟 V10 SP1 + Kunpeng 920（Linux ARM64）；
3. 麒麟 V11 2503 + Kunpeng 920（Linux ARM64）。

至少覆盖：服务账户与 systemd、文件权限、SQLite 初始化/迁移/WAL/备份恢复、Agent 关联、Java 直接启动、绝对路径、信号/退出码、工具安全文件、日志编码/轮转/清理和一次成功/失败执行。

### 7.2 生产发布共同门禁

- 正式认证系统接入和首次管理员受控引导；
- TLS 证书/内部 CA、Agent 机器凭据轮换与撤销；
- 根密钥离线恢复包和跨机器恢复演练；
- SQLite 与根密钥分离备份、升级前备份和应用回退演练；
- 权限、无权枚举、审计、保留清理和磁盘阈值测试；
- 安装、升级、卸载、服务账户变更和故障排查手册；
- 全部正式目标的软件物料清单、版本摘要和发布签名/校验；
- 不使用生产数据完成首次验收。

## 9. 外部输入与责任边界

### 9.1 需要用户/基础设施提供

- 直连 OBServer 测试端点证明，或明确批准修改首条切片连接范围；
- 低权限只读账号及允许的失败负例；
- 覆盖 CSV 特殊值的非生产只读测试表/数据；
- 三个麒麟目标的登录、服务账户和受控测试窗口；
- 将来采用的认证系统/身份来源和初始管理员负责人；
- 内部 CA、备份介质与离线恢复材料保管责任；
- 4.3.5 工具包的可信来源或交付记录。

这些外部输入不阻断 G1/G2，但阻断对应真实集成和发布。工程不能用猜测、模拟成功或扩大产品范围替代。

### 9.2 项目工程负责

- OpenAPI、正式迁移、合成夹具和 CI；
- 参数生成器、SQLite 仓储、Agent、凭据、启动、日志和前端首链；
- 所有失败关闭、权限、幂等、崩溃和敏感信息测试；
- Windows/麒麟发布产物、证据脚本和验证记录；
- 只有在证据通过后更新准入状态。

## 11. 收口后仍然禁止

- 把 G1/G2 准入描述成“产品已经可用”；
- 在真实凭据门禁前连接用户数据库或保存用户密码；
- 用当前疑似 ODP 端点冒充直连 OBServer 验收；
- 用 Windows、交叉编译或 Docker 代替三个麒麟目标机运行；
- 为等待外部环境而继续无边界扩写设计；
- 在实现中静默修改 PC、AS、CS、TL、LG、AD 已确认边界；
- 一次性并行开发全部 V1.0 模块；
- 为赶进度关闭外键、审计、脱敏、权限、幂等或失败测试；
- 将真实密码、完整组合用户名、工具原始日志或运行产物提交 Git。
