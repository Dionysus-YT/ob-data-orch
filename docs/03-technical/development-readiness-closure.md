## 1. 收口目的

本文件回答三个问题：

1. 现有设计是否已经足够，可以停止继续扩写文档；
2. 当前允许开始哪一种工程工作，哪些能力仍不能接入真实环境；
3. 剩余阻断由工程实现、测试环境、平台运维还是联合验证解决。

本轮只形成准入结论和执行顺序，不创建 Go/Vue 工程、不编写业务代码、不建立正式数据库，也不连接真实数据库或运行 OBDUMPER。

## 2. 第一性原理判断

### 2.1 二元门禁为什么不成立

当前清单把多个“需要实现后才能验证”的项目同时标记为“实现前阻断”：

- VS-P0-08 需要正式参数元数据和确定性命令生成器；
- VS-P0-09 需要正式 Agent、凭据注入、双层脱敏和清理流程；
- VS-P0-11 需要真实 Agent 持久状态、断联和恢复逻辑；
- 正式 OpenAPI、`0001` 的 20 表基线与 `0008` 后当前 22 表迁移、日志段和 SQLite 索引也必须先有工程实现才能验证。

若坚持“这些 P0 全部通过后才允许写任何代码”，验证对象永远不会存在。反过来，若因为设计完成就直接开放真实数据源、任务提交和发布，又会绕过安全与环境证据。

因此准入必须按风险逐层开放：

```text
已确认设计
→ 工程骨架
→ 合成数据上的隔离组件实现
→ 获授权 Windows 测试环境集成
→ 三个麒麟目标认证
→ 生产发布
```

### 2.2 当前总体结论

- **停止继续扩写首条切片设计**：当前最小契约已经足够；新增实现细节优先进入 OpenAPI、SQL 迁移、测试和代码评审，不再建立新的平行设计体系。
- **工程骨架可准入**：技术选型、目录职责、接口边界、数据模型和测试目标已经确认，不需要等待外部数据库或麒麟机器。
- **隔离组件实现可增量准入**：只使用合成数据、假 Agent、临时 SQLite 和固定测试夹具；能力默认不可供真实用户调用。
- **Windows 真实端到端暂不准入**：私有 ODP 授权、负例场景、CSV 夹具、输出边界和工具来源摘要已由负责人通过受控渠道确认；正式 Agent 安全槽位、固定预检查 Worker、真实运行链路与可复核证据仍未完成。
- **三个麒麟目标和生产发布不准入**：目标机运行、认证接入、首次管理员、TLS/CA、根密钥恢复、升级备份恢复仍未完成。

DR-R01～DR-R18 已确认：G1 工程骨架正式准入，G2 按组件门禁增量准入；G3/G4 继续阻断。

## 3. 五级准入模型

| 级别 | 名称 | 允许做什么 | 明确禁止 | 当前建议 |
|---|---|---|---|---|
| G0 | 文档与证据基线 | 产品、契约、验证记录、Git 基线 | 把待验证写成通过 | 已完成 |
| G1 | 工程骨架 | Go/Vue 基础工程、配置、日志框架、OpenAPI、迁移器、CI、合成夹具 | 真实凭据、真实任务提交、工具执行 | 可准入 |
| G2 | 隔离组件实现 | 参数生成、状态机、SQLite 仓储、加密、脱敏、Agent 协议的单元/契约测试 | 对真实用户开放、连接真实数据源、把模拟结果标成 P0 | 可按组件门禁增量准入 |
| G3 | Windows 授权集成 | 本机控制面+Agent+4.3.5+获授权非生产私有 ODP 的完整切片 | 生产数据、云 ODP/ODP Sharding、未脱敏链路 | 阻断 |
| G4 | 正式平台认证与发布 | 三个麒麟目标运行、安装升级、备份恢复、安全运维、发布 | 用交叉编译或 Windows 结果替代目标机证据 | 阻断 |

G1/G2 准入不等于功能完成，也不改变页面或任务能力状态。未达到 G3 的真实执行能力必须通过构建标签、运行配置、功能门禁或测试专用入口保持不可用，不能只靠口头约定。

- 把验证用 `tmp/` 程序复制成正式实现而不重新评审和测试；

组件完成门禁失败时只阻断该组件及其下游，不要求回退已经通过的独立组件，也不能通过禁用测试来继续。

### 5.1 S0/S1 可重复开发入口

为避免把生产级授权流程无差别施加到无真实副作用的开发验证，仓库提供固定的 Export 合成入口：

- Windows：`./scripts/verify-export-synthetic.ps1`；
- Linux：`./scripts/verify-export-synthetic.sh`。

入口在子进程范围内强制关闭真实执行、Agent JDBC 连接测试、导出预检查和对象存储连通性探测开关，然后运行 Export domain、假工具、Agent 执行/协议、控制面、临时 SQLite 集成和 Local MVP 边界测试。测试只使用合成身份、假 Agent、假工具、临时目录和临时数据库，不读取真实环境变量中的秘密，不建立外部网络连接，不启动 Java 或 OBDUMPER。脚本通过不等于 G3/EX-V1 通过；真实凭据、真实工具、用户数据库和远端存储仍必须遵循后续授权与证据门禁。

该入口满足 S0/S1 的“无需人工审批即可重复验证”要求，但不改变服务端授权、命令生成器复验、Agent 固定信封、租约/幂等、日志脱敏和结果证据等执行层硬边界。

### 3. 外部输入接收规则

外部输入由项目负责人或测试环境负责人确认后再进入受控验证；本仓库只保存脱敏的事实摘要与结论。

2. **授权边界（WI-12）**：明确允许的测试表、允许动作、不可触碰对象、输出根目录、清理方式、留证位置与紧急停止联系人。输出目录必须是专用绝对路径，平台不自动拼接或改写。
3. **最小测试主体（WI-03/04）**：提供成功、低权限与不存在对象的隔离场景，以及不含业务敏感数据的 CSV 边界夹具；不把真实密码、完整连接串或业务样本写入 issue、文档、测试或命令行历史。
4. **工具交付（WI-01）**：提供可审计的包来源和摘要。现有本地包只能作为候选输入，不能单独证明可信来源。

<a id="windows-entry-4-g3-实施与验收顺序"></a>

### 4. G3 实施与验收顺序

在 P0 外部输入齐备且取得明确 G3 授权后，按以下最小顺序执行；每一步失败都停止扩大范围。

1. **安全启动基线（WI-05、WI-08、WI-11）**：核对确定性命令、无密码 argv、安全材料生命周期、迁移/备份恢复与安全错误快照；先使用合成或隔离输入补足可自动化部分。
2. **真实节点预检查（WI-06）**：由已关联的 Windows Agent 对固定 `EXPORT_PREFLIGHT` 产生连接、对象、工具、路径、非空和空间事实；必须先完成工具环境、输出路径、目录空性和可用空间四项无秘密本机检查，任一未通过即停止，不解析凭据、不启动 JDBC，并以固定未知结果收口数据库/对象检查；不接受任意 SQL、路径浏览或自定义命令。
3. **受控工具结果（WI-07、WI-09）**：验证直接 Java 进程身份、真实终态、结果文件事实与 stdout/stderr/工具文件双层脱敏；批处理包装退出码不能单独决定成功。
4. **故障与恢复（WI-10）**：验证旧租约、重复/乱序事件、Agent 失联、控制面重启、日志补传与核对状态；未知状态不得伪造为成功或失败。
5. **最小切片回归**：仅运行私有 ODP 单表 CSV 的成功、低权限/不存在对象、工具失败和 Agent 中断场景；将脱敏证据追加到专用 G3 记录。

真实执行只能在第 2 步之后、且每次均满足固定绑定与安全边界时发生。G3 通过不自动打开 G4 或生产发布。

<a id="windows-entry-51-2026-07-22-工程进展"></a>

#### 5.1 2026-07-22 工程进展

- 直接 Java 启动器已把 stdout、stderr 改为强制的 Agent 第一层字节级脱敏出口：原始管道不再暴露给调用方，完整记录先在内存中重组并脱敏，随后才转为可传递文本；策略或接收端失败时继续排空管道，但返回安全失败，不能将原文落盘或上传。
- 启动输入只接受可清零字节形式的真实执行脱敏值，拒绝字符串秘密上下文；策略销毁后失效，不能降级为仅按敏感键名掩码。
- 数据源连接测试已具备固定 Java JDBC 探针与 Go 启动适配：只允许包内 `oceanbase-client-2.4.14.jar`、固定主类、显式环境、摘要核验和标准输入短时连接帧；本地合成拒绝连接已到达 JDBC 连接阶段。它不执行任意 SQL，也不生成 OBDUMPER 安全材料。
- Agent 已提供本机运行时校验入口：管理员必须以绝对路径配置 `OB_DATA_ORCH_AGENT_JAVA_PATH`、`OB_DATA_ORCH_AGENT_TOOL_HOME`，可选配置 `OB_DATA_ORCH_AGENT_WORKSPACE_ROOT`；`ob-data-orch agent --check-runtime` 只固定发现包内 Connector/J 并计算摘要，不连接数据库、不解析凭据，也不启动 OBDUMPER。本机 Windows 已使用 Java 8 与本地 4.3.5 安装目录通过该校验。
- 受认证 Agent 关联、心跳以及固定 `claim-next → acknowledge-lease → complete` 预检查信封已完成 G2 合成协议与 SQLite 回执验证。`claim-next` 不接受客户端 precheckId 或 leaseId，控制面原子选择绑定记录并校验绑定摘要、节点事实版本、租约 epoch、控制面时钟和单容量；响应继续固定 `realExecutionEnabled=false`。固定 Worker 先完成不依赖数据库槽位的工具环境、输出路径、目录空性和可用空间检查；任一前置项失败时，数据库/对象结果固定为 `UNKNOWN`，且绝不解析秘密槽位。
- Agent 本地 `DATABASE_CONNECTIVITY` 预检查适配已具备短时槽位、探针工作区、连接失败分类和清理边界。控制面秘密槽位、严格 Agent HTTPS 信封、回执迁移、响应绑定和固定 Worker 已完成合成验证；仅在控制面、Agent 同时设置 `OB_DATA_ORCH_ENABLE_AGENT_JDBC_CONNECTION_TEST=true` 时，才允许 `AGENT_JDBC` 连接测试解析唯一槽位。Windows 本机 MVP 的控制面启动脚本与随包 Agent 启动脚本会显式设置该开关，实际连接仍只由页面一次测试或固定预检查触发；它会先检查冻结主机/端口的 TCP 可达性，只有成功才启动固定 Java/JDBC 探针。2026-07-28 的受控测试最终得到 `SUCCEEDED / DATABASE_CONNECTED`，证明所选本机 Agent 的固定 JDBC 基础连接路径在该时点有效；没有记录端点、凭据或异常原文。该成功不构成 WI-06 通过，`EXPORT_PREFLIGHT` Worker 不会启动 OBDUMPER 或真实导出。
- `DATA_SOURCE_CONNECTION_TEST` 与 `EXPORT_PREFLIGHT` 的数据库槽位现均由控制面在绑定复验后，以已登记的 `username`、`tenant`、可选 `cluster` 短时组装私有 ODP JDBC 身份 `username@tenant` 或 `username@tenant#cluster`；非法分隔符、空白/控制字符、无效 UTF-8 或超过 256 字节时失败关闭。相关测试只使用合成凭据并验证清零，不构成真实 ODP 连接证据。
- 另外五项固定检查尚无真实 Probe，预检查租约/待上报结果没有 Agent 本地恢复队列。上述内容只覆盖直接 Java 的 stdout/stderr 第一层，不覆盖工具文件跟踪、控制面第二层、真实进程、可靠队列或恢复。因此 WI-06、WI-07、WI-09、WI-10 仍未通过，真实任务入口继续关闭。

<a id="windows-entry-7-2026-07-30-windows-本机-mvp-执行链路"></a>

### 7. 2026-07-30 Windows 本机 MVP 执行链路

在当前用户的明确测试授权下，新增的最小链路为：

```text
浏览器：预检查成功后显式提交
→ 控制面：原子冻结任务并由匹配节点 Agent 领取
→ Agent：确认租约、短时取得唯一数据库槽位、生成任务级官方安全材料
→ Agent：直接 Java 启动包内 OBDUMPER，续期租约并上报进程/终态/结果事实
→ 控制面：按连续事件投影状态，实时展示双层脱敏 stdout/stderr
```

- 仅在控制面以 `--local-mvp` 启动且控制面与 Agent 都显式设置 `OB_DATA_ORCH_ENABLE_REAL_EXECUTION=true` 时开放；当前仅允许 Windows AMD64。
- 任务领取重新核验：节点已启用、运行时检查通过、Agent 心跳新鲜且单容量空闲、预检查与当前 Agent 事实匹配、数据源的 `AGENT_JDBC` 测试成功、凭据和创建者仍有效。Agent 不能提交 taskId、argv、路径或秘密。
- `argv` 来自控制面冻结快照并拒绝任何密码令牌；密码仅进入任务私有官方安全文件。日志先在 Agent 做字节级脱敏，控制面再执行批次完整性与展示拦截。
- 当前日志查看是控制面进程内投影，控制面重启后不保留；Agent 没有断线事件/日志本地恢复队列，也尚未跟踪工具文件日志。因此这只是供用户执行首个真实本机测试的 Alpha，不构成 WI-07、WI-09、WI-10 或 G3 关闭证据。
