## 1. 怎么使用这份计划

本文件是导出模块开发顺序的唯一权威。旧 DEV、F、G3 和 WI 记录继续保留证据价值，但不再决定导出模块的产品设计顺序；出现“下一条唯一工作项”等历史文字时，以本文件顶部和第 4 节为准。

本轮路线采用“完整设计先行、能力切片实现、逐切片验证”：

```text
EX-D0 当前实现盘点与冻结
→ EX-D1 导出模块完整产品设计
→ EX-D2 导出模块完整技术契约
→ EX-I1～EX-I8 分能力实现
→ EX-V1 分切片 Windows 真实验证
→ EX-V2 三个麒麟目标认证
→ EX-R 发布评审
```

EX-D1、EX-D2 完成前，不继续用现场 WI 缺口驱动新增导出功能，也不把现有单表 CSV 专用结构直接扩写成“通用”实现。真实连接、真实凭据、真实工具启动和用户数据库操作仍受当次授权及 G3/G4 门禁约束。

## 2. 当前实现基线

当前代码能力统一命名为 `CSV_SINGLE_TABLE_V1`，边界如下：

| 维度 | 当前已实现基线 | 尚未因此具备 |
|---|---|---|
| 连接 | 已登记私有 ODP 数据源 | 云 ODP、ODP Sharding、直连 OBServer 或任意连接 |
| 对象 | 单一数据库/Schema 下的一张明确表 | 全部对象、多表、多库表达式及其他对象类型 |
| 内容 | 仅数据 | 仅 DDL、DDL + 数据及 DDL 行为 |
| 格式 | CSV 最小参数集 | CSV 完整参数、CUT、POS、SQL、Parquet、ORC、Avro |
| 输出 | 执行节点本地绝对路径 | OSS、S3、COS、OBS 或任意 URI |
| 执行 | 固定预检查、命令生成、任务、Agent、日志与结果事实的首链 | 完整高级参数、检查点继续、完整失败恢复或生产可用 |
| 验证 | Windows 上已有获授权局部证据 | G3 全部通过、三个麒麟目标通过或正式发布 |

已有实现必须保持兼容和失败关闭；在 EX-D2 明确迁移与兼容策略前，不原地改变历史草稿、快照、参数元数据版本或任务语义。

## 3. 导出模块功能全景

完整设计必须覆盖下列能力，而不是只围绕当前 CSV 单表页面补功能：

| 能力域 | V1.0 设计范围 |
|---|---|
| 数据源与连接派生 | 已启用数据源选择、默认数据库/Schema、兼容模式、连接环境、sys 凭据状态、字符集和会话配置；连接值从受控事实派生，不在向导重复编辑 |
| 对象范围 | 全部对象/指定对象、多对象表达式、多库 `schema.object`、排除表，以及表、表组、视图、触发器、用户、角色、序列、同义词、类型、包、函数、存储过程等官方对象类型 |
| 导出内容 | 仅 DDL、仅数据、DDL + 数据；对象类型、兼容模式、数据库版本和权限共同决定可用组合 |
| 数据格式 | CSV、CUT、POS、Insert SQL、Parquet、ORC、Avro；同一任务只允许一个数据格式，DDL 不作为数据格式 |
| 输出位置 | 执行节点本地、OSS、S3、COS、OBS；不提供任意 URI，存储凭据按秘密处理 |
| 序列化与文件 | CSV/CUT/POS/SQL 专属设置、日期时间格式、编码、压缩、控制文件、目录布局、文件拆分、总量上限和空结果文件 |
| DDL、筛选与一致性 | DROP、附加对象信息、Schema/序列策略、where、partition、列筛选、数据类型筛选、flashback、snapshot、weak-read 和隐藏主键；`--query-sql` 作为受限专家能力（ENABLED，CAP_SENSITIVE_COMMAND + 二次确认，详见 EX-R07） |
| 性能与资源 | 导出线程、分页、宏块并行、抓取行数、JVM 内存、临时目录和执行节点资源预检查 |
| 确认与执行 | 六步向导、活动配置摘要、确定性脱敏命令、风险确认、全量预检查、不可变快照、提交、状态和日志 |
| 结果与恢复 | 可靠结果事实、失败原因、基于原配置新建、从头执行、满足条件时通过 `dump.ckpt` 创建新的继续任务 |
| 复用与治理 | 参数元数据版本、历史兼容、从成功任务保存导出模板及模板创建草稿；模板实现是否进入 V1.0 仍按产品范围决策，不因本路线静默升为 P0 |

现有 [导出字段与条件矩阵](../02-design/export-field-rules.md) 的 EX-F001～EX-F087 和 [导出参数映射基线](../02-design/export-parameter-mapping.md) 的 109 个长参数是设计输入，不等于全部能力已可提交。每个字段和参数必须最终落入 `ENABLED`、`VALIDATION_GATED`、`HIDDEN`、`LEGACY_READ_ONLY` 或 `BLOCKED`，不得以“文档已列出”替代产品、技术或工具证据。

## 5. 设计阶段门禁

### 5.1 EX-D1 产品设计完成条件

- EX-F001～EX-F087 全部有页面位置、活动条件、必填、默认来源、清值、风险、预检查失效和支持状态。
- 109 个长参数全部有产品处置、来源、适用条件、互斥/依赖、敏感性、风险级别和证据状态；导入侧、废弃及 help-only 参数不进入新建入口。
- 完成对象类型 × 兼容模式 × 数据库版本 × 权限矩阵，以及内容 × 格式 × 输出位置组合矩阵。
- 补齐导出六步向导全部页面的默认、加载、空、错误、无权、阻断、警告、草稿恢复和版本不兼容状态；现有步骤 5、6 低保真不能替代步骤 1～4。
- 明确本地与四种对象存储、文本与结构化格式、DDL 与数据任务的预检查、结果事实和失败处理差异。
- POS、`--block-size`、`--sequence-policy`、对象版本条件、检查点等未确认项具备可证伪的受控验证方案，并在验证前保持阻断或门控。
- 明确解决 `--query-sql` 与项目“不得提供任意 SQL”边界的契约冲突；已决策为受限专家能力（ENABLED，CAP_SENSITIVE_COMMAND + 二次确认，不提供 SQL 编辑器，file:// 不开放），详见 [EX-R07](../02-design/export-module.md) 和 [AGENTS.md](../../AGENTS.md) 第 5 节。
- 保持产品边界：不新增定时任务、审批流、任意 SQL 编辑器、任意 URI、对象浏览器、远程 Shell、通用数据库客户端或自研导出引擎。

### 5.2 EX-D2 技术契约完成条件

- 通用导出草稿、规范化配置、提交快照、能力版本和派生任务关系具有稳定领域模型，不以页面 JSON 或命令字符串充当领域模型。
- OpenAPI 与 SQLite 只承载已确认字段；迁移、历史兼容、乐观锁、幂等、对象授权和无权 404 规则明确。
- 参数元数据仍是唯一命令拼装权威，同时产生确定性 argv、脱敏展示、字段追踪、指纹和秘密槽位；调用方不得自行拼接。
- 预检查按连接、对象、权限、格式、输出、存储、路径、空间、资源、风险和检查点分层，明确事实来源、失效条件和失败关闭行为。
- Agent 信封只包含固定任务类型和受控结构，不引入任意命令、任意 SQL、任意 URI 或控制面主动入站能力。
- 结果、日志、清单、检查点和任务终态分别定义可靠证据，不以包装脚本退出码单独判断成功。
- 每个切片都有正例、权限负例、非法组合、重复/乱序/重启、秘密泄露和跨平台路径测试策略。

## 6. 历史实施与验证记录（保留，不再作为当前路线）

以下内容记录首条单表 CSV 切片的工程与验证事实。其历史“下一步”均已被第 4 节取代。

### DEV-04 实施记录（已完成）

### DEV-04.1 API 安全外壳

- 目标：让浏览器域和 Agent 域具有统一、安全、可测试的 HTTP 边界。
- 已完成：`no-store`、基础安全头、随机 `requestId`、统一安全错误信封；认证未配置时两个 API 域失败关闭。
- 不做：任意请求头身份、万能管理员、真实登录、真实机器凭据。
- 验收：未知路径与未认证域不泄露资源差异、路径、SQL、堆栈或秘密。

### DEV-04.2 合成身份与对象授权适配

- 目标：定义可替换的身份/授权接口，并仅在测试中注入合成身份与授权范围。
- 不做：自行建设用户名密码、组织、用户组、IAM 或把测试身份开放到运行环境。
- 验收：浏览器身份不能调用 Agent 域；Agent 身份不能调用浏览器域；加载授权失败时拒绝访问；无权对象按 404 处理。
- 下一步：通过后才实现首条浏览器业务 API。

### DEV-04.3 首条浏览器业务 API 链路

按以下顺序逐段实现，每段都有独立测试：

1. 数据源列表、新增、读取、编辑、启停和删除/归档；密码只写，不返回密文或占位符。
2. 导出草稿新建、读取、编辑；使用 revision + `If-Match`。
3. 脱敏命令预览；调用已完成的参数生成器，不解析秘密。
4. 发起/查询预检查；绑定草稿 revision、配置指纹、节点和凭据 revision。
5. 任务与任务详情只展示已冻结的非敏感事实；真实执行入口继续关闭。

- 不做：普通导入、旁路导入、模板、调度、取消、重试、批量任务和系统设置 API。
- 验收：写操作要求 CSRF/幂等/乐观锁；同幂等键异内容冲突；秘密不出现在响应、日志、SQLite 普通字段或错误中。

### DEV-04.4 假 Agent 协议适配

- 目标：把 Agent 状态、预检查、日志核心接到 HTTP 适配层，用合成 Agent 验证端到端协议。
- 不做：启动 OS 进程、执行 Java、调用 OBDUMPER、接收任意命令、开放入站 Agent 管理端口。
- 验收：领取、租约、续期、重复请求、旧 epoch、事件缺口、日志批次和 Gap 都可通过 HTTP 合成测试复现。

DEV-04 的完成条件：首条 API 链路在合成 SQLite 与假 Agent 上可演示；真实执行功能门禁仍保持关闭。

### DEV-04 完成记录

- 已完成：数据源安全摘要与写操作、单表 CSV 导出草稿、脱敏命令预览、预检查创建/查询、预检查合成领取/完成、任务幂等冻结/详情；假 Agent 的任务领取、租约续期、状态机事件、日志批次和 Gap HTTP 适配均已具备正反例测试。
- 联合验证：`internal/integration/TestDEV04SyntheticSQLiteHTTPChain` 在同一临时 SQLite 中验证草稿、预检查、任务、执行和事件真实落库，并以假 Agent 经 HTTP 完成领取、事件和日志查看。
- 已完成的安全限制：浏览器与 Agent 身份域分离；写操作要求 CSRF、幂等键或版本前置条件；命令预览、任务详情和浏览器参数数组不返回凭据或用户名；日志入口拒绝可由第一层规则继续脱敏的记录；所有合成响应标记 `realExecutionEnabled: false`。
- 后续但不属于 DEV-04：Agent 本地 `EXPORT_PREFLIGHT`、安全工作目录、假工具进程、执行证据与清理进入 DEV-05；持久日志段/索引、控制面重启投影恢复和 Agent 本地可靠队列继续受后续阶段与 G3/G4 门禁约束。

- 不做：真实数据库连接、真实 OBDUMPER、任意 shell、自动重试或改派。
- 验收：预检查不启动工具；进程前写意图；失败/失联不伪造终态；秘密材料与日志清理可验证。

### DEV-05 完成记录

- 已完成：固定 `EXPORT_PREFLIGHT` 六项检查与失败关闭；未知能力、活动 execution、租约/绑定漂移、非绝对输出路径和不安全证据摘要均拒绝，预检查失败不会调用假工具。
- 已完成：复用 execution 私有安全工作区，原子保存无秘密 `STARTING_PROCESS` 意图；已有或损坏意图要求核对，不能覆盖后重启同一 execution。
- 已完成：假工具成功、明确失败、启动拒绝、中断和证据缺失均以无秘密进程/终态事实映射到既有状态机；中断、未知启动错误或证据缺失只进入核对中，不伪造终态。
- 已完成：仅在终态/结果证据完成后清理合成安全材料和启动意图；清理失败保留目录并返回残留隔离结论。
- 验证证据：[DEV-05 Agent 本地合成适配验证](evidence/dev-05-synthetic-agent-adapter-2026-07-22.md)。
- 未完成：真实数据库、真实凭据解析、真实 Java/OBDUMPER/OS 进程、真实 Agent 网络、Agent 本地可靠队列、控制面持久恢复和四目标环境验证；这些继续阻断 G3/G4。

### DEV-06：最小前端链路

- 目标：把数据源、导出草稿、预检查、命令预览和任务详情连成可操作页面。
- 不做：高保真改版、全部 V1.0 页面、真实执行按钮。
- 验收：前端只使用 API 脱敏数据；正确处理空、加载、校验、冲突和“真实执行未开放”状态。

### DEV-06 完成记录

- 已完成：Vue 页面通过现有浏览器 API 串联已授权数据源选择、单表 CSV 草稿创建/更新、脱敏命令预览、预检查创建/查询、任务提交、任务详情和日志快照查询；所有写请求都携带 CSRF、幂等键和/或 `If-Match`，前端不生成命令、状态或任务快照。
- 已完成：前端只将数据源脱敏摘要、固定 CSV 配置、预检查/任务安全投影和二次检查后的脱敏命令/日志保存到状态。控制面数据源浏览器响应已移除用户名；命令或日志未通过本地二次脱敏检测时拒绝展示。
- 已完成：加载、空态、字段校验、网络/写入错误、409/412 冲突、401 和无权/不存在 404 均有明确安全反馈；页面始终标识 `G2` 和“真实执行未开放”。
- 已完成：前端单元测试、ESLint、TypeScript、生产构建及桌面/390px 本地渲染验证通过，详见 [DEV-06 最小前端链路验证](evidence/dev-06-minimal-web-flow-2026-07-22.md)。
- 契约缺口：运行时浏览器身份/CSRF 注入和执行节点列表尚未接入实际控制面。缺少 CSRF 时客户端拒绝发送写请求；节点标识暂由已登记节点事实提供，服务端无权或不存在统一 404。该限制未通过前端假数据或扩展 Agent 协议绕过。
- 未完成：真实认证会话、真实节点列表、真实数据库/凭据/Agent/OBDUMPER、SSE 持久日志和任何 G3/G4 验证；这些继续阻断真实导出与发布。

### DEV-07：Windows G3 真实集成

- 前提：`development-readiness-closure.md` 的 WI-01～WI-12 全部满足。
- 目标：获授权非生产 Windows 环境完成真实控制面、Agent、OBDUMPER 的单表 CSV 导出成功/失败/清理/失联证据。
- 验收：只以正式 Agent 产物和可复核证据更新 G3 状态，手工命令不替代验收。
- 准入准备：[G3 Windows 真实集成准入准备](g3-windows-entry-readiness.md)；当前只收集脱敏的门禁材料和补足 G2 缺口，不启动真实操作。
- 2026-07-22：用户已授权既定私有 ODP 的非生产单表 CSV G3 范围。已新增直接 Java 启动器的受控本地边界：固定 OBDUMPER 主类、校验 Java 摘要、使用 execution 私有安全配置、拒绝密码 argv 与注入环境，并在启动前持久化意图；stdout/stderr 现在只能经字节级第一层脱敏后进入接收端，原始管道不向调用方暴露。它仍未接入 Agent 机器身份、租约、工具文件采集、控制面第二层、可靠队列、恢复或真实 ODP；不能据此启动真实任务或标记 WI-07～WI-10 通过。
- 2026-07-22：数据源连接测试已新增固定 Java JDBC 探针及 Go 启动适配。它只允许 OBDUMPER 4.3.5 包内 `oceanbase-client-2.4.14.jar`，核验 Java、内嵌探针与驱动摘要；探针只释放到单个预检查的私有运行目录并在清理时回收。连接输入仅经标准输入短时传递，并只接受有限的基础元信息结果；本机 Go → Java → JDBC 的合成拒绝连接已验证。它尚未接入正式 Agent 身份、预检查租约、秘密槽位、控制面结果持久化或真实 ODP，不能据此把 WI-06 或数据源真实连接测试标记通过。
- 2026-07-22：Agent 本地已新增 `DATABASE_CONNECTIVITY` 预检查适配：它只能使用未来受租约约束的数据库槽位，结束时清零连接输入与工作区；只有固定 JDBC 的 `CONNECTION_FAILED` 会成为“数据库连接失败”，其余运行时异常失败关闭为“连接事实不可用”。正式 `ResolvePrecheckSecretSlots`、Agent 机器身份、预检查 HTTP 调用及结果持久化仍未实现，不能据此把 WI-06 或数据源真实连接测试标记通过。
