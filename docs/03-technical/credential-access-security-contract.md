### 2026-09-14 部署修订（DEC-048）

统一启动入口初始化固定 `admin`：PBKDF2-HMAC-SHA256、随机 32 字节盐、600000 次迭代、32 字节派生校验值；不保存登录密码原文。登录后创建内存会话，12 小时到期，Secure/HttpOnly/SameSite=Strict 的 `__Host-ob_data_orch_session` Cookie；CSRF 绑定会话并复验来源。控制面重启要求浏览器重新登录，但不影响 Agent 身份。该明确决策取代下文“暂不建设登录/初始管理员外部输入”的历史范围声明。

浏览器与机器协议仍独立。管理员明确兼任现有节点、数据源和任务操作职责；不提供自定义角色、SSO、MFA。单次注册材料有效期 24 小时，续期不自动生成身份。Windows 服务沿用安装账户，Linux 使用固定专用账户；禁止升级时改变 DPAPI 账户或身份目录绝对路径。

TLS 使用持久的受平台保护信任根（20 年），服务叶证书 90 天、剩余不足 30 天时自动续期；根证书到期或材料不完整失败关闭。Agent 包携带公钥信任，浏览器首次需要由使用环境信任该根。升级不重新生成根。

## 1. 目标与边界

本契约定义首条切片中秘密如何保存、引用、传输、短时使用、轮换、撤销和审计，以及五类既有角色如何在服务端执行最小权限校验。

它覆盖三类秘密：

1. 数据源业务用户密码；
2. Agent 与控制面之间的机器凭据；
3. 控制面用于加密业务秘密的根密钥。

它不建设用户注册、登录、找回密码、MFA、SSO、自定义角色、审批流、通用密钥管理平台或未脱敏日志下载。用户认证来源和初始管理员建立方式仍是进入 API/数据模型设计前必须明确的外部输入。

## 2. 三层风险必须分开

| 层级 | 要解决的问题 | 本契约结论 |
|---|---|---|
| 静态保存 | SQLite、备份或普通文件泄露时不能直接得到数据库密码 | 应用层认证加密，根密钥不进入 SQLite |
| 控制面到 Agent | 任务领取、日志和普通协议不能携带秘密；只有合法执行可短时解析 | HTTPS + 租约/信封/槽位绑定的短时解析 |
| 工具进程 | OBDUMPER 4.3.5 最终如何接收密码，是否暴露在进程参数中 | 平台生成的官方兼容材料已在 Windows 被 4.3.5 实际读取，命令可省略 `--password`；Linux、并发隔离与清理仍需实测，VS-P0-09 继续阻断 |

完成静态加密不代表执行安全已经通过。只要第三层仍无法证明，平台就不能宣称“密码不会暴露在进程参数中”。

## 3. 威胁模型与诚实边界

### 3.1 本契约要防止

- 无权限页面/API 读取或推断密码、机器凭据和根密钥；
- SQLite 文件、普通数据库备份或日志单独泄露后直接恢复密码；
- 网络窃听、错误 Agent、错误节点或过期租约取得任务秘密；
- 调试日志、错误、审计、命令预览、任务快照和 Git 泄露原值；
- 密文被替换到其他数据源、其他修订或其他秘密类型后仍可解密；
- 权限撤销、数据源禁用或凭据撤销后继续开始新执行；
- 密钥轮换、服务重启和请求重发造成明文落盘或使用错误修订。

### 3.2 本契约不能声称防止

- 已获得控制面或 Agent 操作系统管理员/root 权限的攻击者；
- 内核、调试器、进程内存或运行中工具进程已经被控制；
- 数据库账号本身权限过大或被数据库端滥用；
- OBDUMPER 官方安全文件路线无法通过验证、最终仍只能使用可被特权用户查看的命令行密码时的固有暴露；
- 根密钥、SQLite 和运行主机同时整体失陷。

Windows DPAPI 和 Linux 文件权限是在当前轻量部署下保护本机启动根的措施，不是硬件安全模块，也不能替代操作系统安全。

## 4. 秘密分类与普通数据边界

| 数据 | 分类 | 普通页面/API | 普通日志/审计 | 快照 |
|---|---|---|---|---|
| 数据源密码 | 秘密 | 只显示已设置/未设置、修订时间 | 永不记录原值 | 只存 credentialId/revision |
| Agent 机器凭据 | 秘密 | 只显示身份状态和轮换时间 | 永不记录原值 | 不进入任务快照 |
| 控制面根密钥 | 根秘密 | 无查看/复制入口 | 永不记录原值或摘要 | 不进入业务数据 |
| 组合用户名 | 标识敏感 | 命令预览与计划命令可按任务/数据源权限显示 `-uusername@tenant` 或 `-uusername@tenant#cluster` | 统一脱敏 | 保存提交时必要摘要 |
| 主机、端口、数据库名 | 受限业务信息 | 按对象权限显示 | 按统一策略处理 | 保存必要快照 |
| credentialId/keyId/revision | 安全元数据 | 只在诊断需要时显示非敏感摘要 | 可审计 | 可以保存 |

数据源 `username` 是拆分保存的普通业务用户名，不等同于 `username@tenant` 或 `username@tenant#cluster` 组合身份。浏览器在 `GET /api/v1/data-sources` 中只有逐项通过该数据源读取范围校验，才可取得 `username`，且不需要管理范围；这是列表摘要唯一新增的身份字段。单个 `GET /api/v1/data-sources/{dataSourceId}` 详情仍须同时通过读取与管理范围校验，成功 `PATCH /api/v1/data-sources/{dataSourceId}` 已完成同一管理范围校验并复用详情投影。其他写操作响应及仅具读取范围的详情都必须省略它。该例外不放宽组合用户名、sys 账号、sys 密码或任何密码材料的浏览器响应禁令。

秘密不能伪装成普通字符串字段。代码和协议模型必须使用独立秘密引用/槽位类型，禁止把密码加入通用 map 后再依赖日志过滤“补救”。

## 5. 控制面密钥层级

```text
操作系统保护的版本化根密钥 keyId
        ↓
AES-256-GCM 认证加密
        ↓
SQLite 中每个 credential revision 的 nonce + ciphertext + tag + AAD 元数据
```

首版不引入 Vault、云 KMS 或专用 HSM。根密钥与 SQLite 必须位于不同文件，普通 SQLite 备份不得自动捆绑根密钥。

### 5.1 Windows AMD64

- 控制面安装时生成随机根密钥；
- 使用运行控制面的专用 Windows 服务账户作用域 DPAPI 保护根密钥文件；
- 使用非交互模式，不使用已废弃的提示式流程；
- 不使用 `CRYPTPROTECT_LOCAL_MACHINE` 放宽为“本机任意用户可解密”；
- 根密钥文件目录仍使用 ACL 只允许服务账户和明确管理员访问；
- 更换服务账户、迁移机器或管理员重置账户凭据前必须执行受控恢复/迁移验证。

DPAPI 默认通常绑定同一用户和同一机器，因此它适合本机保护，不等于可移植备份。

### 5.2 麒麟 Linux AMD64/ARM64

- 安装时生成同等强度的随机版本化根密钥文件；
- 目录权限 `0700`、文件权限 `0600`，所有者为专用控制面服务账户；
- 根密钥不放入命令行、环境变量、systemd unit 正文、SQLite、日志或 Git；
- 不依赖桌面 Secret Service、特定云厂商 KMS 或目标系统尚未验证的内核密钥环；
- 文件权限只能阻止非特权账户，不能抵抗 root，运维文档必须明确这一限制。

### 5.3 恢复边界

- SQLite 备份和根密钥恢复材料分开保存、分开授权；
- Windows DPAPI 文件不能直接当作跨机器恢复材料；
- 在生产准入前必须定义一次受控“根密钥恢复导出”，生成独立加密的离线恢复包，并完成跨机器恢复演练；
- 恢复包的加密、操作员恢复材料和保管流程在部署/备份契约中定版；未完成前只允许开发/测试环境，不宣称具备生产灾备；
- 根密钥丢失时不得静默重置并让旧密文变成未知数据，应阻断凭据操作并显示明确恢复故障。

## 6. 数据源密码加密格式

每个密码修订独立使用 AES-256-GCM 认证加密：

- 根密钥由加密记录的 `keyId` 选择；
- nonce 使用密码学安全随机源并保证同一 keyId 下不重复；
- 使用标准 nonce 和完整认证标签，不自定义缩短标签；
- AAD 至少绑定：`credentialId`、`revision`、`secretType`、数据源 ID 和加密格式版本；
- SQLite 保存 `keyId`、nonce、ciphertext/tag、修订和非敏感状态，不保存明文；
- 任一 AAD 不匹配、标签验证失败、未知 keyId 或格式版本均拒绝解密并进入安全故障，不尝试容错明文。

实现优先使用 Go 标准库 `crypto/aes` 与 `crypto/cipher` 的标准 GCM 接口，不自行实现加密算法。随机源失败时整个写入失败，不能退化为时间戳、计数器或固定 nonce。

## 7. 数据源密码生命周期

### 7.1 新增与查看

- V1.0 新增数据源密码必填；
- 服务端接收后立即进入秘密处理路径，不写请求日志；
- 页面读取数据源永远不返回密文、可逆编码、固定占位值或密码长度；
- 授权数据源列表在逐项读取范围已确认后可回显拆分保存的普通业务 `username`；单个详情及其成功 PATCH 响应仍仅在同一数据源管理范围已确认后回显；它不包含 sys 账号或组合用户名，其他写操作响应仍不回显；
- 页面只返回 `credentialStatus`、当前 revision 和最近更新时间；
- 数据源管理员可以覆盖密码，但没有“查看已有密码”能力。

### 7.2 编辑与轮换

- 编辑页面密码输入始终为空；未提交新密码表示保持原 revision；
- 提交新的非空密码创建新 revision，并使原连接测试失效；
- 新任务只引用当前有效 revision；
- 已提交且仍可能启动的任务保持原 revision，不静默使用新密码；
- 被旧非终态任务引用的 superseded revision 继续加密保留，只允许对应 execution 在授权租约内解析；
- 不再被非终态任务引用的旧 revision 进入安全清理，不为历史详情或“基于原配置新建”保留可读取密码。

### 7.3 禁用、撤销与删除

- 数据源禁用后禁止新任务选择，等待任务在领取/启动复验时阻断，符合 DS-R09；
- “轮换”与“立即撤销”是不同操作：轮换允许已提交任务按原 revision 执行，撤销则禁止尚未解析的所有 revision；
- 已经运行的工具进程无法远程收回内存中的密码；撤销只阻止后续解析，不伪装成进程取消；
- 无引用数据源物理删除时一并删除凭据密文；
- 存在历史引用时只有显式归档动作可归档数据源；永久删除请求必须拒绝，不能自动转为归档。历史快照只保留 credentialId/revision 元数据；没有活动引用的密码密文按清理规则删除。

## 8. 基础连接测试中的凭据

连接测试继续严格限定为地址/端口、认证、基础数据库连接和直接可得信息，不扩展任务权限或性能诊断。

首条切片的数据源基础测试由用户明确选择的、已认证的执行节点 Agent 执行；控制面只负责权限校验、冻结绑定、短租约、秘密槽位授权、结果校验与审计，不直接连接数据源、不启动 JDBC。测试结果必须记录测试节点和该节点的事实版本，只证明该节点到数据库在该次测试时可达，不能推导其他节点、导入/导出权限、对象权限、性能或任务可行性。

执行规则：

1. 浏览器同时提交数据源版本和测试节点；服务端校验数据源管理权限、节点使用范围、当前已认证 Agent 与节点事实；节点管理状态可为 `DISABLED` 或 `ENABLED`，但 `MAINTENANCE`/`ARCHIVED` 必须拒绝，且诊断资格不授予导出任务资格；
2. 控制面在短事务中冻结数据源连接配置摘要、当前凭据 revision、节点、关联 Agent 与节点事实版本，并写入测试意图与租约绑定；
3. Agent 只能主动领取固定 `DATA_SOURCE_CONNECTION_TEST` 工作，确认当前绑定后才可在短时租约内请求唯一数据库连接槽位；
4. Agent 只使用固定 JDBC 连接探针建立连接并读取允许的基础元信息，不接受任意 URL、SQL、驱动、主类、命令或路径；
5. 控制面仅在数据源配置、凭据 revision、节点/Agent 绑定、节点事实和租约仍一致时持久化无秘密终态；
6. 立即关闭连接并释放秘密引用；最终审计或状态保存无法确认时，不把连接状态更新为“可连接”。

当前私有 ODP 切片依据 [DEC-013](../01-product/decisions.md#dec-013-数据源专项产品规则) 分字段保存 `username`、`tenant`、可选 `cluster`，仅在冻结绑定复验通过后由控制面短时组装 JDBC 身份；集群名为空时为 `username@tenant`，有值时为 `username@tenant#cluster`。该格式与 OceanBase V4.3.5 文档中的私有 ODP 连接身份一致（[Java 客户端连接方式](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001974051)、[ODP 连接方式](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001970916)）。组装值只以可清零字节槽位传递，不持久化、不写日志、不进入审计或浏览器响应；`username` 与 `tenant` 为空、任一非空字段含空白/控制字符、含 `@`、`#`、`:` 分隔符、不是有效 UTF-8 或组合后超过 256 字节时失败关闭。Agent 和 JDBC 探针不得自行猜测、补全或改写该身份。

连接字符串、驱动日志和错误包装器必须逐项验证不会输出密码或完整组合用户名。

## 9. 任务秘密槽位解析

任务信封只包含类型化秘密槽位及 `credentialId/revision`，不包含密码。Agent 在完成启动前校验后、调用系统创建进程前，通过单独操作解析槽位：

```text
Agent 认证
→ 校验 nodeId/agentId/executionId/leaseId/leaseEpoch
→ 校验信封摘要、槽位用途和凭据 revision
→ 复验任务提交者权限状态、数据源启用/撤销状态和执行门禁
→ 写入不含秘密的解析审计意图
→ 控制面短时解密
→ 通过 HTTPS no-store 响应返回精确槽位值
→ Agent 仅在内存中物化原值
→ 按已验证的官方安全文件格式生成任务级加密材料
→ 使用隔离配置启动工具
→ 不回传原值、不持久化明文、不写日志
```

同一 requestId 在有效租约内允许安全重试；控制面可以再次从密文生成同一逻辑响应，但不能缓存明文响应。进程已经确认启动、租约失效、revision 被撤销、节点不匹配或信封变化后拒绝解析。

控制面解密权限属于内部执行服务能力，不映射为任何用户角色的“查看密码”权限。即使系统管理员也不能通过普通 API 调用槽位解析取得明文。

### 9.1 提交前预检查秘密槽位补充

AD-R09 确认的 `EXPORT_PREFLIGHT` 可以在提交前解析当前数据源密码；对象存储输出在满足更窄的前置条件时可解析冻结的存储凭据。两类能力都必须与正式执行隔离：

- 同时校验 precheckId、precheckLeaseId/epoch、nodeId、agentId、草稿 revision、配置指纹、credentialId/revision 和固定检查用途；
- `DATABASE_CONNECTION` 只返回数据库认证所需的类型化槽位，不返回 sys 或其他未来任务秘密；`STORAGE_CREDENTIAL` 只返回成对 access-key/secret-key，且只能用于当前对象存储输出的 `STORAGE_AUTH`。两个槽位必须独立请求、独立 requestId/摘要/回执，不能在一次响应中混合或复用；
- 本地输出的 Agent Worker 必须先完成无秘密的工具环境、输出路径、目录空性和可用空间检查；仅当四项均为 `PASSED` 时才可解析数据库槽位并启动固定 JDBC 探针。对象存储输出只先完成工具环境和临时目录空间检查，再完成数据库/对象检查与无秘密 `STORAGE_CONNECTIVITY`；仅当这些前置均为 `PASSED`、草稿已冻结存储凭据引用且认证探测器显式声明需要凭据时，才可解析存储槽位。任一前置项为 `FAILED` 或 `UNKNOWN` 时，不得接触对应凭据，相关检查以固定 `UNKNOWN` 结果收口；
- 预检查只在内存中建立有限超时数据库连接，不生成 OBDUMPER 安全文件，也不启动 OBDUMPER；允许由固定 Java JDBC 连接探针完成连接、基础元信息和已冻结单表的零行读取验证。探针先用 JDBC 元数据定位对象，再由冻结的 MySQL/Oracle 兼容模式逐段安全引用库或 Schema 与表，固定执行 `SELECT 1 ... WHERE 1 = 0`；不得接受任意 SQL、URL、驱动、主类或环境秘密；
- 同一槽位的 requestId 在有效短租约内可以重试，但控制面和 Agent 均不缓存或持久化明文响应；默认失败关闭的认证探测器不得解析存储凭据。当前尚未启用任何云厂商签名请求，真实凭据探测仍需 EX-V1 的端点、凭据与网络授权；
- 完成、失败、失联或租约过期后立即释放内存槽位；预检查凭据不能复用于正式 execution；
- 正式任务领取后必须按 execution 租约重新解析已冻结 credential revision，不能沿用预检查连接或秘密；
- 数据源禁用、凭据撤销、权限变化、草稿/指纹变化或节点不匹配时拒绝解析并使预检查失效；
- 解析意图和结果继续使用不含秘密的审计事实，普通用户 API 永远不能调用该内部操作。

## 10. Agent 内存与本地边界

- Agent 机器凭据在 Windows 使用专用服务账户 DPAPI 保护；Linux 使用专用账户 `0600` 文件；
- 数据源密码原值不写本地执行日志、环境快照、崩溃诊断或明文临时文件；
- Go 中优先使用可控字节缓冲并减少复制，使用后尽力覆盖；不得声称垃圾回收语言能保证所有内存副本立即物理清零；
- 子进程环境块、参数数组和包装脚本不得被普通日志打印；
- 只有官方 `secure-gen` 兼容方案验证通过后，才允许任务目录短时保存加密敏感文件、私钥和隔离 `security.properties`；这些不是普通任务产物，权限、生命周期和清理单独管控；
- Agent 退出、崩溃或机器被特权调试时仍可能暴露运行中内存，这是威胁模型明确限制。

## 11. OBDUMPER 官方安全文件路线

### 11.1 已确认事实

OceanBase 官方说明：OBLOADER/OBDUMPER V4.2.0 以后可用 `secure-gen` 加密敏感信息；配置完成后，运行命令不必显式提供 `-p/--password` 或 `--sys-password`。

项目中的 4.3.5 发布包实际包含：

```text
tools/secure-gen
conf/security.properties
```

包内配置键为：

```text
encrypt.filePath=
secretKey.filePath=
security.className=
```

包内 `secure-gen` 是 Bash 脚本，依赖 OpenSSL；默认在用户目录生成 RSA 密钥和 `secure.rsa`。脚本没有 Windows `.bat/.cmd` 版本，并且 `-n` 模式需要明文属性文件作为输入。因此“官方有安全功能”仍不等于平台已经具备跨平台、安全、并发隔离的实现证据。

2026-07-21 的受控验证进一步确认了包内实现格式：未加密 PKCS#8 私钥、RSA/PKCS#1 v1.5 密文和 Java Properties 明文载荷。纯 Go 内存生成的合成材料已被 4.3.5 Java 解密器和真实 OBDUMPER Windows 进程读取，实际命令未携带 `--password`。错误私钥被拒绝，两个 execution 的私钥与密文均不同。完整结果和未通过项见[安全文件兼容性验证](evidence/secure-gen-compatibility-spike-2026-07-21.md)。

### 11.2 已部分验证的首选实现候选

首条切片优先验证以下路径：

```text
Agent 短时取得密码原值
→ 在内存中生成与 4.3.5 secure-gen 兼容的任务级 RSA 密钥与 secure.rsa
→ 写入仅服务账户可读的任务级私钥、密文和 security.properties
→ 使用任务级隔离配置启动 OBDUMPER
→ 命令不生成 --password
→ 工具结束并完成证据上传后清理安全材料
```

这不是重新设计工具的密码输入协议，而是用 Go 在 Windows/Linux 上生成与包内 `secure-gen + security.properties` 完全兼容的官方输入格式。Windows 上“4.3.5 读取平台生成产物”已经通过；“读取官方脚本产物”、Linux AMD64/ARM64 工具读取、并发隔离和清理仍未通过。目标 Linux 上必须继续用包内 `secure-gen` 与平台产物交叉核对；无法证明时不得实现。

Windows 验证还发现：官方 `.bat` 没有主动设置 `security.configurationFile`，每进程 `JAVA_OPTS` 注入配置路径可以生效，但批处理继续掩盖 Java 失败退出码。Linux 脚本则把该配置固定到共享 `conf/security.properties`。因此正式 Agent 的跨平台隔离启动入口仍需专项定版，不能修改共享配置，也不能只看 `.bat` 返回值。当前专项建议和 TL-R01～TL-R18 见[跨平台隔离启动入口契约](tool-launch-isolation-contract.md)。

### 11.3 隔离与清理要求

- 不修改发布包共享 `conf/security.properties`，避免并发任务串用密码；
- 每个 execution 使用独立、安全权限的运行配置目录；
- 明文属性文件永不落盘；
- 私钥和 `secure.rsa` 虽不是明文，但二者组合可恢复密码，必须按秘密材料管理；
- 安全材料路径不进入普通命令展示、日志、审计或结果下载；
- Agent 崩溃恢复先识别并监管原 execution，不为同一任务重建第二套材料；
- 任务终态确认后删除任务级安全材料；删除失败进入安全清理告警并阻止目录复用；
- Windows AMD64 已验证预先收紧 ACL 后工具仍可读取；Linux AMD64、Linux ARM64 仍需分别验证 `0700/0600`、路径、OpenSSL 非依赖生成和工具读取；
- Agent 必须先创建并验证安全目录权限，再写入材料。Windows 上仅依赖 Go 文件模式不会自动移除继承的普通用户权限。

### 11.4 与参数契约的关系

如果该路线通过，业务密码仍是任务的必需秘密输入，但不再生成 `--password` argv 令牌。`secretSlots` 需要支持“官方安全文件属性”目标，计划/实际完整命令明确省略密码参数，并展示“密码来源：任务级官方加密配置（已脱敏）”。

因此已确认的 PC-R04 需要在安全路线通过后做一次兼容修订：首条切片仍只有原八项逻辑输入，但实际命令参数从八项收缩为七项，密码改由官方安全文件承载。修订必须留评审记录，不能在代码中静默改变。

### 11.5 备用与阻断

- 不优先研究 `session-config`、stdin、环境变量或自创临时密码文件；官方安全功能已提供更明确方向；
- 同时保留 argv 可见性测试，作为官方安全路线失败时的风险对照，不作为默认实现；
- 如果 4.3.5 安全文件路线最终无法在全部正式目标平台稳定工作，而工具又只能使用进程参数，则必须形成单独风险接受结论；Windows 单平台兼容通过不等于整体通过，在用户确认前 VS-P0-09 继续阻断，不能偷偷降级。

## 12. 命令、页面与日志脱敏

2026-10-09 前端治理补充：存储凭据创建/轮换保持 AccessKey/SecretKey 成对写入原 API，列表只消费既有安全投影。唯一编辑器只在当前编辑会话短时持有输入；取消、切换、成功和卸载清除引用，失败保留当前输入供重试，旧会话响应不恢复输入或反馈。轮换捕获打开时修订并保留 If-Match、CSRF 和幂等；取消 HTTP 等待不撤销服务端事务，JavaScript 清引用不保证物理擦除。该实现不改变密钥信封、安全投影、存储预检查或真实准入契约；维护与合成负例见[凭据索引](../../web/src/workbench/credentials/README.md)。

### 12.1 首条切片

- 命令预览、计划命令和复制展示全部非密码参数；已授权任务的日志、错误和下载保留非秘密运行上下文，但继续遮蔽秘密；审计正文仍只保存非敏感摘要；
- 官方安全文件路线通过后，完整命令不包含 `--password`，页面以密码安全来源摘要解释密码如何生效；
- 密码使用统一固定掩码，不显示长度、前后缀或哈希；
- `--user` 仅在拥有当前任务或数据源对象范围时出现在命令预览和计划命令；
- 经人工确认的任务日志可以保留完整组合用户名、主机/端口、对象、用户路径、非密码命令令牌和工具原始诊断；该可见边界只适用于当前任务对象范围，不产生原始日志或任意文件读取能力；
- 首条切片始终关闭密码原值查看，任何命令查看也不能触发凭据解析；
- 任何接口都不能通过“查看命令”间接调用凭据解析。

### 12.2 双层脱敏

- Agent 在日志读取和上传前使用任务槽位已知秘密及结构化规则完成第一层脱敏；
- 控制面在持久化、SSE 和下载前按同一策略版本再次脱敏；
- 两层策略只遮蔽密码、令牌、访问密钥、私钥、密文、安全材料及其可恢复表示；不得把已确认的非秘密运行上下文误处理为秘密；
- 禁止只靠一组正则表达式兜底；秘密不应先进入普通日志再等待过滤；
- 脱敏策略版本进入任务和日志证据，策略失败时阻断上传或存储，而不是保存原文。

完整日志分段、游标和缺口语义见[日志采集、双层脱敏与执行证据最小契约](log-collection-evidence-contract.md)；LG-R01～LG-R20 已确认。

## 14. 权限变化与执行时复验

- 权限授予或撤销对下一次读取、测试、提交、领取和秘密解析立即生效；
- 提交任务时冻结提交者、权限版本和对象范围摘要，但不把历史权限快照当作永久通行证；
- 用户失去任务创建/数据源使用权限后，尚未开始的任务在领取前阻断；
- 数据源禁用或凭据撤销后，尚未解析秘密的任务阻断；
- 已经运行的任务不因用户权限撤销而自动终止，后续查看和操作按当前权限处理；
- 运行任务继续由平台内部执行身份监管，但不能借此让原用户重新取得秘密或日志权限；
- 权限服务不可用或权限事实无法确认时默认拒绝高敏操作，不使用缓存猜测放行。

## 15. 审计失败策略

以下动作只有在审计意图与业务变更能够由同一 SQLite 短事务可靠保存时才宣称成功：

- 数据源密码新增、轮换、立即撤销和删除；
- Agent 关联、机器凭据轮换和撤销；
- 根密钥创建、轮换、恢复和恢复包导出；
- 权限与对象范围变更；
- 生产任务提交和未来敏感命令操作。

任务槽位解析采用两阶段审计：先保存解析意图，再允许解密；随后保存成功/失败结果。意图无法保存则拒绝解析；结果保存无法确认时停止后续新解析，并把当前执行置为安全核对，不把“可能已经返回秘密”记录成确定未发生。

审计只记录主体、对象、动作、revision/keyId、原因、结果、时间和非敏感差异，不记录密码、机器凭据、根密钥、明文命令或完整业务日志。

## 16. 根密钥轮换

- 根密钥使用单调版本 `keyId`，当前活动 key 只用于新写入；
- 轮换先生成并安全保存新 key，再切换新写入；
- 旧密文按小批次解密并用新 key 重新加密，事务短且可恢复；
- 每批迁移后重新读取并验证认证标签、AAD 和 revision；
- 所有引用迁移完成且备份/恢复验证通过前不得删除旧 key；
- 轮换失败保留旧 key 和明确进度，不产生一半明文或无法解释的混合状态；
- 根密钥轮换不修改 credential revision，因为业务密码值没有变化。

## 17. 明确禁止

- 在 SQLite、配置文件、环境变量、命令行、日志、审计、测试夹具或 Git 中保存明文数据源密码；
- 把加密密钥与 SQLite 默认打包成同一备份；
- 自行实现加密算法、使用 ECB/CBC 无认证加密、固定 nonce 或复用 nonce；
- 页面/API 返回密文、Base64、哈希、密码长度或可提交占位符；
- 系统管理员、数据源管理员或节点管理员拥有密码读取能力；
- 使用用户权限接口调用内部秘密解析；
- 因 TLS 存在就省略任务/租约/槽位授权；
- 把连接测试成功写成导入/导出权限或任务可行性结论；
- 以“尽力脱敏”为由允许原始日志先落盘；
- 在未验证的情况下使用明文临时密码文件、session config、stdin、环境变量或不隔离的共享安全配置；
- 宣称 DPAPI/文件权限能够抵抗 root、管理员或内存攻击。

## 18. 最小安全测试

### 18.1 静态保存

1. SQLite、备份、日志和配置搜索不到测试密码；
2. 密文复制到其他 credential/revision 后因 AAD 不匹配无法解密；
3. 修改 nonce、ciphertext、tag 或 keyId 必须失败；
4. 相同密码两次保存得到不同密文；
5. 根密钥缺失、权限错误和未知版本均安全阻断；
6. Windows 服务账户之外不能正常使用 DPAPI 根密钥文件；
7. Linux 非服务账户不能读取根密钥文件。

### 18.2 API 与权限

1. 所有读取接口不返回密码、密文、长度或机器凭据；
2. 五类角色和对象范围的允许/拒绝矩阵逐项测试；
3. 系统管理员不能通过普通 API 读取密码；
4. 权限撤销、数据源禁用和凭据撤销立即阻断新解析；
5. 审计意图写入失败时高敏操作失败关闭；
6. 无权对象不通过数量、状态或错误差异泄露存在性。

### 18.3 Agent 与传输

1. 错误节点、Agent、execution、leaseEpoch、revision 或信封摘要解析失败；
2. 重放过期解析请求失败；有效 requestId 重试不增加明文持久化；
3. Agent 本地日志、待发送事件、错误和崩溃信息没有测试密码；
4. TLS 验证失败不发送机器凭据或任务秘密；
5. 进程启动后和租约失效后不能再次解析同一槽位。

### 18.4 工具进程门禁

当前执行状态见[安全文件兼容性验证](evidence/secure-gen-compatibility-spike-2026-07-21.md)：第 2 项的 Windows 核心路径和错误私钥负例已通过，其余跨平台、并发、进程可见性与清理项仍待执行。

1. 包内 `secure-gen` 生成的材料能被 4.3.5 在 Linux 读取，且命令不带 `--password`；
2. 平台内存生成材料与官方脚本格式双向兼容，Windows/Linux 工具均可读取；
3. 两个隔离 execution 不会串用 `security.properties`、私钥或密文；
4. Windows 与 Linux 分别检查父进程、包装脚本、Java 和工具进程命令行；
5. 非特权同机用户、同服务账户进程和管理员/root 的安全材料/进程可见性分别记录；
6. stdout、stderr、工具日志、错误文件和崩溃文件搜索不到测试秘密；
7. 崩溃恢复与删除失败不会让安全目录被下一任务复用；
8. 无法证明官方安全路线时 VS-P0-09 保持失败，不以静态加密测试代替。

## 19. 官方技术依据

- [Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)：DPAPI 默认用户/机器绑定、完整性保护和 `CRYPTPROTECT_LOCAL_MACHINE` 的放宽边界。
- [Go crypto/cipher](https://pkg.go.dev/crypto/cipher)：标准 GCM 接口、标准 nonce 长度及随机 nonce 使用约束。
- [NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)：GCM 作为带附加数据的认证加密模式。
- [OceanBase Loader/Dumper Security Features](https://en.oceanbase.com/docs/common-oceanbase-dumper-loader-10000000002265507)：`secure-gen`、敏感字段、`security.properties` 及省略命令行密码的官方机制。

## 20.1 DEV-03 凭据核心实现状态

`internal/credential` 已用运行时随机合成秘密验证以下边界：

- 版本化根密钥通过 Windows 当前进程 DPAPI 或 Linux 私有 `0600` 文件载体保存；根密钥文件与 SQLite 备份分离；
- 每个凭据封套使用标准 AES-256-GCM、随机 nonce 和绑定 `credentialId/revision/secretType/dataSourceId/formatVersion` 的 AAD；密文、nonce、keyId、格式或绑定事实被篡改时拒绝解密；
- execution 私有目录拒绝复用和路径穿越；Windows 通过受保护 DACL 仅授予当前服务主体、SYSTEM、Administrators，Linux 实现并核对 `0700/0600`；
- 任务级 PKCS#8 私钥、RSA/PKCS#1 v1.5 `secure.rsa` 与 `security.properties` 在不创建明文属性文件的情况下生成；实际命令仍不生成 `--password`；
- 正常清理只删除本 execution 已知材料并拒绝复用残留目录；测试树和错误信息不包含运行时合成秘密。

这些是纯核心验证，不能替代 CS-R10 的 Agent/租约/HTTPS 槽位协议、Windows 正式服务账户部署、三个麒麟目标实机权限、官方脚本交叉读取、并发/崩溃清理或完整 VS-P0-09。

### 9.2 数据源可选 sys 凭据（2026-08-10 实现）

参考 ODC 数据源高级设置，数据源可成对配置可选的 sys 账号/密码（--sys-user/--sys-password，拥有 sys 租户视图查看权限的账号如 root，账号勿填 @sys#集群 后缀）：

- 存储：sys 密码使用与数据库密码相同的 AES-GCM 信封（AAD 绑定 credentialId/revision/secretType=SYS_PASSWORD/dataSourceId），存独立表 `sys_credential_revisions`（迁移事务内无法关闭 foreign_keys，重建 credential_revisions 会触发外键失败，故不改历史表约束）；`data_sources` 只保存 `sys_user`、`sys_credential_id`、`sys_credential_revision` 元数据；
- 创建/更新：账号与密码必须成对提供（一侧为空即 422）；轮换递增 sys 修订并把旧 ACTIVE 修订标记 SUPERSEDED；账号与密码同时置空表示清除（ACTIVE 修订标记 REVOKED）；物理删除数据源时随事务清理 sys 修订；
- 投影：浏览器只收到派生状态 AVAILABLE/UNAVAILABLE，不下发 sys 账号或任何秘密；`sys_credential_id` 仅供受控写路径识别版本，绝不进入浏览器响应；
- 解析：sys 凭据的短时解析与任务秘密槽位同机制（本契约第 9 节）；`--add-extra-message` 等依赖 sys 凭据的能力只在数据源 sysCredentialState=AVAILABLE 时考虑启用，当前仍保持关闭（待实测）；
- 幂等摘要：`createRequestDigest` 只以 sys 存在性参与，不落入密码内容或摘要。

- 连接测试（2026-08-10 扩展）：数据源配置了 sys 凭据时，基础连接测试在数据库验证成功后额外用 sys 身份（集群为空时为 `sysUser@sys`，有集群时为 `sysUser@sys#cluster`，平台组装）经固定 JDBC 探针验证 sys 租户认证；sys 结果独立记录（sys_verification_status/sys_result_code，枚举 SYS_CONNECTED/SYS_* 错误码），不阻断数据库启用门禁；未配置 sys 凭据的数据源请求 SYS_CONNECTION 槽位失败关闭；绑定摘要包含 sys 引用，Agent 领取/确认/槽位/完成全程复验。
