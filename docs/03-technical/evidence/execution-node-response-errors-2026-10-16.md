# 执行节点响应兼容与错误说明整改

日期：2026-10-16。

## 问题与边界

普通导入接入后，控制面按授权范围返回最近五条节点任务，其中可能包含 `OBLOADER_NORMAL_IMPORT`。前端 `parseNodeRecentTasks` 仍只接受导出，且详情即使隐藏近期任务也会校验该投影，导致整份响应被拒绝。用户看到“无法打开执行节点 / 控制面返回了无效节点采集事实”，无法判断原因或下一步。

本轮修复该兼容遗漏，并整改执行节点模块列表、详情、编辑/保存、启用、环境检查、删除结果及注册材料中的同类响应错误。只修改前端解析与安全反馈，不增加产品能力、请求、权限或真实执行授权，不放宽未知数据的校验。

## 实现与维护入口

- `web/src/api/nodeRuntimeFacts.ts`：近期任务接受导出与普通导入，保留真实类型；未知业务类型、任务状态、读取范围、过量或畸形记录继续失败关闭。主机、完整检查、操作与近期任务的错误说明区域、具体原因与建议。
- `web/src/api/nodeResponseValidation.ts`：API 层唯一的节点响应错误说明能力，保留 `RESPONSE_INVALID`。同步解析只包装已知的校验错误，内层区域优先；程序异常继续向外传播，由节点反馈使用固定提示。无请求、缓存或业务状态。
- `web/src/api/browser.ts`：节点状态、资源、额度、检查记录、版本、上传队列、活动执行、空间采样及注册材料按区域包装。上传时间矛盾、检查缺项、未知任务类型等使用各自原因；已知服务错误给出处理方向，未知错误不展示原始消息。
- 写请求已经送达后，成功 HTTP 响应无法校验时，提示操作可能已经生效，先刷新核对。注册材料不可信时拒绝返回，提示关闭弹层、刷新节点并核对版本。
- 原有 `useNodeList`、`useNodeDetail`、`useNodeForm`、`useNodeEnrollment` 继续持有各自唯一状态。首次失败不能发布部分响应；刷新失败保留上一份可信事实与成功时间；授权撤销、切换和卸载的失效规则不变。

错误仅使用固定区域/字段标签及固定原因，不拼入未识别枚举、路径、网络地址、原始异常、响应内容或一次性材料。未新增日志、持久化错误对象、通知状态或 UI 组件包装。
