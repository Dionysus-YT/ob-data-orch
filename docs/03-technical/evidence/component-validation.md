## API 与数据模型 SQLite 约束最小验证

> 验证日期：2026-07-21
> 验证环境：Windows AMD64、Go 1.26.4、modernc.org/sqlite v1.54.0
> 结论：核心关系约束候选可行；正式 20 表迁移、API 和目标麒麟运行仍待实现验证

<a id="api-sqlite-1-目的与边界"></a>

### 1. 目的与边界

本次验证只回答 SQLite 能否直接保护以下关键不变量：

- 草稿 revision 乐观并发；
- 提交任务快照不可修改；
- 同一配置指纹允许两个独立任务；
- 同一 task 并发领取只有一个 execution；
- execution 事件必须绑定正确 lease/epoch 且序号唯一；
- 同一幂等键不能绑定不同请求摘要；
- 同一日志序号范围不能写入不同内容摘要；
- 业务事实和审计事实能够同事务回滚。

验证夹具位于 Git 忽略的 `tmp/api-data-model-spike/`。它使用合成 ID、合成密文字节和空业务 JSON，不读取真实凭据、现有 P0 数据库或 OBDUMPER 日志，不属于业务代码或正式迁移。

<a id="api-sqlite-2-验证模型"></a>

### 2. 验证模型

<a id="api-sqlite-5-得到的设计结论"></a>

### 5. 得到的设计结论

- task 提交快照和运行状态必须分表；否则无法同时保证快照不可变和状态更新；
- `configFingerprint` 不是唯一业务键，两次明确提交相同配置必须获得不同 taskId；
- taskId 在 task_executions 上唯一即可让两个并发 Agent 只有一个领取成功；
- execution 事件复合外键必须包含 executionId、leaseId 和 leaseEpoch，只校验 executionId 不足；
- 乐观锁可以直接用带 revision 条件的 UPDATE 影响行数判断；
- 审计和业务事实在同一短事务内保存，不需要第二套消息系统；
- 约束只能拒绝冲突；API 仍需识别“完全相同重发”并返回原确认，而不是把所有唯一冲突都显示成失败。

<a id="api-sqlite-7-dev-03-核心仓储后续验证"></a>

### 7. DEV-03 核心仓储后续验证

后续实现已将正式 `0001` 迁移与显式 SQLite 仓储接入同一套本地合成夹具，新增验证：

- 启动时固定 `foreign_keys=ON`、WAL、`synchronous=FULL` 和 5 秒 `busy_timeout`，并拒绝未启用外键的数据库；
- 通过 `VACUUM INTO` 创建新备份文件，快速完整性核对后重新打开并应用同一迁移集合；
- 草稿 revision 更新只允许一个正确期望版本成功；
- 提交任务与审计事件同一短事务，审计主键冲突时任务插入一并回滚；
- 同一任务两个并发领取请求只有一个 `task_executions`、lease 和初始事件成功；
- 任务快照保持不可变；错误 lease、重复 eventSeq、`--password` argv 与含密码值的通用 JSON 均被拒绝。

这些均是临时数据库和合成 ID/字节的纯核心测试。未实现 API、认证、真实 Agent、凭据解密、日志文件 fsync/恢复或目标麒麟运行；因此 G3/G4 和真实业务链路继续阻断。

## SQLite 跨平台最小技术验证（2026-07-21）

> 证据状态：Windows AMD64 构建与运行通过；Linux AMD64/ARM64 构建通过、目标麒麟运行待执行
> 验证范围：纯 Go SQLite 驱动、关闭 CGO、三目标构建、Windows 基础事务与备份
> 非目标：业务数据模型、任务调度实现、性能压测和国产 Linux 认证

<a id="sqlite-platform-1-验证目的"></a>

### 1. 验证目的

确认 SQLite 轻量路线不会破坏以下平台约束：

- 同一份 Go 代码能生成 Windows AMD64、Linux AMD64、Linux ARM64 产物；
- 国产 ARM Linux 不需要为平台 SQLite 额外安装 C 编译器或 SQLite 服务；
- 最小事务、WAL、外键、完整性检查和一致备份行为成立；
- 编译成本和产物大小处于轻量项目可接受范围。

本验证位于 Git 忽略的 `tmp/sqlite-cross-platform-spike/`，没有创建或提交业务代码、正式数据库或部署配置。

## 日志流重组与脱敏最小验证

> 验证日期：2026-07-21
> 验证环境：Windows AMD64、Go 1.26.4
> 结论：记录边界重组、双层幂等脱敏和批次摘要候选可行；正式采集协议与跨平台运行仍待实现验证

<a id="log-redaction-1-目的与边界"></a>

### 1. 目的与边界

本次验证只回答三个实现前问题：

1. 当密码或 UTF-8 字符跨越操作系统管道读取块时，能否在持久化前完整重组并脱敏；
2. Agent 与控制面使用相同固定掩码重复处理时，结果能否保持稳定；
3. 同一批日志的重发能否通过摘要幂等识别，而相同序号不同内容能否被拒绝。

验证程序和结果位于 Git 忽略的 `tmp/log-contract-spike/`，只使用运行时随机合成秘密和合成组合用户名，不读取真实数据库凭据，不属于正式业务代码。

<a id="log-redaction-2-已有-obdumper-日志事实"></a>

### 2. 已有 OBDUMPER 日志事实

对 `tmp/p0-validation/` 中已有 10 份 `ob-loader-dumper.info` 做了不输出正文的只读统计：

- 文件大小为 396～11,548 字节；
- 每份 5～113 个非空物理行；
- 只有部分物理行带可识别的时间/级别前缀，说明异常、列表或堆栈会形成续行；
- Windows 文件使用 CRLF；
- 10 份文件均包含完整组合用户名；
- 未发现此前测试密码原值。

因此不能简单地把“每次 Read 返回值”或“每个物理行”都当作完整产品日志记录，也不能原样上传工具文件。

<a id="log-redaction-3-合成验证方法"></a>

### 3. 合成验证方法

验证输入包含：

- 一个随机生成且不输出的合成密码；
- 一个合成组合用户名；
- 中文 UTF-8 文本；
- 密码与中文字符都被故意切在两个读取块之间；
- 一个超过 256 KiB 且没有及时换行的异常记录；
- 同一流和序号范围的重复批次及冲突批次。

处理顺序为：

```text
读取任意字节块
→ 按来源维护内存重组缓冲
→ 得到完整记录或确认超限
→ Agent 第一层固定掩码脱敏
→ 控制面第二层相同规则再次脱敏
→ 生成带来源和序号的 JSONL 记录
→ 计算流、序号范围和内容摘要
→ 写入临时脱敏段文件
```

超长记录不会把原文持久化；采集器丢弃到下一个安全记录边界，并生成不含原文的缺口记录。

<a id="log-redaction-4-验证结果"></a>

### 4. 验证结果

| 项目 | 结果 |
|---|---|
| 密码跨两个读取块 | 已按记录边界重组 |
| UTF-8 字符跨两个读取块 | 重组后仍为有效中文 |
| 段文件包含合成密码 | 否 |
| 段文件包含合成组合用户名 | 否 |
| Agent/控制面重复脱敏 | 结果幂等 |
| 同一批次重复摘要 | 相同，可安全确认重发 |
| 相同序号范围、不同内容 | 摘要不同，应判冲突 |
| 超过 256 KiB 的无边界记录 | 原文不保存，生成显式缺口 |

本次脱敏段文件为 309 字节，SHA-256：

```text
12f8533b5e2b390d5025e09b359face35cc5c53b3eb8024e457696dc544c5d93
```

该摘要只标识本次随机合成验证产物，不是正式日志格式或发布摘要。

<a id="log-redaction-5-得到的设计约束"></a>

### 5. 得到的设计约束

- 脱敏必须在记录重组之后、首次持久化之前完成；
- 不允许直接逐 Read 块替换字符串，否则跨块秘密会泄露；
- 每个来源必须有独立缓冲、序号和重连状态，不能把 stdout、stderr 和工具文件混成一个流；
- 超长或无法安全解析的记录采用失败关闭：不保存原文，显式产生缺口；
- 双层脱敏必须使用同一策略版本和固定掩码，不允许第二层恢复或改变第一层掩码；
- 批次幂等必须同时绑定来源流、序号范围和内容摘要；只看 requestId 或序号不足以发现冲突；
- 组合用户名属于标识敏感信息，需要与密码不同的分类，但普通日志同样不得保留完整值。

<a id="log-redaction-6-尚未验证"></a>

### 6. 尚未验证

- Windows/Linux 正式 Agent 管道背压和长时间运行；
- OBDUMPER 文件追加、截断、轮转和 Agent 重启后的文件身份；
- 两个并发 execution 的独立游标和本地脱敏队列；
- 控制面文件段与 SQLite 索引的崩溃一致性；
- 网络中断、重复上传、缺口声明与恢复补传；
- 实际页面查询、SSE 持续加载和脱敏下载；
- 麒麟 V10 SP3 C86、V10 SP1 ARM64、V11 ARM64 的文件与编码行为。

因此本验证只支持进入[日志采集与执行证据最小契约](../log-collection-evidence-contract.md)评审，不代表 VS-P0-09、VS-P0-10 或日志中心技术门禁已经通过。

<a id="jdbc-probe"></a>

## JDBC 连接探针最小验证

> 验证日期：2026-07-22
> 验证环境：Windows AMD64、Java 8 JDK
> 验证对象：OBDUMPER 4.3.5 包内 `oceanbase-client-2.4.14.jar`
> 结论：固定探针完成本地无凭据负例；未连接真实 ODP 或数据库

<a id="jdbc-probe-1-目的"></a>

### 1. 目的

为数据源连接测试和固定 `EXPORT_PREFLIGHT` 提供受控 JDBC 路径，而不引入 Go MySQL 驱动或把一次真实导出当作连接测试。

探针的固定边界如下：

- 固定加载 `com.oceanbase.jdbc.Driver`；
- 输入只经标准输入二进制帧传递主机、端口、用户名和密码；
- 不接受命令行连接参数、环境变量秘密、任意 JDBC URL、任意 SQL、任意驱动或任意 Java 主类；
- 成功时仅返回数据库/驱动基础元信息；失败时仅返回固定状态码，不返回异常原文；
- 不生成 OBDUMPER 安全文件、不启动 OBDUMPER、不读取或写入用户数据。

<a id="jdbc-probe-2-构建结果"></a>

### 2. 构建结果

使用本机 Java 8 JDK 编译 `internal/jdbcprobe/java` 中的固定主类，并生成：

```text
internal/jdbcprobe/assets/ob-data-orch-jdbc-probe.jar
```

构建脚本为 `scripts/build-jdbc-probe.ps1`，显式接收 JDK 根目录，不依赖系统 `PATH`。

<a id="jdbc-probe-3-合成负例"></a>

### 3. 合成负例

| 场景 | 结果 |
| --- | --- |
| 标准输入缺失 | 返回 `INVALID_INPUT` |
| 合成账号连接 `127.0.0.1:1` | 驱动已加载，返回 `CONNECTION_FAILED` |

第二项证明二进制输入、固定驱动加载和 JDBC 连接路径均已执行，失败发生在预期的本地拒绝连接阶段。该验证不涉及真实端点、真实凭据、ODP、数据库对象或导出文件。

2026-07-22 进一步以 Go 启动适配执行同一合成负例：适配层已核验本机 Java、探针 JAR 和包内 Connector/J 的摘要，以显式环境和标准输入启动 Java，并将探针失败安全投影为受控错误。探针 JAR 会由内嵌资产释放到单个预检查的私有运行目录，结束后与该目录一同清理；单元测试已覆盖该清理边界。由此确认本机 Go → 私有工作区 → Java → JDBC 链路可工作；它仍不是正式 Agent、控制面或真实数据源连接验证。

2026-07-22 又将该探针接入 Agent 本地的 `DATABASE_CONNECTIVITY` 预检查适配：适配只接受由未来 `ResolvePrecheckSecretSlots` 提供的短时连接槽位，检查结束即清零用户名和密码、回收私有工作区。探针仅把已确认的 `CONNECTION_FAILED` 投影为“数据库连接失败”；驱动、输入、进程、解析或清理异常一律投影为“连接事实不可用”，不把技术故障伪装为数据库拒绝。当前仍没有正式秘密槽位端点，因此不具备真实数据源测试入口。

## DEV-06 最小前端业务链路验证

> 验证日期：2026-07-22

<a id="dev06-1-范围与最小设计"></a>

### 1. 范围与最小设计

页面仅覆盖一条固定路径：读取已授权数据源摘要，创建或更新单表 CSV 草稿，读取控制面脱敏命令预览，发起和查询预检查，提交冻结任务，并读取任务详情与已脱敏日志快照。

前端不提供普通导入、旁路导入、模板、调度、取消、重试、系统设置或真实执行按钮；也不保存密码、用户名、密文、凭据引用、原始日志或未脱敏命令。数据源 API 的浏览器投影已同步移除用户名，前端只解析显式白名单字段。

<a id="dev06-2-对抗性处理"></a>

### 2. 对抗性处理

| 风险 | 实现与验证结论 |
|---|---|
| 未配置身份/CSRF | 写请求只有取得运行时 CSRF 元数据时才发送；缺少元数据返回本地安全错误，不生成伪造令牌。 |
| 旧草稿或并发写入 | 写请求带 `If-Match`；409/412 显示刷新提示，客户端不自行重试或覆盖。 |
| 无权或不存在对象 | 401 和 404 使用不枚举资源的通用提示；不显示响应体或请求标识中的对象详情。 |
| 命令和日志泄露 | 不读取 `argvTemplate` 等非必要字段；命令与日志在展示前执行第二层模式检查，失败时隐藏内容。 |
| 真实执行误导 | 页面固定显示 G2 与真实执行未开放；提交仅调用既有任务冻结 API，页面不连接数据库、Agent 或工具。 |
| 未实现节点 API | 不创建本地节点数据；节点标识由已登记节点事实提供，失败保持服务端 404 语义。 |
