# 导出对象大目录完整性与性能验证

2026-10-08，按用户要求取消单类 100 项、五类合计 500 项的对象加载限制，同时处理大量对象的页面性能。数据库目录仍保留原 100 项与关键字筛选规则；结果集导出的数据行上限不受影响。

## 实现范围

- 固定 Java JDBC 探针读到结果集结束；Go 探针、Worker、Store、浏览器 API 和 OpenAPI 同步取消对象条数限制。保留固定查询范围、名称验证、去重、身份、租约与过期清理。
- 对象目录及五类分组不接受 `truncated=true`，旧节点的部分结果失败关闭。单类元数据不可用仍明确标记，不能伪装成空目录。
- 探针响应字节预算 16 MiB，Java 预留序列化开销；预算不足时整体失败。五类查询仍只用一次连接，逐类累计预算，避免先积累五个超大结果才发现溢出。
- 连接测试完成回执接口预算 17 MiB（目录 + 信封）；其他机器接口仍为 1 MiB。未知字段、冻结绑定、机器身份与结果校验保留。小目录输出缓冲从 4 KiB 起增长，不预分配整个 16 MiB 预算。
- 导出 feature 的 `useExportObjectViewport.ts` 仅持有视口坐标与观察器。超过 100 行时按可见范围和缓冲行渲染 Ant List，目录、搜索、计数和全选仍使用完整业务集合。该数值是 DOM 渲染阈值，不是对象加载或选择上限。
- 固定 400px 两栏工作面、独立滚动和分类交互保持；虚拟行固定高度，长名称保留 title。滚动更新合并到动画帧，卸载移除监听、观察器和待执行帧。
- 搜索关键字只归一化一次；已选对象按类型一次分组；恢复/批量勾选使用 Set 查找，消除候选与已选集合逐项 includes 的二次复杂度。
- 保留用户手工删除的说明、标题和占位文案；对应浏览器断言改为当前页面可见字段，不回填被删除内容。
