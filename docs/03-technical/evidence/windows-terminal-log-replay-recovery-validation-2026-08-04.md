# Windows 终态日志补传重启验证

> 验证日期：2026-08-04  
> 范围：已登记 Windows `test-recovery` 独立 Agent 身份、同一控制面本机 MVP、此前实际终态 execution 留下的已第一层脱敏且已 `fsync` 的普通日志批次  
> 结论：终态日志补传恢复通过本次受控现场回归；WI-10 与 G3 仍未通过

## 1. 目的与边界

本次只验证“终态 execution 遗留的已持久化 Agent 日志批次，能否在同一 Agent 身份重启后获得严格确认并安全删除本地队列副本”。不创建新任务、不读取或复制日志正文、不重新连接数据库、不启动 Java 或 OBDUMPER，也不停止常驻 Agent。

此前一次实际终态任务已把一个已脱敏批次写入该独立 Agent 的私有队列，但旧控制面实现因租约已 `RELEASED` 拒绝补传。此次先重启为包含终态补传授权修复的控制面，再以当前源码构建的**标准** Agent 二进制复用同一受保护身份状态。

## 2. 准入与判定规则

- 仅允许同一 Agent 身份、原 `leaseId`、原 `leaseEpoch`、重新计算的冻结信封摘要及 `RELEASED + SUCCEEDED/FAILED` execution；
- 仍由既有日志端点核对来源序号、前序摘要、批次摘要和双层脱敏；
- Agent 仅在控制面回显同一位置与摘要、且为 `ACCEPTED` 或幂等 `DUPLICATE` 后删除队列文件；
- 本次通过条件为：启动前普通待确认批次为 1，重启 Agent 后为 0，且私有无正文账本末尾依次出现 `RECOVERY_REPLAY_ATTEMPT`、`CONTROL_PLANE_CONFIRMED`；
- 任一身份、租约、摘要或回显不一致均应保留条目并失败关闭。

## 3. 实际步骤与结果

1. 重新启动回环 TLS 本机 MVP 控制面，使其运行当前源码构建；常驻 Agent 未被停止。
2. 只枚举独立 Agent 私有队列的文件数量，确认存在 1 个普通待确认批次；未读取其日志正文。
3. 以当前源码构建的标准 Agent 二进制启动该独立身份。前两次启动分别因监督器相对路径和测试过程中的通信配置覆盖在身份加载前失败；两次均未启动工具、未连接数据库，且队列仍为 1。
4. 移除通信配置覆盖后第三次启动成功。Agent 用新的 `bootId` 执行恢复重放，控制面严格确认同一批次；普通待确认批次从 1 变为 0，无正文缺口仍为 0。
5. 私有账本最后两条为 `RECOVERY_REPLAY_ATTEMPT`、`CONTROL_PLANE_CONFIRMED`。随后通过独立监督器受控退出该临时 Agent，监督器结果为 `exit=0`。

本次没有创建新导出文件、没有查询业务数据、没有把端点、凭据、完整命令、日志正文或身份状态写入仓库。

## 4. 结论与剩余门禁

该结果证明：对这一个此前实际终态 execution 的已持久化批次，重启后的同一 Agent 身份可以在不恢复 execution、不续租、不改写终态的前提下完成控制面确认和本地队列清理。

它不证明低权限账号负例、CSV 特殊值内容、长期不可达、完整工具运行中进程恢复、跨平台环境、正式认证、备份恢复或全部 WI-10/WI-01～WI-12 完成。因此 **WI-10 和 G3 均保持未通过**。
