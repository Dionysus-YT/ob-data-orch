# 单管理员首次审计授予验收 · 2026-10-26

按用户明确选择的[方案 1 / DEC-065](../../01-product/decisions.md#dec-065-单管理员首版与一次性审计读取授予)，保留固定 admin，实现原安装入口的显式一次性审计读取授予。**本地实现和隔离验收完成；未安装现役服务、升级现役库或授予现役账号。** 不据此宣称多用户认证、完整 V1、G3/G4 或正式发布完成。

## 实现与使用边界

- Windows `启动.cmd` / Linux `start.sh` 的控制面菜单新增“6 首次授权 admin 审计读取”。原安装目录、已安装服务及原账户校验沿用现有入口；Agent 不可调用，活动或未知服务状态拒绝。不自动停止或恢复服务，使用顺序见[运维说明](../deployment-operations.md#单管理员首次审计授权)。
- 控制面底层 `-bootstrap-audit-access` 与其他启动模式互斥。只读现有安装配置，拒绝缺失或损坏配置、缺失业务库；独占原监听端口至操作结束。原 admin 密码和固定确认短语均通过后才打开已有库，不初始化、重置账号或修改密码。密码由菜单隐藏输入并通过 stdin 传递，短生命周期字节缓冲区清零，不进入 argv、环境、输出或 SQLite。
- `internal/accesscontrol` 定义窄类型，`internal/deployment` 持有离线输入与部署顺序，`internal/store` 持有资格及原子授权事务；`cmd/` 只装配。限定 ACTIVE 初始身份、当前系统管理员职责及未使用资格，只增加 CAP_AUDIT_LOG。普通权限 API 继续拒绝修改自己，不新增 HTTP 接口、账号、角色、依赖或通用授权工具。
- 授予、版本递增、既有未提交证明失效、使用标记及 `PERMISSION_INITIAL_AUDIT_GRANTED` 审计同事务提交；审计失败全部回滚。成功复读一致才输出完成，不把无法确认的结果写成未发生。
- 0042 在既有权限版本表增加 `audit_bootstrap_consumed`，保护使用证据不被重置或删除。已有能力或历史成功授权/撤权记录只回填已使用，不增加任何授予；普通管理员以后显式授予/撤销初始账号审计也消耗此入口。重启、重开、重复调用和撤权后不能部署重授，独立于审计保留期限。源码链为 **42 项迁移、43 张 STRICT 表**，不是现役库升级声明。
