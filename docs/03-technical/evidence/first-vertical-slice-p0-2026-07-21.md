## 4. OBDUMPER 运行发现

### 4.1 Windows 本地库发现

首次运行在连接数据库后报错：

```text
org.apache.hadoop.io.nativeio.NativeIO$Windows.access0(Ljava/lang/String;I)Z
```

工具包包含 `hadoop.dll` 和 `winutils.exe`，但 Windows 启动脚本没有把其目录加入本地库搜索路径。首次验证通过进程级路径补充绕过该问题。

用户随后配置了用户级 `HADOOP_HOME` 和 `%HADOOP_HOME%\bin`。2026-07-21 10:38 刷新进程环境后复测，`NativeIO$Windows.access0` 不再出现，确认本地库问题已经修复。工具能够完成连接、表元数据查询、任务拆分并进入 CSV 写入阶段。

### 4.2 Windows 直接绝对路径问题与适配方案

分别验证了默认嵌套输出、`--no-nested-dir` 和标准 `file:///E:/...` 输入，工具最终都构造出以下错误路径：

```text
file://nullE:/...
```

错误发生在 CSV 文件创建阶段，不是连接、认证、表不存在或磁盘空间不足。OceanBase 官方文档将 `-f/--file-path` 定义为本地磁盘绝对路径，但当前 4.3.5 Windows 运行结果与文档不一致。

已验证的 Windows 适配方式是：

1. 平台保存并校验用户选择的绝对目标目录；
2. Agent 将进程工作目录设置为该目标目录的受控父目录；
3. `--file-path` 传入从工作目录计算的 `/` 风格相对路径，例如 `./run-09/output`；
4. 命令证据同时记录工作目录、实际参数和解析后的绝对输出目录。

不能使用 Windows `\.\` 风格相对路径，本次实测会报 `Illegal character in path`。采用 `./` 后，最终文件仍落在预先确定的绝对目录中。因此这是 Windows 命令适配，不是把产品输出路径降级成不确定的相对路径。

### 4.3 退出码不可信

多次工具日志均记录 `System exit 1`，但 `obdumper.bat` 返回 0。Agent 必须结合受控 Java 进程、工具终态日志、结果文件和任务事实判断结果，不能只读取批处理退出码。
