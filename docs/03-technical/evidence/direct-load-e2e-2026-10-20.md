## 发现并修复：ODP 版本被固定为空

原 `DirectLoadProbe.Observation.json()` 无条件输出空 `odpVersion`，探针也没有读取 ODP 版本，私有 ODP 的版本门禁因此不可能通过。这是源码缺口，不是本轮数据库错误的猜测解释。

依据官方 [ODP SHOW 定义](https://www.oceanbase.com/docs/common-odp-doc-cn-1000000003575638)补入固定只读 `SHOW PROXYINFO BINARY`，只在私有 ODP 场景使用当前业务连接。严格要求单行 `binary info`、有界官方前缀和三/四段数字版本，输出不包含原始构建信息；无权限、零/多行、语法错误、未知格式或异常保持空值，不借 OBServer 版本补齐、不接收 proxysys/sys 凭据。输入与响应协议保持 v11，不增加任意 SQL、URL 或秘密槽位。

Java 正反例及相关 Go 检查通过；重建后的固定探针在本轮自有目标上两次观测一致，数据库/写权限/结构均可读，但当前连接仍无法提供 ODP 版本。该真实结果证明没有把查询失败变成版本通过，不证明已验证一条可用 ODP 通道。修复仅在源码/重建探针资产和独立组件测试中生效，尚未安装到现役服务。

当前 `DirectLoadProbe.java` SHA256 为 `9c7b4f5906062ca41218c77d261e88b2d5709d52e14dd48784d9051969802c03`，重建内嵌探针 JAR 为 `9f8a633ddaac3fea531e8df5686f0a91ba48c1b26cff4fcd2ac97d66235cc213`。工作树已有其他修改，不以 HEAD 或旧运行二进制冒充本次实现。
