# 登录后首页加载性能 · 2026-11-03

本轮按用户“输入账户密码点击登录后跳转慢，请优化”的要求，只调整前端路由加载。已实现并通过定向合成验证；未提交、安装二进制、部署正式包或执行真实数据库/存储/工具验证。

## 原因与修复

- 现场进程为 `scripts/dev.mjs control-plane --real-execution`，通过回环 Vite 提供开发网页；本次没有停止或重启该进程及 Agent。
- 原 `web/src/router/index.ts` 静态导入 15 个页面。即使只进入首页，也必须先加载导出、普通导入、旁路导入、任务详情等业务组件和依赖；开发模式的独立模块请求放大了等待。
- 所有页面改为 Vue Router 的字面量动态导入，进入对应路由才加载。保留路径、重定向、查询、子路由、meta 和原有离开守卫；不改登录模板、POST→303→GET、PBKDF2 参数、同源、限流、Cookie、CSRF 或 API。
- 维护入口仍为 `router/index.ts`；没有新增加载状态、预取器、共享缓存、依赖或业务所有者。`tests/startup.spec.ts` 通过真实网络失败反例约束首页不依赖无关页面，并验证后续导出导航和步骤可用。

## 测量口径与结果

Windows AMD64、Node 24.16.0、Chrome 156.0.8078.80；1440×1024，headless、新建浏览器上下文。临时 `httptest` TLS 服务使用当前真实 `Browser.DevelopmentHandler`、独立合成管理员和同一隔离 Vite（15174）；所有业务 API 均由 Playwright 返回合成响应，未使用现役账户或业务库。计时从点击登录到首页标题及合成指标按钮可见，包含真实密码派生、会话建立和 303 导航；浏览器路由拦截使资源缓存关闭。Vite 服务和操作系统文件缓存未清空，结果不是现场 SLA。

初轮修改后同时进行类型检查，数据为 3883 / 3001 / 3774 ms，不能与空闲时段混成一个样本。为排查冷启动差异，在同一已预热 Vite 中仅用浏览器路由响应恢复原 15 个 eager import，得到 4772 / 4034 / 4239 ms、268 个请求；移除该测试替换后为上表最后三次。该补充是加载方式的合成对照，不表示回退或重新安装了旧源码。计时有 CPU、TLS 测试证书处理和开发服务波动，不能单独归因所有毫秒差异；请求量和生产构建依赖量是确定的改善。

生产大小由前后两次 `vite build --manifest` 产物计算，首页总量包含 `index.html` 入口和首页 chunk 的递归 `imports`，不把仅入口 chunk 的缩减当作首页总量缩减。未压缩体积不是网络传输量。开发环境仍有较大的 Ant/Vue 调试依赖，密码派生也保留原成本；本轮未调整它们。
