# 执行节点页面重构验证（2026-09-29）

## 范围

本次仅重构 `/nodes`、`/nodes/new`、`/nodes/:id/edit`、`/nodes/:id` 的前端呈现与交互；不变更 Agent 协议、节点状态投影、API、真实工具或数据库能力。管理列表按 P0 Management / Table、详情按 Diagnostic / Detail 呈现。状态文案集中在 `executionNodePresentation.ts`，同一阻断原因在列表与详情保持一致。

## Design System Change · 页面表格与详情结构

执行节点列表由九列收敛为八列，Agent 关联与心跳合并为同一列中的两个独立文字事实；操作收纳到行菜单。表格仍使用共享 `OrchOperationalTable`，删除或归档继续使用 `OrchDangerConfirm`。注册/编辑由旧双栏布局改为分区单工作面，详情由五张状态卡改为连续事实条与证据分区。此记录只描述执行节点页面的结构变化，不修改 Product Shell、全局 token、共享表格几何或状态语义。

列表将 Agent 关联和心跳放在一个事实列，保留管理状态、工具环境、容量与接收任务结论的独立维度；筛选仅作用于控制面一次返回的当前授权节点。列表接口目前没有分页、服务端筛选、工具版本、主机地址或资源明细投影，页面不伪造这些事实。详情只展示当前 API 返回的配置、Agent 快照与目录空间；维护、禁用、任务和事件入口仍以对应后端契约与准入为前提。
