# JDBC 连接探针最小验证

> 验证日期：2026-07-22
> 验证环境：Windows AMD64、Java 8 JDK
> 验证对象：OBDUMPER 4.3.5 包内 `oceanbase-client-2.4.14.jar`
> 结论：固定探针完成本地无凭据负例；未连接真实 ODP 或数据库

## 1. 目的

为数据源连接测试和固定 `EXPORT_PREFLIGHT` 提供受控 JDBC 路径，而不引入 Go MySQL 驱动或把一次真实导出当作连接测试。

探针的固定边界如下：

- 固定加载 `com.oceanbase.jdbc.Driver`；
- 输入只经标准输入二进制帧传递主机、端口、用户名和密码；
- 不接受命令行连接参数、环境变量秘密、任意 JDBC URL、任意 SQL、任意驱动或任意 Java 主类；
- 成功时仅返回数据库/驱动基础元信息；失败时仅返回固定状态码，不返回异常原文；
- 不生成 OBDUMPER 安全文件、不启动 OBDUMPER、不读取或写入用户数据。

## 2. 构建结果

使用本机 Java 8 JDK 编译 `internal/jdbcprobe/java` 中的固定主类，并生成：

```text
internal/jdbcprobe/assets/ob-data-orch-jdbc-probe.jar
```

构建脚本为 `scripts/build-jdbc-probe.ps1`，显式接收 JDK 根目录，不依赖系统 `PATH`。

## 3. 合成负例

| 场景 | 结果 |
| --- | --- |
| 标准输入缺失 | 返回 `INVALID_INPUT` |
| 合成账号连接 `127.0.0.1:1` | 驱动已加载，返回 `CONNECTION_FAILED` |

第二项证明二进制输入、固定驱动加载和 JDBC 连接路径均已执行，失败发生在预期的本地拒绝连接阶段。该验证不涉及真实端点、真实凭据、ODP、数据库对象或导出文件。

2026-07-22 进一步以 Go 启动适配执行同一合成负例：适配层已核验本机 Java、探针 JAR 和包内 Connector/J 的摘要，以显式环境和标准输入启动 Java，并将探针失败安全投影为受控错误。探针 JAR 会由内嵌资产释放到单个预检查的私有运行目录，结束后与该目录一同清理；单元测试已覆盖该清理边界。由此确认本机 Go → 私有工作区 → Java → JDBC 链路可工作；它仍不是正式 Agent、控制面或真实数据源连接验证。

2026-07-22 又将该探针接入 Agent 本地的 `DATABASE_CONNECTIVITY` 预检查适配：适配只接受由未来 `ResolvePrecheckSecretSlots` 提供的短时连接槽位，检查结束即清零用户名和密码、回收私有工作区。探针仅把已确认的 `CONNECTION_FAILED` 投影为“数据库连接失败”；驱动、输入、进程、解析或清理异常一律投影为“连接事实不可用”，不把技术故障伪装为数据库拒绝。当前仍没有正式秘密槽位端点，因此不具备真实数据源测试入口。

## 4. 未通过项

- 正式 Agent 对 Java 和包内驱动的运行时身份发现、摘要核验与配置交接；
- Agent 秘密槽位端点、机器身份、租约和受控标准输入交接；
- 真实私有 ODP 的成功、认证失败和基础元信息验证；
- 固定对象存在/可访问检查；
- Windows 与三个麒麟目标的原生验证；
- 控制面第二层日志、审计、可靠队列和恢复。

因此本记录不构成 G3 通过证据，也不打开真实任务执行入口。
