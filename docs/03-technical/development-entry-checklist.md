## 4. 已确认的准入顺序

1. DEV-01 工程骨架与 CI；
2. DEV-02 OpenAPI、正式迁移草案和参数元数据只读资源；
3. DEV-03 纯核心组件及各自契约测试；
4. DEV-04 控制面最小 API 与假 Agent；
5. DEV-05 Agent preflight、执行适配和假工具；
6. DEV-06 最小前端链路，保持真实执行关闭；
7. DEV-07 Windows 获授权真实集成并补齐相关 P0；
8. DEV-08 三个麒麟目标认证；
9. DEV-09 生产安全、备份恢复和发布评审。

## 5. 不采用的门禁方式

- 不等待全部 83 个 P0 用例通过后才开始任何工程工作；
- 不要求 VS-P0-08/09/11 在其验证对象尚不存在时先通过；
- 不因静态低保真完成就直接并行实现全部模块；
- 不先建立完整数据库和全部 API 再回头验证工具行为；
- 不把只读 `--help`、单次成功或退出码为 0 当作运行行为通过；
- 不把“待官方参数映射确认”能力加入默认命令或可提交字段。
