## 3. 准入顺序

1. 建立首次 Git 基线提交；
2. 确认首条切片范围和 TD-001～TD-008；
3. 准备隔离环境、测试数据、授权和证据目录；
4. 先执行会影响选型的连接、工具、输出、进程和日志 P0，失败项收缩或阻断；
5. 根据真实环境证据选择技术栈和部署方式；
6. 完成参数元数据、命令生成、Agent、状态、日志、凭据、API 和数据模型最小契约；
7. 补齐依赖实现契约的 VS-P0-08、VS-P0-09、VS-P0-11，并在可用执行节点重跑失败项；
8. 进行首条纵向切片开发准入评审；
9. 通过后进入工程骨架和业务实现。

## 4. 不采用的门禁方式

- 不等待全部 83 个 P0 用例通过后才开始任何工程工作；
- 不因静态低保真完成就直接并行实现全部模块；
- 不先建立完整数据库和全部 API 再回头验证工具行为；
- 不把只读 `--help`、单次成功或退出码为 0 当作运行行为通过；
- 不把“待官方参数映射确认”能力加入默认命令或可提交字段。
