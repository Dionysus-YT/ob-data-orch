# 首条纵向切片：数据源到基础 CSV 导出

> 文档状态：切片范围已确认，P0 与实现契约待完成
> 切片目标：用最小真实链路验证产品基线、参数元数据、命令生成、Agent、状态和日志架构
> 评审结论：首条纵向切片范围已于 2026-07-21 确认
> 更新日期：2026-07-21

## 1. 目标

首条切片不是先制作全部页面骨架，而是完成一个可验证的最小闭环：

```text
新增或选择直连 OBServer 数据源
→ 基础连接测试
→ 创建单表 CSV 导出草稿
→ 服务端预检查
→ 查看完整脱敏命令
→ 提交任务
→ 在一个执行节点启动 OBDUMPER
→ 查看任务状态、结果和当前任务日志
```

该切片验证平台能否安全、确定和可追踪地封装官方工具，而不是验证所有格式和参数。

## 2. 切片范围

### 2.1 包含

- 单一、隔离、非生产 OceanBase 测试环境；
- 直连 OBServer 数据源；
- 数据源新增、编辑、禁用和基础连接测试；
- 已授权数据库中的单表导出；
- CSV 格式和已经确认的最小通用参数；
- 用户显式选择的执行节点；
- 计划命令、实际命令、任务快照、状态、日志和结果事实；
- 页面与服务端权限校验、命令脱敏和审计事实；
- 成功、工具启动失败、工具非零退出和 Agent 中断四类最小结果。

### 2.2 不包含

- 私有 ODP、云 ODP、ODP Sharding 和 Oracle 兼容模式；
- POS、CUT、SQL、ORC、Parquet、Avro 和对象存储；
- `--block-size` 冲突默认、空文件兼容拼写和 help-only 参数；
- 普通导入、旁路导入、模板保存、检查点继续和任务重试；
- 自动节点选择、复杂调度、批量任务和任务取消；
- 敏感命令明文开放、审批流、告警、AI 诊断或自动修复；
- 生产环境、性能压测和大数据量验证。

超出范围的能力继续保留产品与参数元数据记录，但页面隐藏、只读或提交阻断。

## 3. 切片 P0 证据

以下用例通过或明确收缩后，才允许实现对应业务能力：

| ID | 验证内容 | 最小证据 | 未通过处理 |
|---|---|---|---|
| VS-P0-01 | 工具身份 | 压缩包来源、校验摘要、`obdumper --version` 与 `--help` 记录一致 | 阻断工具注册 |
| VS-P0-02 | 直连连接表达 | 地址、SQL 端口、用户名、租户等组合能够连接目标测试库且无歧义 | 收缩数据源字段并阻断保存/任务 |
| VS-P0-03 | 基础连接测试边界 | 网络、认证、数据库连接和直接可得基础信息结果可区分 | 不提供任务权限或性能诊断结论 |
| VS-P0-04 | 单表 CSV 最小命令 | 只使用已确认参数导出一张最小表，退出码、日志和文件一致 | 阻断 CSV 提交 |
| VS-P0-05 | CSV 基础序列化 | 分隔符、包围符、转义、NULL、首行和 UTF-8 结果可人工核对 | 失败字段保持受限 |
| VS-P0-06 | 对象与权限预检查 | 有权表成功，无权或不存在表在执行前得到准确阻断 | 不允许依赖工具失败代替预检查 |
| VS-P0-07 | 输出目录与节点事实 | 目录存在、可写、空间事实和 OBDUMPER 版本来自实际 Agent | 节点不可接收任务 |
| VS-P0-08 | 命令确定性 | 相同快照重复生成结果一致，未选择和非活动参数不进入命令 | 阻断提交并修正元数据/生成器 |
| VS-P0-09 | 凭据与命令脱敏 | 页面、复制、日志、审计和快照均不暴露敏感原值 | 安全阻断，不进入实现 |
| VS-P0-10 | 状态与日志证据 | 启动、运行、成功、非零退出和启动失败均能对应真实进程/日志证据 | 未证实状态不得开放 |
| VS-P0-11 | Agent 中断语义 | 中断保留最后可信状态并进入核对，不直接判失败 | 阻断失联状态实现 |
| VS-P0-12 | 重复执行一致性 | 至少两次独立运行输出、命令、退出码和终态口径一致 | 标记不确定并继续阻断 |

VS-P0 不替代现有 EVT-P0、NIV-P0 和 DLV-P0；它从已有计划中抽取首条开发切片真正需要的最小证据，后续能力仍按原验证计划开放。

### 3.1 当前执行结论

2026-07-21 已使用获授权测试连接执行 VS-P0-02～VS-P0-12 或完成可执行性判定，结果见[首条纵向切片 P0 执行记录](evidence/first-vertical-slice-p0-2026-07-21.md)。VS-P0-04 和 VS-P0-12 已通过，当前仍存在三类阻断：

- 提供的 `2883` 端点和组合用户名疑似经过 ODP，不能直接证明“直连 OBServer”；
- Windows 实际命令按用户确认的盘符绝对路径格式执行；早期自动化出现的 `file://nullE:/...` 作为环境差异回归项，仍需在正式 Agent 环境验证；
- 参数生成器、正式凭据方案和执行 Agent 尚未实现，VS-P0-08、VS-P0-09、VS-P0-11 不能获得实现级通过证据。

因此首条切片 P0 尚未通过，业务代码继续不准入。

## 4. 实施阶段

### 阶段 A：只读验证工具

- 固化本地压缩包摘要、版本和帮助输出；
- 建立隔离测试环境记录和最小测试表；
- 不连接生产环境，不执行导入或破坏性命令。

### 阶段 B：技术设计评审

- 依据已确认的 TD-001～TD-008 细化实现边界；
- 确认参数元数据、命令生成、任务状态、Agent 通信、凭据和日志最小契约；
- 建立追踪矩阵和安全评审记录。

### 阶段 C：工程骨架

- 只建立已评审技术栈、模块边界、配置、迁移、测试和持续集成骨架；
- 不实现未通过切片 P0 的业务能力。

### 阶段 D：纵向实现

- 依次实现数据源、CSV 草稿与校验、命令生成、提交快照、Agent 执行、状态和日志；
- 每个能力同时具备自动化测试和对应验证证据。

## 5. 验收条件

1. 用户能在不重复填写连接信息的情况下选择已测试数据源；
2. 连接测试只给出网络、认证、基础连接及直接可得信息；
3. CSV 单表草稿只显示当前活动且有证据的参数；
4. 前后端使用相同参数元数据和条件语义，服务端拒绝非法组合；
5. 完整命令可查看、可复制且默认脱敏，实际命令有独立证据；
6. 提交后任务快照不可变，数据源或元数据变化不回写历史任务；
7. 任务状态、日志和结果能够追溯到真实 Agent、进程和工具证据；
8. Agent 中断、工具失败和数据不足不会被误写为成功或确定失败；
9. 未验证格式、参数、调度和操作保持隐藏、受限或阻断；
10. 所有变更可通过 Git 审查和回退。
