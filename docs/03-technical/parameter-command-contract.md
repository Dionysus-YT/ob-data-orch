# 参数元数据与确定性命令生成契约

> 文档状态：首条纵向切片专项契约已确认  
> 适用范围：OBDUMPER 4.3.5，私有 ODP、单表 CSV 导出
> 对应门禁：VS-P0-08、VS-P0-09  
> 评审结论：PC-R01～PC-R15 已于 2026-07-21 确认  
> 实现状态：参数元数据 `v2` 与确定性生成器已通过隔离契约测试；Agent、安全文件全链路与真实执行仍阻断
> 更新日期：2026-07-21

## 1. 目的与边界

本契约把已经确认的产品字段、官方参数映射和首条切片范围转成实现前必须统一的输入、校验、命令和脱敏规则。它回答以下问题：

- 哪些值可以进入命令，哪些值只能显示、继承或阻断；
- 同一任务为何必须得到相同的有序参数序列；
- 页面预览、提交快照和 Agent 实际执行如何使用同一份规范化结果；
- 密码、完整用户名等敏感值如何避免进入普通配置、日志和审计；
- Windows 与 Linux 路径如何在不改变工具参数语义的情况下执行。

本文件不是数据库表设计、REST API、Agent 通信协议或凭据存储实现，也不开放首条切片以外的导出能力。后续模块可以复用本契约的模型，但不得假定本轮已经确认普通导入或旁路导入的实际命令行为。

## 2. 权威输入与优先级

发生冲突时按以下顺序处理：

1. 安全阻断与受控实测证据；
2. OBDUMPER 4.3.5 官方能力边界及项目发布包的版本化参数映射；
3. 在官方能力边界内已经确认的产品范围、字段状态和互斥规则；
4. 本契约的实现约束。

任何层级出现“待官方参数映射确认”、官网冲突、仅本地 help 可见或实测不通过时，参数可以保留在元数据基线中，但不得因此成为可提交参数。工具 `--help` 中出现名称不等于产品已支持该能力。

## 3. 核心术语

| 术语 | 定义 |
|---|---|
| 参数定义 | 某个官方参数在特定工具版本下的名称、类型、适用条件、风险和生成方式，不包含任务值 |
| 参数元数据版本 | 一组不可变参数定义的版本标识；发布后不得原地改写 |
| 草稿配置 | 用户编辑中的结构化产品字段，可包含尚未活动或尚未通过校验的值 |
| 派生事实 | 数据源、执行节点、工具身份或环境产生且用户不能在任务中自由编辑的值 |
| 规范化配置 | 草稿配置与派生事实经过类型转换、活动计算和校验后形成的唯一结构化结果 |
| 提交快照 | 提交瞬间冻结的规范化配置、版本、来源和风险确认；之后不可被外部数据回写 |
| 计划参数 | 控制面根据提交快照生成的、尚未解析秘密值的有序参数令牌 |
| 实际执行参数 | Agent 核验快照并在本地解析秘密引用后交给目标进程的参数令牌 |
| 显示命令 | 由有序令牌渲染出的只读命令文本，仅用于查看或复制，不作为进程执行输入 |

## 4. 字段值状态

每个任务字段在一次规范化中必须且只能落入一种状态：

| 状态 | 含义 | 是否进入快照 | 是否进入命令 |
|---|---|---:|---:|
| `UNSET` | 用户未显式设置，沿用官方默认行为 | 记录“未设置”及默认依据版本 | 否 |
| `EXPLICIT` | 用户显式选择或填写，且字段当前活动 | 是 | 按映射生成 |
| `DERIVED` | 由数据源、节点或安全配置派生，当前活动 | 是，记录非敏感值或来源引用 | 按映射生成 |
| `INACTIVE` | 因格式、模式或条件不成立而不活动 | 只保留草稿命名空间，不进入提交快照 | 否 |
| `BLOCKED` | 缺少证据、值非法、依赖不满足或存在未解决冲突 | 记录阻断原因，不得形成提交快照 | 否 |

官方默认值只用于解释“工具未收到该参数时会怎样”，不得替用户补成 `EXPLICIT`。布尔参数只有在用户显式启用或派生规则要求启用时才生成；显式关闭等同于不生成该开关，除非官方存在独立的反向参数。

## 5. 参数元数据最小模型

本节定义逻辑字段，不预先决定 SQLite 表结构。每条参数定义至少包含：

| 字段 | 用途 |
|---|---|
| `definitionId` | 稳定的内部定义标识，不使用展示名称作主键 |
| `tool` / `toolVersion` | 目标工具及精确版本，本切片固定为 OBDUMPER `4.3.5-RELEASE` |
| `metadataVersion` | 参数集合版本；已发布版本不可变 |
| `productFieldId` | 对应 EX-F 字段，保证追踪到产品规则 |
| `longName` | 规范长参数名，例如 `--file-path`；新任务不生成废弃别名 |
| `category` / `order` | 规范分类与分类内顺序，用于稳定生成 |
| `valueType` | `flag`、`string`、`integer`、`enum`、`path`、`secret-slot` 等 |
| `cardinality` | 单值、列表或可重复；不允许实现层自行猜测拼接方式 |
| `activation` | 活动条件，使用受限、可验证的声明式规则 |
| `requiredWhen` | 条件必填规则 |
| `conflictsWith` / `dependsOn` | 互斥与依赖定义 |
| `sourcePolicy` | `USER`、`DATA_SOURCE`、`NODE`、`SECURITY` 或固定格式选择 |
| `supportState` | `ENABLED`、`VALIDATION_GATED`、`HIDDEN`、`LEGACY_READ_ONLY`、`BLOCKED` |
| `sensitivity` | 普通、标识敏感或秘密；决定快照与显示策略 |
| `riskLevel` / `confirmationRule` | 风险级别及需要的确认规则 |
| `officialEvidence` | 官方来源和待实测项，避免元数据脱离依据 |

约束如下：

- 活动、必填、互斥和依赖规则不得使用可执行脚本或任意表达式；
- 在线管理界面不得任意新增官方参数、修改命令名或解除阻断；
- 同一工具版本的新规则必须发布为新元数据版本，历史任务继续引用旧版本；
- 未知字段、重复参数名、循环依赖、无稳定顺序或无产品字段来源的元数据版本不得发布；
- `secret-slot` 只允许引用凭据，不允许默认值、普通字符串回填或日志输出。

## 6. 首条切片可提交参数集合

首条切片只开放能完成“私有 ODP、单表、CSV 数据导出”的最小集合。其余 4.3.5 导出参数仍保留在完整产品参数基线中，但本切片必须隐藏或阻断。

| 顺序 | 参数 | 值来源 | 切片规则 |
|---:|---|---|---|
| 10 | `--host` | 数据源快照 | 必填；单一私有 ODP 地址；由 G3 证明 SQL 端口与连接表达 |
| 20 | `--port` | 数据源快照 | 必填；单一 SQL 端口 |
| 30 | `--user` | 数据源快照派生 | 必填；按已验证连接表达生成，快照和普通日志按标识敏感信息处理 |
| 40 | 数据库密码（逻辑输入） | 凭据引用 | 平台 V1.0 必填；不生成 `--password`，只生成指向官方安全文件属性的秘密槽位 |
| 50 | `--database` | 任务显式值 | 必填；可由数据源默认值回填，但提交时冻结为任务值 |
| 60 | `--table` | 任务显式值 | 必填；本切片只允许一个已预检查的明确表名，不允许 `*`、列表或任意表达式 |
| 70 | `--csv` | 格式选择 | 必填固定开关；本切片不接受其他格式 |
| 80 | `--file-path` | 任务显式值 | 必填；执行节点上的完整绝对路径，按平台规则原样传入 |

### 6.1 PC-R04 兼容修订

PC-R04 确认的八项是首条切片的**逻辑输入集合**，不是八个实际命令行参数。后续已经确认的 CS-R12、TL-R08 以及 Windows `secure-gen` 兼容性证据要求采用更严格的安全边界：

- 逻辑输入仍为 host、port、user、password、database、table、csv、file-path，共八项；
- 实际 `argvTemplate` 只包含 host、port、user、database、table、csv、file-path，共七项；
- password 只保存版本化凭据引用，生成到 `secretSlots`，目标属性固定为 `oceanbase.jdbc.password`；
- `argvTemplate`、环境变量和显示命令均不得出现 `--password` 或密码原值；
- 参数元数据 `obdumper-4.3.5-slice-v1` 保持不可变，`v2` 以校验和固定 `v1` 并只覆盖密码发射目标；现行 `v3` 同样固定 `v1`，保留该密码覆盖并将能力版本切换为私有 ODP。

该修订不代表 VS-P0-09 整体通过。Linux 安全文件、并发隔离、异常清理和正式 Agent 注入仍由后续组件及 G3/G4 门禁验证。

### 6.2 有条件登记但暂不默认开放

以下 CSV 参数在 4.3.5 映射中已有官方含义，但 VS-P0-05 特殊值夹具尚未全部通过：

- `--skip-header`
- `--column-separator`
- `--column-quote`
- `--column-quote-mode`
- `--escape-character`
- `--line-separator`
- `--null-string`
- `--file-encoding`

它们应以 `VALIDATION_GATED` 进入元数据。对应受控实测通过前，用户显式设置这些字段必须得到 `BLOCKED`，而不是忽略用户输入或用官方默认值生成参数。未设置时不生成，继续使用官方默认行为。

### 6.3 本切片明确不生成

- 云 ODP、ODP Sharding 与云环境参数：`--public-cloud`、`--logical-database`；
- sys 与会话参数：`--no-sys`、`--sys-user`、`--sys-password`、`--session-config`、`--character-set`；
- 输出覆盖能力：`--skip-check-dir`；非空输出目录由预检查阻断；
- DDL、其他格式、对象存储、筛选、一致性、性能、压缩、检查点与所有专家参数；
- 废弃、导入侧、help-only 或官网含义不足的参数。

若实际数据源事实不是私有 ODP，控制面必须返回“连接范围不符合首条切片”阻断。`--cluster` 是否需要及其确切映射仍为“待官方参数映射确认”，不得静默增加或修改连接类型来绕过范围门禁。

## 7. 规范化与校验顺序

命令生成前必须完成以下固定步骤：

```text
读取指定元数据版本
→ 校验工具版本和切片能力标识
→ 合并草稿字段与版本化派生事实
→ 完成类型规范化
→ 计算活动状态
→ 校验必填、互斥、依赖和支持状态
→ 完成对象、连接、节点与输出目录预检查
→ 形成不可变规范化配置
→ 按稳定顺序生成计划参数
→ 生成指纹、脱敏预览和阻断/警告结果
```

规则计算必须由服务端执行。前端可以使用同一份只读元数据改善交互，但前端状态不是可信输入。提交时服务端必须重新读取已锁定的派生事实并再次规范化；草稿预览结果不能直接升级为提交快照。

存在任一错误或阻断时，不得生成“可提交”结果。警告仅用于不影响正确性且产品规则允许继续的情况，不能把未知参数、敏感值泄露或范围偏差降级为警告。

## 8. 确定性生成

### 8.1 唯一执行来源

生成器输入只允许是：

- 精确工具版本；
- 精确参数元数据版本；
- 规范化活动配置；
- 版本化的数据源、节点和安全引用事实；
- 已通过且未失效的风险确认事实。

生成器不得读取当前时间、随机数、进程环境变量、工作目录、数据库最新值或未记录的全局配置。运行时必须变化的任务标识、租约等不属于 OBDUMPER 业务参数，不得混入参数确定性判定。

### 8.2 稳定顺序

完整产品的参数顺序固定为：

```text
程序与连接
→ 数据库与连接环境
→ 对象范围
→ 内容与格式
→ 格式序列化
→ DDL / 筛选 / 一致性
→ 输出与文件
→ 性能与资源
```

分类内使用元数据的显式 `order`，不得依赖 map、JSON 对象或数据库查询的自然顺序。同一参数只允许生成一次。多值参数必须由该参数定义指定“重复令牌”或“单值编码”方式；没有规则时阻断，不自行使用逗号或空格拼接。

### 8.3 生成产物

一次成功生成至少返回：

- `argvTemplate`：只包含可安全进入进程参数的有序令牌；本切片不含密码参数或密码槽位；
- `redactedCommand`：默认页面与复制使用的脱敏显示文本；
- `secretSlots`：秘密槽位到凭据引用、发射目标及版本的映射，不含原值；本切片的密码槽位指向官方安全文件属性；
- `configFingerprint`：规范化输入的 SHA-256 指纹；
- `metadataVersion` 与 `toolVersion`；
- 每个令牌对应的产品字段、参数定义和值来源；
- 警告、风险确认和预检查证据引用。

进程启动必须使用令牌数组，不得把显示命令重新解析成令牌，也不得接受用户粘贴的任意命令片段。

### 8.4 指纹规则

指纹输入使用 UTF-8 规范 JSON，字段顺序由契约固定，map 键按字典序，列表保持有业务含义的顺序。至少包含：

- 工具名与精确版本；
- 参数元数据版本；
- 切片能力版本；
- 规范化活动字段及值来源；
- 会影响命令的非敏感数据源与节点事实版本；
- 凭据引用标识与修订号，但不包含秘密原值；
- 有效风险确认的规则与版本。

显示格式、创建时间、数据库自增 ID、日志位置和秘密原值不参与指纹。同一指纹必须生成逐令牌完全一致的 `argvTemplate`；字符串显示因 Windows/Linux 转义不同可以不同，但不能改变令牌值。

## 9. 跨平台路径与显示

### 9.1 规范参数令牌

路径在参数列表中是一个完整令牌。路径校验与路径转换分离：平台验证绝对性、允许根目录、可创建/可写、目录穿越、剩余空间和非空状态，但不为“兼容”而改变已经确认的工具参数格式。

- Windows：使用任务快照中的完整盘符绝对路径，例如 `E:\workespace\ob-data-orch\tmp\p0-validation\run-06\output-test`；不拆分工作目录、不改为 URI、不自动追加任务子目录；
- Linux：使用 `/` 开头的执行节点绝对路径；不使用 Windows 路径映射，也不把控制面路径当作 Agent 路径；
- 路径属于执行节点事实；控制面所在机器能访问该路径不构成可用证据。

### 9.2 显示与进程启动分离

显示渲染器根据目标平台对空格、引号和特殊字符作可读转义；该文本只用于人读和复制。Agent 的进程适配器直接接收有序令牌，并针对 Windows `.bat` 包装器或 Linux 启动脚本单独处理进程边界。

早期验证已发现 Windows `obdumper.bat` 的外层退出码可能掩盖内部失败。因此显示文本正确不代表启动适配正确；进程、退出状态和日志终态由后续 Agent 契约定义。

## 10. 凭据与脱敏边界

### 10.1 控制面

- 草稿、规范化配置、任务快照、指纹和普通审计不得保存密码原值；
- 密码只在规范化配置中表现为不可与普通文本混淆的类型化秘密引用，不进入 `argvTemplate`；
- 页面、复制、日志和审计默认只输出统一掩码，不输出可逆编码；
- 完整组合用户名按“标识敏感”规则处理：任务详情可按权限展示必要摘要，普通日志和跨任务搜索不默认暴露全值。

### 10.2 Agent

Agent 只能在拥有有效任务租约、快照指纹和节点授权时解析秘密引用。解析结果只存在于最短必要运行生命周期中，不回传控制面、不拼入普通日志，也不得进入 argv 或环境变量。Windows 兼容性验证已确认 OBDUMPER 4.3.5 可从 execution 私有安全文件的 `oceanbase.jdbc.password` 属性取得密码，因此正式链路不得回退到 `--password`。

安全文件只是受控秘密载体，不是普通任务文件。其 Linux 行为、并发隔离、异常清理和正式 Agent 注入仍需 VS-P0-09 后续实测；在证明完整链路前：

- 不开放明文命令查看或复制；
- 不把当前自动化中“密码作为命令参数”的方式当作正式方案，也不提供回退开关；
- VS-P0-09 与业务实现准入保持阻断。

当前实现只锁定“秘密引用 → 官方安全文件属性”的生成边界，不创建安全文件、不解析真实凭据，也不启动 OBDUMPER。

## 11. 计划命令、实际命令与差异

提交快照生成的是计划参数模板。参数规则只由控制面的版本化生成器解释，Agent 不复制产品活动、互斥和命令排序规则，也不重新生成业务参数。Agent 执行前必须核验：

- 工具身份和版本与快照一致；
- 任务信封结构、不可变模板摘要和控制面授权有效；
- 元数据/能力版本是信封中已声明且可审计的版本；
- 节点路径与环境预检查仍有效；
- 凭据引用可按授权解析；
- 收到的模板摘要与任务信封一致，参数令牌中不存在未知槽位或任意命令片段。

实际执行记录保存脱敏后的真实程序、参数顺序、进程适配器版本、工具版本和启动事实。计划与实际若在非秘密令牌、顺序、工具版本或路径上存在差异，必须拒绝启动并记录差异，不允许 Agent 自行修正后继续。数据源类型、对象和产品参数条件已经在控制面提交事务中冻结；Agent 只核验执行时事实，不承担第二套业务校验器职责。

秘密槽位解析为 execution 私有安全文件不视为计划差异，但安全属性名、凭据修订号、解析结果或槽位数量与信封不一致均为阻断。密码不得被追加到实际 argv 或环境变量。历史任务展示必须区分计划命令与实际命令，不能用后来重新生成的命令覆盖历史证据。

## 12. 必须阻断的情况

以下任一情况不得提交或启动：

- 工具版本、元数据版本或切片能力版本未知、不匹配或已撤销；
- 元数据包含未知参数、重复参数、循环条件或无稳定顺序；
- 草稿提交未知字段、重复字段、错误类型或原始秘密值；
- 必填项缺失，互斥/依赖不满足，或非活动字段试图进入提交快照；
- `VALIDATION_GATED` 参数被显式设置但证据未通过；
- 数据源不是私有 ODP，或为云 ODP、ODP Sharding、逻辑库、Oracle 模式，或无法证明其连接表达属于本切片；
- 表不存在、无权访问、不是单一明确表名或对象预检查已失效；
- 输出路径不是目标节点绝对路径、越过允许根目录、不可写、空间不足或目录非空；
- 用户要求自动改写路径、自动追加目录或隐式启用 `--skip-check-dir`；
- 命令中出现任意片段、shell 运算符、未声明环境变量替换或未绑定秘密槽位；
- 计划模板、任务信封摘要和 Agent 收到的令牌不一致；
- 凭据无法安全解析，或脱敏策略不能覆盖页面、复制、日志、审计与错误信息。

## 13. 最小契约测试

### 13.1 VS-P0-08：确定性

至少覆盖：

1. 相同输入重复 100 次，`argvTemplate` 和指纹逐字节一致；
2. 输入 JSON 字段顺序不同，规范化结果一致；
3. 未设置的 CSV 默认参数不进入命令；
4. 非活动字段即使草稿中有旧值也不进入快照和命令；
5. 元数据版本、工具版本或有效活动值变化会改变指纹；
6. 只改变显示平台时令牌值不变，显示转义可变；
7. Windows 完整盘符路径令牌保持原值；
8. 未知参数、重复参数、非私有 ODP 数据源和非空目录均阻断；
9. 页面预览与提交重算使用同一规范化夹具得到一致模板；Agent 对同一任务信封校验出相同摘要且不改变令牌；
10. 新元数据版本不改变旧任务的历史计划命令。

当前 `internal/commandgen` 已用纯合成数据覆盖第 1～5、7～9 项中属于生成器的边界，并验证 Windows AMD64、Linux AMD64、Linux ARM64 的绝对路径语法。非空目录属于 Agent 预检查，Agent 信封核验和旧任务持久化属于后续组件，因此 VS-P0-08 只记为“生成器子集通过”，不提前宣称全链路通过。

### 13.2 VS-P0-09：秘密与脱敏

至少使用不会出现在代码库中的一次性测试秘密覆盖：

1. 草稿、快照、SQLite、指纹、页面响应、复制文本、审计和普通日志搜索不到原值；
2. 生成器只产生类型化秘密槽位，槽位缺失或多余时阻断；
3. 控制面无法通过普通命令预览接口取得原值；
4. Agent 只在有效租约内解析，并在执行后清理内存与临时载体；
5. 启动失败、超时、工具非零退出和 Agent 中断不会把秘密写入错误信息；
6. Windows 进程与包装脚本、Linux 进程可见性均完成受控检查；
7. 完整组合用户名按标识敏感规则覆盖日志和搜索入口。

任一敏感原值在不允许的位置出现，VS-P0-09 直接失败，不接受“概率很低”或“用户通常看不到”作为通过理由。
