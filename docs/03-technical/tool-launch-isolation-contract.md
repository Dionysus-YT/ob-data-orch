# OBDUMPER 跨平台隔离启动入口契约

> 文档状态：首条纵向切片启动基线，TL-R01～TL-R18 已确认
> 适用范围：OBDUMPER 4.3.5、Windows AMD64、Linux AMD64/ARM64
> 关联契约：PC-R01～PC-R15、AS-R01～AS-R16、CS-R01～CS-R18
> 更新日期：2026-07-21

## 1. 要解决的最小问题

首条切片只需要可靠启动并监管一个“私有 ODP、单表、CSV、本地绝对路径”的 OBDUMPER 进程。启动入口必须同时做到：

1. 密码通过 execution 私有的官方兼容安全文件提供，不进入 argv；
2. 不修改发布包共享配置，不让两个任务串用密码、日志或临时文件；
3. Windows/Linux 都使用结构化参数，不经过 cmd/Bash 二次解释；
4. Agent 直接取得真实 Java 进程、退出码和恢复身份；
5. 保留 4.3.5 官方脚本中的必要 JVM、系统属性和本地库设置；
6. 用户填写的输出绝对路径原样传给工具。

本契约不实现任务取消、并行执行器、容器隔离、远程 Shell、通用 Java 启动器、动态插件或用户自定义 JVM 参数。

## 2. 第一性原理结论

真正需要运行的是包内 Java 主类和 JAR，不是 `.bat` 或 Bash 本身。官方脚本提供的是以下启动知识：

- 如何找到 Java；
- 如何形成类路径；
- 对应版本的 JVM 选项；
- 工具所需系统属性；
- 最终主类和业务参数。

当前脚本本身却不能同时满足隔离与终态要求：

- Windows 脚本允许外部注入安全配置，但会掩盖 Java 失败退出码；
- Linux 脚本保留 Java 退出码，但把安全配置和日志固定到共享目录；
- 两者都会增加一层 shell 参数解释和父子进程关系；
- 修改发布包脚本会造成校验摘要漂移和升级差异。

因此建议把“与精确 4.3.5 包绑定的直接 Java 启动配置”作为 Agent 唯一生产入口。官方脚本继续作为配置核对证据和人工诊断入口，不作为平台任务执行入口。

这不是自行实现 OBDUMPER 能力。平台仍运行官方 JAR、官方主类和官方参数，只把脚本中的确定启动知识转成可校验的结构化配置。

## 3. 候选方案比较

| 方案 | 任务隔离 | 真实退出码/进程 | 跨平台一致性 | 发布包完整性 | 结论 |
|---|---|---|---|---|---|
| 外层包装官方脚本 | Windows 可注入，Linux 仍共享 | Windows 不可靠 | 低 | 保持 | 不选 |
| 每任务复制/链接一套工具目录 | 可实现 | 仍有脚本层 | 中，链接语义不同 | 容易形成漂移 | 不选 |
| 修改官方脚本 | 可实现 | 可修正 | 需维护两套补丁 | 破坏原始摘要 | 禁止 |
| Agent 直接启动 Java 主类 | 可实现 | 直接 Java PID/退出码 | 统一进程模型、保留平台配置 | 共享包只读 | 建议选择 |

## 4. 启动配置不是用户参数

每个受支持组合使用只读、版本化启动配置：

```text
tool = obdumper
toolVersion = 4.3.5-RELEASE
os = windows | linux
arch = amd64 | arm64
profileVersion = 内部版本
```

启动配置至少包含：

- 发布包身份和关键文件摘要；
- Java 版本规则和可执行文件解析规则；
- 主类；
- 类路径策略；
- 固定 JVM 选项；
- 固定及任务派生系统属性；
- 环境变量允许列表；
- 工作目录、临时目录、日志目录和安全配置目标；
- 目标平台进程身份采集规则；
- 配置自身摘要。

它属于随 Agent 版本发布的受控元数据，不存为普通数据库可编辑记录，也不允许用户、任务 API 或前端覆盖。工具包摘要、Java 事实或启动配置不匹配时，节点能力不可用，不回退到“试着运行”。

## 5. 发布包与 Java 门禁

### 5.1 发布包

- 工具根目录必须是注册并验证过的绝对路径；
- 发布包目录、`lib/`、`conf/` 和启动脚本对 Agent 服务账户只读；
- 至少核对主 JAR、平台启动脚本及启动配置记录的关键文件摘要；
- 禁止从 execution 目录、当前目录或系统 `CLASSPATH` 加载额外 JAR；
- 禁止跟随指向允许工具根目录之外的类路径或配置链接；具体链接判定按目标文件系统验证。

### 5.2 Java

- 使用节点注册时验证过的 Java 绝对路径，不通过 `PATH` 临时搜索；
- 首条切片限定已验证 Java 8 补丁版本；版本变化使节点能力进入“待复验”；
- 启动前核对文件身份、版本输出和架构与节点声明一致；
- 不允许任务选择另一套 Java，也不接受 `JAVA_EXE`、用户 JVM 参数或任意主类。

## 6. execution 私有目录

每次执行建立独立目录，示意如下：

```text
executions/<executionId>/
├── security/
│   ├── key.pem
│   ├── secure.rsa
│   └── security.properties
├── runtime/
│   ├── tmp/
│   └── work/
├── tool-raw-log/
└── evidence/
```

- `security/`、`runtime/` 和 `tool-raw-log/` 先创建并验证权限，再写任何内容；
- Windows 关闭普通继承权限，只允许 Agent 服务账户、SYSTEM 和明确管理员；
- Linux 父目录 `0700`，秘密文件 `0600`，所有者为 Agent 专用账户；
- `evidence/` 只保存无秘密的进程身份、摘要、事件游标和清理状态；
- 工具发布包不复制到 execution 目录；
- 用户输出目录不放进该树，也不被平台改写。Windows 继续原样使用完整盘符路径，Linux 原样使用 `/` 绝对路径；
- executionId 必须由控制面签发并按安全文件名规则编码，不接受用户路径片段。

## 7. 结构化启动计划

Agent 只接收并执行结构化令牌：

```text
javaExecutable
jvmArgs[]
systemProperties[]
classpath
mainClass
businessArgs[]
workingDirectory
environment
```

禁止把这些内容拼成 shell 字符串后交给 `cmd /c`、PowerShell、Bash、`eval` 或 `/bin/sh -c`。完整命令页面继续显示已确认的逻辑 OBDUMPER 命令；内部 Java 启动计划只提供脱敏诊断摘要，不把安全配置路径、原始环境或 JVM 内部细节当作用户可复制命令。

### 7.1 固定边界

- `javaExecutable`、`mainClass`、类路径和固定 JVM 选项只来自启动配置；
- `businessArgs[]` 只来自已确认的参数生成器；
- `security.configurationFile`、日志、TEMP/TMP 和工作目录只来自当前 execution；
- 同名系统属性只能出现一次；未知属性、重复属性或用户 JVM 输入直接拒绝；
- `--password`、`--sys-password` 及密码原值不得出现在业务参数、JVM 参数或环境中；
- 安全材料路径不得包含用户名、密码、数据库名或用户输入文本。

## 8. Windows 与 Linux 启动配置

### 8.1 共同部分

首条切片保留 4.3.5 脚本已经使用的共同规则：

- 默认 `-Xms4G -Xmx4G`；
- Java 8u300 及以上使用 G1，以下使用 CMS；
- 线程栈、Metaspace、无类卸载、暂停目标及 UTF-8 stdout/stderr 设置；
- `picocli.usage.width`、并行写、上传缓冲、SQL monitor、表定义相关的固定系统属性；
- `tool.base.dir` 指向只读发布包；
- `session.configurationFile` 和 log4j 配置指向发布包只读配置；
- `security.configurationFile` 和 `log4j.output` 改为 execution 私有路径；
- 主类固定为 `com.oceanbase.tools.loaddump.cmd.Obdumper`。

启动配置必须逐项记录它与对应官方脚本的相同、覆盖和省略项。工具升级时先生成差异报告，再决定是否发布新配置，不能沿用旧配置猜测兼容。

### 8.2 Windows 专属

- 类路径使用发布包 `lib/*` 的受控绝对路径，不读取继承 `CLASSPATH`；
- 保留包内 Windows Hadoop 目录属性；
- 对 obproxy、decrypt 等 Windows 脚本已有属性保持原样，除非专项验证证明可以删除；
- 业务参数通过 Windows 进程 API 的结构化参数边界传递，不经过 `.bat`；
- 直接监管 Java 进程，因此不再把 `.bat=0` 作为执行事实。

### 8.3 Linux 专属

- 类路径按 Linux 官方脚本规则对发布包 JAR 排序，并包含只读 `conf/`；
- 保留 Linux 脚本专属的已发现系统属性，不擅自与 Windows 合并；
- 不使用共享 `<tool>/conf/security.properties`，由任务属性指向 execution 私有配置；
- Java 进程不经过 Bash/`eval`；
- Linux AMD64 和 ARM64 可以共用逻辑配置，但必须分别保存实机验证结果，不能以交叉编译替代。

## 9. 内存、GC 与堆转储

首条切片不开放 `--mem`，使用官方脚本默认 4G 堆。Agent 预检查必须验证节点可用内存满足堆和本地开销要求，不满足则节点不可执行，而不是自动缩小内存改变工具行为。

后续开放 `--mem` 时，由同一规范化字段同时派生 JVM 堆和 OBDUMPER 业务令牌；不能出现页面值、JVM 值和命令值不一致。

官方脚本默认开启 OOM 堆转储，但堆转储可能包含数据库密码和业务数据。建议 V1.0 生产任务默认关闭自动堆转储，不把它写到共享工具目录；未来如开放受控诊断，必须单独授权、写入 execution 私有安全目录、禁止普通下载，并按秘密材料清理。这是一项明确的安全覆盖，不伪装成与官方脚本完全相同。

## 10. 子进程环境

Agent 从空环境或最小基础环境开始构造子进程环境，不复制完整服务环境。

必须移除：

```text
JAVA_OPTS
JAVA_TOOL_OPTIONS
JDK_JAVA_OPTIONS
_JAVA_OPTIONS
CLASSPATH
LD_PRELOAD
```

按平台允许的内容至少包括：

- Windows：`SystemRoot`、`WINDIR`、execution 私有 TEMP/TMP、受控 Java/系统路径及经验证的本地库所需项；
- Linux：execution 私有 `TMPDIR`、必要 locale、受控 Java/本地库路径及目标系统验证后的最小项；
- 两端均不得在环境中放数据源密码、机器凭据、根密钥或任意用户 JVM 选项。

环境键和值只记录允许列表版本和摘要。普通日志不输出完整环境快照。

## 11. 日志与崩溃材料

- stdout/stderr 使用管道读取，先按已知秘密槽位和结构规则脱敏，再进入本地待发送队列；
- 不把未处理 stdout/stderr 重定向到普通日志文件；
- OBDUMPER 自身通过 log4j 写文件的行为无法由管道替代，因此只允许写入 execution 私有 `tool-raw-log/`；
- `tool-raw-log/` 是受限的短时工具材料，不是产品日志，不进入普通查询、下载或备份；
- Agent 从中读取增量内容，完成第一层脱敏后生成产品日志分段；
- 原始文件可能含组合用户名或其他受限信息，终态取证完成后按安全材料规则删除；删除失败进入清理告警和目录隔离；
- 密码理论上不应进入工具日志，但每个目标平台仍必须以合成秘密执行全目录扫描；发现原值立即判安全失败；
- JVM 崩溃文件、错误日志或未来受控堆转储与 `tool-raw-log/` 使用相同或更严格的边界。

这不是允许“普通原始日志先落盘”。它承认官方工具会自行写文件，并把该目录收缩为服务账户私有、短时、不可下载的执行安全材料。该解释需要作为本专项评审项明确确认。

## 12. 启动顺序

```text
核对租约、信封、参数与节点能力
→ 核对工具包、Java 和启动配置摘要
→ 校验输出目录但不改写路径
→ 创建并验证 execution 私有目录权限
→ 解析秘密槽位
→ 内存生成并写入官方兼容安全材料
→ 形成结构化 Java 启动计划并检查无重复/未知输入
→ 持久化不含秘密的启动意图和计划摘要
→ 创建直接 Java 子进程
→ 取得 PID、开始时间、可执行文件和首次存活事实
→ 上报 PROCESS_STARTED
→ 监管 stdout/stderr、工具原生日志、进程和结果事实
```

日志记录重组、双层脱敏、分段和缺口的实现边界见[日志采集、双层脱敏与执行证据最小契约](log-collection-evidence-contract.md)；LG-R01～LG-R20 已确认。

进程创建失败时必须确认没有 Java 进程再上报 `START_REJECTED`。不能因为秘密已经解析就重建另一套 execution 或自动改走官方脚本。

## 13. 进程身份、退出和恢复

### 13.1 运行期间

- Java 是 Agent 的直接子进程；
- Windows 至少记录 PID、进程创建时间、Java 文件身份和进程句柄事实；
- Linux 至少记录 PID、`/proc` 启动时间、可执行文件身份和进程组事实；
- 不仅记录 PID，防止 PID 复用；
- `Wait` 返回的直接 Java 退出码是强证据，但仍与工具终态和结果事实交叉核对；
- 终态继续严格使用 AS-R01～AS-R16 的证据矩阵，不因入口改变而简化。

### 13.2 Agent 崩溃或重启

- 首条切片不配置“父进程退出就杀 Java”的行为；Agent 崩溃不能被包装成用户取消；
- Agent 重启后按 PID、开始时间、可执行文件和原计划摘要核对，不重新启动；
- Linux 不设置使父进程死亡即终止子进程的策略；Windows 不依赖 `KILL_ON_JOB_CLOSE` 形成隐式终止；
- 能证明原 Java 仍运行时继续监管；能证明结束时依靠持久工具终态、日志和结果；无法证明则保持“状态核对中”；
- 原 execution 未解除前不领取新任务。

首条切片不实现任务取消。进程组、Windows Job Object 和完整进程树终止在取消专项中确认，本轮只要求它们不能破坏已确认的恢复语义。

## 14. 清理与失败关闭

清理只在进程已结束、必要终态/结果证据已安全持久化且不会继续读取材料后开始：

1. 关闭日志读取和文件句柄；
2. 删除私钥、密文和安全配置；
3. 删除/隔离工具原始日志、崩溃材料和临时文件；
4. 记录每类材料的清理结果；
5. 删除空的 execution 工作目录。

任一步骤失败时：

- 不把目录重新分配给其他 execution；
- 记录不含敏感路径细节的安全告警；
- 节点进入“存在安全残留”事实；
- 残留超过策略阈值或权限异常时阻断新任务；
- 不通过先生成新目录来掩盖旧残留。

## 15. 启动计划摘要

任务和事件只保存不可逆、无秘密摘要：

- 工具包和启动配置版本/摘要；
- Java 文件身份和版本摘要；
- mainClass 固定标识；
- 规范化业务参数摘要；
- 安全配置目标类型，不保存具体秘密路径；
- 环境允许列表版本；
- 工作目录和日志目录的 execution 归属摘要；
- 实际 PID、开始时间和平台身份事实。

摘要用于恢复和审计，不用于重建密码或让控制面发送任意启动命令。

## 16. 最小验证矩阵

### 16.1 每个平台必须执行

1. `--version`、`--help` 与官方脚本结果一致；
2. 合成安全材料能读取，命令和进程列表没有 `--password`；
3. 错误配置、错误私钥、缺失 JAR、错误 Java 和权限不足均在正确阶段失败；
4. 单表 CSV 成功、连接失败、工具失败和结果异常取得一致终态；
5. 包含空格、中文和平台绝对路径的令牌不被改写；
6. 两个 execution 并发时安全配置、TEMP、日志和工作目录不串用；
7. Agent 网络中断、崩溃、重启后不重复启动且能恢复监管或进入核对中；
8. stdout、stderr、工具日志、JVM 错误、进程参数和环境搜索不到合成密码；
9. 正常、失败、崩溃和清理失败四类路径的残留策略符合契约；
10. 共享发布包摘要执行前后不变。

### 16.2 当前状态

- Windows AMD64：直接 Java 负例、任务安全配置、含空格路径、最小环境、直接父子进程和退出码已通过，详见[验证记录](evidence/direct-java-launch-spike-2026-07-21.md)；
- Windows 成功导出、并发、崩溃恢复和清理：待验证；
- 麒麟 V10 SP3 C86、V10 SP1 ARM64、V11 ARM64：全部运行项待验证；
- 因此本契约确认后仍不能直接判定开发门禁全部通过。

## 17. 明确禁止

- 修改或覆盖共享 `conf/security.properties`；
- 为每个任务修改官方 `.bat`/Shell；
- 通过 shell 字符串启动 Java；
- 接收用户 JVM 参数、mainClass、classpath、环境变量或 Java 路径；
- 从当前目录或系统 CLASSPATH 加载未知 JAR；
- 在 argv、环境、工作目录名、日志目录名或配置路径中放密码；
- 把私钥、密文、原始工具日志或崩溃材料作为普通任务附件；
- 只看 Java 退出码或一条日志决定成功；
- Agent 重启后自动重跑未知状态 execution；
- 用 Windows 一次负例或 Linux 交叉编译声称三个国产系统通过。

## 18. 对现有契约的影响

- 与 TS 5.4 的“经验证等价受控入口”一致，不改变 Go + Java 工具的技术路线；
- 简化 AS-R11：正式入口确认后 Java 就是直接受控进程，但 AS 终态和恢复规则保持不变；
- 落实 CS-R11～CS-R13 的任务级安全材料、无密码 argv 和双层脱敏；
- PC-R04 暂不修改，直至 Linux、安全清理和全链路门禁通过；
- 产品展示的完整命令仍是 OBDUMPER 逻辑命令，不变成内部 Java/JVM 调试命令。
