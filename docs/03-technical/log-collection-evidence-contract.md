# 日志采集、双层脱敏与执行证据最小契约

> 文档状态：首条纵向切片专项契约已确认，LG-R01～LG-R20 已确认
> 适用范围：首条单表 CSV 导出、任务详情执行日志、日志中心任务预设
> 关联基线：TD-008、TS-R14、AS-R01～AS-R16、CS-R13、TL-R13
> 更新日期：2026-08-04

## 1. 目标与边界

本契约定义：日志从哪里产生、如何在 Agent 端重组和脱敏、如何可靠上传、如何在控制面再次脱敏并分段保存、如何证明缺口，以及哪些日志可以成为任务终态证据。

首条切片只实现完成单任务排障和终态核对所需的最小闭环：

```text
真实来源
→ 来源独立重组
→ Agent 第一层脱敏
→ 本地可靠队列
→ 带序号/摘要上传
→ 控制面第二层脱敏
→ 脱敏日志段 + SQLite 索引
→ 任务详情查询/持续加载/下载
→ 终态证据引用
```

本轮不建设 Elasticsearch/OpenSearch、全文索引集群、日志分析大屏、正则查询语言、告警、AI 诊断、链路追踪、外部日志接入、异步下载中心或未脱敏日志入口。

### 1.1 已确认的任务日志可见边界

经人工确认，已通过任务对象范围校验的用户读取当前任务日志时，`message` 必须保留工具当前可观测的全部**非秘密**运行上下文，包括完整组合用户名、主机和端口、数据库/Schema/表、用户填写的输出或日志路径、非密码命令令牌、工具原始诊断和错误文本。双层脱敏的含义是遮蔽秘密，而不是删除这些排障所需的运行事实。

此确认不提供未脱敏原始日志入口，不允许读取 Agent 任意文件，也不扩大任务、节点、日志下载或 SSE 的对象授权范围。密码、令牌、访问密钥、私钥、密文、安全材料及其可恢复表示仍必须在上传前和持久化前遮蔽；无法可靠遮蔽时仍失败关闭。

## 2. 关键原则

1. **来源不能丢**：stdout、stderr、工具文件、Agent 事件、调度事件和审计事件始终分开。
2. **读取块不是记录**：先在内存中按来源重组安全记录边界，再脱敏和持久化。
3. **秘密原文不上控制面**：Agent 上传的第一字节就必须是完成秘密遮蔽的内容；已确认的非秘密运行上下文按第 1.1 节保留。
4. **第二层仍失败关闭**：控制面在任何文件/SQLite 写入前再次脱敏；无法应用策略时拒绝该批次。
5. **顺序只在来源内承诺**：跨来源按时间辅助展示，不推断因果。
6. **缺口是数据**：丢失、截断、超限、轮转遗漏和保留清理都必须显式表达。
7. **状态与日志分离**：日志可以提供证据，但日志延迟或缺失不直接改写任务状态。
8. **轻量存储**：脱敏正文写控制面本机分段文件，SQLite 只保存批次、段、时间、范围、完整性和摘要索引。

## 3. V1.0 来源模型

### 3.1 真实来源

| `sourceKind` | 产生位置 | 采集方式 | 首条切片 |
|---|---|---|---|
| `SCHEDULER_EVENT` | 控制面 | 结构化任务/调度事件投影 | 接入 |
| `AGENT_EVENT` | Agent/控制面协议 | 已确认执行事件的脱敏展示投影 | 接入 |
| `OBDUMPER_STDOUT` | Agent | Java stdout 管道 | 接入 |
| `OBDUMPER_STDERR` | Agent | Java stderr 管道 | 接入 |
| `OBDUMPER_FILE` | Agent | execution 私有工具日志目录受控跟踪 | 接入 |
| `AUDIT_EVENT` | 控制面 | 审计事件的有权展示投影 | 接入日志中心审计预设，不复制正文 |
| `OBLOADER_*` | Agent | 与 OBDUMPER 相同的未来来源模型 | 本切片不执行，预留枚举 |

查询预设只组合这些来源，不创建“任务日志”复制件。调度、Agent 和审计事件继续以 SQLite 中的结构化事实为权威来源；查询层把它们投影成统一显示记录，不再复制进日志段文件。

### 3.2 Agent 服务日志边界

V1.0 不把 Agent 自身任意服务日志文件整体上传。节点/Agent 预设优先使用已经登记的关联、心跳、环境检查、任务领取、启动、采集和恢复事件。只有后续明确登记且完成脱敏验证的 Agent 文件来源才能加入，不提供远程文件浏览。

### 3.3 工具文件允许范围

- 只跟踪当前 execution 私有 `tool-raw-log/` 下由启动配置登记的文件模式；
- 不跟踪发布包共享日志目录、用户输出目录或任意节点路径；
- 记录文件身份、打开时间、规范化路径摘要和读取偏移；
- 文件被替换、截断或轮转时创建新的 `sourceEpoch`，不把新文件续接成旧文件；
- 发现未知文件时按安全材料隔离，不自动上传；需要的新增来源必须先更新启动/采集配置并验证。

## 4. 原始材料与产品日志

| 数据 | 所在位置 | 是否可查询/下载 | 生命周期 |
|---|---|---|---|
| stdout/stderr 未脱敏字节 | Agent 内存管道缓冲 | 否 | 重组/脱敏后立即释放 |
| OBDUMPER 原生日志文件 | Agent execution 私有安全目录 | 否 | 终态取证和上传确认后清理 |
| Agent 脱敏待发送批次 | Agent 本地可靠队列 | 否普通用户；Agent 恢复使用 | 控制面确认后释放 |
| 控制面脱敏日志段 | 控制面本机日志存储 | 是，按权限 | 普通日志保留策略 |
| 调度/Agent/审计结构化事件 | SQLite | 是，按来源权限 | 对应任务/审计保留策略 |

控制面永远不接收工具原始文件、未脱敏管道块、私钥、密文或安全配置。所谓“完整任务日志”只指当前保留范围内所有有权、已脱敏、已采集来源的组合结果，并附带完整性状态，不代表提供节点原始文件。

## 5. 日志记录模型

每条可查询记录至少具有：

| 字段 | 规则 |
|---|---|
| `recordId` | 由来源流、epoch 和来源序号确定；不使用消息正文作为唯一身份 |
| `executionId` / `taskId` | 有可靠关联时保存；无关联不强填 |
| `nodeId` / `agentId` | Agent 来源保存受控标识 |
| `sourceKind` | 第 3 节登记的真实来源 |
| `streamId` | 当前 execution/节点下稳定来源实例，不含用户输入和路径原文 |
| `sourceEpoch` | 来源重开、文件替换/轮转后递增 |
| `sourceSeq` | 同一 streamId + epoch 内从 1 递增且不复用 |
| `sourceTimeRaw` | 来源提供的时间文本；脱敏后保留，无法可靠解析不丢弃 |
| `sourceTime` | 只有版本化解析器确认时保存 UTC 值 |
| `receivedAt` | 控制面首次接受批次的 UTC 时间 |
| `levelRaw` | 来源明确提供的级别原值；没有则为空 |
| `levelNormalized` | 只按版本化映射得到；否则 `UNMARKED` |
| `message` | UTF-8、纯文本、已完成双层脱敏的正文 |
| `recordKind` | `LOG`、`GAP`、`TRUNCATED` 或登记的结构化事件 |
| `redactionPolicyVersion` | 双层处理使用的策略版本 |
| `parserVersion` | 来源解析器版本 |
| `integrity` | 当前记录/来源是否完整及原因代码 |

本轮不为每条工具日志在 SQLite 建一行。上述记录保存在版本化段文件中；SQLite 只索引段、批次及范围。结构化事件仍保留在原有 SQLite 事实表，由查询层投影相同字段。

## 6. 字节流、记录和多行规则

### 6.1 stdout/stderr

- Java 管道每次 Read 的字节数没有业务意义；每个来源维护独立 UTF-8 重组缓冲；
- CRLF 和 LF 都视为物理行边界，CR 不进入消息；
- 无法解码的字节使用明确替代标记并设置解码异常，不静默按系统默认编码重试；
- stdout 不自动映射为 INFO，stderr 不自动映射为 ERROR；
- 只有 OBDUMPER 4.3.5 版本化解析器识别到来源明确前缀时，才提取时间和级别；解析失败保留纯文本和 `UNMARKED`。

### 6.2 工具文件多行记录

已有 P0 文件显示大量物理行没有时间/级别前缀。对已登记的 4.3.5 文件格式：

- 可识别时间/级别前缀开始一条逻辑记录；
- 后续无前缀行作为该来源上一记录的续行；
- 文件开头无前缀时形成独立 `UNMARKED` 记录，不并入其他来源；
- 解析器不能确认时宁可保留多个记录，也不跨来源或跨文件猜测合并；
- 多行正文保留换行，页面折叠只影响显示。

### 6.3 单记录安全上限

V1.0 单条重组记录上限为 256 KiB（按 UTF-8 字节）。超过上限时：

1. 不保存已累积原文；
2. 继续排空该来源直到下一个安全记录边界，避免阻塞工具；
3. 生成不含原文的 `TRUNCATED/GAP` 记录；
4. 将来源完整性标记为“不完整”；
5. 记录安全告警，但不据此擅自终止工具进程。

该规则避免无限内存和跨块秘密泄露。最小验证见[日志流重组与脱敏证据](evidence/log-stream-redaction-spike-2026-07-21.md)。

## 7. 双层脱敏

### 7.1 统一输出

- 固定掩码使用 `******`，不体现原值长度、前后缀或哈希；
- 同一策略对已是固定掩码的内容保持幂等；
- 记录只保存 `redacted=true/false`、策略版本和非敏感原因类别，不保存命中原值、可逆编码或秘密摘要；
- 页面、关键字查询、复制、上下文和下载只使用双层脱敏后的 `message`。
- 双层脱敏只移除秘密；已授权任务日志中的运行标识、路径、非密码命令令牌和原始工具诊断按第 1.1 节保持可见，不能被第二层策略静默删除。

### 7.2 Agent 第一层

Agent 在内存中完成：

1. 使用当前 execution 已解析的秘密槽位做精确值替换；
2. 覆盖该执行路径实际可能产生的已登记表示形式，例如属性键值、URI userinfo 和已确认编码表示；
3. 按结构化规则处理 `password`、`secret`、`token`、访问密钥等敏感键；
4. 保留第 1.1 节定义的非秘密运行上下文，用于 OBDUMPER 连接、路径、对象和失败诊断；不得将该边界扩展到密码、令牌、访问密钥、安全材料或其可恢复表示；
5. 对平台生成的命令/错误优先从结构化字段渲染脱敏文本，不先拼原文再依赖正则；
6. 只有处理成功的记录才能进入本地待发送队列。

任一实际秘密超过策略能力、策略版本未知或规则执行异常时，该记录不落盘、不上传，产生安全缺口并上报结构化安全错误。

### 7.3 控制面第二层

控制面在日志段、SQLite 错误摘要、SSE 和下载写入前重新执行同版本策略：

- 槽位解析时建立与 execution、credential revision 和策略版本绑定的短时 `redactionContextId`；
- 只持久化 contextId、revision 和策略版本，不持久化明文或秘密哈希；
- 控制面重启后如仍在合法日志收尾期，可从受保护 credential revision 在内存中重建上下文；
- credential revision 至少保留到 execution 的日志流完成或收尾期限结束，属于活动安全引用，不用于历史查看；
- 无法建立第二层上下文时拒绝持久化该批次，返回可重试安全错误；收尾期限后仍无法处理则登记明确缺口，不降级为只信任 Agent；
- 第二层发现第一层遗漏时，保存脱敏结果并产生安全事件；对应节点/策略进入复验，不能把“控制面兜底成功”当作 Agent 通过。
- 第二层策略必须与第 1.1 节保持一致：它可以继续遮蔽秘密，但不得将已确认的非秘密运行上下文改写为不可追溯的摘要。

## 8. 来源流、序号和摘要

### 8.1 流身份

唯一流范围为：

```text
executionId 或 nodeScope
+ sourceKind
+ sourceInstance
+ sourceEpoch
```

stdout、stderr 和每个工具文件分别拥有流。文件截断、替换或轮转创建新 epoch。Agent 重启不能把未知新文件冒充旧流。

### 8.2 批次

每个上传批次至少包含：

- execution、Agent、节点、租约和协议版本；
- streamId、sourceEpoch；
- `firstSeq`、`lastSeq`；
- 上一已确认批次摘要；
- 当前双层前的 Agent 脱敏记录；
- 内容摘要、策略版本、解析器版本和 requestId。

控制面规则：

- 首个新批次的 `firstSeq` 必须等于期望序号；
- 相同范围和相同摘要重发返回原确认，不重复写入；
- 相同范围但摘要不同属于 `LOG_BATCH_CONFLICT`，拒绝并进入安全核对；
- 序号超前时返回期望序号，Agent 优先补传；
- 确实无法补传时必须发送显式 `LogGapNotice`，包含同一 `sourceKind`、`streamId`、`sourceEpoch`、缺失范围（能取得时）、稳定原因码、脱敏策略版本和解析器版本；来源身份或版本缺失时控制面拒绝，不能猜测为 stdout/stderr；
- 缺口被确认后才允许后续序号继续，不能由控制面静默跳号。

日志序号独立于 AS `eventSeq`。状态事件保持一个连续事件序列；日志每个来源使用自己的序列，避免多个管道并发时伪造全局顺序。

## 9. Agent 本地可靠队列与背压

- 原始字节只在内存中停留；本地磁盘队列只保存 Agent 已脱敏批次；
- 批次达到 500 条、512 KiB 脱敏正文或等待 2 秒任一条件即封包；终态和错误证据立即封包；
- 每个 execution 的脱敏待发送队列默认上限 1 GiB，并纳入节点磁盘预检查；
- `LOCAL_SPOOL_LIMIT` 无正文缺口使用独立的 16 MiB 元数据上限；达到该上限同样失败关闭，不能覆盖已有缺口或把无法记录的丢失范围伪装成完整日志；
- Agent 重启打开队列时重新扫描普通批次与缺口的实际文件大小；运行中只在原子写入并 `fsync` 成功后增加计量、在控制面确认后的删除成功时减少计量，不能以每次入队全量扫描替代该边界；
- 1 GiB 物理容量验证不是常规单元测试：必须显式启用验证开关并提供已有、非链接的隔离根目录；测试仅在该根目录下创建随机子目录，验证结束时只清理该子目录。执行前应预留至少 2 GiB 空间；未提供上述条件时测试必须跳过或失败，不能占用工作区或节点数据目录；
- 控制面确认批次摘要和序号后，Agent 才能释放对应本地数据；
- 执行已经以完整进程、工具终态和结果事实收口时，已 `fsync` 的尾部批次或缺口仍可由同一 Agent 身份重启补传；控制面必须同时复验原 `leaseId`、`leaseEpoch`、不可变信封摘要和 `RELEASED + SUCCEEDED/FAILED` 终态，且不得因日志确认恢复执行、续租或改写终态；
- 已过期租约、其他 Agent、摘要不符、非终态已释放租约、错位回执或任意事件/状态写入一律不能借终态补传放行；
- 网络中断时继续采集和本地排队，不阻塞工具 stdout/stderr；
- 达到上限时不覆盖旧批次，不保存未脱敏内容；继续排空来源并记录可证明的 `LOCAL_SPOOL_LIMIT` 缺口；
- 空间恢复后先上传已有批次和缺口，再继续正常批次；
- 存在未确认日志/缺口时，execution 本地恢复记录不能被当作已完全清理。

这些是首版保护值，不进入系统设置页面。运行证据表明不合适时，通过版本化配置和评审修改，不能由单任务任意放大。

### 9.1 无正文队列证据

每个 Agent 私有队列根还维护一个最多 16 MiB 的追加式 `queue-evidence.jsonl`。每行完成 `fsync` 后才可作为本机恢复与受控测试证据；该文件不属于浏览器 API、SSE、下载或任意文件读取能力。

每条证据只能包含 `type`、`streamId`、`sourceEpoch`、`firstSeq`、`lastSeq`、`batchDigest` 与 `occurredAt`。允许的类型为 `ENQUEUED`、`UPLOAD_ATTEMPT`、`RECOVERY_REPLAY_ATTEMPT`、`UPLOAD_FAILED`、`RETRY_ATTEMPT` 和 `CONTROL_PLANE_CONFIRMED`。不得增加消息正文、任务/租约标识、路径、命令、原始错误、凭据或配置字段；解析到未知字段、格式错误或超限时失败关闭，待确认批次不得因此删除。

确认顺序固定为：已密封批次入队并 `fsync` → 写入入队证据 → 写入发送/重放尝试 → 控制面确认 → 写入确认事实 → 删除队列批次。控制面确认必须回显当前批次的 `streamId`、epoch、首末序号、摘要和下一期望序号；Agent 仅在回显与本地已密封批次完全一致、且决策为 `ACCEPTED` 或幂等 `DUPLICATE` 时删除队列文件。延迟、重复或错位响应一律保留批次并失败关闭。发送失败只追加失败事实并保留原批次；重启读取到原批次后必须重放，不能凭本地文件存在或重启本身视为已确认。容量满时的缺口单独 `fsync` 为无正文条目；控制面只在回显同一来源范围、规范化缺口摘要和下一期望序号后才可删除。它不复用普通批次账本字段，而以其持久条目和控制面缺口记录形成证据；同一来源恢复时，旧普通批次与缺口必须先于后续正常批次按序确认。

### 9.2 测试专用的队列恢复屏障

为验证“工具尚未结束时控制面不可达”及页面续传的最小恢复路径，`queuevalidation` **测试构建**可以在首个已密封日志批次的入队前、`fsync` 入队后和控制面确认后各暂停一次。屏障只在 Agent 私有身份状态目录写入本地标记，标记只包含阶段、流标识、来源序号、批次摘要和时间；不得包含日志正文、命令、路径、任务标识或秘密。每次暂停最多两分钟，超时失败关闭，以免测试构建意外阻塞工具。

该屏障不接受浏览器、HTTP、任务参数、环境变量或远程指令的开启请求；普通 Agent 构建固定不安装观察器，既不写标记也不改变上传时序。它仅用于受控测试取证，不是产品遥测、运维开关或队列读取入口，不能替代第 9 节要求的可审计入队、确认和重传证据。

## 10. 控制面分段文件与 SQLite 索引

### 10.1 文件格式

- 双层脱敏记录以 UTF-8 JSON Lines 保存；多行消息由 JSON 转义保持逻辑记录边界；
- 每个活动段只包含同一 execution/node scope 和同一来源流，避免权限混写；
- 目标段大小 8 MiB；达到大小或服务正常关闭时封段；来源完成封段仍待正式 Agent 采集完成事实接入；
- 封段后文件不可变，计算 SHA-256、字节数、记录数、序号和时间范围；
- 文件名只使用内部段 ID，不包含任务名、用户名、节点名或用户路径。

首版不压缩活动段，避免随机读取、上下文和崩溃恢复复杂度。归档压缩不在本切片范围。

### 10.2 SQLite 只保存索引

至少保存：

- segmentId、格式版本、scope 和真实来源；
- streamId/epoch、首末序号；
- 来源/接收时间范围；
- 文件相对标识、状态、字节数、记录数和 SHA-256；
- 已确认批次范围、摘要和文件偏移；
- 策略/解析器版本、完整性和缺口摘要；
- 保留截止时间和清理状态。

SQLite 不保存逐行工具正文、原始文件路径或未脱敏消息。

### 10.3 文件与索引崩溃一致性

控制面按固定顺序处理新批次：

```text
校验身份、序号、摘要和权限
→ 第二层脱敏
→ 向 .open 段追加完整批次帧
→ flush + fsync
→ SQLite 短事务登记批次偏移、摘要和段范围
→ 返回确认
```

- 崩溃发生在 SQLite 提交前：恢复时把 `.open` 文件截断到最后已登记偏移；
- SQLite 已登记的批次必须已有 fsync 文件内容；缺失或摘要不符时标记存储损坏和日志不完整，不伪造恢复；
- 封段使用同文件系统原子重命名，再更新段状态；若改名后进程中断，启动恢复必须重新核对 `.jsonl` 的字节数和 SHA-256 后才更新段状态；
- 启动恢复先核对活动段和索引，再开放日志写入/查询；
- 日志文件不得放在网络共享盘，继续服从单控制面本机磁盘边界。

## 11. 查询与排序

### 11.1 查询来源

查询层按权限合并：

- SQLite 中的调度、Agent 和审计结构化事件；
- SQLite 段索引定位到的双层脱敏日志段。

不把结构化事件复制进日志段，也不把段记录逐行复制进 SQLite。关键字只在权限过滤后的脱敏正文中做普通文本包含；首版不建立 FTS、倒排索引或正则引擎。

### 11.2 时间和稳定顺序

- 同一来源优先按 sourceEpoch + sourceSeq 保持真实顺序；
- 跨来源聚合使用可靠 sourceTime，否则使用 receivedAt；
- 相同展示时间使用 sourceKind、streamId 和 sourceSeq 做稳定排序，仅为页面稳定，不表示因果；
- 保留 sourceTimeRaw、解析状态和 receivedAt，页面可追溯；
- 不用节点时钟偏差自动改写来源时间。

### 11.3 重复内容

stdout、stderr 和工具文件即使文本相同也分别保留。首条切片不自动删除或折叠重复记录；未来只有取得可证明的同源重复事实时才允许增加“可能重复”标记，仍不改写原文。

## 12. 查询游标与持续加载

- 页面游标是版本化不透明令牌，绑定用户权限范围、筛选摘要、查询快照水位和最后排序位置；
- 游标不暴露本地路径、SQLite 行号、秘密引用或 Agent 内部序号；
- 权限、筛选或策略版本变化后旧游标失效，页面重新查询；
- 快照查询固定水位，新日志不插入当前页；
- 单一活动任务持续加载采用 SSE，不引入 WebSocket；
- SSE 只发送控制面已经双层脱敏并持久化/确认的记录；
- 浏览器使用最后可靠页面游标重连；断开时必须释放当前流，陈旧断开回调不得关闭已续传的新流，且不能用“连接恢复”推断 Agent 端缺口已补齐；
- 页面暂停只停止追加和滚动，控制面/Agent 采集不暂停。

SSE 是页面传输机制，不是 Agent 上传协议，也不承载任务状态写入。

## 13. 采集状态与缺口

内部来源状态至少包括：

```text
COLLECTING
COMPLETED
DELAYED
INTERRUPTED
INCOMPLETE
UNKNOWN
```

页面映射沿用 LC-R12。以下事实形成“不完整”：

- 本地队列超限；
- 超长记录丢弃；
- 文件在已读前被截断、替换、删除或超过跟踪边界；
- Agent 无法补传连续序号；
- 控制面段损坏或索引不一致；
- 脱敏策略失败而拒绝持久化；
- 保留期内文件意外缺失。

正常保留清理不是采集故障，但查询跨越已清理范围时显示“已过保留期”。未知缺失原因不得伪装成已过期。

## 14. 与任务终态证据的关系

日志记录本身不直接修改任务状态。版本化终态解析器可以从已确认来源中生成 `TOOL_TERMINAL_OBSERVED` 候选：

- 只识别已验证的 4.3.5 精确模式；
- 保存解析器版本、来源流、sourceSeq、段摘要和脱敏证据引用；
- `System exit 0/1` 仅在来源和上下文可靠时作为工具终态证据；
- 消息文本含“success/error”不自动映射任务状态；
- 阶段、行数、文件数和速率同样只有通过已验证解析规则才进入结构化事实；
- 日志缺口、延迟或解析失败只使证据未知，不直接判任务失败；
- 最终仍按 AS-R15 的进程、工具终态和结果事实矩阵形成成功/失败。

错误摘要引用日志证据，不复制未经脱敏原文。规则不确定时展示原始脱敏上下文，不生成自动修复建议。

## 16. 下载格式

V1.0 下载 UTF-8 纯文本 `.log`：

- 文件头以注释形式记录生成时间、平台时区、筛选摘要、来源集合、记录范围、脱敏声明、采集状态和是否截断；
- 每条记录包含展示时间、级别/未标级别、真实来源、关联对象摘要和脱敏消息；
- 脱敏消息保留第 1.1 节定义的非秘密运行上下文，下载不另行收窄该内容；
- 多行消息使用缩进续行，保持纯文本；
- 下载只读取控制面双层脱敏段和有权结构化事件，不回读 Agent 原始文件；
- 采集中下载固定生成时水位，不承诺包含后续日志；
- 成功/失败都记录不含正文的审计事件。

## 17. 权限与审计

- 先按任务、节点、调度或审计对象权限缩小候选段/事件，再读取正文和做关键字匹配；
- 无权记录不进入数量、候选、上下文、SSE、错误差异或下载；
- 日志查询、SSE 重连本身不扩大来源页面权限；
- 已授权读取、复制、SSE 和下载使用同一“秘密遮蔽、运行上下文保留”边界；不得因页面或传输方式改变可见正文；
- 审计日志查询需要独立能力；系统管理员身份不自动获得；
- 下载、审计查询、高敏环境日志访问和大段复制记录操作者、筛选摘要、结果范围与结果，不复制日志正文；
- 任何用户角色均无权读取 Agent 原始工具文件或未脱敏段。

## 18. 保留与清理

### 18.1 控制面脱敏日志

- 普通日志段服从普通日志保留期，审计事件服从独立审计保留期；
- 任务/节点归档不提前破坏保留期内关联；
- 清理先在 SQLite 标记候选和批次，再删除段文件，最后确认元数据状态；
- 崩溃后继续 `DELETING` 状态，不把意外缺失伪装成正常清理；
- 降低保留期按系统设置高影响规则执行，不提供任务页或日志中心手工删除。

### 18.2 Agent 短时材料

- 已确认的脱敏待发送批次在控制面确认后删除；
- 工具原始日志和安全材料在进程结束、终态/结果取证及日志确认后清理；
- 清理失败按 TL-R17 隔离目录、告警并按阈值阻断节点；
- Agent 原始工具日志不进入普通日志保留或备份。

## 19. 最小验证矩阵

1. 密码、令牌、访问密钥和安全材料分别跨管道块、物理行、批次和段边界，所有持久位置搜索不到原值；组合用户名、连接/对象/路径事实、非密码命令令牌和工具诊断在已授权任务日志中按第 1.1 节保留；
2. stdout、stderr、多个工具文件并发时各自序号连续且来源不混；
3. CRLF/LF、UTF-8 拆分、多行异常、无级别、无来源时间和超长记录按规则处理；
4. 重复批次同摘要幂等确认，相同序号不同摘要拒绝；
5. 网络中断后补传连续；无法补传时缺口明确且后续可继续；
6. Agent/控制面在追加、fsync、SQLite 提交和封段各阶段崩溃后恢复一致；
7. 第二层发现第一层遗漏时不保存原值，并触发 Agent/策略复验；
8. 任务详情快照、SSE 重连、上下文和下载使用同一脱敏内容；
9. 无权用户无法通过数量、关键字命中、候选、游标、SSE 或下载发现日志存在；
10. Windows AMD64 及三个麒麟目标分别验证管道、文件跟踪、编码、背压、重启和清理；
11. 终态解析器只对已验证模式产生证据，缺口/延迟不误判任务失败；
12. 保留清理、文件意外缺失和索引损坏具有不同完整性结果。

当前已完成 Windows 合成记录边界、双层幂等脱敏、批次摘要和超长失败关闭验证，详见[最小验证记录](evidence/log-stream-redaction-spike-2026-07-21.md)。F3.3 另增加当前任务的 `.open` JSONL 段、SQLite 批次偏移索引、固定水位/最后可靠游标与单条 SSE 事件游标的合成代码验证：普通批次先完成文件 fsync，随后才登记 SQLite；登记失败时恢复到已登记偏移；读取只依据已登记偏移。控制面会拒绝超过 256 KiB 的单记录、超过 500 条或 512 KiB 正文的批次，避免未受控批次越过查询读取边界；读取与启动恢复会复算已登记批次摘要，等长内容篡改也失败关闭。合成测试现覆盖 8 MiB 阈值后的 SHA-256 封段与新活动段、带 `sourceKind`/策略/解析器身份的持久 `GapNotice`、改名后索引未确认的启动恢复，以及跨进程未登记尾部截断后继续追加。本轮补充验证了请求标识包装仍能透传底层 `http.Flusher`，且底层不支持刷新时保持 `LOG_STREAM_UNAVAILABLE` 失败关闭；另以合成持久段索引覆盖首连发送事件 ID、客户端关闭后追加记录、携带 `Last-Event-ID` 重连且仅补送新增记录，游标继续绑定主体和任务。上述结果只覆盖控制面中间件与服务端续传契约，不等同于真实浏览器或网络断线重连。为满足既有索引非空列，当前代码写入未参与清理的 30 天占位 `retain_until`；它不是已确认的产品保留策略，系统设置接入前不得以此删除日志。2026-08-03 已在 Windows 本机 MVP 的单一已授权 CSV 任务运行期间重启控制面；恢复后任务终态成功，浏览器重新加载仍可读取持久日志，结果文件存在，Agent 本地待确认队列为空。该现象不能证明本次发生过队列重传或不存在日志缺口：实现尚无不泄露正文的队列入队、发送失败和重传遥测。仍未验证活动任务真实浏览器断线后的 SSE 续传、Agent 进程重启期间补传、长时间控制面不可达、队列上限，以及正式来源封段和可靠队列的完整恢复流程；不能据此宣称 LG-R10、LG-R12 或 G3 已完成。

补充更正：上述“尚无不泄露正文的队列入队、发送失败和重传遥测”已不再适用。当前队列已记录无正文的入队、发送失败、重放和确认事实；受控假控制面测试进一步经真实 Agent 身份 TLS 协议与私有队列验证持续不可达、缩小上限、恢复按序重放、响应丢失后的幂等重复确认和错位确认回执的失败关闭。该测试不连接数据库、不启动 OBDUMPER，也不等同于 Agent 二进制或任意时长网络分区的现场验证。容量满时仍缺少持久化并补传 `LOCAL_SPOOL_LIMIT` 缺口的实现；活动任务真实浏览器断线后的 SSE 续传、Agent 进程重启期间补传、长时间控制面不可达、1 GiB 队列上限，以及正式来源封段和可靠队列的完整恢复流程仍待验证；不能据此宣称 LG-R10、LG-R12 或 G3 已完成。

进一步更正：容量满时已实现独立受限、无正文、`fsync` 的 `LOCAL_SPOOL_LIMIT` 缺口条目，并经受控假控制面测试验证恢复后会在同一来源的后续正常批次前确认；缺口确认同样严格匹配来源范围、规范化摘要和下一期望序号。此前段落中“仍缺少持久化并补传”的表述已被本段取代。实际常规 Agent 二进制、任意时长网络分区、1 GiB 上限和跨目标环境的现场验证仍待完成，LG-R10、LG-R12 与 G3 状态不变。

## 20. 明确禁止

- 把未脱敏 stdout/stderr 或工具文件上传控制面；
- 把管道 Read 块直接当日志记录；
- 把逐行工具正文写 SQLite；
- 把工具原始文件放入普通查询、下载或备份；
- 只靠一组无版本正则表达式声称脱敏完成；
- 在秘密/策略不可用时降级保存原文；
- stdout=INFO、stderr=ERROR 或按消息单词猜任务状态；
- 跨来源全局序号、自动去重或按时间接近推断因果；
- 静默跳过序号、超限、文件轮转或存储损坏；
- 用页面 SSE 连接状态替代 Agent 采集完整性；
- 提供正则查询、全文分析平台、未脱敏下载或任意节点文件访问；
- 用一次 Windows 合成验证声称全部目标平台通过。

## 21. 对现有契约的影响

- 落实 TD-008 的“真实来源事件流与查询存储分离”；
- 落实 TS-R14 的“脱敏正文分段文件化、SQLite 保存索引摘要”；
- 承接 AS-R12 的可靠事件原则，但日志使用来源独立序号，不占用状态 eventSeq；
- 承接 AS 的终态证据矩阵，不用日志替代进程与结果事实；
- 落实 CS-R13 的 Agent/控制面双层脱敏和失败关闭；
- 落实 TL-R13 的管道脱敏与私有工具原始日志边界；
- 不改变 LC-R01～LC-R20、LC-FR01～LC-FR15 和 LC-LF-R01～LC-LF-R18 的产品语义；
- 本契约确认后仍需 API、SQLite 数据模型和正式 Agent 实现/测试，不能直接把 P0 标记通过。

## 22. 本轮评审项

| ID | 评审项 | 建议结论 | 状态 |
|---|---|---|---|
| LG-R01 | 来源模型 | 查询预设不复制日志；每条记录保留调度、Agent、stdout、stderr、工具文件或审计真实来源 | 已确认 |
| LG-R02 | 原文边界 | 原始管道仅驻内存，工具原始文件仅在 Agent 私有短时目录，控制面永不接收原文 | 已确认 |
| LG-R03 | 记录重组 | 每个来源独立重组 UTF-8 记录；禁止按 Read 块脱敏/持久化 | 已确认 |
| LG-R04 | 多行与级别 | 只按版本化 4.3.5 解析器合并续行和提取级别；stdout/stderr 不自动映射级别 | 已确认 |
| LG-R05 | 超长记录 | 256 KiB 上限；超限不存原文、排空到安全边界并生成缺口 | 已确认 |
| LG-R06 | 双层脱敏 | 固定 `******`；Agent 第一层、控制面持久化前第二层，策略版本一致且幂等；仅遮蔽秘密，已授权任务日志保留非秘密运行上下文 | 已确认 |
| LG-R07 | 脱敏上下文 | credential revision 保留到日志收尾；无法重建第二层上下文时拒绝持久化并记缺口 | 已确认 |
| LG-R08 | 流与序号 | 每来源 streamId + epoch + sourceSeq；文件替换/轮转使用新 epoch | 已确认 |
| LG-R09 | 上传幂等 | 序号范围 + 前序摘要 + 内容摘要；同序号不同内容拒绝，缺失必须显式 GapNotice | 已确认 |
