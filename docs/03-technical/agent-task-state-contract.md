# Agent 协议与任务状态最小契约

> 文档状态：首条纵向切片专项契约已确认  
> 适用范围：单控制面、用户显式选择的一个执行节点、单表 CSV 导出  
> 对应门禁：VS-P0-07、VS-P0-10、VS-P0-11  
> 评审结论：AS-R01～AS-R16 已于 2026-07-21 确认；AD-R09 已补充提交前预检查协议
> 更新日期：2026-08-04

## 1. 目标与非目标

本契约定义控制面如何把一个已提交导出任务安全地交给指定 Agent，如何接收真实进程事实，以及如何在网络、Agent 或控制面中断时保持可信状态。

首条切片只需要证明：

```text
Agent 主动认证连接
→ 心跳和环境事实可用
→ 原子领取一个指定给本节点的任务
→ 校验不可变任务信封
→ 启动并监管一个 OBDUMPER 进程
→ 可靠上报状态、终态和结果事实
→ 中断后不重复启动、不伪造失败
```

本轮不设计自动选节点、优先级队列、定时调度、任务抢占、批量任务、自动重试、检查点继续、任务取消、多控制面高可用或跨地域容灾。首条切片每个 Agent 同时只执行一个任务；协议保留容量字段，但不提前实现并行执行器。

## 2. 第一性原理约束

1. **控制面拥有业务状态**：Agent 只能上报事实和请求，不能直接把任务写成“成功”或“失败”。
2. **Agent 拥有机器事实**：进程、文件、工具版本和节点资源必须来自实际 Agent，控制面不能用自己的文件系统推测。
3. **网络传输至少一次**：请求和事件可能重复，所有有副作用操作必须幂等。
4. **启动意图至多一次**：租约超时不代表进程停止，不允许自动把同一任务交给其他 Agent。
5. **终态必须有证据**：外层脚本退出码、单条日志或连接中断都不能单独决定终态；对象存储在 EX-V1 远端 MANIFEST 接入前采用[导出通用契约第 8.4 节](export-general-contract.md#84-终态证据)定义的受限便利性例外，仅接受受控进程退出码 0 与固定成功终态的组合，且结果清单保持空值。
6. **失联不等于失败**：无法证明当前进程时保留最后可信持久状态，并附加“状态核对中”。
7. **单一参数生成权威**：控制面发送已确认的不可变参数令牌；Agent 校验并执行，不重新解释产品参数规则。
8. **无任意远程执行**：协议只接收已发布能力类型和结构化任务信封，不提供 shell、终端或自由命令接口。

## 3. 协议参与者与标识

| 标识 | 生命周期 | 作用 |
|---|---|---|
| `nodeId` | 节点记录生命周期 | 用户选择和权限范围中的执行节点 |
| `agentId` | Agent 机器身份生命周期 | 关联到一个节点，可撤销和轮换凭据 |
| `bootId` | Agent 每次进程启动 | 区分 Agent 重启前后的内存状态 |
| `taskId` | 一个已提交任务 | 对应产品中的一次不可变执行意图 |
| `executionId` | 一次任务执行记录 | 首条切片与 `taskId` 一对一，仍单独标识执行事实 |
| `precheckId` | 一次提交前预检查 | 绑定草稿 revision、配置指纹、数据源/凭据和节点，不是 task/execution |
| `precheckLeaseId` | 一次预检查领取 | 只授权固定 `EXPORT_PREFLIGHT` 检查，不授权启动工具 |
| `precheckLeaseEpoch` | 预检查单调隔离令牌 | 拒绝旧 Agent、旧领取和延迟检查结果 |
| `leaseId` | 一次有效领取 | 标识当前租约 |
| `leaseEpoch` | 单调递增整数 | 拒绝旧租约和延迟消息的隔离令牌 |
| `eventId` | 全局唯一 | 事件去重 |
| `eventSeq` | execution 内从 1 递增 | 检查事件顺序和缺口 |
| `requestId` | 单次协议请求 | 请求追踪和幂等响应 |

`taskId`、`executionId`、`agentId`、`leaseId` 和 `leaseEpoch` 必须同时匹配，事件才有资格改变执行事实。只匹配任务 ID 不足以证明消息属于当前执行者。

控制面新建资源和响应 `requestId` 使用规范小写 UUIDv4。当前 `agent-v1` 实现由 Agent 使用同一生成规则创建新的 `agentId`、`bootId` 与协议 `requestId`，这与旧版“外部 ID 均由服务端生成”的表述形成 `TD-ID-01` 归属待决项；本轮只记录实现事实，不把它提升为新的架构决策。为保证本机身份状态、SQLite 外键和回执重放可恢复，`agent-v1` 暂时只把已有非 UUID 标识视为受长度和绑定校验约束的不透明历史值，绝不在原地迁移或改写。真实 G3 Worker 接入前，`leaseId` 必须有唯一的共享 UUIDv4 生成点；在此之前不把当前合成调用方提供的 `leaseId` 描述为已完成的 UUID 边界。

### 2026-09-14 注册与配置生命周期修订（DEC-048）

注册仅用于首次关联或明确更换机器身份，单次材料 24 小时有效。普通启动自动识别已保存身份，配置损坏不自动覆盖。安装包携带固定控制面 HTTPS 地址和 CA 公钥；禁止重定向、HTTP 降级和跳过证书校验。

新增 `POST /agent/v1/runtime-configuration:sync`：Bearer 机器认证，请求只含 `protocolVersion`。在同一只读事务核验当前 Agent 并读取其绑定节点配置，响应为平台、工具目录、Java 路径、allowedRoots、revision、digest。不得请求其他节点或携带任意操作。客户端验证结构、平台、非回退版本和确定性摘要，仅在无工具运行时原子替换本机加密配置；机器凭据保持不变。环境和真实路径仍由固定本机检查复核。此段取代历史“仅首次关联下发、变更须重新关联”的限制。

主循环串行处理连接测试、预检查和配置同步；异步执行从领取起持有运行配置读锁，直到执行及结果处理结束。新配置等待空闲应用，不改变冻结任务配置。旧控制面明确返回 404 时只保留原配置，支持滚动升级；认证失败、无效摘要、跨平台或版本回退不得容错应用。

## 4. 注册与机器认证

### 4.1 最小注册流程

```text
管理员创建节点记录
→ 控制面生成一次性、短时、单次使用的关联材料
→ 管理员在目标机器配置控制面地址和关联材料
→ Agent 在本机生成高强度不透明机器凭据并先写入受保护配置
→ Agent 通过 HTTPS 发起关联
→ 控制面绑定 nodeId 与 agentId，只保存机器凭据的单向校验材料
→ 后续所有请求使用机器凭据认证
```

首版使用“HTTPS + 应用层不透明机器凭据”，不要求用户先建设客户端证书基础设施。机器凭据由 Agent 本地生成，控制面只保存校验材料，不保存可再次展示的原始凭据；即使关联成功响应丢失，Agent 仍持有同一凭据，可用相同 requestId 安全重试并得到关联结果。凭据的加密落盘、轮换和恢复由凭据安全契约进一步定义。

### 4.2 强制安全边界

- Agent 必须验证控制面 TLS 证书、主机名和信任链；允许配置内部 CA，不允许跳过证书校验；
- 一次性关联材料使用后立即失效，过期、重复或节点不匹配均拒绝；
- 一个 Agent 机器身份只绑定一个节点；重新关联必须撤销旧身份并留下审计事实；
- 机器凭据不得进入 URL、普通日志、任务信封或诊断导出；
- 节点禁用、归档或凭据撤销后，心跳可返回明确拒绝，但不得继续领取任务；归档仅在没有 `STARTING`、`RUNNING` 或 `CANCELLING` 任务时允许，并原子撤销当前机器凭据和未使用关联材料；
- 协议版本不兼容时拒绝任务领取，并保留足够的非敏感升级原因。

## 5. 通用消息信封

除首次关联外，每个请求至少携带：

| 字段 | 规则 |
|---|---|
| `protocolVersion` | 精确版本；不兼容时明确拒绝，不猜测降级 |
| `agentId` / `nodeId` | 必须与机器身份绑定关系一致 |
| `bootId` | 当前 Agent 进程启动标识 |
| `requestId` | 同一请求重发保持不变 |
| `sentAt` | Agent 观测时间，只作诊断，不作为租约权威时间 |
| `payloadType` | 固定枚举，不接受任意类型名称 |
| `payload` | 按类型校验大小、结构和字段 |

租约的创建、续期和过期一律使用控制面时间。Agent 时间只用于机器时钟偏差提示；控制面不得因为 Agent 时间快慢直接提前过期租约。

## 6. 首版协议操作

本节只定义语义，不提前锁定 REST URL 和数据库表。

| 操作 | 方向 | 作用 | 是否允许重发 |
|---|---|---|---:|
| `EnrollAgent` | Agent → 控制面 | 使用一次性材料关联机器身份 | 同 requestId 返回原结果；材料不可二次消费 |
| `Heartbeat` | Agent → 控制面 | 上报在线、版本、容量和活动执行摘要 | 是 |
| `ClaimExecution` | Agent → 控制面 | 长轮询领取一个指定给本节点的等待任务 | 是；同 requestId/租约返回同一结果 |
| `AcknowledgeLease` | Agent → 控制面 | 确认收到任务信封并完成基础校验 | 是 |
| `RenewLease` | Agent → 控制面 | 续期当前执行租约并带运行摘要 | 是 |
| `AppendExecutionEvents` | Agent → 控制面 | 批量上报有序状态与进程事实 | 是；按 eventId/eventSeq 去重 |
| `ReconcileExecution` | Agent → 控制面 | 重连后报告本地进程和持久证据 | 是 |
| `ReleaseTerminalExecution` | Agent → 控制面 | 终态事件已确认后释放本地执行上下文 | 是 |

心跳、长轮询和事件上传都由 Agent 主动出站发起。控制面不主动连接 Agent，不开放 Agent 入站管理端口。

### 6.1 提交前预检查补充

AD-R09 补充以下固定操作，但不改变正式任务的 `ClaimExecution` 和 eventSeq：

| 操作 | 方向 | 作用 | 是否允许重发 |
|---|---|---|---:|
| `ClaimNextPrecheck` | Agent → 控制面 | 服务端原子选择并领取明确绑定本节点的下一条 `EXPORT_PREFLIGHT` | 是；严格 `EXPORT_PREFLIGHT_CLAIM_NEXT` 信封不接受 precheckId 或 leaseId，同 requestId/同摘要返回原 binding、bindingDigest、checkSet 和租约；没有工作返回 `204 No Content`，不写回执或租约 |
| `AcknowledgePrecheckLease` | Agent → 控制面 | 确认草稿 revision、指纹、检查清单和短租约 | 是；严格 `EXPORT_PREFLIGHT_ACKNOWLEDGE_LEASE` 信封，必须回送 leaseId、epoch 和 bindingDigest |
| `ResolvePrecheckSecretSlots` | Agent → 控制面 | 在有效预检查租约内解析固定 `DATABASE_CONNECTION`，或在 `STORAGE_AUTH` 阶段解析冻结的 `STORAGE_CREDENTIAL` | 是；两个槽位必须使用独立 requestId/摘要/回执，均不缓存明文 |
| `CompletePrecheck` | Agent → 控制面 | 返回结构化检查项、脱敏证据摘要和完整性 | 是；严格 `EXPORT_PREFLIGHT_COMPLETE` 信封，只提交按固定顺序的六项结果，不提交独立 `succeeded` |

- 预检查只执行登记的数据库连接、对象存在/可读取、工具/Java、允许根目录、路径可写/非空和空间检查；`OBJECT_ACCESS` 对冻结的表使用固定 JDBC `DatabaseMetaData.getTables` 确认元数据可见，再以同一连接执行固定 `SELECT 1 FROM <安全引用的库或 Schema>.<安全引用的表> WHERE 1 = 0`，不读取业务行。视图、函数、存储过程、序列仅在 DDL 内容中活动，按冻结的对象类型分别由固定 JDBC 元数据接口精确核对名称；不对它们执行表的零行读取。驱动不提供所需元数据时结果为 UNKNOWN；即使名称来自目录，预检查仍独立核对。MySQL/Oracle 的命名空间位置和引用字符只能由冻结数据源的兼容模式决定，不能由浏览器或 Agent 自由输入 SQL。连接已建立后，对象不可见统一投影为 `FAILED/OBJECT_NOT_ACCESSIBLE`，不区分权限不足、对象不存在或不可见；只有连接中断、超时、探针运行时异常或安全转义无法确认时才投影为 `UNKNOWN/OBJECT_ACCESS_UNAVAILABLE`，且两者都不得携带 SQLState、错误号或异常原文；
- 一次预检查在私有工作区只安装一次内嵌 JDBC 探针资产，并核对该资产的固定摘要。`SPECIFIED` 范围以固定 v5 帧一次传入全部冻结对象类型与名称，在一个 JVM 进程、一条 JDBC 连接中按顺序核对；表额外执行固定零行读取，五类对象只返回汇总三态，不返回对象名、SQL 或异常原文。`ALL` 范围仍使用数据库级连接探针。探针执行失败时 Agent 本机服务日志只记录固定阶段和错误类别，不记录 JDBC 输出、异常原文、连接输入或对象名；
- 本地输出的 Agent 在租约确认且有效后，必须先按本机执行顺序完成 `TOOL_ENVIRONMENT`、`OUTPUT_PATH`、`OUTPUT_EMPTY`、`AVAILABLE_SPACE`。仅当四项均为 `PASSED` 时，才允许调用 `DATABASE_CONNECTION` 并执行 `DATABASE_CONNECTIVITY`、`OBJECT_ACCESS`；任一为 `FAILED` 或 `UNKNOWN` 时，不得请求数据库槽位或启动 JDBC，后二项分别以 `UNKNOWN/DATABASE_CONNECTION_UNAVAILABLE`、`UNKNOWN/OBJECT_ACCESS_UNAVAILABLE` 收口。对象存储输出仅先完成 `TOOL_ENVIRONMENT`、`AVAILABLE_SPACE`，再执行数据库/对象检查；二者均通过后才可执行无秘密 `STORAGE_CONNECTIVITY`，且仅当其通过、草稿冻结了存储凭据引用并且探测器显式声明需要凭据时，才可调用独立 `STORAGE_CREDENTIAL` 槽位执行 `STORAGE_AUTH`。任一前置不通过时不得解析存储凭据，相关存储检查以固定 UNKNOWN 收口。完成报告仍按固定六项契约顺序序列化，不随执行顺序改变；
- 不接受任意 SQL、Shell、自由命令、任意文件路径或 OBDUMPER 启动请求；
- 预检查短租约由控制面时间控制，结果绑定 precheckId、lease/epoch、Agent、草稿 revision、配置指纹、credential revision 和节点事实版本；对象存储凭据探测还绑定可选的 storageCredentialId/revision，并将其纳入 bindingDigest；
- 预检查不创建 taskId、executionId 或 execution event，不生成正式输出，也不改变任务状态；
- 首条切片 Agent 有活动 execution 时不领取预检查，避免检查争用正式执行的唯一容量；
- 失联或租约过期的预检查结果标为未知/过期，不能据此提交任务，也不自动改派后合并两个结果。

预检查的机器请求使用 `agent_precheck_receipts` 持久化最小回执：claim 记录 `LEASED`，acknowledge 记录 `ACKNOWLEDGED`，complete 记录 `SUCCEEDED`、`FAILED` 或迟到的 `EXPIRED`。回执以 `(agentId, requestId)` 和请求摘要防止控制面重启后重新签发租约或重复写入终态；同一 requestId 但摘要不同必须拒绝。`precheck_runs` 仍是预检查业务状态权威，acknowledge 不能把它从 `LEASED` 提升为成功。控制面时钟到期后，迟到的 acknowledge/complete 不得改变预检查通过状态，不能作为任务提交依据；迟到 complete 的回执与 `EXPORT_PRECHECK_COMPLETION_EXPIRED` Agent 审计必须同事务落库。

### 6.2 Windows 本机 MVP 的固定导出信封

在 `--local-mvp` 且控制面、Agent 同时显式启用真实执行开关时，已实现如下单任务协议；它只用于受授权的 Windows AMD64 单表 CSV 测试：

| 固定 payloadType | 入口 | 控制面约束 |
| --- | --- | --- |
| `OBDUMPER_EXPORT_CLAIM_NEXT` | `POST /agent/v1/executions:claim-next` | 不接收 taskId、argv、目录或秘密；控制面选择已冻结且满足全部准入条件的一条任务 |
| `OBDUMPER_EXPORT_ACKNOWLEDGE_LEASE` | `POST /agent/v1/executions/{executionId}:acknowledge-lease` | eventSeq 固定为 2，确认 Agent 已收到信封 |
| `OBDUMPER_EXPORT_RENEW_LEASE` | `POST /agent/v1/executions/{executionId}:renew-lease` | 控制面时间续期，不能切换任务、节点、参数或秘密 |
| `OBDUMPER_EXPORT_RESOLVE_SECRET_SLOTS` | `POST /agent/v1/executions/{executionId}/secret-slots:resolve` | 只在当前租约、任务信封摘要、权限和凭据仍有效时返回短时数据库连接槽位 |
| `OBDUMPER_EXPORT_APPEND_EVENT` | `POST /agent/v1/executions/{executionId}:events:append` | 只接受 `PROCESS_STARTED`、`PROCESS_EXITED`、工具终态、结果文件事实或无进程启动拒绝；序号连续 |
| `OBDUMPER_EXPORT_APPEND_LOG` | `POST /agent/v1/executions/{executionId}:logs:append` | 只接受已密封、已完成第一层秘密脱敏的 stdout/stderr 批次；正文可保留已确认的非秘密运行上下文（路径、非密码命令令牌和工具诊断），不能承载原始文件字节或任何秘密。正常上传要求活动未过期租约；终态补传仅接受同一机器身份、同一已释放租约和同一冻结信封。确认必须回显当前批次位置、摘要和下一期望序号；错位或不完整回执不得释放本地批次 |
| `OBDUMPER_EXPORT_APPEND_LOG_GAP` | `POST /agent/v1/executions/{executionId}:logs:gap` | 只接受 Agent 私有队列容量已满时形成的无正文连续缺口；固定原因码为 `LOCAL_SPOOL_LIMIT`。正常上传要求活动未过期租约；终态补传只适用同一机器身份、同一已释放租约和同一冻结信封。确认必须回显来源范围、规范化缺口摘要和下一期望序号；错位或不完整回执不得释放本地缺口 |

领取时控制面创建 eventSeq=1 的 `SCHEDULED` 事实。Agent 只能发送没有密码令牌的冻结 argv；密码经短时槽位写入任务私有官方安全文件后，直接 Java 启动包内主类。工具进程存活期间每 30 秒续期；进程已启动后即使事件上报失败，Agent 也先等待进程退出再清理安全材料，避免删除仍被 Java 使用的文件。

当前 MVP 已提供仅用于**已第一层脱敏、已密封日志批次**的 Agent 私有可靠队列：批次在控制面确认前保留，Agent 启动后会按稳定顺序重放。它不恢复工具进程、不读取任意文件，也不等同于工具文件日志采集或自动对账。终态 execution 的重放使用既有两个日志端点，不新增恢复入口：控制面重新计算不可变任务信封摘要，且只在请求的 Agent 身份、`leaseId`、`leaseEpoch` 与已释放终态租约完全一致时接受。新的 `bootId` 允许表示同一 Agent 进程重启；过期租约、其他机器、摘要不符、非终态已释放租约和所有状态/事件写入仍失败关闭。接受日志或缺口不会恢复 execution、延长租约、改变终态或降低事件证据要求。控制面仅在回显相同位置与摘要后允许 Agent 删除本地条目。控制面发现 `ISSUED`、`ACKNOWLEDGED` 或 `ACTIVE` 租约已过期时，会将租约标为 `EXPIRED`，把关联 execution 收口为 `FAILED + reconciliation_required=1` 并记录审计；这会释放节点容量，但绝不自动重新领取同一任务或宣称成功。

## 7. 心跳与节点在线事实

### 7.1 心跳最小内容

- Agent、操作系统和架构版本；
- `bootId`、本次启动时间和机器事实采样时间；
- 当前活动 `executionId`、`leaseId`、`leaseEpoch` 及本地最后事件序号；
- 首条切片容量：最大并发 1、当前占用 0 或 1；
- OBDUMPER/Java 环境检查版本或最近证据摘要；
- CPU、内存和相关磁盘的当前快照；
- Agent 本地持久事件待上传数量和最近上传结果摘要。

心跳不携带数据库密码、命令明文、完整日志或任意文件内容。

### 7.2 阈值关系

具体秒数进入系统配置，不在代码多处硬编码，但必须满足：

- 心跳有效窗口大于正常心跳间隔并容纳短暂网络抖动；
- 租约有效期大于允许的连续心跳/续期间隔及网络余量；
- 长轮询时长小于反向代理和服务端连接空闲超时；
- Agent 在租约到期前留出足够重试时间，不能到最后一刻才续期。

节点离线只改变节点心跳维度和接收新任务结论，不直接修改运行任务的持久状态。

## 8. 领取与租约

### 8.1 可领取条件

控制面只向满足以下条件的 Agent 返回任务：

- 任务持久状态为“等待调度”；
- 任务快照明确选择当前 `nodeId`；
- 节点已启用、在线、非维护、环境正常且容量可用；
- Agent、协议、工具与目标平台版本满足快照；
- 当前任务没有有效租约、未确认的旧启动事实或“状态核对中”阻断；
- 启动前必须复验的路径与环境事实仍有效。

首条切片不自动选择或改派节点。节点不可用时任务保持“等待调度”，展示阻断原因。

### 8.2 原子领取

SQLite 的一个短事务完成：

```text
再次检查可领取条件
→ 创建 execution/lease 事实
→ 增加 leaseEpoch
→ 将任务从等待调度改为启动中
→ 写入调度事件和审计摘要
→ 提交事务
```

同一任务只能有一个当前租约。同一 `ClaimExecution` 请求重发时返回原租约或空结果，不创建第二次执行。工具运行期间不持有数据库事务。

### 8.3 租约过期

租约过期只说明控制面暂时收不到当前 Agent 的有效续期，不能证明工具进程已经停止。因此控制面必须：

- 保留任务最后可信持久状态；
- 设置独立的“状态核对中”标识及原因；
- 禁止该任务再次领取或改派；
- 记录最后 Agent、租约、事件、心跳和控制面接收时间；
- 等待原 Agent 恢复并核对，或进入后续明确授权的人工处置流程。

首条切片不提供“租约过期后自动重跑”。这不是缺少容错，而是避免同一导出进程仍在运行时产生重复执行。

## 9. 不可变任务信封

Agent 领取到的任务信封至少包含：

- 协议、能力、工具和参数元数据精确版本；
- `taskId`、`executionId`、`leaseId`、`leaseEpoch`；
- 选定节点和 Agent 约束；
- 不可变快照及 `configFingerprint`；
- 有序 `argvTemplate` 和任务信封摘要；
- 秘密槽位引用及用途，不含秘密原值；
- OBDUMPER 启动文件、Java 路径和受控环境块的版本化引用；
- 工作目录、输出路径、日志路径与允许根目录；
- 需要重新确认的节点/路径预检查项；
- 日志和状态事件的脱敏策略版本；
- 创建、领取和租约到期的控制面时间。

Agent 只接受已知能力类型 `OBDUMPER_EXPORT` 和 `EXPORT_PREFLIGHT`。前者只接受已确认的单表 CSV 参数模板；后者只接受 6.1 节固定检查清单且永不启动 OBDUMPER。未知字段可以按协议兼容规则忽略的前提是明确标记为非关键；未知关键字段、未知槽位、任意命令文本、shell 运算符或摘要不一致必须拒绝。

## 10. Agent 本地执行状态

Agent 使用与产品状态分离的本地阶段：

```text
RECEIVED
→ VALIDATING
→ READY_TO_START
→ STARTING_PROCESS
→ PROCESS_RUNNING
→ PROCESS_EXITED
→ EVIDENCE_UPLOADING
→ RELEASED
```

任一阶段都可以进入 `LOCAL_RECONCILIATION_REQUIRED`。本地阶段只用于恢复和诊断，不直接展示成新的产品任务状态。

Agent 必须维护最小本地持久执行日志，至少保存任务/执行/租约标识、信封摘要、非敏感进程身份、最后事件序号和待确认事件。不得保存密码原值。实现可以使用原子文件或轻量本地存储，具体格式留到数据模型设计，不引入第二套服务端数据库。

启动操作必须使用本地写前意图：调用操作系统创建进程之前，先原子持久化 `STARTING_PROCESS`、execution 标识和信封摘要；成功创建后再补写进程身份。Agent 如果在两次写入之间崩溃，恢复时将该 execution 置为核对中，不能因为缺少 PID 再次启动。

## 11. 进程启动与身份

### 11.1 启动前校验

Agent 在启动任何进程前必须核验：

- 租约仍有效且 epoch 匹配；
- 信封摘要、命令模板和秘密槽位结构有效；
- OBDUMPER 和 Java 的实际文件、版本与快照一致；
- Windows/Linux 目标平台与进程适配器匹配；
- 工作目录、日志目录和输出目录符合允许根目录及任务规则；
- 未显式启用 `--skip-check-dir` 时输出目录为空或可新建；启用时仍核验路径、允许根目录、可写性和空间，但不再把目录非空作为启动阻断；
- 本机不存在该 execution 已启动但尚未核对的进程证据；
- 凭据能按授权解析，且不会写入普通日志或本地持久文件。

校验失败上报结构化 `START_REJECTED` 事实；控制面核对后可以从“启动中”进入“失败”。Agent 不自行修改任务状态，也不尝试其他路径、工具版本或节点。

### 11.2 进程已启动证据

“调用启动 API 没报错”不足以证明工具已启动。最小进程身份包括：

- PID；
- 进程开始时间或等价的防 PID 复用事实；
- 实际启动入口和受控 Java/工具标识；
- 脱敏命令摘要；
- 父子进程关系或进程树证据；
- Agent `bootId`；
- 首次可验证存活时间。

Windows `.bat` 只是包装入口。Agent 必须跟踪能够代表实际 Java/OBDUMPER 生命周期的受控进程或进程树，不能把批处理返回 0 当作任务成功。

## 12. 执行事件与可靠上传

### 12.1 最小事件类型

| 事件 | 事实含义 |
|---|---|
| `LEASE_ACKNOWLEDGED` | Agent 已收到并通过任务信封基础校验 |
| `START_REJECTED` | 启动前校验失败，未创建工具进程 |
| `PROCESS_STARTED` | 已取得最小进程身份和存活证据 |
| `PROCESS_OBSERVED_RUNNING` | 当前仍能证明同一进程存活 |
| `PROCESS_EXITED` | 已确认同一进程树结束及观察到的退出事实 |
| `TOOL_TERMINAL_OBSERVED` | 发现脱敏后的工具成功/失败/未知终态证据 |
| `RESULT_FACTS_OBSERVED` | 文件、行数、摘要等可靠结果事实 |
| `EVIDENCE_CONFLICT` | 退出码、日志和结果相互矛盾 |
| `LOCAL_RECOVERY_STARTED` | Agent 重启后开始核对本地执行 |
| `LOCAL_RECOVERY_RESULT` | 恢复后进程仍运行、已结束或无法证明 |

日志正文由[日志采集、双层脱敏与执行证据最小契约](log-collection-evidence-contract.md)承接；本协议事件只携带状态判定所需的脱敏摘要和证据引用，不把完整工具日志复制进状态表。LG-R01～LG-R20 已确认。

### 12.2 顺序、去重与确认

- Agent 为每个 execution 生成从 1 递增且不复用的 `eventSeq`；
- 每个事件另有唯一 `eventId`；
- 未收到控制面确认的事件保留在本地持久待发送队列；
- 批次重发使用原 eventId/eventSeq，不重新生成事件；
- 控制面事务内完成事件去重、顺序检查、事实落库和状态投影；
- 重复事件返回已确认结果；发现序号缺口时返回期望序号，Agent 从该位置重发；
- 旧 leaseEpoch 的迟到事件只保存为拒绝/诊断事实，不改变当前状态。

网络请求成功但响应丢失时，Agent 重发同一批次；该场景不得产生重复状态流转。

## 13. 产品状态投影

### 13.1 八种持久状态与附加标识

产品继续使用已经确认的八种持久状态：

```text
草稿、等待调度、启动中、运行中、取消中、成功、失败、已取消
```

“状态核对中”是独立附加标识，不是第九种持久状态。首条切片不实现任务取消，因此不会由用户操作进入“取消中/已取消”，但协议不得把这两个产品状态改名或另造替代状态。

### 13.2 首条切片允许的状态流转

| 当前状态 | 可信事实 | 下一状态 |
|---|---|---|
| 草稿 | 提交复验通过并固化快照 | 等待调度 |
| 等待调度 | 原子领取和租约创建成功 | 启动中 |
| 启动中 | `PROCESS_STARTED` 证据被控制面接受 | 运行中 |
| 启动中 | `START_REJECTED`，确认没有工具进程 | 失败 |
| 运行中 | 进程结束、工具成功证据和结果核对一致 | 成功 |
| 运行中 | 进程结束且有可信工具失败或结果失败证据 | 失败 |
| 启动中/运行中 | 租约过期、Agent 失联或证据冲突 | 状态不变，附加“状态核对中” |

终态不可逆。成功、失败一旦由完整证据形成，重复或迟到的非当前租约事件不得改写；发现历史证据矛盾时追加异常审计并进入人工核查流程，不静默改终态。

### 13.3 终态证据矩阵

| 场景 | 进程事实 | 工具终态 | 结果事实 | 控制面结论 |
|---|---|---|---|---|
| 启动失败 | 未创建工具进程 | 无 | 无 | 失败：启动失败 |
| 明确成功 | 已结束 | 可信 `System exit 0` 或已确认等价证据 | 必需输出存在且核对通过 | 成功 |
| 明确工具失败 | 已结束 | 可信 `System exit 1`/失败事实 | 缺失或与失败一致 | 失败：工具执行失败 |
| 结果异常 | 已结束 | 成功或未知 | 必需输出缺失、损坏或核对失败 | 失败：结果核对失败 |
| 外层脚本 0、工具失败 | 已结束 | 可信工具失败 | 与失败一致 | 失败；忽略外层 0 的成功暗示 |
| Agent 失联 | 未知 | 未知 | 未知 | 保留状态 + 核对中 |
| 证据矛盾/缺失 | 已结束或未知 | 冲突/未知 | 冲突/未知 | 保留状态 + 核对中 |

“进程仍运行”不能进入失败；“外层返回 0”不能单独进入成功；“日志暂时没更新”不能单独进入失败。

## 14. 中断与恢复

### 14.1 Agent 重启或崩溃

Agent 启动后先读取本地持久状态，再领取新任务。当前实现先重放未获确认的脱敏日志批次；完整的进程身份恢复仍受后续门禁约束。控制面收到同一 Agent 身份的**新** `bootId` 时，会把仍持有活动租约的旧 execution 附加为“状态核对中”并写入审计，保留其原持久状态、租约和证据，绝不因此自动判定终态或重新派发。存在未释放 execution 时，完整恢复目标为：

1. 上报新 `bootId`、旧 execution 和最后本地事件序号；
2. 使用 PID、开始时间、进程树和信封摘要核对原进程；
3. 能证明仍运行时，请求控制面签发同一 execution 的延续租约（新 leaseId/leaseEpoch）并继续监管，不创建新 execution；
4. 能证明已结束时，上报持久终态、日志和结果证据；
5. 无法证明时上报 `LOCAL_RECOVERY_RESULT=UNKNOWN`，保持核对中；
6. 原 execution 未解除前，不领取新任务。

不得仅凭 PID 相同认定为原进程，防止 PID 复用。

### 14.2 控制面重启

租约、最后已确认事件序号和状态投影保存在 SQLite。控制面恢复后：

- 接受 Agent 对相同 requestId/eventId 的安全重发；
- 对已经过期但未核对的租约设置核对中，不自动改派；
- 使用控制面持久事实与 Agent 本地事实核对；
- 不要求 Agent 因控制面短暂不可用停止仍受监管的工具进程。

### 14.3 网络分区

Agent 在短暂网络中断时继续监管已启动进程并把事件写入本地待发送队列。租约无法续期后，Agent不得启动尚未启动的新进程；对已经启动的进程继续监管和取证，不因失去控制面连接擅自终止。恢复后按原 leaseEpoch 核对，旧 epoch 无权改变新事实。

## 15. 错误分类与证据

首条切片至少区分：

| 分类 | 例子 |
|---|---|
| `PROTOCOL_REJECTED` | 版本、身份、信封或摘要不匹配 |
| `AGENT_PREFLIGHT_FAILED` | 工具、Java、路径、容量或凭据校验失败 |
| `PROCESS_START_FAILED` | 操作系统拒绝启动、入口不存在或包装器立即失败 |
| `TOOL_EXECUTION_FAILED` | 工具已运行并给出可信失败事实 |
| `RESULT_VERIFICATION_FAILED` | 工具结束但必需输出事实不满足 |
| `COMMUNICATION_INTERRUPTED` | 心跳、租约或事件通道中断，当前结果未知 |
| `EVIDENCE_CONFLICT` | 进程、退出码、日志与结果事实矛盾 |

错误事件保存稳定错误码、发生阶段、控制面接收时间、脱敏原始消息和证据引用。不得把密码、机器凭据、完整敏感命令或未经脱敏的工具日志写入错误摘要。

## 16. 明确禁止

- 控制面通过 SSH、WinRM 或远程 shell 启动工具；
- Agent 接受浏览器直接命令或任意 shell 字符串；
- 因长轮询超时、心跳丢失或租约过期直接标记失败；
- 租约过期后自动改派同一任务；
- Agent 自行更换节点、工具版本、输出路径或参数；
- 只看 `.bat` 退出码形成终态；对象存储便利性例外也必须同时具备受控进程退出事实与固定成功终态事件；
- 丢弃未确认事件后继续推进状态；
- 通过重新生成 eventId/eventSeq 掩盖事件重发；
- 把完整日志正文重复保存到状态事件和 SQLite 状态记录；
- 为首条切片引入 Redis、消息队列、WebSocket 或独立调度服务。

## 17. 最小契约测试

### 17.1 领取与幂等

1. 两个并发领取请求只能有一个获得同一任务；
2. 同 requestId 重发返回同一租约，不增加 epoch；
3. 指定节点之外的 Agent 永远领不到任务；
4. 旧 leaseEpoch 的续期和事件不能改变状态；
5. 任务领取事务完成后即使响应丢失，重试也不创建第二次执行。

### 17.2 状态与终态

1. `PROCESS_STARTED` 前保持启动中；
2. 启动前失败且确认无进程时进入失败；
3. `.bat=0 + System exit 1` 必须进入失败；
4. 工具成功但输出缺失必须进入结果核对失败；
5. 只有完整成功证据才能进入成功；
6. 终态后的重复和迟到事件不改写终态；
7. 日志延迟不单独改变任务状态。

### 17.3 中断与恢复

1. Agent 在启动前失联：保持启动中并核对，不允许第二 Agent 领取；
2. Agent 在运行中失联：保持运行中并核对，不自动失败；
3. Agent 重启后能用持久日志恢复事件序号并重发未确认事件；
4. PID 被复用时不能误认原进程；
5. 控制面在事件提交前后分别崩溃，恢复后都不产生重复流转；
6. 网络恢复后的事件缺口能够从期望序号补传；
7. 无法证明进程或终态时保持核对中，不制造确定结论。

### 17.4 安全

1. 过期、复用和节点不匹配的关联材料均被拒绝；
2. 撤销机器凭据后不能心跳、领取或上传事件；
3. TLS 校验失败时 Agent 拒绝连接；
4. 未知关键字段、任意命令、未知秘密槽位和摘要不一致均阻断；
5. 协议、Agent 日志、本地执行日志和错误事件搜索不到测试秘密原值。
