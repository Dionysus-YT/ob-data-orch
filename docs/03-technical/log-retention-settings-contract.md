# 普通任务日志保留设置契约

2026-10-23 用户授权平台设置首条实际配置链路。范围仅普通任务脱敏日志，不新增任务历史、审计日志设置或手动清理入口；本轮仅本地实现与合成验证，不安装服务、不清理现役日志。

- 浏览器 `GET/PATCH /api/v1/settings/log-retention` 使用现有认证；读取、修改均要求当前 ACTIVE `ROLE_SYSTEM_ADMIN`。写入复验权限、CSRF、`If-Match: "rev-N"`、幂等键及 1–200 字变更原因。未知字段、秘密式原因及不完整请求失败关闭。
- `ordinary_log_retention_policy` 为独立单例，迁移仅初始化空覆盖与版本 1。覆盖值优先于启动配置 `logRetentionDays`；未覆盖时配置 0 使用内置 30 天，其余配置及覆盖只允许 7–365 天。返回实际天数、来源（`PLATFORM_SETTING/DEPLOYMENT_CONFIG/BUILT_IN_DEFAULT`）、版本、可用的修改人和 UTC 修改时间，不返回部署文件、安全配置或全平台任务数量。
- PATCH 仅接收 `retentionDays/reason/confirmed`；降低当前期限须 `confirmed=true`。同值为无修改回执，不创建覆盖、不递增版本。策略、审计和幂等回执在同一短 SQLite 事务提交；审计失败全部回滚。当前授权先于幂等重放，同键异内容拒绝。回执仅含 `revision/changed/replayed`，页面另读当前快照，不能把历史回执当当前状态。
- 保存与每批最多 64 段的清理共享可取消的串行门闩。每批重新读取 SQLite 策略，读取或校验失败跳过本批，禁止沿用旧值。门闩不扩展 SQLite 事务到文件操作。确认保存后新批次使用新策略；每小时及启动时的既有调度保持不变，不立即触发清理、不需要重启。
- 清理仍以终态任务结束时间为准；运行中、待核对和异常段沿用既有保护。已提交 `DELETING` 意图继续按原账本恢复，延长期限不能恢复已删除或撤回已登记清理的日志。页面降低确认明确指出该范围，不能承诺撤销。
- 页面独立持有读取、编辑和保存会话；取消、路由变化和卸载立即失效旧会话，取消请求，清除确认和原因。迟到读取、失败、finally 或写回执不得恢复旧编辑状态或重放成功。网络结果不确定时保留同一请求内容与幂等键供重试；修改内容产生新键。此时旧快照只标记为最近读取值、当前值待核对；取消仅结束编辑，不等同撤销服务器写入，重新读取前阻断新的编辑。

验收覆盖来源优先级、重启、越界/非整数、权限撤销、CSRF、版本冲突、幂等、降低确认、审计回滚、策略读取失败及保存与批次互斥；使用临时 SQLite 与合成段文件。实现与验证状态以任务地图及独立验收记录为准。
