# 技术路线与部署选型基线

> 文档状态：TS-R01～TS-R14 与首条切片最小实现契约已确认；目标平台运行验证待完成
> 适用范围：V1.0 与首条纵向切片
> 依据：TD-001～TD-008、首条切片 P0 真实环境证据
> 更新日期：2026-07-22

## 1. 结论先行

前端实现补充（2026-09-16）：保持 Vue 3 + TypeScript + Vite，Primitive 统一使用 Ant Design Vue；实际锁定版本、Canonical Token、产品组件契约、样式架构和升级验证见 [前端平台基线](frontend-platform-baseline.md)。P0/P1 和业务契约优先，不由框架默认值改变产品规则。

确认采用以下技术路线：

```text
Vue 3 + TypeScript + Vite
          ↓ HTTPS / JSON REST；日志增量使用 SSE
Go 模块化单体控制面
          ├── SQLite：业务元数据、任务租约、状态和审计索引
          └── 本机文件：分段后的原始脱敏日志
          ↑ Agent 主动发起 HTTPS 长轮询、心跳和批量日志上报
Go Agent（Windows AMD64 / Linux AMD64、ARM64）
          ↓ 受控子进程
Java 8 + OB Loader/Dumper 4.3.5
```

首版不引入 Redis、Kafka/RabbitMQ、Elasticsearch、Kubernetes、微服务拆分或通用工作流引擎。它们只有在单机关系库和受控 HTTP 通道出现可量化瓶颈后才重新评估。

SQLite 不需要独立数据库服务，符合当前轻量目标，但只在“单控制面实例 + 本机磁盘数据库文件 + 短写事务 + 原始日志文件化”的边界内成立。若未来要求多个控制面实例同时读写或数据库文件放在共享盘，必须重新评估客户端/服务端数据库，不能继续硬撑 SQLite。

TS-R01～TS-R14 已于 2026-07-21 确认。数据库采用 SQLite，平台正式支持 Windows AMD64，并将三个指定麒麟环境作为国产 Linux 白名单；首条切片最小实现契约和 DR-R01～DR-R18 已确认。当前允许 G1 工程骨架和 G2 合成数据隔离组件；相关 P0、认证接入、正式迁移和目标平台运行验证继续阻断 G3/G4。

## 2. 第一性原理判断

### 2.1 系统不可省略的能力

无论采用什么框架，平台都必须具备五类能力：

1. 浏览器中的复杂参数向导和管理页面；
2. 保存数据源、任务快照、状态和审计事实；
3. 在实际执行节点管理 Loader/Dumper 进程与文件；
4. 让控制面与 Windows AMD64、Linux AMD64/ARM64 Agent 可靠交换任务和事实；
5. 保证凭据、命令、日志和任务终态安全可追溯。

“轻量”不能删掉这些正确性要求，只能减少实现它们所需的独立组件和运维对象。

### 2.2 对初学者真正重要的轻量

- **少安装**：控制面一个 Go 程序、一个 SQLite 文件、一个静态前端目录；Agent 一个 Go 程序；
- **少语言**：后端和 Agent 统一 Go，页面统一 TypeScript；除 OBDUMPER 外，仅允许一个固定用途的 Java 8 JDBC 连接探针，禁止新增通用 Java 平台服务、业务模块或插件机制；
- **少中间件**：没有独立数据库服务、Redis、消息队列、搜索引擎或 Kubernetes；
- **清晰边界**：页面不启动工具，控制面不直接碰执行机文件，Agent 不决定产品参数；
- **可恢复**：程序、配置、数据库和日志各有明确位置，能够备份、检查和替换。

技术最少不等于文件最少或只用一种语言。把复杂向导硬写成服务端模板，或让 Node.js 同时承担浏览器、控制面和系统 Agent，表面少一种语言，实际会把进程、服务和类型边界混在一起。本项目采用 Go + TypeScript 是两种语言，但职责清楚，整体风险更低。

### 2.3 SQLite 是否合理

结论是“当前合理，但有条件”：

| 条件 | 当前判断 |
|---|---|
| 单控制面实例 | V1.0 接受；不做控制面集群 |
| 多个浏览器用户和多个 Agent | 可以；所有请求仍进入同一个控制面进程 |
| 并发任务 | 可以有限并发；数据库写事务必须短，工具运行不占用数据库事务 |
| 大量持续日志 | 不逐行写 SQLite；原始脱敏日志按任务分段写本机文件，SQLite 只保存索引和摘要 |
| 数据库文件位置 | 必须是控制面本机磁盘，不允许 NAS、NFS、SMB 或其他网络共享盘 |
| 高可用 | V1.0 不支持；故障恢复依赖备份与单实例恢复 |
| 多控制面实例 | 不支持；出现明确需求时迁移到 PostgreSQL 等服务型数据库 |

SQLite 官方将其定位为应用本地存储，并明确支持应用服务器把请求串到一个 SQLite 数据库的使用方式；WAL 可以让读取与写入并行，但仍只有一个写入者，而且不能工作在网络文件系统上。因此它适合当前单控制面轻量项目，不适合伪装成分布式数据库。

## 3. 选择驱动因素

选型按以下顺序判断，不以框架热度为依据：

1. 控制面和 Agent 必须正式支持 Windows AMD64、Linux AMD64 与 Linux ARM64；Linux ARM64 是国产操作系统的主要部署目标，不是次级兼容项；
2. 控制面是轻量模块化单体，不应因任务分发提前引入分布式中间件；
3. 控制面与 Agent 应尽量共用一种后端语言、协议模型和测试方式；
4. 任务提交、不可变快照、租约、状态事件和审计需要明确事务语义，但首版不需要独立数据库服务器；
5. 参数条件多且存在复杂向导、表格和日志页面，前端需要成熟的类型与组件生态；
6. OB Loader/Dumper 使用独立 Java 8 运行时，平台不能把自己的运行时与工具 Java 路径混为一谈；
7. 首条切片应能在当前 Windows 环境开发，并生成 Windows AMD64、Linux AMD64、Linux ARM64 三套控制面和 Agent 可发布产物。

## 4. 推荐技术栈

| 层级 | 推荐 | 版本策略 | 选择原因 |
|---|---|---|---|
| 控制面后端 | Go 标准库优先的模块化单体 | Go 1.26，构建时使用当前安全补丁 | 单二进制、跨平台、进程/并发模型直接；可与 Agent 共用协议和基础包 |
| 执行 Agent | Go 跨平台服务 | 与控制面同一 Go 主版本 | 无需在节点再安装平台运行时；与工具 Java 8 隔离；正式覆盖 Windows AMD64、Linux AMD64/ARM64 |
| Web 前端 | Vue 3 + TypeScript + Vite | Node.js 24 LTS；依赖锁文件固定 | 适合配置向导、条件表单和管理台；当前官方脚手架即采用 Vite |
| 元数据存储 | SQLite 3 | 随应用固定并记录实际版本 | 无独立服务和账号运维；单文件适合单实例控制面；通过短事务承载快照、租约、状态与审计索引 |
| 原始日志存储 | 控制面本机分段文件 | 格式版本化 | 避免持续日志写入与业务事务争用；SQLite 只保存任务、时间范围、级别、完整性和文件摘要索引 |
| 浏览器 API | HTTPS + JSON REST | `/api/v1` 起步，OpenAPI 作为契约 | 首条切片请求/响应边界清晰，便于权限、审计和契约测试 |
| 浏览器增量事件 | SSE | 仅任务状态与日志增量 | 浏览器主要是服务端单向推送，不需要为首版引入 WebSocket 双向协议 |
| Agent 通道 | 出站 HTTPS 长轮询 + 独立心跳 + 批量事件上报 | 协议版本化 | 满足 Agent 主动连接；经过常见防火墙；无需消息代理即可实现领取、租约和断线重连 |
| 数据库迁移 | 版本化 SQL 迁移 | 只允许前向迁移并在发布前验证回滚方案 | 保留真实 SQL 和审查能力，不先引入完整 ORM 模型生成体系 |
| 自动化测试 | Go 单元/契约测试、前端单测、浏览器关键链路测试 | 随首条切片建立 | 优先覆盖命令确定性、脱敏、状态机、任务租约和 Windows 进程适配 |
| 数据源连接探针 | 固定 Java 8 JDBC 子进程 | 复用 OBDUMPER 4.3.5 包内 `oceanbase-client-2.4.14.jar` | 避免引入第二套 Go 数据库驱动；仅测试私有 ODP 的连通、认证、基础 JDBC 连接和安全元信息 |

### 4.1 Go 使用边界

- 控制面与 Agent 位于同一仓库、不同可执行程序，共用协议类型、错误码、脱敏规则和版本信息；
- 业务模块不得直接依赖 HTTP、数据库或进程实现，通过明确端口隔离领域规则；
- 仅在必要处引入小型路由、SQLite 驱动、迁移和系统服务依赖，不选择一站式大框架；
- SQL 保持显式、可审查，领域对象不与数据表结构一一强绑定；
- Windows 与 Linux 使用各自的平台适配层；CPU 架构只影响构建产物和环境事实，不能在业务层散落架构判断。

### 4.2 Java 运行时隔离

平台不使用当前系统 `PATH` 中的 Java 作为隐式事实。每个执行节点分别配置并核验：

- Agent 自身不依赖 Java；
- OB Loader/Dumper 的工具目录；
- 工具专用 Java 8 可执行文件绝对路径；
- `HADOOP_HOME`、本地库搜索路径和工具所需环境变量；
- 启动时使用的工作目录、日志目录和完整任务输出路径。

Agent 通过显式环境块启动工具，不修改机器级环境，也不把控制面运行时与工具 Java 8 绑定。

数据源连接测试与 Agent 预检查允许启动固定主类 `com.obdataorch.jdbcprobe.ConnectionProbe`。该探针随 Agent 源码受控构建，类路径只允许其自身 JAR 与已核验的 OBDUMPER 包内 `oceanbase-client-2.4.14.jar`；它从标准输入接收短时二进制连接输入，拒绝任何命令行连接参数、环境变量秘密、任意 SQL、任意 JDBC URL、任意驱动或任意 Java 主类。它只建立 JDBC 连接并读取数据库/驱动的基础元信息，返回不含异常原文的结构化状态。该例外不改变“Java 不承载平台业务”的主路线，也不能用于导出、导入、权限诊断或任意数据库操作。

### 4.3 SQLite 运行边界

- 数据库文件、WAL 文件和共享内存文件必须位于控制面本机磁盘的同一目录；
- 启用 WAL、外键约束和合理的 busy timeout；具体值通过并发测试确定，不在产品文档猜测；
- 控制面只允许一个进程实例打开正式业务库；升级或恢复时先停止该实例；
- 长轮询等待、工具运行、文件复制和网络调用期间不得保持数据库写事务；
- 任务领取采用短原子事务和租约，不依赖 PostgreSQL 的 `SELECT ... FOR UPDATE`；
- 不把导出文件、原始凭据、完整命令明文或逐行原始日志写入 SQLite；
- 备份使用 SQLite Online Backup API 或 `VACUUM INTO` 形成一致快照，不在服务运行时直接复制单个 `.db` 文件；
- SQLite 驱动必须在 Windows AMD64、Linux AMD64/ARM64 上通过相同迁移、事务、崩溃恢复和备份恢复测试。2026-07-21 已验证 `modernc.org/sqlite v1.54.0` 在关闭 CGO 时可生成三目标产物，Windows 事务与备份运行通过；三套麒麟运行、升级和并发门禁通过后再最终锁定驱动，详见[SQLite 跨平台最小技术验证](evidence/component-validation.md#sqlite-platform)。

## 5. Windows/Linux 多架构基线

### 5.1 交付矩阵

前端静态资源与 CPU 架构无关，构建一次即可。首版至少交付并测试以下六个 Go 二进制：

| 产物 | Windows AMD64 | Linux AMD64 | Linux ARM64 |
|---|---|---|---|
| 控制面 | Windows Service 或前台受控进程 | systemd 或前台受控进程 | systemd 或前台受控进程 |
| Agent | Windows Service | systemd 服务 | systemd 服务 |

上述是构建产物矩阵，不等于支持所有 Linux 发行版。V1.0 国产 Linux 支持范围严格限定为以下三个认证目标：

| ID | 操作系统与版本 | 构建信息 | CPU/架构 | 已提供内核基线 | 当前状态 |
|---|---|---|---|---|---|
| OS-KY10-ARM | Kylin Linux Advanced Server V10 SP1（Tercel） | aarch64 Build20，2021-05-18 | Kunpeng 920 / `aarch64` | `4.19.90-23.8.v2101.ky10.aarch64` | 已纳入首版；平台集成待实测 |
| OS-KY11-ARM | Kylin Linux Advanced Server V11 2503（Swan25） | aarch64 Build20.01，2025-07-15 | Kunpeng 920 / `aarch64` | `6.6.0-32.7.v2505.ky11.aarch64` | 已纳入首版；平台集成待实测 |
| OS-KY10-C86 | Kylin Linux Advanced Server V10 SP3 2403（Halberd） | x86_64 Build20.01，2024-04-26 | Hygon C86-4G / `x86_64` | `4.19.90-89.30.v2401.ky10.x86_64` | 已纳入首版；平台集成待实测 |

海光 C86 对 Go 和 Linux 用户空间呈现为 `x86_64`，因此使用 `linux/amd64` 产物；两套鲲鹏系统都使用同一份 `linux/arm64` 产物，但必须分别完成系统集成验证。

除上述三个麒麟目标外，其他麒麟版本、统信、openEuler、其他 Linux 发行版、Linux 32 位 ARM、LoongArch、RISC-V、macOS 和 Windows ARM64 均不属于当前承诺。后续新增必须先补充兼容目标和验证记录。

### 5.2 控制面

- Windows AMD64、Linux AMD64 与 Linux ARM64 都是正式支持环境，使用同一份数据库迁移和 API 契约；
- 每套部署都是一个控制面实例和一个本机 SQLite 数据库文件，不能让两台控制面共享同一个数据库文件；
- 控制面进程同时提供 API 和构建后的静态前端资源；
- 数据目录、配置目录、日志目录由平台适配层给出默认值，并允许部署时显式配置；
- TLS 可由现有入口代理终止，若无入口代理则由控制面直接提供；具体证书来源在部署设计中确认；
- 首版不要求容器，后续可以补充容器镜像作为一种交付方式，但容器不是架构前提。

### 5.3 国产 Linux 适配边界

- 平台以 `linux/arm64`（AArch64）作为构建目标，不把“Linux ARM”模糊处理成 32 位 ARM；
- 控制面和 Agent 启动时记录操作系统、CPU 架构、发行版标识与版本、内核版本和平台构建版本；
- 国产操作系统以 5.1 节三个目标为白名单。不能只在任意 AMD64/ARM64 虚拟机运行一次就声称支持其他国产系统；
- 平台二进制优先关闭 CGO，减少对发行版 C 运行库的耦合；若 SQLite 驱动或后续依赖必须开启 CGO，则分别维护 Linux AMD64/ARM64 原生构建与运行测试；
- systemd 是默认服务交付方式；目标系统不使用 systemd 时，必须保留前台受控运行方式，并为该发行版补充明确服务脚本；
- 用户已确认目标国产 ARM 环境具备兼容的 OB Loader/Dumper 4.3.5、Java 8 和本地库。平台仍需验证环境发现、启动参数、日志采集、取消和终态核对集成，不再把官方工具的 ARM 能力本身列为待确认项。

### 5.4 Agent 与工具启动

- Windows Agent 调用工具包的 `bin/windows/obdumper.bat`、`obloader.bat` 或经验证的等价受控入口；
- Linux Agent 调用工具包的 `bin/obdumper`、`bin/obloader` 或经验证的等价受控入口；
- Agent 由运维人员在目标机安装并关联，平台不通过 SSH、WinRM 或远程脚本安装；
- Agent 只出站访问控制面，不开放远程命令、Shell 或通用文件接口；
- 工具进程在任务专属上下文中运行，记录 PID、开始时间、工具终态、结果事实和最后可信状态；
- Windows 导出实际参数中的 `--file-path` 原样使用任务快照保存的完整盘符绝对路径，例如 `E:\...\output-test`，不拆分工作目录、不改写成 URI、不自动追加子目录；
- Linux 导出实际参数中的 `--file-path` 原样使用 `/...` 开头的绝对路径；
- 控制面把任务路径作为不透明字符串保存，不跨操作系统转换；任务只能分配给路径类型匹配的 Agent；
- 节点同时上报 `os` 和 `arch`；调度只能把任务分配给已通过对应平台环境检查的 Agent；
- 已存在目录的可写性、工具待创建目录的父目录可创建性、剩余空间和非空判断由实际 Agent 完成，属于预检查，不得改变用户填写的路径或提前创建用户目录。

### 5.5 四类目标环境最小验证门禁

以下验证必须分别在 Windows AMD64 以及 `OS-KY10-ARM`、`OS-KY11-ARM`、`OS-KY10-C86` 实机或同等受控环境执行：

1. 控制面启动、静态前端、SQLite 初始化、迁移、事务、备份和恢复；
2. Agent 安装、服务启动、机器身份关联、心跳、重连和升级前版本核对；
3. 操作系统、架构、发行版、Java 和工具环境事实采集；
4. 本机绝对路径校验、目录权限、空间、非空目录和任务工作区隔离；
5. OBDUMPER/OBLOADER 版本与帮助输出采集；
6. 首条切片单表 CSV 导出、日志采集、工具终态、结果核对和重复执行；
7. 启动失败、工具失败、Agent 中断、进程清理和控制面重启恢复；
8. 平台与工具日志的用户名、密码和命令脱敏。

其中平台和 Agent 的单元/契约测试可在交叉编译环境执行，但服务、文件权限、进程信号和工具集成必须在对应操作系统与 CPU 架构上运行，不能用“编译成功”代替。

## 6. 首版任务通道

```text
Agent 启动并认证
→ 上报版本和环境事实摘要
→ 定期心跳
→ 长轮询领取一个带租约的执行任务
→ 确认任务快照与协议版本
→ 取得短时执行上下文
→ 执行本地预检查
→ 启动并监管受控工具进程
→ 批量上报状态事件和脱敏日志
→ 上报工具终态与结果文件事实
→ 控制面核对后形成平台终态
```

任务租约和状态更新使用 SQLite 短事务保护；同一控制面可以连接多个 Agent 并运行多个工具任务，但所有数据库写入最终由 SQLite 串行提交。工具运行期间不持有数据库事务。

不以 `obdumper.bat` 返回码单独判定终态。Windows 已观察到脚本返回 0、工具内部 `System exit 1` 的情况，必须结合受控进程、工具终态日志和结果文件事实。

## 7. 安全基线对选型的约束

- 浏览器会话使用安全、HttpOnly、SameSite Cookie；不把长期访问令牌放入浏览器本地存储；
- Agent 首次关联使用一次性、短时注册材料，关联后使用独立机器身份；具体采用 mTLS 还是等价证书方案在 Agent 协议评审中确认；
- 数据源密码仅以凭据引用进入任务，任务快照、计划命令、复制命令、日志和审计正文不保存明文；
- 正式工具执行不能把密码长期暴露在进程参数中；4.3.5 可用的安全注入方式必须先完成验证，无法证明时 VS-P0-09 继续阻断；
- Agent 在上传前做第一层脱敏，控制面入库前再次执行统一脱敏；原始工具日志默认不直接进入查询面；
- 所有协议消息包含任务、执行、Agent、协议版本和幂等标识，拒绝跨任务复用执行上下文。
- SQLite 文件不提供天然的服务端账号隔离。数据库文件、备份和日志目录必须使用操作系统文件权限保护；凭据仍需应用层加密或外部密钥引用，不能因为数据库是单文件就明文保存。

## 8. 明确不选的方案

| 方案 | 当前不选原因 | 何时重评 |
|---|---|---|
| 微服务 + Kubernetes | 当前模块规模和团队信息不足以抵消部署、链路和事务复杂度 | 单体出现可测量的独立扩缩容或发布隔离需求 |
| Redis 作为任务队列 | SQLite 已是首版事实库，当前任务量没有第二套持久化的证据 | SQLite 任务租约出现明确瓶颈且有压测证据 |
| Kafka/RabbitMQ | 首条切片只需可靠领取、心跳和事件上报 | 事件吞吐、重放或跨系统订阅形成已确认需求 |
| Elasticsearch/OpenSearch | 首版日志限定于任务与来源查询，尚无全文分析规模证据 | 关系库/分段存储无法满足已量化查询目标 |
| Electron 桌面应用 | 产品是多用户管理平台，不是单机工具壳 | 产品定位变化并经过重新立项 |
| Node.js Agent | 能实现但需要额外运行时和打包边界，Windows 服务及进程监管不是本项目的最小风险路径 | 团队只具备 TypeScript 能力且完成进程监管验证 |
| Java 8 平台后端/Agent | Java 8 仅为 4.3.5 工具兼容环境，不应成为新平台技术基线 | 不重评 |
| Java 21 控制面 + Go Agent | 技术上成立，但会增加一种后端语言和两套协议模型实现 | 团队 Java 能力显著强于 Go，且能承担双语言成本 |
| PostgreSQL/MySQL 作为首版元数据存储 | 独立数据库服务增加安装、账号、备份和升级成本；当前单控制面没有充分收益 | 明确要求多控制面实例、高可用或 SQLite 写入成为实测瓶颈 |

## 12. 官方依据

- [Go 发布历史与支持策略](https://go.dev/doc/devel/release)：Go 1.26 为稳定版本，官方支持最近两个主版本并持续发布安全补丁。
- [Go 支持的目标平台](https://go.dev/doc/install/source)：官方工具链明确支持 `windows/amd64`、`linux/amd64` 和 `linux/arm64`，ARM64 默认架构级别为 ARMv8.0。
- [Go Windows Service 包](https://pkg.go.dev/golang.org/x/sys/windows/svc)：提供 Windows Service 会话识别和服务运行接口。
- [Vue 3 官方快速开始](https://vuejs.org/guide/quick-start.html)：官方脚手架使用 Vite，并支持 TypeScript、Router、Pinia 和测试选项。
- [Node.js 发布计划](https://nodejs.org/en/about/previous-releases)：生产应用应使用 LTS，Node.js 24 当前处于 LTS。
- [SQLite 适用场景](https://www.sqlite.org/whentouse.html)：适合本地应用存储，也可由单一应用服务器封装为面向客户端的服务。
- [SQLite WAL](https://www.sqlite.org/wal.html)：读写可并发但只有一个写入者，且 WAL 不支持网络文件系统。
- [SQLite 锁与并发](https://www.sqlite.org/lockingv3.html)：SQLite 通过文件锁和事务保证原子性与一致性，写入冲突可能返回 `SQLITE_BUSY`。
- [SQLite Online Backup API](https://www.sqlite.org/backup.html)：支持在线、一致地生成数据库快照；也可使用 `VACUUM INTO`。
- [Server-Sent Events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events)：浏览器可通过标准 `EventSource` 接收服务端单向增量事件。
