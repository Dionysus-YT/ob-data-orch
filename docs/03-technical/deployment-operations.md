# 安装、使用与运维手册

本文面向安装和使用 OB Data Orch 的人员，适用于当前成品包的统一启动入口。快速概览见 [README](../../README.md)；实现依据为 [DEC-048](../01-product/decisions.md#dec-048-单一启动入口与-agent-运维简化)，准入与可用范围以[开发任务地图](development-task-map.md)为准。

## 源码开发模式

Windows AMD64 日常开发使用仓库根目录的 `scripts/dev.ps1`，不需要安装服务，也不用生成三目标 ZIP。首次执行 `npm --prefix web ci` 安装依赖，然后：

```powershell
# 终端一：控制面及前端 HMR
.\scripts\dev.ps1 -RealExecution

# 终端二：开发 Agent（需要节点联调时）
.\scripts\dev.ps1 -Agent -RealExecution
```

控制面固定地址为 `https://127.0.0.1:18443`，内部 Vite 使用 `127.0.0.1:15173`。首次启动会隐藏输入开发 `admin` 密码；需在本机信任 `var/dev/control-plane/data/control-plane-ca.pem` 公钥后访问网页。开发入口不修改系统证书库。

创建 Windows 节点后，在 Agent 终端粘贴注册码，无需下载 Agent 包。节点环境与启用条件仍正常校验。后续启动复用 `var/dev/agent/data/agent-security/` 身份，无需再次注册。监视器使用 `18444`、`18445` 回环端口防止重复运行；端口占用时退出，不接管已有进程。

| 修改内容 | 开发反馈 |
|---|---|
| `web/src/` 内 Vue、TS、CSS | Vite HMR，无需重编译控制面 |
| 对应 `cmd/`、`internal/`、`contracts/`、`migrations/` 的 Go、JSON、SQL，以及 `go.mod` / `go.sum` | 约一秒检测；真实模式只提示，结束测试后输入 `r` 并回车重建重启。合成模式自动重启 |
| Go 编译失败 | 保留数据；真实模式修复后输入 `r` 重试，合成模式等待源码变化重试；不运行旧程序冒充新版本 |
| 控制面重启 | SQLite、CA 和 Agent 身份保留；浏览器重新登录 |
| 启动器或开发配置变化 | 退出对应终端后重新执行入口 |

按 `Ctrl+C` 停止对应入口。固定停止标记触发正常关闭流程；停止超时则阻止二进制替换。不要直接关闭终端窗口来代替正常退出。

要停止整套开发环境，先结束当前测试任务，在 Agent 终端按 `Ctrl+C`，再在控制面终端按 `Ctrl+C`；后者会同时退出它管理的 Vite。关闭浏览器不等于停止开发服务。开发数据和身份会保留，下次使用相同命令启动即可。

`scripts/dev.ps1` 是开发用户入口；同目录的 `dev.mjs`、`dev-settings.mjs`、`dev-initialize.ps1` 是它依赖的实现文件，不能单独删除。`build-package.ps1` 用于稳定版本构建，`distribution/` 是安装包启动器，`tests/` 和 `verify*`、`check-secrets*` 属于验证工具；`build-jdbc-probe.ps1` 用于固定 JDBC 探针构建，`visual-regression-diff.ps1` 是通用图片差异工具。

`var/dev/` 在首次启动后生成。已有 `var/local-mvp.db`（含 WAL/SHM）、根密钥、`local-mvp-logs/` 和 `local-mvp-obdumper-4.3.5/` 仍可能承载旧数据、证据和测试工具，不因名称包含 `local-mvp` 就判定可删；它们不会由开发启动器自动迁移或删除。

开发实例只使用 `var/dev/`。`-RealExecution` 分别将控制面的 `var/dev/control-plane/data/settings.json` 和 Agent 的 `var/dev/agent/agent-config.json` 中 `realExecutionEnabled` 开启；后续启动保留原值，不再强制关闭。需要关闭时先正常退出对应开发进程，将该字段改回 `false`，再不带 `-RealExecution` 启动。全新配置未指定参数时仍为合成模式。

真实模式下可按当前已授权范围验证数据库、固定 JDBC 探针和官方工具；正常任务授权、环境校验、预检查、命令生成及证据门禁不变。前端 HMR 继续工作，Go 保存不会自动中断测试；输入 `r` 或 `Ctrl+C` 是明确重启/停止动作，执行前应结束当前测试。启动器清除继承的业务环境变量，但读取并保留本机持久化开关。HTTPS、管理员登录、CSRF、浏览器/机器身份隔离继续生效，只有认证后的页面与 HMR 转发给 Vite。

稳定后执行 `scripts/build-package.ps1`，再按安装包升级步骤交付。下文唯一菜单入口约束适用于安装包，不限制源码开发入口。

## 安装前准备

| 项目 | 要求 |
|---|---|
| 部署形态 | 一个控制面实例，连接一台或多台主动出站的 Agent |
| 控制面目录 | 固定的本机磁盘目录；SQLite 不放在网络共享盘 |
| 访问地址 | 浏览器和所有 Agent 均可访问的固定 HTTPS 地址，如 `https://orch.example.internal:8080`；不带业务路径 |
| 网络 | Agent 能向控制面 HTTPS 端口发起连接；控制面无需主动连接 Agent |
| Windows | AMD64；安装和菜单维护需要管理员权限，并使用同一 Windows 账户 |
| Linux | 仅限[技术栈指定的麒麟目标](technology-stack.md#51-交付矩阵)；需要 systemd 和入口使用的系统工具，安装目录的父目录须允许专用账户访问 |
| 执行环境 | Agent 机器准备 Java 8、OB Loader/Dumper 4.3.5；运行账户能访问所配置的工具与工作目录 |

控制面与 Agent 分机部署时，不要把访问地址设置成 `localhost` 或 `127.0.0.1`，这些地址在 Agent 上指向 Agent 自己。首次地址会写入证书与下载包，后续更换属于部署迁移。

Windows 安装时会用到两类密码：`admin` 密码用于网页登录；Windows 账户密码用于安装后台服务，不能用 PIN 替代。已有服务的维护账户不能随意更换，否则原加密身份可能无法读取。

> 服务安装和自启已实现，但 Windows 服务管理器安装、开机自启以及麒麟原生运行尚未完成验收。下面描述当前操作方式，不将这些未验收项视为已验证。

## 首次安装控制面

### 选择并解压完整包

按控制面机器选择 `ob-data-orch-windows-amd64.zip`、`ob-data-orch-linux-amd64.zip` 或 `ob-data-orch-linux-arm64.zip`。没有包时，按 [README 的构建步骤](../../README.md#从源码构建)生成。

解压后进入实际包含控制面程序的目录，保持以下内容一起部署：

```text
控制面安装目录/
├── control-plane.exe      Windows 程序；Linux 为 control-plane
├── 启动.cmd               Windows 用户入口；Linux 为 start.sh
├── manage.ps1             Windows 入口内部实现
├── web/                   已构建网页
├── agents/                各平台 Agent 分发素材
└── data/                  首次运行后生成，升级保留
```

`agents/` 是控制面生成下载包的素材，不是可直接注册的 Agent 安装目录。页面下载的包才包含当前控制面地址和 CA 公钥。

### Windows 启动

1. 右键 `启动.cmd`，选择“以管理员身份运行”。
2. 选择 **1 启动**，或直接回车。
3. 按提示输入固定 HTTPS 地址，为 `admin` 设置至少 8 个字符的密码。
4. 输入当前 Windows 账户的密码，完成服务安装。
5. 等待服务状态和 HTTPS 健康检查通过。入口随后将 CA 公钥安装到本机信任库，并显示访问地址。
6. 浏览器打开该地址，以 `admin` 和刚设置的密码登录。

### Linux 启动

在控制面解压目录执行：

```sh
chmod +x control-plane start.sh
sudo ./start.sh
```

选择 **1 启动**，填写访问地址及 `admin` 密码。入口建立专用账户 `ob-data-orch` 和同名 systemd 服务，随后检查服务与 HTTPS 健康状态。Linux 包的交叉构建不代表目标机器运行已验收。

### 浏览器证书信任

Windows 控制面入口会处理本机信任；从其他机器访问或在 Linux 上使用浏览器时，需要通过所用系统或浏览器的证书管理功能信任控制面 `data/control-plane-ca.pem`。先核对文件来自这台控制面，随后使用证书对应的配置地址访问。

Agent 下载包已经带入相同的 CA 公钥，不需要人工配置 CA 路径。普通重启和升级保留原信任根，叶证书由程序自动续期。不要通过删除证书或私钥来处理信任错误。

## 安装与关联 Agent

1. 登录网页，进入“执行节点”，创建节点。
2. 按执行机器填写平台、Java 路径、工具路径、允许目录等页面要求的配置。路径属于 Agent 机器，不是浏览器或控制面机器。
3. 在节点页面取得注册码并下载对应平台的 Agent 包。注册码单次使用、24 小时有效；不要把它保存到日志或命令参数中。
4. 将包解压到执行机器的固定目录。
5. Windows 右键 `启动.cmd`，以管理员身份运行；Linux 在目录内执行下方命令。
6. 选择 **1 启动**，首次按提示粘贴注册码。Windows 首次安装服务还需当前 Windows 账户密码；Linux 使用专用账户 `ob-data-orch-agent`。
7. 回到节点页面检查关联结果、最新心跳和环境检查。新节点环境检查通过后，执行页面“启用”操作。

```sh
# 仅用于 Linux Agent 安装目录
chmod +x agent start.sh
sudo ./start.sh
```

Agent 包应包含：

```text
Agent 安装目录/
├── agent.exe              Windows 程序；Linux 为 agent
├── 启动.cmd / manage.ps1   Windows 入口；Linux 为 start.sh
├── agent-config.json      控制面地址、状态目录与执行开关
├── control-plane-ca.pem   控制面 CA 公钥
└── data/agent-security/   运行后生成的身份、状态与日志
```

正常重启和升级复用原身份，不需要再次注册。注册码过期或首次关联未完成时，根据页面提示重新取得注册码并重试；已有身份损坏时应恢复原材料，不能靠清空身份目录重新关联来处理。

编辑节点的 Java、工具或允许目录后，Agent 会在空闲时同步并检查，运行中的工具继续使用原配置。页面出现“等待同步”时等待心跳和配置应用；出现“环境不满足”时根据检查结果修正目标机器环境。已有节点保留管理状态，但配置与检查未对齐前不能接收新任务。

## 网页使用与真实执行

### 操作顺序

1. **执行节点**：确认节点已关联、在线、环境满足且已启用。
2. **数据源**：维护目标连接信息；在真实验证已获授权时，选择执行节点进行连接测试，查看结果后再按页面条件启用数据源。
3. **导出向导**：选择数据源并完成内容、对象、格式、运行与输出配置；只使用当前页面开放且有验证依据的能力。
4. **预检查与提交**：先看预检查结果，解决阻断项；通过后由操作者提交任务。
5. **任务中心**：查看状态、日志及结果证据。Agent 在线、受控进程结束和结果已验证分别代表不同事实，不能互相替代。

对象存储在远端 MANIFEST 取证接入前，即使任务证据投影为 `VERIFIED`，空的文件数、字节数和清单也不代表远端对象已逐项核实。真实能力范围查任务地图与对应验证记录。

### 开启获授权的真实执行

安装包默认 `realExecutionEnabled=false`。开启前须满足任务地图规定的环境、授权及证据要求；修改开关本身不代替这些条件。

1. 从控制面菜单停止服务。
2. 在原 `data/settings.json` 中仅将 `realExecutionEnabled` 改为 `true`，保留其他设置；通过菜单重新启动并确认健康检查。
3. 新下载的 **Windows** Agent 包会携带当前设置。已有 Windows Agent 应先从其菜单停止服务，在原 `agent-config.json` 修改同名字段，再启动并确认节点心跳。
4. 完成页面中的连接测试、预检查及提交条件后，再运行已获授权的任务。

普通节点配置同步不会远程开启这个开关。Linux Agent 包保持真实执行关闭；不要通过修改开关外推 Linux 真实执行支持。需要关闭时，在两端停止对应服务、将同名字段改回 `false` 并重新启动。

## 日常操作

所有操作都从原安装目录的同一菜单进入，Windows 使用 `启动.cmd`，Linux 使用 `sudo ./start.sh`。

| 选项 | 含义 | 操作后检查 |
|---|---|---|
| 1 启动 | 首次安装或启动已有服务 | 控制面健康检查及登录页；Agent 节点心跳 |
| 2 停止 | 停止当前目录对应的服务 | 对应服务停止，数据和身份保留 |
| 3 升级 | 从独立解压目录安装新版本 | 见下方升级步骤 |
| 4 查看状态 | 查询本机系统服务状态 | Agent 是否在线仍以节点页面为准 |

Windows 服务名分别为 `OBDataOrch`、`OBDataOrchAgent`；Linux 为 `ob-data-orch`、`ob-data-orch-agent`。菜单只管理对应服务，不会同时启动另一台机器的组件。关闭浏览器或菜单窗口不会停止已启动的后台服务。服务已配置自动启动及故障重启，实际开机自启仍需目标机验收。

## 升级与故障恢复

### 普通安装包升级

1. 准备与原组件、平台和架构匹配的新版包，解压到**独立目录**。控制面使用完整控制面包；Agent 使用由控制面页面下载的 Agent 包。
2. 确认当前任务状态，安排允许短暂不可用的维护时段。控制面和每台 Agent 分别升级。
3. 在**原安装目录**运行启动入口，选择 **3 升级**，填写新版包解压后的实际程序目录，不是 ZIP 文件路径。
4. 入口核验新版程序及必需文件后停止旧服务，再删除旧程序、安装新版并更新启动器。Windows 控制面还检查监听端口已关闭；Linux 当前实现依赖 systemd 停服，不具备同等的独立端口关闭复核。
5. 等待恢复检查：控制面须通过 HTTPS 健康检查并能登录，Agent 须在节点页面恢复心跳。服务状态为运行中不单独证明 Agent 已连接。

升级保留原 `data`、`agent-config.json` 和 CA，不将新版下载包中的配置覆盖到现有 Agent。升级遇到复制或健康检查失败时，不能视为完成，也不要假定已自动回滚；保留原身份材料，按下方日志定位后从原目录恢复服务。

### 2026-09-14 旧入口首次更新

旧启动器不会自动更新自身，且 Windows 旧版可能误拒绝无空格安装路径。首次采用 2026-09-15 修复时：

1. 关闭旧菜单窗口。
2. 将新版包中的 `启动.cmd` 和 `manage.ps1` 复制到原 Windows 安装目录；Linux 仅复制 `start.sh`，必要时恢复可执行权限。
3. 不手工覆盖运行中的程序、`data`、配置或 CA。
4. 从更新后的原目录入口执行普通升级。后续升级会自动更新启动器。

### 旧 Local MVP 部署迁移

旧 Local MVP 的运行参数、数据布局与当前服务安装方式不同，不能将一个新包直接覆盖到旧目录后就视为迁移完成。仓库内源码和成品构建不会自动迁移现有部署。

迁移时需要核对并完整保留：

- 控制面原数据库 `var/local-mvp.db`、根密钥 `var/local-mvp-root-key.json` 和日志 `var/local-mvp-logs`，以及原 TLS 信任材料。
- Agent 原身份目录的绝对位置、CA、控制面地址、运行账户及原执行开关。
- 旧服务的启动参数与工作目录。Windows 身份保护依赖原账户，不能靠复制到另一账户或另一机器直接恢复。

先明确原布局到新安装目录的映射及恢复方式，再停止旧服务、确认端口关闭并执行迁移。当前下载包的状态目录使用包内相对路径，不能把旧身份绝对路径直接填入新包配置。地址、信任根、账户或身份目录发生变化时，须按独立迁移处理，不能套用普通升级步骤。

## 数据与日志位置

以下路径均相对于对应组件的安装目录：

| 组件 | 路径 | 用途 |
|---|---|---|
| 控制面 | `data/settings.json` | 访问地址、登录校验配置和真实执行开关 |
| 控制面 | `data/local-mvp.db` | SQLite 业务数据；文件名兼容历史 |
| 控制面 | `data/local-mvp-root-key.json` | 原数据解密依赖的根密钥 |
| 控制面 | `data/control-plane-ca.pem` | 可分发给浏览器与 Agent 的 CA 公钥 |
| 控制面 | `data/service.log` | 服务启动与故障诊断 |
| 控制面 | `data/local-mvp-logs/` | 持久化任务日志 |
| Agent | `agent-config.json`、`control-plane-ca.pem` | 连接配置与信任 |
| Agent | `data/agent-security/` | 加密身份、状态与恢复材料 |
| Agent | `data/agent-security/service.log` | Agent 服务诊断 |

维护时保留完整 `data` 目录，不能只保留数据库而遗漏密钥或 TLS 私钥。除 CA 公钥外，不分发身份和密钥材料；也不通过删除 `settings.json`、数据库或身份目录来“重置”故障。

## 常见问题

| 现象 | 检查方法 |
|---|---|
| Windows 提示需要管理员或原账户 | 以原安装账户运行，并选择“以管理员身份运行”；服务安装输入 Windows 密码，不是 PIN |
| 提示服务安装在其他目录 | 返回原安装目录；若使用 2026-09-14 旧入口，先按上文更新启动器 |
| 控制面健康检查失败 | 检查 `data/service.log`、配置的地址和端口、CA 与私钥是否完整；不要跳过证书验证 |
| 浏览器提示证书不受信任 | 信任这台控制面的 CA 公钥，并使用配置地址访问，不能任意改成另一个主机名 |
| Agent 下载提示包缺失 | 控制面必须部署完整 `agents/` 分发资源，重新构建并通过菜单升级完整包 |
| Agent 注册失败 | 检查注册码时效、下载包是否来自当前控制面、目标机能否访问配置地址；查看 Agent 日志 |
| Agent 服务运行但页面离线 | 检查控制面可达性、证书、Agent 日志与最新心跳；服务运行状态不等于关联成功 |

| 升级失败或服务未恢复 | 保留原配置和身份，查看日志及失败步骤；确认恢复成功前不要继续提交任务 |
